# 人物关系数据编码手册（CODING）

> 适用数据：`dataset/character-relationship-3d.json`（22 节点 / 32 边）
> 版本：v0.1.0 · 批次 W1138 · 更新日期 2026-11-05
> 编码者：项目维护者（人工整理）
> 文本依据：世德堂本（明万历二十年，1592）为底本，参校人民文学出版社整理本

本手册说明这份关系网络**怎么编、为什么这么编、哪些地方不能当结论用**。它是数据字典的一部分，不是文学评论；目标是让另一个研究者能复现、能质疑、能逐条纠错。

---

## 1. 这份数据是什么，不是什么

**是什么**：一张人工整理的《西游记》人物关系示意网络，覆盖取经团、天庭、佛门、妖界与龙族五个阵营的 22 个节点和 32 条关系边。

**不是什么**：

- 不是全量人物关系抽取。22 个节点是示例性选择，不等于全书人物总数。
- 不是统计推断样本。节点与边的规模不足以支撑度中心性、聚类系数或显著性检验的推断性结论。
- 不是 NLP 共现网络。站内另有一套基于 100 回原文抽取的共现网络（35 节点 / 329 边，权重=同回/同场景共现次数），两套口径不同，**不可混用**。
- 不是原文引文汇编。`summary` 是情节转述；如需引用原文，须先跑 `scripts/_cite_probe.py` 核对，不能把转述当引文。

## 2. 字段定义

### 2.1 数据集级 `meta`

| 字段 | 含义 | 必填 |
|---|---|---|
| `title` / `version` / `w_id` / `direction` | 页面原有元信息，保留不改 | 是 |
| `coding_version` | 编码规则版本；规则改动时递增 | 是 |
| `provenance_batch` | 本版溯源字段落地的批次号 | 是 |
| `coder` | 编码者标识（人或 agent 名称） | 是 |
| `updated` | 最近更新日期（YYYY-MM-DD） | 是 |
| `text_source` | 文本依据版本 | 是 |
| `coding_doc` | 指向本手册的仓库相对路径 | 是 |
| `evidence_policy` | 证据级别与标注规则摘要 | 是 |
| `weight_method` | 权重评分方法摘要 | 是 |
| `note` | 使用边界声明 | 是 |

### 2.2 节点 `nodes[]`

| 字段 | 含义 | 必填 |
|---|---|---|
| `id` | 节点编号，边引用它 | 是 |
| `name` | 人物名 | 是 |
| `group` | 页面聚类编号 0–4 | 是 |
| `faction` | 阵营中文名：取经团 / 天庭 / 佛门 / 妖界 / 龙族 | 是 |
| `importance` | 页面视觉权重 1–10，**不是**统计指标 | 是 |
| `desc` | 一句话人物定位 | 是 |
| `evidence` | `文本事实` 或 `解读假设` | 是 |
| `chapter_range` | 主要登场回目区间（叙述性） | 是 |
| `source_chapters` | 关键回目示例（不是穷举） | 是 |
| `note` | 边界说明（跨阵营、身份变化等） | 否 |

### 2.3 边 `links[]`

| 字段 | 含义 | 必填 |
|---|---|---|
| `source` / `target` | 节点 `id` | 是 |
| `type` | 页面显示用的关系类型 | 是 |
| `relation` | 归一化关系类型（与 `type` 同值，供检索） | 是 |
| `rule` | 编码规则编号（E-01 ～ E-07） | 是 |
| `chapters` | 来源回目，整数列表，范围 1–100 | 是 |
| `summary` | 情节转述（不是原文引文） | 是 |
| `rationale` | 判定理由，须能回到 `rule` | 是 |
| `evidence` | `文本事实` 或 `解读假设` | 是 |
| `weight` | 人工关系强度评分 0–1 | 是 |
| `weight_basis` | 权重档位编号（W-1 ～ W-4） | 是 |
| `weight_basis_label` | 权重档位中文说明（如「核心关系」） | 否 |
| `disputed` | 是否有编码争议 | 是 |
| `source_note` | 回目列举与转述边界说明 | 是 |

## 3. 关系类型与判定规则

一条边只归一个主类型；同一对人物若同时存在合作与冲突，按**当前边所表达的语义**取主类型，并在 `summary` 里注明另一面。多类型冲突时优先级：亲缘 > 师徒 > 从属/授职 > 敌对/冲突 > 合作/互助 > 索取/授予 > 同僚/并列。

| 规则 | 类型 | 判定标准 | 正例 | 反例（为什么不算） |
|---|---|---|---|---|
| E-01 | 师徒 | 有明确拜师、收徒、逐徒或随行至西天的事件 | 唐僧—悟空（第 14 回收徒，第 27 回逐徒） | 仅同路而行、无师徒名分者不算 |
| E-02 | 亲缘 | 文本明确父子、母子、夫妻、兄弟 | 牛魔王—铁扇公主（夫妻） | 同殿为将不自动算兄弟 |
| E-03 | 从属/授职 | 天庭或佛门内部有明确君臣、授职、调遣 | 玉帝—托塔天王 | 仅出现在同一场景不算 |
| E-04 | 敌对/冲突 | 有明确交战、擒拿、击杀、反叛或对抗 | 悟空—白骨精（第 27 回） | 单次口角若无冲突事件，降为对话/合作 |
| E-05 | 合作/互助 | 有明确救助、结盟、并肩作战 | 悟空—牛魔王（第 3 回结拜） | 单方受惠但无互动，不算 |
| E-06 | 索取/授予 | 有明确求取法宝、传授经文、授职 | 悟空—东海龙王（第 3 回借宝） | 仅提及宝物归属，不算 |
| E-07 | 同僚/并列 | 同一体系内职衔并列，但文本未直接称同僚 | 观音—文殊 | 必须有职衔或体系依据；纯读者联想不算 |

## 4. 权重规则

`weight` 是**分析者的人工强度评分**，不是互动次数，也不是统计概率。

| 档位 | 分值 | 含义 | 示例 |
|---|---|---|---|
| W-1 | 1.0 | 核心关系：主线结构或明确亲缘 | 师徒四对、如来—唐僧、牛魔王—铁扇公主 |
| W-2 | 0.8 | 多次互动：跨多个回目反复出现 | 悟空—二郎神、悟空—铁扇公主 |
| W-3 | 0.6 | 单次事件或间接关系 | 悟空—东海龙王、红孩儿—牛魔王 |
| W-4 | 0.4 | 间接推断或弱关联 | 本数据暂未使用 |

评分示例：`唐僧—悟空` 取 1.0，因为第 14 回收徒、第 27 回逐徒、第 57–58 回真假美猴王、第 100 回成佛构成主线；`悟空—东海龙王` 取 0.6，因为核心事件集中在第 3 回借宝。

## 5. 证据级别

| 级别 | 判定 | 处理 |
|---|---|---|
| `文本事实` | 关系有明确情节事件或文本称谓支撑 | 必须能落到 `chapters` 与 `summary` |
| `解读假设` | 关系标签依赖解释框架或读者归类 | 必须在 `rationale` 写明「按…归类」，并建议 `disputed: true` |

**本次标为解读假设的边**：

- 观音—文殊、观音—普贤：同僚/并列是职衔归类，文本未直接称同僚。
- 二郎神—哪吒：兄弟是同袍类推，不是文本亲缘。
- 悟空—六耳猕猴：宿敌是关系标签，文本呈现为真假之争。

这些边保留在图中，但引用时不得当作文本事实。

## 6. 节点阵营边界案例

| 节点 | 归属 | 理由 |
|---|---|---|
| 观音菩萨 | 佛门 | 跨天庭/佛门，按取经事业中的授职归佛门 |
| 白龙马 | 取经团 | 西海龙王三太子，但随行后按团队身份归取经团 |
| 牛魔王 | 妖界 | 最终归顺佛门，按主要身份与出场语境归妖界 |
| 六耳猕猴 | 妖界 | 假冒悟空，按事件身份归妖界 |
| 黄袍怪 | 妖界 | 奎木狼下凡，按事件身份归妖界 |
| 二郎神 | 天庭 | 玉帝外甥，受天庭调遣 |

阵营是**页面聚类用的粗分类**，不是严格的宗教或政治身份判定。

## 7. 解释框架声明（团队动力学数据另见）

`dataset/pilgrim-team-dynamic-network.json` 中的 Belbin 角色、Tuckman 阶段与群体动力学映射，属于**本文采用的解释框架**，不是《西游记》文本自带的结论。引用这些内容时：

- 必须标为「解读假设」，不得与文本事实混写；
- 不得把「震荡期 38 回」当作文本给出的分期，它只是分析者按冲突密度做的切分；
- 不得据 5 节点 / 10 边或 22 节点 / 32 边做统计推断；
- 相关页面应显示边界声明（关于页与团队动力学页已有说明）。

## 9. 校验与纠错

```bash
python scripts/check_dataset_provenance.py
```

该命令与 `verify_delivery.py` 第 61 门禁同源：校验 22 节点 / 32 边网络与 `edge-wukong-tangseng.json` 的 9 组标杆事件；字段完整性、节点引用、回目 1–100、规则编号、权重 0–1、证据级别、重复边、`disputed` 边 rationale、引文回目落在事件区间、**每条引文去空白后必须是 `dataset/text-search.json` 对应回目原文的精确子串**（W1145 起，伪造/改写引文即判红）、`edge_weight = max(event_weight)`、页面 `EMBEDDED_DATA` 同步标记。提交前全量 verify 会自动执行，不再依赖人工记得跑。

发现编码错误时，请开 GitHub Issue（模板：数据纠错 / 编码争议），写清：

- 数据集与边（source → target）
- 当前编码
- 你建议的编码
- 依据回目与原文摘要（原文引用请先跑 `scripts/_cite_probe.py`）

## 10. 引用边界

> 本网络是**示意性人工整理网络**，用于展示人物关系的结构性样貌，不用于统计推断。引用具体边时，请同时引用 `chapters` 与 `rationale`，并注明「编码者人工判定」。
