结构：

```json
{
```

## 2. line 号口径判定（最重要陷阱）

### 单回内行号（正确口径）

格式：`第 N 回 line X`，X 为小数字（1~99）。含义：引文在第 N 回正文内的第 X 行。这是 text-search.json `text` 字段按 `\n` 拆行、1-based 定义的**唯一正确口径**（line_check.py 失效前用的也是同一口径）。

### 全书累计行号（易崩坏口径）

格式：X 为大数字（如 1459 / 4378 / 4432）。含义：从第 1 回第 1 行累计到全书某个位置的绝对行号。**本项目不采用此口径**，论文里若出现这种大数字，几乎必然对不上，需重做。

### 判定方法

- 抓出所有锚点，X > 100 的即为累计口径（可疑），X 在 1~99 的为单回口径。
- 同篇论文若两种数字混用（如既有 line 51 又有 line 1459），说明混用了两套口径，逐条重做。

### 验证方法（用 text-search.json）

⚠️ **重要前提**：`text` 字段里大量行含「中文字符间空格」（全书约 1700 行，如「我今 熟读了牒文」），而论文引文通常已去掉空格。**验证前必须先把原文和引文都去掉所有空白再匹配**，否则会误报 NO_MATCH。

对每条锚点，用内联 Python 读 `dataset/text-search.json`，去空白后在对应回的 `text` 字段里定位引文并输出行号：

```bash
cd /d/1/xiyouji && python - <<'PYEOF'
import json, re
d = json.load(open('dataset/text-search.json', encoding='utf-8'))
ch = d['chapters']

def norm(s):
    return re.sub(r'\s+', '', s)

def find(n, kw):
    lines = ch[n-1]['text'].split('\n')
    hits = [i for i, l in enumerate(lines, 1) if norm(kw) in norm(l)]
    print(f'第{n}回「{kw}」:', [f'line {i}' for i in hits] or 'NO_MATCH')

# 逐条填写待验证锚点
find(7, '皇帝轮流做')
find(29, '倒换文牒')
find(57, '我今熟读了牒文，我自己上西方拜佛求经')
PYEOF
```

输出的行号必须与论文声称的 X 一致，否则就是错误锚点。批量验证时把全部锚点写成多行 `find(回目号, 引文)`。

## 3. 回目陷阱

回目标题（如「心猿归正 六贼无踪」）在 `title`/`fullTitle` 字段，`text` 字段只含正文（不含回目）。

因此「回目 + line 号」组合（如 `第 14 回 line 1459 回目"心猿归正"`）**本身不成立**——无论单回还是累计口径都命中不了。

正确处理：删掉 line 号，改成「第十四回回目『心猿归正 六贼无踪』」。

## 7. 常见失误自检

- 直接改原文却忘了同步匿名稿（或反之）——两份要一起改，锚点口径一致。
- 把「全文累计行号」误当「单回行号」直接沿用——大数字（>100）必须重做。
- 把诠释性表述硬挂 line 号——引文必须是 text 里能命中的原文句子。
- 匿名稿改了正文却没删「关联文档」段——该段是最大的项目痕迹源。
- **验证时没去空格就精确匹配**——text 字段约 1700 行含「中文字符间空格」，论文引文通常无空格，直接匹配会 NO_MATCH。必须去空白后再比。

## 8. 批量校验脚本 verify_anchors.py

同目录附带 `verify_anchors.py`，把「去空白匹配 + 行号定位 + 批量重定位」封装成三个子命令，替代手工逐条写 `find()`。它只读 `dataset/text-search.json`（不碰已失效的 line_check.py），默认项目根目录 `D:/1/xiyouji`，可用 `--root` 覆盖。

三个子命令：

- `peek <回号> <line>`：查看某回某行的原文，判断原锚点行号内容对不对。
- `locate <回号> <关键词...>`：在该回内去空白搜关键词，返回命中行号，用于重定位。
- `batch <anchors.json>`：批量校验 + 重定位，输出对照报告。

`anchors.json` 格式（`line` 为论文声称的行号，`kws` 为释义对应的原文关键词）：

```json
[
  {"num": 29, "line": 3, "desc": "呈递关文遇黄袍怪", "kws": ["倒换文牒", "关文"]},
  {"num": 14, "line": 1459, "desc": "心猿归正回目", "kws": ["心猿归正"]}
]
```

示例：

```bash
python verify_anchors.py peek 29 3
python verify_anchors.py locate 29 倒换文牒 关文
python verify_anchors.py batch anchors.json
```

`batch` 对每条输出「原行实际内容 → 建议改为 line X（命中原文）」，并把「关键词命中回目（title/fullTitle）但正文无命中」的情况标为「回目+line 不成立」。脚本内部已做去空白匹配，无需像内联 `find()` 那样手写 `norm()`；但若要对匹配结果做二次人工核对，仍可回到内联 `find()` 逐条确认。
