# 门禁红灯定位模板（W1022 沉淀 · 配套 gates.md 的 52 槽定义）

> `gates.md` 讲「每一槽判什么」，本文讲「**红了怎么查**」。定位错层会把真缺陷修成假绿。

## 五步法（按顺序，不许跳）

1. **读 FAIL 行原文**，不读汇总数字。汇总只会说「1 项核心 FAIL」，原文才给出脚本名与退出码。
2. **单跑该脚本**（不要重跑全量——全量 13 分钟，单脚本通常 <1 分钟），拿到完整明细与自带自测：
   `python scripts/check_xxx.py` → 若支持，再跑 `--self-test` 确认判据本身没坏。
3. **读判据源码**（30 行以内就够），问三个问题：
   - 它的**事实源**是什么（文件？git 索引？台账？磁盘实算？）
   - 它**怎么定位**（固定下标？正则？位置判定？）
   - 它**怎么判定**（阈值？子串？白名单？）
4. **分类**：属于哪一类——
   - **数据错**：产物真的错了 ⇒ 修数据
   - **判据错**：真正当的事被误判 ⇒ **改判据**（不是补数据去迎合）
   - **期望值过期**：判据正确但基线是上一批的 ⇒ 重算期望值
   - **未落盘/未暂存**：多数 `C4-f`「漏 add」属此类 ⇒ 先 `git add` 再看
5. **选修法并写进批次记录**：① 改数据 ② 改判据 ③ 改期望值 ④ 归档 ⑤ 登记留痕（须写理由）。

## 四条红线

- **禁止用豁免/白名单把红灯压绿**。豁免是给「设计上就应该例外」的，不是给「我不想修」的。
- **禁止为迎合脆弱判据补产物**（如往文件里塞识别串）——那是补丁加补丁（用户令·坑表 E-25 族）。
- **禁止在判据未执行时判绿**（门禁脚本异常必须 WARN 留痕，禁静默跳过）。
- **禁止只看汇总数字**：`核心全部通过` 与 `1 项核心 FAIL` 之间可能差着 353 条明细。

## 高发误判（本项目实证）

| 症状 | 真因 | 处置 |
|---|---|---|
| 某槽昨天绿、今天红，产物没变 | **增量缓存按页 hash**：改了别的页让缓存失效，暴露存量问题 | 查是否存量（对照 HEAD 版本），存量登记基线而非硬修 |
| 一改就红一大片（200+ 页） | **判据靠脆弱特征**（如块内注释文本、固定下标、子串） | 改判据（W1019：注释剥离后 228 页误判 → 改标记配对） |
| 只有 1–2 个文件红，且都是刚 mv/renamed 的 | **索引态路径集**含删除侧旧路径 | 删除侧也要进 spec 的 `file_index_rows`（W1019/51 槽实证） |
| 目录文档红，提示「先 git add 再 refresh」 | 生成器**按 Git 索引收集** | `git add` 之后才跑 `gen_folder_docs.py --refresh`（W1019 实证） |
| 台账/文档一加行就超窗 | **只进不出**（行窗/段窗） | 跑对应归档器，禁止只加标记不迁出（W1020/1021） |
| 规则/脚本文档写着旧判据 | 改了实现没改 docstring | 同批订正（W1022 P3：`check_token_coverage` 头注仍写已废判据） |

## 变红的两种「好红」

- **门禁抓到了真缺陷**（W1022：`check_audit_trigger` 的 fail-open——写一行在途登记即可永久压制告警）。
- **门禁自测抓到了自己的判据缺陷**：`--self-test` 失败优先于业务失败处理，
  因为它说明「判据已不可信」，此时任何绿灯都没有意义。
