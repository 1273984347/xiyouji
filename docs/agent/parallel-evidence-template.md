# 并行取证模板（W1022 沉淀 · 回答「为什么只派一个 subagent」）

> **一句话**：**判断串行、取证并行**。需要跨项串联才能得出的结论，交给单个 agent；
> 可穷举、结果可机械汇总的取数，拆成 N 个 agent 并行。

## 何时并行 / 何时串行

| 任务形态 | 派法 | 理由 |
|---|---|---|
| 逐条/逐页穷举（29 条 Backlog 对账、857 页链接扫描、87 页逐页检查） | **并行** N 份 | 条目之间互不依赖，汇总 = 拼接 |
| 需要跨项串联的归因与定级（对抗审查 A–G 全项） | **串行** 单份 | 见下「交叉印证会丢」 |

**实证（W1022）**：对抗审查若拆成「仓库+守恒」「门禁实跑」「代码审查」「文档三层」四份，
则「330 页工作树全 CRLF 与 `.gitattributes eol=lf` 背离」这条 **P2 永远抓不到**——
它是 B 项（`git ls-files --eol` 看到 `i/lf w/crlf`）与 D 项（读 `open(..., "w")` 文本模式）
**在同一个视角里串起来**才成立的。同源还有 P3「`--force` 非幂等」（D 项读码顺手复现）、
P2-1「裸跑内联 526 页」（C 项跑门禁看到输出）。

**实证（W1020）**：Backlog 对账 29 条拆 3 个 agent 并行，各领 6–8 条，
每条只要求「判定 + 证据 + 实测数字」，20 分钟内收敛——因为那活**不需要判断，只需要举证**。

## 派发 prompt 骨架（每份复制后用）

```text
你是取证员，对 D:\xiyouji 仓库做**只读取证**，不修改任何文件、不跑会写盘的命令。

## 你负责的条目（只报这些，不要扩大）
<条目清单：每条一行，带原始登记文字>

## 输出格式（严格照此，一段一条）
<条目号>：<已完成 / 部分完成 / 未动 / 登记已过时 / 无可执行项>
  证据：<命令或文件路径 + 实测数字/字段值>
  说明：<一句话>

## 硬要求
- 数字必须实跑得出，禁止「大约 / 推测 / 应该」。
- 若发现「已解决但登记没改」，明确指出（这是本批要找的东西）。
- 找不到落盘位置的条目不猜，写「未定位」并说明查了哪些路径。
- 总输出 ≤45 行，信息密度优先。
```

## 汇总者的三条义务（防「二手结论」背书）

1. **不转述**：agent 报「X 已修复」时，追证据行号/文件名；追不到就不写进报告。
2. **抽样复核**：至少独立重跑 2 条最关键的结论（W1020 里我重算了 BL-1 的 52/92、BL-3 的 133 处）。
3. **矛盾不外推**：两份报告冲突时不取「看起来更可信的」，而是自己跑一次。

## 成本参考

- 单 agent 全项对抗审查（A–G）：W1022 实测 **5 分 12 秒**（W998 首跑 40 分钟 / 3.9M tokens）。
- 3 agent 并行对账 29 条：约 20 分钟，但每份只读自己那 6–8 条，上下文成本约为单 agent 的 1/3。
- **每个并行 agent 都要重建上下文**（读 HANDOVER / AGENTS / pitfalls / gates）⇒ 拆 4 份 ≈ 4 倍重复读盘，
  只在「条目数 ≫ 上下文成本」时划算。
