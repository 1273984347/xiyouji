- **同族方向修简报后仍可能只修好一个——裁决材料必须「逐方向」复算指标，不得用「本批已修订」推定两方向同时达标**（W1264 实证·E-251·跨项目通用·设计域）：修订简报（解除两条禁令）后重派两个零参考方向，同口径复算身份指标（覆盖 ≥80% 页面·去重口径）：**甲2 暖承载 29.4% / 冷数据 16.5%（冷热已倒转·与现役同构·达标）**，**乙2 暖 17.6% / 冷 41.8%（仍倒向冷·首页读作通用仪表盘·未达标）**。⇒ 要点与纪律详见归档 E-251
- **「身份/承载层」与「版式/结构层」是正交的两层——两个方向的强项落在不同层时，正交移植的成本远低于重做或折中调色**（W1264 实证·E-252·跨项目通用·设计域）：甲2 强在**色板与承载层**（暖宣纸底 #EDE7D9 + 朱砂 #A8321F + 墨栏分隔 + 百回拓片条 + 账簿式 KPI。⇒ 要点与纪律详见归档 E-252
- **表格型台账/清单的单元格内含未转义竖线 ⇒ 列解析整体错位 ⇒ 行状态被误读 ⇒ 迁移归档机制被永久锁死**（W1265 实证·E-253·跨项目通用·判据/数据域）：台账「状态列」按**固定列位**取格（cells[5]），但台账行有 9/10/11 三种列数，且 4 行的**描述单元格内含裸竖线**（如 W1179 的「类型｜all」）。⇒ 要点与纪律详见归档 E-253

- **基线冻结必须晚于并行线交付——冻结于在途状态会把在途缺陷冻成合规**（W1265 实证·E-256·跨项目通用·协作域）：基线冻结加 --strict 零容忍是正确的存量治理形态，但**冻结时点**决定它冻结的是什么：本批判据在并行页面线仍在施工时冻结基线。⇒ 要点与纪律详见归档 E-256
- **写入侧常量 + 门禁侧正则 + 受管文件是「三方共同契约」——单方改写会让每批收官都卡在同一句断言上**（W1266 实证·E-258·跨项目通用·流程/契约域）：本批级联连续三次在同一处（`_face_agents`）断言失败，症状都是「异常」二字，与真正病因相距极远：① **尾锚点异常**——AGENTS.md 脚注尾句写「如与权威文档冲突，以权威文档为准。」，而写入侧常量 `batch_cascade._AGENTS_TAIL` 与门禁侧正则 `check_doc_size_budget._FOOTNOTE_TAIL_RE` **都**要求「如与**上述**权威文档冲突」。⇒ 要点与纪律详见归档 E-258
- **并行会话的 worker 仍在运行时收官提交 ⇒ 暂存集被代提 + 半成品入库 + 基线冻结在中间态**（W1266 实证·E-259·跨项目通用·协作域，与 E-257「目录分组行按子树展开稀释代提防线」同族）：本批收官时暂存集从 191 件涨到 **253 件**，混进 16 张参考件截图（旧方向子代理遗留的 `_verify_shots/*.png`，从未入库）与 14+ 个逐页过程产物（`scripts/output/_w1266_check_*.json` 等）；同时 `site/data/` 下 14 个页面正被另一会话的 worker 持续改动。**根因**：并行会话的三个 worker 仍处运行态并自行执行 `git add`（把未跟踪件一并带进索引），而主会话按「已收到交付报告」判断为可提交。⇒ 要点与纪律详见归档 E-259
- **pytest 报出的断言字面量若与源码里看到的不一致 ⇒ 先清字节码缓存重跑，别急着改文件**（W1266 实证·E-260·跨项目通用·取证域，与 E-249「读片段 + 整文件写回致静默截断」同族的「磁盘状态与认知脱节」族）：pytest 报 `test_w851_j1_name_audit` 失败，断言内容是 `('--series-5: #8B9BBC' in css)`；但磁盘上同一行早已是 `#76749E`（且工作区与 HEAD 逐字一致）。⇒ 要点与纪律详见归档 E-260
- **pytest 断言失败要分清两种情形：「缓存假象」与「真陈旧断言」——处置相反，混判会白改文件或错误回退资产**（W1266 实证·E-260 补充分 · 与 E-249「读片段 + 整文件写回致静默截断」同族的「磁盘状态与认知脱节」族）：判别表——。；【全文详见归档 E-260】
  | 情形 | 判别 | 处置 |
  |---|---|---|
  | **缓存 / 环境假象** | pytest 报的断言字面量 **≠ 源码里实际写的那个** | 先清字节码缓存（`__pycache__` / `.pytest_cache`）重跑，**别改文件** |
  | **真陈旧断言** | pytest 报的断言字面量 **= 源码里写的**，但**目标文件里确实没有该值** | **订正测试断言跟随现役值**（禁反向回退现役资产） |
  实测两例同批并存：① `test_w851_j1_name_audit` 的暗色 `--series-5` 锚点——清掉 258 个 `.pyc` 后重跑即绿（缓存假象；现役 `tokens.css` 的 `--series-5` 是 `#76749E` 而非旧值 `#8B9BBC`）⇒ **改的是测试锚点，不是现役色板**；② 同一测试文件在清缓存前报出源码里根本不存在的字面量 ⇒ 混判会让人去改一份没问题的文件。⇒ **纪律**：① 见到断言字面量与源码不一致，**第一动作是清缓存重跑而不是编辑**；② 见到「测试要的值现役确实没有」⇒ 改**测试**、不改资产（与「现役资产被测试锚点锁住时订正测试」同向）；③ 两种情形都要**留下判别依据**（缓存计数 / 现役取值 grep 结果），否则下批会有人把「真陈旧」当缓存白改一次，或反之把「缓存」当陈旧而错误回退资产；④ **交付前自检环境要干净**（清 `__pycache__` + `.pytest_cache`），否则会把「上一次运行的旧结论」当证据。
- **预告 / 未确认的转述只能进会话，不能进交付物——写错了还要回头改记忆里同一份错误数据**（W1266 实证·E-261·跨项目通用·协作/取证域，与 E-260「断言字面量与源码不一致」同族的「证据等级」族）：并行会话转述「43/176 静态含图页渲染后无图。⇒ 要点与纪律详见归档 E-261
- **分类判据必须覆盖该对象的「全部载体形态」——漏一种载体就会把整类对象误分类；且分类类结论应用两套互不依赖的探针交叉印证**（W1266 实证·E-262·跨项目通用·判据域，与 E-261「预告不得进交付物」同族的「分类判据自证」族）：本轮同一条「渲染后无图」结论上连出两次同类缺陷——① 某审计工具按 **id/class 是否含 `chart|graph|plot|viz` 关键词**分类 chart/icon，而 **JS 动态创建的图表 svg 通常没有 chart 类名**。⇒ 要点与纪律详见归档 E-262
- **「实测」与「转述」的边界是「可复跑性」，不是「谁做的」——引用任何实测数字前先确认产物在仓内 + 取数命令可复跑；多源交叉印证必须注明各源判据的宽窄**（W1266 实证·E-263·跨项目通用·取证域，与 E-261「预告不得进交付物」同族）：本轮我在「等正式报告」时，把**他方一份仓内可复跑的三件套实测**（脚本 + 输入清单 + 输出 JSON + 复跑命令）也一并归入「转述」而拒收。⇒ 要点与纪律详见归档 E-263
- **判据要锚在「可观测的现象」上，成因枚举只作解释附在其后——把成因当判定条件会整类漏判**（W1266 实证·E-264·跨项目通用·判据域，与 E-262「载体形态须全覆盖」同族）：我一度把「环境性未加载（env_blocked）」写成「**数据类请求失败 且** 图未渲染」两条件同时成立。⇒ 要点与纪律详见归档 E-264
- **改文件前若只读了片段（read 带 limit/offset），则禁止用 write 覆写整文件——必须先取全量**（W1264 实证·E-249·跨项目通用·与 E-199「改写完整性」同族的「编辑手段本身致损」族）：给一份已存在的设计规范加「冻结标注」时，先 read 了带 limit 的片段（取到 12 行），随后用 write 把**这 12 行 + 标注**写回。⇒ 要点与纪律详见归档 E-249
- **用「字符串区间切片」解析 CSS 规则块会因相邻块污染而误判 ⇒ 判据必须块感知（按大括号配对提取规则块）**（W1264 实证·E-248·跨项目通用·与 E-246「判据须验交付物本身」同族的「判据自身失效」族）：本批写「明暗两态令牌块是否逐项相等」的判据，用 indexOf 定位 attr 块、slice 切 media 块，结果对两个**完全正确**的设计连续误报「两态取值全不同」（90+ 个令牌全报差异）。**两次不同的根因**：① 目标文件把覆写块写成 :root[data-theme="dark"]（带 :root 前缀）而判据只找裸属性选择器。⇒ 要点与纪律详见归档 E-248

- **判据自证必须用负样本跑·且负样本只破坏一个维度——「自测通过」不等于「判据可证伪」**（W1073 实证·承坑表 E-05/E-06）：本批机器判据写完后补了 6 条负样本自测（纸底偏色/线条收细/主体跑偏/安全区污染/朱砂被抹/尺寸不对），**当场抓出两条判据自身是恒真的假判据**：① **J1 尺寸判据恒真**——判据读的是**裁切后**的尺寸，而裁切函数总会把图变成 2400×1017 ⇒ 任何尺寸错都判不出；⇒ 修法：尺寸须在**裁切前**取原始尺寸再判（负样本实测 raw=(1200,508) 被抓到）。② **J7 朱砂判据口径两头都错**——初版太松（朱砂混向金色后仍满足 ⇒ 抓不到退化），收紧到「高饱和核心」后又对「派生路线」假红（实测 09：浅 819px → 深 58px·但视觉面积相当且更鲜明）。⇒ 修法：**判不变量而非判像素数**——朱砂「存在 + 包围盒与浅色版同一处」（位置一致性是母版规格的真实不变量），像素数只作「几乎消失」的下限；同时色相带放宽到能覆盖「被提亮后核心缩小」的形态。⇒ 推广：**判据写完必须跑负样本自测**——「跑通」只证明它对好图不误杀，**只有负样本能证明它对坏图不放过**；每条负样本只破坏一个维度，否则一坏样本会掩盖其余维度（承 E-05）。



- **跨配色版本的「同形对比」判据：bbox 口径不可用——须用投影重心**（W1073 对抗复核 F3 实证）：做「深浅两版必须同主体同站位」的几何对比时，**bbox 宽高/中心对比会连续踩三个坑**：① 深浅两版的「墨」若按**颜色阈值**定义（浅底版取暗墨·暗底版取亮线）⇒ **口径不同不可比**（实测 06：深宽 519 vs 浅宽 843·差异来自白瓷/米白与暗芯部件被归到不同侧）；② 改用统一的「偏离中位亮度」掩码后，bbox 又被**暗底上放大的纸面纹理**污染（实测 06：深宽 1992 vs 浅宽 529）；③ 用 min/max 取 bbox 时，**单颗孤立噪点**就能把 bbox 拉爆（实测 06：12 颗噪点把 bbox 从 x[1536,2338] 拉成 x[0,2386]）。⇒ 正解：**列投影重心 + 行投影重心**（对纹理噪声不敏感）+ **实测标定容差**（现役 9 张落点 dx ∈ [-5.7, 30.7]·dy ∈ [-2.0, 53.6] ⇒ 取 dx≤70·dy≤110）⇒ 负样本（主体平移 300px）实测 dx=139 ⇒ 必被抓到。⇒ 推广：**凡「两版几何是否一致」的判据，先确认两版的「目标物」定义是否同口径**；定义不同就换到与配色无关的特征（重心/边缘）上比。

- **暗底会放大浅底上不可见的纹理与微小偏差——映射类操作必须做「相对可见度」评估**（W1073 对抗复核 F2 实证）：程序化把浅色素材映射到暗底时，**母版纸面的细微纹理（与纸底色距离 1-5/255）在浅底上完全不可见**（浅色版 dev p99=5），但映射到暗底后其**相对亮度占比放大** ⇒ 变成可见的灰白纤维划痕（实测 09 号左安全区偏离纸底 >12 的像素 7113 个·密度 0.00634·目视明显）。⇒ 关键辨析：这 98.75% 的位置**在浅色版同位置也是纤维纹理**（随机基线仅 4.63%）⇒ **不是 AI 凭空添加**，而是母版纹理的暗底可见度问题 ⇒ 修法不是「让 AI 重画」而是「压掉/收敛纹理」。⇒ 正解两条：① **映射后对文字安全区做偏离压缩**（把该区像素朝纸底色收敛·实测压缩系数 0.90 ⇒ 偏离密度 0.00000）；② 降噪/滤波**只限文字安全区**（实测全图降噪会连主体细笔一起抹掉 ⇒ 主体区边缘密度掉 22%·K1 判红）。⇒ 推广：**任何「换底色/换主题」的图像派生，必须单独评估「原底色上不可见 → 新底色上可见」的纹理**。

- **母版段「无实心色块填充」约束不住「密排纹理」与「渲染笔触」——两者都要在主体段显式禁**（W1049 实证·E-55）：母版段明写「无实心色块填充、无渐变、无阴影、无光效」，但模型给**铠甲鳞纹**画成密集排线、给**山石**画成灰擦渲染笔触。⇒ 要点与纪律详见归档 E-55

- **视觉回归探针的「采样顺序」会污染读 localStorage 的页面——元素数跳变先查采集条件而非改产品**（W1076 B1 实证）：页面内容若来自浏览器本地存储（遥测队列 / 访问日志 / 阅读进度），探针自身的前序页面导航会把这些键写进去 ⇒ 被采页的元素数随**采样顺序**跳变（实测 `rum-viewer` 45→189、`visit-viewer` 33→129），而**同页序重拍两拍一致**（209 = 209）⇒ 那批差异是采集面污染，不是产品变化。⇒ 修法：① 前后两拍必须**同页序同前序**才可比（含 `--pages` 顺序）；② 探针补 `--isolate`（每页独立 context 隔离存储），**两侧须同模式**（隔离↔隔离），一侧隔离一侧不隔离仍不可比；③ 报告差异时先核「元素数是否跳变」，跳变即先查采集条件。⇒ 推广：凡「页面渲染依赖客户端状态」的静态站，视觉回归判据必须显式声明采集隔离口径——**差异的第一嫌疑是判据的采集条件，不是被测产品**。
- **「证伪」本身也要复核·且换变量前必须先判「值会不会被回读/参与计算」**（W1080/W1081/W1082 实证）：把 D3 `.style('fill','#hex')` 换成 `var(--chart-N)`（style 属性层·CSS 规范上确实解析变量）后，图表页暗色**元素数由 533 稳定掉到 109** ⇒ 不是颜色变了，是**元素被隐藏**（探针可见性判据 = display / visibility / **零尺寸**）⇒ 机理 = `var()` 串进入 **SVG 文本量测与避让**路径（D3 量文本宽度取到 0）⇒ 避让算法把文本整批隐藏 ⇒ **图表看起来空了一半**。⇒ 两条纪律：① **换变量前先问「值会不会被回读/参与计算」**（量宽 / `getComputedStyle` / 颜色运算）——会则必须**读令牌喂图表**（`getComputedStyle` 求值 + token helper），不可靠 `var()` 串；② **「证伪」本身要用同态基线复核**（回退态连拍两拍 + 改动前基线三方对拍 ⇒ 区分「改动造成」与「采集抖动」），否则会把一次抖动误判成一次证伪。⇒ 配套判据：视觉回归只比颜色属性**测不出图表崩没崩** ⇒ 必须加「**渲染完整性对拍（元素数/结构不变）**」。

- **删除页内私有样式声明前要逐条确认共享实现是否覆盖——漏一条即回落浏览器默认值**（W1076 B1 实证）：把页内第二套实现收敛到共享实现时，若共享实现**未声明某属性**，删掉页内声明后该属性直接回落到**浏览器默认值**（按钮的 UA 字体）——本批删除页内 `.filter-tab` 后 7 枚按钮字体由 `Noto Sans SC` 回落 `Arial`（J2 computed style 抓到 font-family 差异 14 条），肉眼与代码审阅都不易发现。⇒ 修法：收敛前把被删属性**逐条对照共享实现**列出（font-family / line-height / border-style / letter-spacing 这类「共享实现常不写」的属性是漏网高发区），共享未覆盖者在页内补一条声明兜住，并把「共享实现该属性的目标值」登记为共享层待办。⇒ 推广：**属性收敛类改动必须配「删前清单 × 共享覆盖对照表」**，且**必须由计算样式对拍验收**——纯视觉回归比对只看元素数与主属性会漏掉字体回落。

- **共享实现的「改动半径」要先量再动——半径超批次灰度口径的组件收敛必须独立成批**（W1076 B1 实证）：仓内「单一事实源 + 内联副本」架构下（共享 CSS + 数百页内联副本），改共享实现的影响面 = 副本页数（实测 `.filter-tab` / `.search-box` / `.kpi-card` 各被 ≈250 页消费），而**只有少数页外链共享文件**⇒ 共享层改动会级联远超「每批 ≤10 页灰度」口径。⇒ 修法：① 动手前先量「消费面 = 共享文件 × 内联副本页数」；② 半径超口径 ⇒ 共享收敛**独立成批**并与「副本传播」同批一次做完（零散传播会造成源-副本失同步）；③ 批次内的「组件归一」只做页内私样式向共享实现**对齐**（不动共享值），并在交付物里把共享层的数值差（如规格卡 6px 14px vs 现役 7px 16px）登记为待办。⇒ 推广：**凡「单一事实源 + 分发副本」架构，共享层改动先算半径再决定落点**。
- **J2 视觉回归的属性集**不含** SVG `stroke`/`fill` ⇒ 图表颜色变化在「零差异」报告里**根本测不出来**（W1086 实测·E-82）：J2 探针（`scripts/visual_regression_probe.py`）的 `PROPS` 集合为 color / background-color / font-* / line-height / padding-* / margin-* / border-* / border-radius-*（**28 项**）——**不含 `stroke` / `fill`** ⇒ 图表颜色的变化不进入对拍面 ⇒ 本批把两处 `.style()` 硬编码色换成 `var(--chart-1)` 后「J2 零差异」（**1065 元素逐属性对拍**）完全真实，但该「零差异」**不能作为「颜色未变」的证据**。⇒ 修法：颜色/令牌跟随类变更**须另测 SVG `stroke`/`fill` 的**计算样式**（不是内联样式），且**明分主动变化与被顶掉两类**（本批行 1903 的 text fill 被该页暗色 `svg text { fill: var(--ink) !important }` 顶掉 ⇒ 主动改动在暗色下**不可见**，若不分取会误读为「改动未生效」）。⇒ 推广：任何「视觉零差异」结论都必须先问「采集面覆盖了我证的变量吗」。

- **SVG 表现属性位的 `var()` 能解析且随令牌变（推翻旧结论）；但「按 content attribute 字面值匹配」的暗色补偿在令牌化后必然失配（W1097 实测·E-86）：① **表现属性位不需改写为 `.style`**——`<path>.attr("fill", "var(--accent-soft)")` 的 `getComputedStyle().fill` = **令牌值**（浅 `rgb(233,184,133)` / 暗 `rgb(232,169,159)`，**随主题变**），同页硬编码 `#c8463a` 暗色下**不变**（对照清晰）⇒ 因此「把 `.attr(fill, "#hex")` 改写成 `.style(fill, "var(--x)")`」是**多一步且有害**（改写会抬升优先级：style 属性 > 表现属性 ⇒ 顶掉 CSS 类色）；保留 `.attr` 直写 `var(--x)` 则**零优先级变化**。② **补偿失配是真实视觉变化，而不含 `filter` 的视觉回归集**测不到——每个页的暗色补偿都写成 `svg path[fill^="#"] { filter: brightness(...) }`（**按 content attribute 字面值匹配**）⇒ 换成 `var(--chart-N)` 后该规则**不再命中**⇒ 补偿消失是真实视觉变化⇒ **采集面必须含 `filter`**（实测：变更前 `brightness(1.12) saturate(1.05)` → 变更后 `none`，10 页共 7 处）。③ **元素数跨时段采集有 ±1 抖动**——判据差 1 先同态连采两次归因（实测：同一**未改动**页面两次采集均与改动后一致 ⇒ 差异在「改动前」那一次采集）；不得因此回退正确改动。④ **推广**：改颜色写法前先实测「目标层能否解析 var()、是否随主题」，并查该页是否有 `[*^="#"]` 这类**按属性字面值匹配**的规则——它们会在改写后静默失配。

- **补偿失配有两种后果形态：`filter` 消失（亮度补偿丢失）**与**computed fill 落回 CSS 类色**（而非变成硬编码色）⇒ 判读必须逐元素读 computed 值，不能按「颜色会变硬编码色」的直觉推断（W1098 实测·E-88）：某页暗色补偿规则写作 `svg [fill="#3a6b8c" i] { fill: #7d99a9 }`——**按 content attribute 字面值匹配**且特异性 (0,1,1) **高于**该元素的 `.axis-label { fill: var(--ink) }`（0,1,0）⇒ 改前该轴标签 computed fill = #7D99A9（补偿值胜出）；把 `.attr("fill", "#3a6b8c")` 换成 `.attr("fill", "var(--chart-2)")` 后 content attribute 不再以 `#` 开头 ⇒ 补偿规则**失配** ⇒ 该元素落回 **CSS 类色** `var(--ink)`（暗色 #F2EBDC）⇒ 与同组其它标签**统一**（改前同组 4 个标签暗色色值为 2 个 #7D99A9 + 2 个 #F2EBDC 的不一致，改后统一为 #F2EBDC）⇒ 本次改动**修复了原有不一致**，不是回归。② **推广**：补偿规则的**特异性优势只在字面值命中时存在** ⇒ 令牌化后元素可能落回**设计系统自己的颜色**，结果可能是「更一致」而非「更差」；判读必须做**受控回退对照**（还原页 + **同步重算 CSP 哈希** + 同参数重读）拿到 before 态实测读数，否则只能靠规范推理。

- **同一页面同一状态的两拍采集元素数可以不一致（实测 ±5~6）⇒ 元素数比较必须取稳定值，不能用单拍**（W1099 实测·E-89）：根因是**异步渲染**——en/philosophy.html 暗色热力图的数值标签（text.heat-val）渲染完成时刻不定 ⇒ 同态连采实测得施工前 {5072, 5078, 5078}、施工后 {5078, 5073}，稳定值 5078 ⇒ 纪律：① 采集前先做静态勘查判断该页是否有异步渲染组件；② 对拍前对同态**连采多拍**取一致者为稳定值，只有稳定值之间的比较才有效；③ 元素数不一致时**先看身份差集**再判回归（新增项若属同一类动态标签 ⇒ 抖动）；④ 采集器改进方向：采集后立即复采一次做「渲染完成」自检，不一致则重采。**推广**：凡「元素数 / 元素清单」类比对的通用前置纪律——单拍不构成证据，稳定值才构成证据；另注：受控回退对照的还原一律用**版本控制权威口径**（git checkout HEAD --）而非手工。

- **盘点口径必须「互斥归类 + 调色板色/自有色分层」，否则跨批数字不可比**（W1100 实测·E-90）：① 归档盘点脚本的六形态是**各形态独立计数**（同一处会被多形态重复计入）⇒ 表面「合计」不是互斥总数 ⇒ 改写为**互斥归类**（按优先级先命中者归层，并记录已占区间避免重复计入）后口径才自洽。② 必须**层内再分「调色板色 / 页面自有 hex」**——否则用「任意 6 位 hex」统计会把档 1/档 2 误算成 994 处（实测）⇒ 与「按调色板色已归零」的结论直接矛盾；分层后校验项「档 1/2 的调色板色 = 0」才能真正成立（本次实测 = 0）。③ **溯源法**：对「同一段规则出现在 N 页」的问题，用**规则集合指纹**判定是否同源——本次实测 330 页的补偿规则指纹**只有 1 种**（每页 112 条一模一样）⇒ 一眼看出「可机械批量处理」而非「330 页各自维护」⇒ 工程量判断从「逐页改写」降为「一段文本替换 + 断言替换数」；并进一步查清**是否存在生成器**（scripts/ 命中 0 ⇒ 属历史一次性手工/模板粘贴，但 tokens.css 另有一份共享副本）⇒ 改写路径应「共享层先改 + 页内机械批改」。④ **推广**：任何「按形态统计后要排施工批」的盘点，报告里必须同时给出：互斥层定义 + 校验项（应为 0 的层应为 0）+ 规则/字面量的**同源指纹数** ⇒ 否则排期与工程量都会误判。备份（手工备份的语义可能与命名相反，本次即出现过一次自伤）。

- **阈值类判据必须用「站内既有机制的经验分布」校准，不能拍脑袋取整；且判据锚点要用外部标准常数而非自算值**（W1103 实测·E-91）：本批要把「补偿失配可接受幅度」变成机器判据，初版建议值 **12** 属拍脑袋 ⇒ 实测站内两套补偿机制的等效 ΔL\* 分布是**两个互不重叠的区间**：**弱补偿**（前缀型 filter: brightness(1.12)·59 个补偿原色全覆盖）等效 ΔL\* **1.1~5.6**（中位 4.5）、**强补偿**（字面值型重映射）等效 ΔL\* **14.7~55.1**（中位 24.2）⇒ 据此把三档定在 **OK ≤ 6**（= 弱补偿等效上限 5.6 的向上取整）/ **WARN 6~12**（落在弱补偿上限与强补偿下限之间的**自然间隙**）/ **BLOCK > 12**（接近强补偿下限 ⇒ 差异不可忽视）⇒ 阈值从「拍脑袋」变为**有实测分布支撑**。② **同族纪律**：判据的**锚点必须用外部标准常数**（本批用 CIE 的 L\*(#000000)=0 · L\*(#ffffff)=100 · L\*(#808080)=53.585）而不是自算值 ⇒ 自算值自证（同 E-90「同实现自检 ⇒ 口径漂移不可见」族）；③ **推广**：凡「允许多大差异」类阈值判据，先量出**站内既有机制的经验分布**、取分布里的自然间隙做分档 ⇒ 换一批数据只需重算分布，不必重拍阈值。

- **基线快照与复采快照必须同采样面；元素数差 1 的定性靠「受控回退对照」而非「同态连采」（W1097 实测·E-87）：① **同态连采不足以定性**——连采两次用的是同一采样面（单页），而改动前的基线快照是十页批量采的 ⇒ 两者元素数本就不必相等（实测同页差 1：批量基线少一个 `<text>`）⇒ 「连采两次一致」只证明**同面采集稳定**，不证明**基线可比**；本批前序结论「跨时段采集抖动」据此订正为「采样面差异」。② **受控回退对照**才是定性手段：把目标文件 `git checkout <施工前 commit> -- <file>` 回退、**同步重算 CSP 哈希**（否则内联脚本整块被拒执行、页面塌缩到静态 HTML 水平）、用**同参数同采样面**重采 ⇒ 两态唯一差异 = 本批改动（实测：回退态与改动态元素数完全相同，差异只有预期的 fill/stroke/filter）⇒ 把「相关」升级为「因果」。③ **元素数差异的机器判据**用**身份多重集差集**（Counter 而非 set：同身份元素数量变化在 set 口径下差集为空会被误判为「无差异」）并按**形态**二分——两侧皆非空 ⇒ 真实增删（身份集变化）；仅一侧非空 ⇒ 同身份元素数量增减（抖动）；「两边皆空 = 抖动」是**死分支**（元素数不同 ⇒ 多重集差集必有一边非空）不可写进判据。④ **推广**：任何「基线 vs 改后」的元素数比对，先问「两拍是否同采样面、同参数、同隔离模式」；差 1 时先做受控回退对照再定性，不得据此回退正确改动。

- **图表内文字「看不清」的根因常不是重叠，而是「对比度崩塌 + 字号被公共层 !important 压掉」——归因前必须逐元素实测三种机制**（W1282 实证·E-284·跨项目通用·与 E-285「判据底色口径」同族的「视觉可读性」族）：用户报「图表里的字看不清」时，可能的机制至少有四种（行重叠 / 前景与底色对比度不足 / 字号过小 / 描边冲淡），**凭视觉印象选一个机制开修必错**。本批实证：treemap 标签用硬编码白字压色块 ⇒ 浅赭底 #e9b885 上 CR 仅 **1.80**（远低于 3:1 图形对象线）；页面内 d3 写的 .style('font-size','0.74rem')（11.84px）被公共层 `svg text { font-size: max(9px,0.625rem) !important }` 压到实测 **10px**（!important 覆盖内联 style ⇒ 页面作者以为设了、实际没生效）；页内 `svg text { stroke: rgba(255,255,255,0.88) }` 白描边叠白字 ⇒ 浅底上轮廓与填充一起糊。⇒ 纪律：① 「看不清」类反馈一律**逐元素采集**（computed fill/font-size/stroke + getBBox 几何 + 实际压底色的配对）再定机制，禁凭观感选机制；② **公共层 !important 会静默压制页内意图**——局部可读性修复用**页内私有 class 提特异性**覆盖，禁改公共层（影响面全站）；③ 前景色须**按渲染后实际底色自适应**（暗色态公共层会给图形加 brightness() 提亮，字面色亮度方向可能相反 ⇒ 照抄参照实现在暗态会选错字色、CR 仅 1.90）；④ 描边须随前景切换（深字配浅描边，禁深字压深描边）。⇒ 要点与纪律详见归档 E-284
- **判据的「底色」概念必须覆盖该对象的全部载体形态——SVG 图形的底色是 fill 属性，不是 CSS backgroundColor ⇒ 查不到就等于该面从未被测量**（W1282 实证·E-285·跨项目通用·与 E-262「分类判据载体形态全覆盖」同族的「判据盲区」族）：第 80 门禁声称在管「文字对比度 ≥ 3:1」，但底色口径只找 CSS backgroundColor ⇒ **SVG 图形的底色是 fill 属性** ⇒ backdropOf() 永远找不到 ⇒ 「文字压在色块上」的真实对比度**从未被测量过**（基线「违例键 0 条」⇒ 该门禁自建立以来在这块面一直是空跑·实测 graphic 口径违例 646 条 / 45 页而同期 body 口径 0 条）。⇒ 纪律：① 凡「对比度/可见性」类判据，底色取值必须覆盖该对象的**全部载体形态**（SVG fill / canvas 像素 / CSS background 三者分列）；② 底色须取**几何上真正覆盖该文字的图元**并按图元分档（rect 按交集比例 ≥ 0.6 / circle 落真实椭圆 / path 仅 bbox 完全包含才计），配对错 ⇒ 结论错；③ **坐标系须归一化**（getBBox + getCTM 变换到同一 viewBox 用户空间，禁用 getBoundingClientRect——视口像素在缩放/变换后会与图形层错位）；④ 光晕豁免要看「光晕与真实底色的分离度」而非「有没有光晕」（白字+白晕压浅底 ⇒ 零增益 ⇒ 豁免须失效）；⑤ 新口径接入 CI 前先**决策存量基线**（一次性判红 45 页会淹没真缺陷）。详见归档 E-285
- **修复工具与判据必须同源——底色取值 / 判红线 / 光晕分离度 / 几何配对四处任一不同，就会出现「工具改完仍被判红」**（W1283 实证·E-287·跨项目通用·与 E-285「判据底色口径」同族的「双实现漂移」族）：本批把「按底色自适应文字色」做成页面侧公共资源 `site/static/js/label-contrast.js`，同时第 80 门禁 graphic 口径要能判它 ⇒ 两套实现必须共用同一套规则。实测**四处漂移**：① 矩形档（工具按交集比例、判据按文字中心点是否落在包围盒内 ⇒ 边缘文字被误算覆盖）；② 无覆盖图形时（工具按最近 CSS 背景、判据按 body 底色 ⇒ 工具不改、判据判红）；③ 图形底色（判据用 computed fill 原值、工具乘 filter 提亮系数）；④ 光晕分离度（工具按纯描边色、判据按 alpha 合成到底色后算·纯白 3.18 vs 合成 2.79 ⇒ 差 0.4 即判红不同）。⇒ 纪律：① 「页面侧修复 + 门禁判据」成对机制，**共用的常量与规则必须同源**（同文件优先，否则至少共用常量且变更须同步）；② 判据口径变更**必须同批更新回归锁断言**（本批探针自测 8→9 项）；③ 口径对齐后须实跑对照确认「工具改动后残留数下降」——这是同源是否真对齐的**唯一可信证据**。详见归档 E-287
- **运行时修复工具的三类静默失效：去抖被 DOM 持续变化无限推迟 · 只监听一种主题信号 · 模块导出漏项**（W1283 实证·E-288·跨项目通用·与 E-283「同源模块」族互补的「运行时工具」族）：本批的标签自适应工具引入即自动执行，但连续三轮「改了没效果」全部静默：① 用 **去抖**（clearTimeout + 200ms）调度重算，而页面 count-up 动画使 DOM 持续变化 ⇒ timeout 被无限重置 ⇒ **apply 永不执行**（工具已加载、控制台干净、效果为零）；改为**节流**（每 200ms 至少跑一次）+ 补跑轮次后生效；② 只监听 `data-theme` 变更，而门禁探针以 `prefers-color-scheme`（colorScheme）模拟明暗四态 ⇒ CSS 已随系统配色变化而工具算出的内联色未变 ⇒ 改完仍被判红；须**同时监听两类主题信号**；③ UMD 工厂的 return 对象漏导出 `auto` ⇒ 引入即抛 `api.auto is not a function`。⇒ 纪律：① 页面侧运行时修复工具的调度必须**节流而非去抖**（DOM 持续变化是常态）；② 主题监听须覆盖**显式主题属性 + 系统配色媒体查询**两条通道；③ 工具引入即执行的，必须有「执行了多少处」的**可观测计数**（本批靠残留 fill 是否变深墨反推，否则无法区分「未生效」与「无需改」）。
- **探针命中数 ≠ 缺陷数：几何配对必须归一化，且须抽样目视复核每个类别**（W1283 实证·E-289·跨项目通用·与 E-282「验收抽样≠判定面」互补的「配对判据」族）：本批做全站标签低对比普查，第一版探针用「文字中心点是否落在图形包围盒内」配对前后景 ⇒ 实测命中 1290 处 / 111 页，但抽样目视复核发现**大量假阳性**：条形图/柱状图的数值标签在色块**外侧**、折线图标签不压任何图元 ⇒ 真面只有 1236 条（归一化后的门禁口径）。另一类真缺陷被既有口径掩盖：浅色文字直接落在纸底上，既有 body 口径靠「有光晕即整条跳过」掩盖，graphic 口径按分离度判定后才暴露（visual-art 明态 CR 1.58·暗态同字正常）。⇒ 纪律：① 「按几何关系配对」的审计脚本**必须做坐标系归一化**（getBBox + getCTM 变换到同一 viewBox 用户空间；禁用 getBoundingClientRect——视口像素在缩放/变换后会与图形层错位）；② **每个命中类别都要抽样目视复核**（条形/柱状/折线/网络图/环形图各类误判形态不同）；③ 命中数只能当**待核清单**的下界，不能直接当缺陷数写进交付物。
- **同源化不是「对齐了主要口径」就够——图形候选的过滤规则也要同源，否则真违例永远修不掉**（W1284/W1285 实证·E-291·跨项目通用·与 E-287「修复工具与判据同源」同族的「过滤规则」族）：W1283 对齐了四处口径却仍留 182 条 ⇒ 根因是页面里 `fill:none` 的装饰性 path 被工具当成「覆盖图形」⇒ 工具放弃不改而门禁跳过 ⇒ 两边对「有无底色」结论不同 ⇒ 真违例永远修不掉。⇒ 纪律：① 同源化须逐条对照**候选筛选 + 覆盖判定 + 底色取值 + 豁免条件 + 候选选择规则**五段，缺一段就会出现「工具认为有底、判据认为没底」或「工具与判据选出不同的底」；② 候选不可用须**继续找下一个候选**而非放弃（门禁语义是 continue 不是 break）；③ 铺开清单要按**最新**命中面重算（口径修订后须重铺，否则真违例无从修）；⑤ 多层候选的**选择规则**也须同源（以门禁语义为准）；⑥ **注释必须与实现一致**——同源化的对象是代码行为，不是注释描述。详见归档 E-291
- **注入浏览器的采集函数是独立作用域——模块级函数在其中不可见，提到模块级会静默让整份产物失效**（W1284 实证·E-292·跨项目通用）：第 80 门禁的探针把 `COLLECT` 作为**箭头函数注入浏览器**执行，作用域独立于 node 模块 ⇒ 把 `effectiveFill` 从 COLLECT 内部提到模块级（为在 node 自测里直接断言）后，浏览器侧报 `effectiveFill is not defined` ⇒ 探针 **fatal 648/648、全部页面失败** ⇒ 产物无效（若门禁只读「违例条数」而不看 fatal 字段，会呈现「0 违例·全绿」的假象！）。⇒ 纪律：① 「注入页面执行」的函数与「模块内执行」的函数**不共享作用域**——需要两侧共用时，要么在注入体内部保留一份副本（逐字同源），要么改为「模块侧纯函数 + 注入侧只采集原始数据」；② 探针产物必须校验 **fatal 行数**（全失败 ⇒ 拒绝通过），不能只看违例数；③ 归一化/工具化改动的「同源」是**代码文本同源**，不是「同一函数对象」。
- **判据里的「分组键」必须能区分同页的多个同类容器——否则跨容器错配会产生假红（假阳）或漏检（假阴）**（W1284 实证·E-294·跨项目通用·与 E-289「几何配对须归一化」同族的「分组键」族）：第 80 门禁探针用 `svgId`（`ownerSVGElement.id`）把 texts 与 shapes 分组后做几何配对；页面里多个 `<svg>` **没有 id** 时该键全为空串 ⇒ texts 与 shapes 全部归进同一组 ⇒ **一幅 SVG 的文字被配到另一幅 SVG 的图形上**（实测 famous-time-travel：明信片正文被配到另一幅插画的矩形·底色错配·CR 2.10 假红）。全站 **147 页含多 SVG，其中 23 页存在「多个 SVG 无 id」**⇒ 同等中招。⇒ 纪律：① 「按容器分组」的判据，分组键必须**能区分同页的多个同类容器**——有 id 用 id，**无 id 则按 DOM 顺序分配稳定键**（如 `#anon-N`），且 texts 与 shapes 必须共用同一套映射；② 跨容器错配是**双向失真**（配错 ⇒ 底色取错 ⇒ 假红；配漏 ⇒ 真违例漏检）⇒ 发现「某页违例数异常多」时应先怀疑分组键而非页面；③ 修法优先**判据侧根治**（一次修好全站 23 页）而非逐页给 SVG 加 id（23 页 × 手工，易漏）；④ 修完须复跑全站看总量变化——本批由 27 条降到 **2 条**（大量原「违例」实为错配假红）。
- **判据的去重键必须能区分「同页同名但落在不同底色」的文字——只按文案去重会让其一被漏判**（W1285 实证·E-295·跨项目通用·与 E-294「分组键须区分同页同类容器」同族的「去重面」族）：第 80 门禁探针的 `seen` 集合原以「文案前 24 字」为键 ⇒ 同页同名文字只判第一个 ⇒ 若两次落点的底色不同（宽屏压深色面板 / 窄屏落到浅色纸底 / 同名标签在不同子图里），**其一被静默漏判**。实测：修判据的分组键后，同页「无底洞·最后大难」这类「同名两处·底色不同」的标签立即暴露（修复前被掩盖、修复后判红）。⇒ 纪律：① 去重键须含**判定所依赖的全部维度**（本例是：所属容器 + 底色来源 + 底色值），否则去重会掩盖真实差异；② 去重时机必须在**判定依据算出之后**（先算底色再组键，否则键里的底色维度恒为空）；③ 同底色的重复仍要去重（保留既有语义与基线可对账性）；④ 改去重键后**存量违例数会上升**（原本被掩盖的真违例浮出）⇒ 上升不等于回归，须逐条重判。
- **判据的「扫描面」要显式核对，别让「默认子集」成为永久盲区**（W1285 实证·E-296·跨项目通用·与 E-282「验收抽样≠判定面」互补的「覆盖面」族）：第 80 门禁探针的页面枚举长期只含 `site/data` + `site/en` 两个子目录 ⇒ **站点根的 10 页从未被测过**（含图页 6 个：about / curated / dashboard / dukou-engine / guide / index）⇒ 根页的 dashboard 等页的真实缺陷（如白字压亮色块 CR 1.4）长期不可见。根页一旦纳入即暴露 **dashboard 16 条**（补接入公共工具后自动清零）。⇒ 纪律：① 建判据时**显式列出扫描面**并核对「应测集合 ⊇ 实测集合」（含站点根、reader 树等易被漏的分支）；② 路径深度不同的分支要分别处理（根页的公共资源路径是 `static/js/...` 而非 `../static/js/...`）；③ 纳入新分支后**存量违例会上升**⇒ 须逐条重判而非直接冻结（本次 40 条靠补接入工具自动清零，说明「先补工具、再看残留」比「先冻结基线」更根治）。
