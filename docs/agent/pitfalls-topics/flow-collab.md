### 流程 / 协作 / 取证（224<!--stats:pitfalls_flow--> 条）

- **设计方向类交付必须「同数据 + 同结构」才可对比**（W1260 实证·跨项目通用）：评审「三个视觉方向哪个好」时，若三者的页面结构或数据不同，评审者看到的是**内容差异**而非**设计差异**，结论无效。⇒ **纪律**：① 多方向样板共用同一份真实数据与同一套 DOM/图表逻辑，只允许改 CSS 与图形绘制参数；② 样板页必须用真数据（禁 mock、禁随机数、禁「示例数据」免责话术）；③ 评审材料里同时给**实拍截图 + 实测数字**，让审美判断与技术验收分离。
- **方向评审用「可测代价表」代替「审美偏好争论」**（W1260 实证）：推翻现设计语言若只说「旧设计不好看」，会陷入主观争执。⇒ **纪律**：把现设计的每条做法换算成**可测量的代价**（本批 11 项：全衬线正文 / 渐变光晕 / 纸纹拟物 / 令牌无比值→112 处对比度 <3:1 / 标签无避让→87–108 页裁切 / 图标 transform 凑栅格 / 10 页 hex 2409 次 / 全站间距 29,285 处 / 内联 CSS 18.9MB 占 37%），再定义新语言的**边界**（「保留哪些符号 + 换掉哪些执行方式」）⇒ 评审从「喜不喜欢」变成「认不认这些代价」。
- **长文档不要塞进 run_code 的 JS 模板字符串**（W1260 实证·连续失败三次）：模板串里的反引号、引号、中文标点会与 JS 模板字面量冲突，报错信息还指向错误的位置，排查成本高。⇒ **纪律**：含反引号或大量引号的长文档/脚本，用 write 工具直接落文件；run_code 里只放短命令。
- **自建探针的命中项必须先回答「这个判据凭什么认为它是缺陷」再进报告**（W1259 实证·一次审查 4 处假阳）：本批 4 处假阳全部由探针口径造成——① `MOYUN_RM` 单侧缺失 26 页（实为第 58 槽已认 `MOYUN_RM`/`REDUCE_MOTION` 两种命名）② 内嵌≠真值 3 页（实为聚合层派生：洞府 22 条 / 魔法 5 类 / 背景 4 类与真值全等）③ 徽标态全 live 136 页（实为把 CSS 样式行 `[data-status="live"]` 当 DOM 元素）④ fetch 目标缺消费键（实为 `loadJson(path, EMBEDDED.key)` 第二参是**回退值**不是路径键·且实测无空图）。⇒ **纪律：探针的语义前提先在源码层确认再批量应用；「发现 N 项」必须同时记录「其中 M 项是探针错」**，否则后续维护者会照错误结论去改正确的页面。
- **无效产物一旦入库就会成为「假证据」——门禁读它、报告引它、审阅者信它**（W1259 实证·交付前盲审抓出）：本批 `scripts/output/render-state-audit.jsonl` 按探针默认 `--proto http` 产出，**3492 行全部含 `ERR_CONNECTION_REFUSED`**，却被级联链当作合法产物入库；真正的有效数据（3489 行）只存在于 gitignore 的 tmp 目录 ⇒ **仓内证据链断裂**（报告引用的「112 处 / 5 页」在仓内找不到支撑文件）。⇒ **纪律**：① 生成器改口径后，**入库前必须核对产物内容不是全量 fatal**（一行抽检即可：`grep -c ERR_CONNECTION_REFUSED`）；② 报告引用产物时**写明该产物的真实口径与取数命令**；③ 判据类产物入库前跑一次「首行内容抽检」，别让「文件存在且非空」冒充「数据有效」。
- **渲染态/视觉普查探针若默认协议不可执行且不 fail-closed ⇒ 产物 100% 无效却退出码 0**（W1259 实证）：`scripts/_audit_render_states.js` 默认 `--proto http`，local 未起 8000 服务时 **3492 行全部 fatal**（ERR_CONNECTION_REFUSED）而**退出码仍为 0** ⇒ 该判据在默认口径下从未真正执行过（本批改用 `--proto file` 才取得 3489 行有效数据）。⇒ **纪律：产出类工具必须区分「跑了但有失败」与「没跑成」**——凡以「产物行数」作门禁输入的机制，先判「行数 > 0 且 fatal 占比不超阈」，否则门禁读的是空壳（与坑表「暗色/站点审计须先起 http 服务·否则探针全 404 假 0」同族：那是路由错，本条是协议错 + 不 fail-closed）。
- **`git commit --amend --only <pathspec>` 改提交信息时会把该提交的其余文件从 HEAD 弹掉**（W1259 实证·踩坑后已复原）：`--only` 的语义是「用当前工作树中指定路径的内容重建提交」⇒ **未列入 pathspec 的文件不进新提交**，若它们原本属于这一笔，则等于被回退（本次 444e137cf 的坑表计数 330→332 被弹出，靠 `git reset --soft HEAD` + 带完整 pathspec 重建才复原）。⇒ **纪律**：① 改提交信息优先用 `git commit --amend -m … -- <全部原文件>`（保持文件集不变）；② 确需缩小文件集时，先 `git show --stat <hash>` 记录原文件集，amend 后 `git diff <原hash> HEAD -- <文件>` 逐个核对是否有内容被意外弹出，**发现即回退重建**（本批实证：回退正解 = `git reset --soft HEAD~1` 后用带完整 pathspec 的 `git commit` 重建，勿用 amend 再试）。
- **spec.file_index_rows 必须是「路径 | W | 说明」三列形态，写成纯路径会退化成裸行**（W1259 实证·登记面空壳）：级联的 `batch_spec.fi_group_rows` 按 `cells[0]/cells[2]` 取路径与说明列；写成纯路径字符串 ⇒ 重建后 file-index 段为「无登记表格/登记行」被判空壳。⇒ **纪律：spec 的登记行按级联的期望格式写**（先读 `batch_spec.py` 的 `fi_group_rows`/`assert_clean_rows` 再写 spec），别凭直觉写字符串列表。
- **git `core.quotePath` 默认转义中文路径 ⇒ 以 git 输出比对仓内清单必假红**（W1259 实证·第 51 槽 7 件假红）：`git diff --cached --name-only` 默认把中文路径输出为八进制转义形态，而 spec 的 `file_index_rows` 是原始中文 ⇒ 形态不匹配被判「索引含本批 spec 之外的文件」。⇒ **纪律：任何以 git 输出与仓内清单比对的自检，取数一律加 `-c core.quotePath=false`**（与坑表「中文路径分类」条目同源·那是取 git 输出侧·本条是反向的比对侧）。

- **护栏要覆盖默认路径，不能只写在 `--force` 分支**（W1022 审查实证）：`inline_css.py` 的「外链页转内联须显式 `--inline-links`」护栏原嵌在 `force` 分支内 ⇒ 照 docstring 敲**裸命令**会一次把 **526 个外链页**转内联（正是护栏想防的事）。⇒ 加护栏时先问「不加任何参数时走哪条路」——默认路径往往才是高频入口。

- **改/加 Markdown 会连锁触发搜索索引与 CSP**（W1022/W1023 连踩两次）：`docs/` 下新增或改动 md 后，`_gen_search_index.py` 要重跑（否则第 46 槽报条目数不符）；索引里含内联脚本 ⇒ **必须**再跑 `generate_csp.py` 重算哈希（否则第 20 槽报 CSP 漂移）。⇒ 顺序固定：改 md → 生成索引 → 重算 CSP → 跑门禁；两步都不做的话，门禁会连着红两次、修完又红一次。

- **fail-closed 触发器上线前必须给历史事件补 token**（W1021 实证）：周期触发器的判据若是「台账里有没有事件 token」，那**首次上线时历史事件必然没有 token**（它们发生在建器之前）⇒ 器会立刻报「从未做过」假警——W1021 的 Backlog 对账触发器首跑即判「从未对账」，而 W1020 明明刚做完对账。⇒ 建器与**给历史事件补 token 必须同批做**（本批在 W1020 行状态列补「Backlog 对账已执行」即消警）。同族：对抗审查触发器（W1000）上线时同样踩过——凡以登记 token 为事实源的器物，都有这一道。

- **脚本退休后工具表/文档会留下幽灵条目**（W1020 实证）：`sync_docs.py` 已于 W793 退休、文件已删除，但 `scripts/README.md` 工具表仍列着它（含 `--fix` 用法）长达 11 天无人发现——读者按表执行只会得到「文件不存在」。⇒ 退休动作必须**连带清点四处引用**：脚本自述表 / README 工具表 / Makefile target / CI workflow；否则「登记面」会持续指向已不存在的东西。
