### git / 提交 / 并发（39<!--stats:pitfalls_git--> 条）

- **批量暂存：git add 带不存在的路径会整批放弃（包装层不查退出码 ⇒ 末位产物漏进提交且无任何红灯）**（W1118 实证·E-145·跨项目通用）：只要 pathspec 里有任一不存在的路径，git add 报「pathspec did not match any files」并**整批不做部分暂存**（rc≠0）。；【全文详见归档 E-145】
- **已推分支遇到新 main 用 merge 而非 rebase（保已推历史）；且「我方未合并 PR」不阻塞对方合并 ⇒ 冲突成本归后落地者**（W1118 实证·E-146·跨项目通用）：跨会话并行下 main 持续前进（对方 PR 先合），我方分支已推过若干笔。⇒ 要点与纪律详见归档 E-146
- **rebase 解冲突时「按行主键去重」会丢掉同一行的列级修改**（W1118 实证·E-147·跨项目通用）：回填笔（把某登记行的 3 个列从占位符改成实值）在 rebase 时与上游同文件冲突。⇒ 要点与纪律详见归档 E-147
- **补订他批交付物在「按索引顶段定归属」的提交范围门禁下必须新立批次号**（W1118 实证·E-148·跨项目通用）：批 B 想订正批 A 已合并的交付物（如报告里的旧数）。⇒ 纪律要点详见归档；【全文详见归档 E-148】
- **占号工具的两处结构性耦合：会话标识回落主机名 + 取号与「顶段推进」耦合 ⇒ 撞号不可机械防住 / 取号被堵死**（W1118 实证·E-149·跨项目通用）：① `reserve_w.py` 的 `session_id()` = `os.environ.get("WB_SESSION", socket.gethostname())`。⇒ 要点与纪律详见归档 E-149

- **`git mv` 的删除侧旧路径也要进 spec**（W1019 实证·第 51 槽）：批次 spec 的 `file_index_rows` 若只写新路径，第 51 槽比对**索引态路径集**时会报「含本批 spec 之外的文件」——因为 `git mv` 在索引里同时记录新增与删除。⇒ 归位/改名类批次必须**两端都列**（旧路径 + 新路径）。

- **批量改 md 一律 Python `open(encoding='utf-8')`，禁用 PowerShell `Set-Content`**（后者默认写 UTF-8 BOM，项目 W427 曾全库清 BOM；`Add-Content` 同理慎用）。
- **同文件多个 Edit 必须串行执行**（并行 Edit 基于同一原始内容计算 diff，后写覆盖先写——W505 复现 4 次：金角银角「唐僧肉」/CHANGELOG W506 段/项目说明头部/交接文档标题均丢失）；并行批次后必须 Grep 验证所有修改点。
- **Windows 多行字符串/heredoc 一律走 Write 临时文件 + 命令 `-F` 参数 + Delete 临时文件**，禁用 `cat <<'EOF'` heredoc（PowerShell 不支持，报错；W514 git commit -F 中文提交信息二度复用教训）。**W706 升级为场景分层铁律：单行简单命令任意 shell 均可，多行/复杂转义/heredoc/大段文本一律落 Python 脚本文件再调用（`scripts/_wNNN_*.py`）——Git Bash 的 `python <<EOF` 同样有转义地狱（本批三败：反斜杠四层转义错位/迭代器静默空/混行尾吞段），bash heredoc 禁令与 PowerShell 无关、与「多行文本进 shell」本身冲突**。**W985 补（四败实测）：落了 Python 文件只消掉 shell 层，还有 Python 字符串层第二层转义——Windows 路径直写 `d:\xiyouji\` 触发 `\x` 十六进制转义 SyntaxError、正则非 raw string 吃 `\w\d` SyntaxWarning（3.12 向报错演进）⇒ 路径一律 raw string 或正斜杠、正则必 `r""`、以 `\` 结尾的字符串是禁手；Git Bash 侧 `python -c` 引号形态=外层单引号内层双引号（单引号内 `$`/反引号不展开·与查坑表 PowerShell 行互补）；中文输出前挂 `PYTHONIOENCODING=utf-8`（GBK 控制台）；**停止信号**=内联写到第三个函数就是要入册的工具，转正 `scripts/` + docstring + ruff + 单测（W985 gen_tools_inventory 即此路径）**
- **并行会话在场的未提交工作树编辑会被吸收或覆盖——只有已提交状态是安全停车位**（W985-W989 连环实证）：工作树是多会话共享面——① 未提交编辑会被对方重 `git add` **吸收**进其暂存快照（W985 实测：pitfalls 编辑被 W988 卷入·内容随其提交落库·归属错位但内联署名「W985 补」保住了溯源）；② 对方的 restore/清偿扫过的区域**会被覆盖**（同批险情：编辑一度 worktree diff 归零·幸而只是暂存吸收非真丢）⇒ 纪律：**并行在场禁 `git add -A`**（按文件名单精确暂存·W985 两次实操）；跨批次内容**立即提交**或在台账/CHANGELOG 留字据——工作树不是停车位；③ 对方在途件把自己卡在门禁（C4-f 假红·W837 判据=件在现役顶段文件行内且工作树残留）→ 按 W932/W984 先例**核 diff 完整自洽后代提**（提交信息+台账双向留痕·W988「登记并行 W989 代提事实」口径），成色不够则等对方落库。**W1006 加机器硬拦**：`safe_commit.py --expect-spec <本批 spec>` 在提交前把**索引态路径集**与 spec 的 `file_index_rows` 求差，出现 spec 之外的文件即拒绝（W989/W1002/W1004 三次代提的同一处方）；给 `--expect-spec` 时可省 pathspec（索引 ⊆ spec 即可提交）——**批次收官一律走这条**，别再靠「我记得不用 add -A」。**但工具不是门**：`git commit` 直提绕得过（pre-commit 钩子在 `.git/hooks/`·未版本化）⇒ **W1007 已把同一判据搬进 verify 第 51 槽（恒跑）**，归属批次按「索引 CHANGELOG 顶段」判定，`docs`/`site` 轨的提交同样判——现在没有任何提交路径能夹带他方在途件。
- **跨 session / 涉及远端状态**：执行前先 `git log --oneline -5` + `gh run list` 确认最新状态，识别并行交付真实增量（E41）；workflow 触发条件必须匹配真实开发流、门禁建置即绿、引用文件先 `git ls-files` 确认（E36-E42 CI 类，详见 HANDOVER「三」W516 段）。
- **W537 三新规（W536 批次声明失真复盘）**：① CHANGELOG「验证」栏必须以当批实跑 `verify_delivery` 的输出为准填写，「状态」栏仅在提交/推送实际落地后为真——自制批量文档脚本绕过 bump_version 防护时同样适用（W536 实证：声明先于验证 → 4 项 FAIL 状态下写出「全绿 + 已推送」）；② 版本行/页脚更新须整行替换并同步改描述文本——第 22/23 门禁只校验 W 号不校验描述（三简单页脚「W536 号挂 W535 描述」串号实证）；③ CHANGELOG「文件」清单中的新建文件必须 `git add`——W723 起有门禁覆盖（第 31 门禁 C4-f：路径 ⊆ HEAD 树且无工作树残留·见上条）；④ JS/工具脚本改动推送前必须以真实参数冒烟一次——node --check 不覆盖运行时（W537/W538 白名单形状回归实证；batch_cascade.py 冒烟口径同此）。
- **环境依赖型测试：写之前先问「clean checkout 里它能跑吗」**（W1147 实证·E-补）：探针基线复核测试依赖 tmpe 临时报告+实时浏览器，本地全绿 push 后 CI 首红；skip 兜底又用错形态（非 TestCase 类无 self.skipTest）连环二红 ⇒ 三纪律：①写测试先答「CI job 里依赖都在吗」（不在则显式 pytest.skip() 调用形态兜底）；②环境依赖测试与纯逻辑测试分文件（CI 挑纯逻辑跑）；③skip 不是丢分（本地照常真跑）。
- **动工前先在对账表登记认领「表格行」**（W720 强制·W719 流程遗漏实证）：预留豁免 bullet（`- **WXXX**：现势下一自由号…`）只是防 C4 误拦的登记，**不算认领**——第 31 门禁 C4 已细分：CHANGELOG 现役段 W 号无表格行则主提交即红；认领流程=取号→表格加行（状态**进行中**）→动工→级联→主提交→收官 chore 翻「已收官」。
- **手工级联脚本必须自建 `_cascade_files_<批号>.txt` 清单**（W722 成文·用户裁决 2A）：batch_cascade --apply（生成级联清单·**其后须再 git add 一次再刷目录索引**·否则新清单件漏收） 自动输出清单，手工级联（跳号/合并段批）同等义务——W691/W693 先例已实践（70 份在库），第 31 门禁 C4-e 校验提交树 ⊇ 清单（无清单 NOTE·漏 add 即红），清单义务自此成文。
- **多组 git add 禁 `2>/dev/null`**（W719 实证）：吞错即漏 add（同族 partial commit）；amend 后必须 `git show --stat` 核对文件数与预期一致再继续。
- **CHANGELOG「文件」行必须写 repo 相对路径且全量列名**（W723 强制·用户圈选根修候选）：级联清单只含级联面，**手工编辑件（本批改的脚本/文档）唯「文件」行可追溯**——第 31 门禁 C4-f 对其做入库对账（路径 ⊆ HEAD 树且无工作树残留·漏 add 即红）；W721/W722 连续两批凭清单 add 漏手工件三处（batch_cascade S-29/复盘报告/pitfalls 等），本地 pre-commit 跑工作树新版全绿而 CI 拉旧版即红（W700 复刻）；级联 precheck 已强制 body 含「文件」行（W537③"无门禁覆盖"就此清偿）。
- **脚本三档归位（W1002 定式·替代旧「`_` 前缀=一次性」口径）**：① **探索/试跑/一次性诊断** → `tmpe/`（.gitignore:139 已忽略）或系统临时目录，**不入库**——判据「跑完不再需要第二次」；② **批次可重放脚本**（迁移/判据/修复·事后要能复查）→ 入库但落 `archive/scripts/batches/<wNNN>/`，**随批收官移动，不在 `scripts/` 根过夜**（`archive/scripts/batches/` 已存 900+ 件·先例 W977）；③ **转正到 `scripts/` 顶层**（去 `_` 前缀 + docstring + ruff + 单测）须满足其一：**被门禁/测试/Makefile/CI 引用**，或**跨批复用的判据脚本**（ROOT `dirname(dirname(__file__))` 在归档目录下会算错·见上条 E-05）。机器判据：第 42 门禁 C4（历史批 `_w*.py|js` 仍在 `scripts/` 根即判红）。**扫描口径（W1004 补·实证漏网）**：分级扫描的「活引用面」必须**包含 `_` 前缀脚本自身**——W1002 只扫非 `_` 脚本 ⇒ 漏掉 `_w988_subject.py`（被 `_w951_check_crop.py` `from` 引用），转正 `check_crop.py` 后 ImportError；同批已把它转正为 `scripts/subject_band.py`。
- **pre-commit scope 分级与提交重试（W698·用户裁决「动工」·外部挑刺 P2 两条落地）**：verify_delivery.py 支持 `--scope full|docs|site|auto`——11 个内联廉价段恒跑，32 个 subprocess 委托段按生效集统一短路（`_GATE_SUMMARY_MARKERS` 兜住防静默跳过 wrapper 的汇总行校验），段自洽锁非 full 档按生效子集断言；`auto` 按变更路径白名单分类（doc-ish/site-ish 正则，任何越界文件→full；未跟踪 docs/site 内容文件在场→full 保守回退），`.git/hooks/pre-commit` 传 `--scope auto`，**CI verify-delivery job 与批收尾七步③恒为全量不缩水**；实测 docs 档 2.3s vs 全量 62s（热缓存）。**W781 R-1 演进**：`_GATE_SUMMARY_MARKERS` 改由 `_STRICT_GATES` 元组派生（手工字典删除）+ `_assert_registry_consistent()` 启动期四查（段名重复/缺 EXPECTED_SECTION_NAMES/相对序漂/scope 未覆盖段须显式登记 `_FULL_ONLY_SECTIONS`）+ 段自洽锁补反向查（实跑多出声明外段即红）——挂槽手工面自五处收敛为两处（门禁元组+顺序表）且漏改启动期即红（W780 双实证：漏 markers 在 scope 跳过路径爆「缺汇总行」假红·漏 EXPECTED 被单向锁放行）。并行会话提交改用 `python scripts/safe_commit.py -F <msg> [--] <pathspec...>`——ref-lock 竞争核对并行增量与 pathspec 无交集后自动重试一次（`--self-test` 4 负样本）；仓库体量监视挂 release.py 步骤 3（count-objects·1GB 告警线·处置红线=禁历史重写，裁决史 SHA 锚定）。**worktree 每会话一树根治候选评估关闭（2026-10-11 用户采纳判断）**：git 禁止两 worktree 共 checkout 同分支→侧分支+合并编排的改造代价≫safe_commit+scope 分级后的残留摩擦（撞车已降为一次自动重试·级联顺序等待与 git 拓扑无关·tmpe/S4 本地件会碎片化）；重启条件=safe_commit 自动重试频率>1 次/周。
- **workflow/脚本用 git diff 输出做路径分类必须加 `-c core.quotePath=false`**（W523）：git 默认把非 ASCII 路径输出为带双引号的八进制转义串（交接文档.md → `"\344\272\244..."`），首尾引号破坏 bash case/glob 匹配（连 `*.md`、`docs/*` 都失配）→ 免审/定向分支被静默架空、恒走兜底全量（Screenshot Review scope 步骤曾因此每次推送 ~11min 全量截图）；验证靠本地 Git Bash 复刻分类逻辑对真实范围双向模拟。
- **touches 冲突声明与交集拒绝（W739）**：对账表 touches 列登记本批计划**手工修改**的共享文件（级联面由 batch_cascade 单写路径 + safe_commit pathspec 互斥保护·不列；对账表追加认领行属 append 安全操作·不列；但改本表表头/规则/历史行等**结构性**修改必须列）；动工前跑 `python scripts/preflight_check.py --touches "<逗号分隔清单>" --self W###`——与在途批次（状态非已收官/已闭环且 touches 非空）有交集即 FAIL 拒绝并行（等对方收官或人工裁决）；语义=「同文件 Edit 串行」铁律的跨 Agent 版——串行保证「我一人不并发」，touches 保证「跨人无覆盖」；实证：W738 收官与 W739 认领在两个并行会话间交错完成（本会话读时 W738 未提交·写完已收官·幸未造成损坏），即 A 类读→写窗口漂移实例——touches 把该类冲突从「写回阶段才发现」前移到「计划阶段就拒绝」。

- **部分提交（pathspec）的 pre-commit 钩子跑在「临时索引」上**（W833 实证）：`git commit -- <pathspec>` 会构造临时索引（= HEAD + 本次 pathspec 的工作树内容）供钩子使用 ⇒ **并行会话已暂存未提交的件，在钩子视角下`git status` 显示为「工作树未提交残留」**。若该件恰在现役顶段「文件」行内（如 `docs/11-方案报告/README.md`），第 31 门禁 C4-f 即判红——**与本批内容无关的假红**（手动跑同一门禁为绿·两者结论相反是识别它的判据）。解法：把该件纳入本次 pathspec，或先请他方落库；**禁为此改门禁**。
- **git 在 pre-commit 钩子全时长持有 `index.lock`**（W833 实证）：并行会话 `git commit` 期间 `index.lock` 会存在数分钟（钩子跑完才释放）⇒ 另一会话的提交报 `Unable to create index.lock`。纪律：**活锁不删**（有 git 进程在跑就等它释放）；确认无 git 进程后残留锁方可清理。自动化提交建议「等锁 → stage → 提交 →按门禁失败点重试」的小包装器，并把每轮门禁输出落文件（后台任务被终止时仍可取证失败点）。
- **C5d 与 C5b 双向绑定：stats.json 刷新后实体标记必须同步**（W836 实证）：`stats.py --w <批号>` 刷新 stats.json 后，**实体标记**（`<!--stats:KEY-->` 形态的数字·如 pytest.ini 头注与 `docs/11-方案报告/` 根层报告内的标记）若未同步，C5b 反向判红（标记 782 ≠ stats 783）；而 stats.json 不刷新时 C5d 又判红——**两侧互锁** ⇒ 改任一侧后两侧都要刷。（本批即因并行会话新增 1 例收集项后两侧同时滞后而被门禁挡下。）
- **PowerShell 管道会给行文本加 BOM**（W836 实证）：`Get-Content x | py -3 script.py` 传入的行首带 U+FEFF ⇒ 写入台账后该行成为 `U+FEFF| W836 | …` ⇒ 第 31 门禁 C4 的登记正则 `^\|\s*W(\d{3})\s*\|` 不匹配 ⇒ 判「该 W 号未在对账表登记」红——而**明面完全看不见**（编辑器不显示行首 BOM）。纪律：**登记行必须以文件直写传入**（`open(..., encoding="utf-8")`），禁经管道；写入后核 `git show HEAD:<file>` 的行首。
- **守卫不能把自己判红**（W836 实证）：扫描被禁字面量的守卫若①在注释里写出字面量、②在自检样本里硬编码字面量，①会被自己命中、②入库后即自指违规 ⇒ 字面量以 **base64 存储·运行时解码**（明文扫描仍为 0 而守卫仍能检出回归）；自检的**正例探针由解码结果在运行时派生**（`pat` / `pat.upper()` / `pat.capitalize()` / 词内嵌形态），只有反例才硬编码。守卫上线后先跑自身扫描——它会当场报出你刚写下的字面量。
