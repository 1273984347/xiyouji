- **判定类产物的结论必须「可复现」才可采信——稳定判据要同时排除「动画中间态 / 未渲染 / 判定面为空」三种形态**（W1285 实证·E-298·跨项目通用·与 E-292「产物必须校验 fatal 行数」同族的「判定面可信度」族·与 E-297「批量写入产物要回读」互补）：第 80 门禁探针原以「指纹连续两次相同」为稳定判据 ⇒ 命中颜色渐变动画的「平台期」⇒ 采到动画中间态颜色 ⇒ 同一页在不同次跑动里判出不同结果（实测两组违例集互不包含）⇒ 「全站 0 条」这类结论不可复现。⇒ 纪律：① 「结论」与「结论的可复现性」是两件事——收官判据应是**连跑两遍、违例集完全一致**；② 稳定判据须覆盖三形态：**动画中间态**（指纹含 display/visibility 且要求**连续 3 次**相同·两次易命中平台期）、**未渲染**（稳定须「已渲染产出 > 0」以排除平凡解）、**判定面为空**（采集时刻无 svg text ⇒ 改记 empty_rows·不记 unstable）；③ 未能稳定 ⇒ **显式记 unstable 并 fail-closed 拒绝通过**（退出码 4 + unstable_rows > 0），报告**缺**该字段（旧版产出）⇒ 同样 fail-closed（按缺字段→0 处理属 **fail-open**）；④ 引用「A 跑 N 条 / B 跑 M 条」前须先确认 A、B 用的是**同一份可复现的测量工具**（否则会把「工具的假阳」当成「被测物的缺陷」，甚至据此推翻上一批的收官结论）；⑤ 探针判据存在已知盲区时，「全站 0 条」不作为达标证据。详见归档 E-298

- **worker 产出必须先核对「官方口径下是否真的违例」再决定保留——过度修复会引入页内重复实现与口径漂移风险**（W1285 实证·E-299·跨项目通用·与 E-291「同源化要逐段对照」互补的「协作面」族）：本批派 worker 清偿两页标签低对比，worker 交回 **367 行页内私有代码**（把公共工具 `site/static/js/label-contrast.js` 的逻辑在页内重新实现一遍）。但 worker 自己在回执中写明：**这两页在官方口径（工具开启）下改动前就是 3 轮 × 4 态全 0**，被点名的违例只在「拦掉公共工具」的源级状态下复现 ⇒ 本批**并无实例违例** ⇒ 该改动超出必要范围。⇒ 风险：① 页内重新实现公共工具 = **两份实现** ⇒ 未来判据口径变更要改两处 ⇒ 必然漂移（E-287/E-291）；② 引入新 hex 与按底色改色 ⇒ 可能触发分类类判据的副作用（按格色着色 ⇒ 填充色组变多 ⇒ 被判成多系列图无图例）；③ 违反「横向能力抽公共资源、页面只做接线」的项目原则。⇒ 纪律：① **worker 回执里若写明「官方口径本已判绿」，其改动默认不予保留**（先备份再撤销，保证可逆——不可逆操作前必须先落备份）；② 派单时若目标是「源级稳健（工具失效时仍可读）」，应**单独立项**并写进遗留，而不是搭车混进「清偿违例」批次；③ 撤销 worker 改动前**必须先备份**（`git checkout HEAD --` 不可逆·W1284 实证曾因此丢失整批改动）；④ 验收时同时看**「官方口径违例数」与「源级违例数」两个数**，二者不是同一件事。

- **「加了 CSS 规则」不等于「页面有了对应节点」——判据读 DOM·worker 只写样式 ⇒ 门禁照红**（W1286 实证·E-300·跨项目通用·与 E-237「覆写层须先量真实 DOM 类名」同族的「判据与实物脱节」族）：本批 worker 补了 `.insight-list`/`.scene-legend` 等**完整 CSS 规则**并注「沿用仓内既有约定」，但**页面 DOM 里没有对应节点** ⇒ 判据按 class 扫真实节点扫不到 ⇒ C2/C4 照红（实测 legend_items=0 而 svg_colors=13 ⇒ 多系列却无图例）。**门禁全绿只证明「无基线外新增」，不证明「目标判据已转绿」** ⇒ 必须**逐条直读目标判据的布尔值**（本批用 analyze_html() 直读 C2/C4，而非只看末行 FAIL=0）。修法：补真实 DOM 节点（div.insight-list > div.insight-item / div.scene-legend > div.legend-item > span.legend-swatch），内容取自页面既有语义。详见归档 E-300

- **判据的「页面内容哈希」必须按仓内规范（LF）归一后计算——否则 Windows 工作树与 CI 的 blob 永不相等，「档案过期」会在 CI 上恒红**（W1286 实证·E-303·跨项目通用·与 E-244「视觉改动须看渲染图」同族的「跨平台可复现」族）：仓内 .gitattributes 声明 * text=auto eol=lf（blob 恒 LF），但本机 core.autocrlf=true ⇒ 工作树检出即 CRLF ⇒ 判据侧按 read_bytes() 算的是 CRLF 哈希、CI 上是 LF blob 哈希 ⇒ 同一页两侧 sha 永不相等 ⇒ 「档案过期/报告陈旧」在 CI 上必红（实证 about.html：本地 309d118255fa / CI f917041c34ea）。**症状极具误导性**：本地全绿、CI 判红，像「改了页面忘了重跑」，实则是**判据跨平台不可复现**。⇒ **纪律**：① 凡以文件字节派生的哈希锚点，一律先做 EOL 归一再哈希，且**判据侧与产物生成侧必须同款实现**（本批同改 4 处）；② 判据哈希与仓库规范（.gitattributes）必须对齐，否则「按工作树算哈希、按 blob 校验」的组合不可复现；③ 排查「本地绿·CI 红」先比对**同一文件的两种 sha**（工作树 vs blob），而非急着重跑探针。详见归档 E-303

- **装饰性图形（背景轨道/槽位）会被「深底上亮度 <0.16 ⇒ 隐形」判据误计——槽位不是数据图形，修法是「暗态 fill:none + 保留 stroke 描边」而非改色值**（W1286 实证·E-304·跨项目通用·与 E-243「不可见判据须算 filter 效果」同族的「判据适用面」族）：暗态审计把所有 svg circle/rect 里亮度 <0.16 的深色填充判为「隐形图形」（每页上限 10 条·正好触顶）⇒ 条形图背景轨道改用 var(--paper)（暗态亮度 0.015）后被记账 ⇒ **两个叠加因素**：判据不区分「数据图形」与「装饰槽位」+ **暗态基线长期未刷新**（缺陷被记账掩盖数批）。⇒ **根治**：装饰槽位改 fill:none + stroke 描边表达轮廓（判据明确跳过 fill=none·视觉上暗底反而更清楚）⇒ 立 --track-fill 令牌统一 4 页 4 处。⇒ **连带纪律**：① 改判据阈值涉及的元素（哪怕只换一个更暗的令牌）⇒ 必须同步刷新基线，否则下批必被「新增 N」打脸；② 每页 10 条上限会把少量缺陷放大成满额告警，排查先看元素身份（owner svg id）不只数条数；③ 判据的「跳过条件」就是豁免面——设计装饰元素优先选被判据已豁免的形态。详见归档 E-304

- **暗态审计的「文字低对比」判定必须与第 80 槽的 graphic 口径同源分工——「压在图形上的文字」交 graphic 口径判，否则暗态下深墨字压浅色色块会被误报**（W1286 实证·E-305·跨项目通用·与 E-287「工具与门禁须同源」同族·与 E-304「判据适用面」互补）：暗态审计原按「文字 fill vs **body 底色**」判低对比，而第 80 槽已确立分工——**文字压在图形上 ⇒ 由 graphic 口径按图形实际底色判**（body 口径只判「不压任何图形的文字 vs 页面底色」）。两处口径分叉 ⇒ 暗态下「深墨字压被提亮的浅色色块」（视觉完全可读·CR 按图形底色算达标）被判成不可读（按 body 深底算 CR 1.1）⇒ 门禁报「新增低对比」。实证 dashboard 中心数字「81」/「总计」与 monster-ecology 节点标签「黄风怪」等 7 处。⇒ **纪律**：① 同一「低对比」概念在两套判据里**必须共享同源分工**（谁判哪种场景），否则一处修好另一处必假红；② 判据侧改动须**用官方判定函数实测**（本批用 `page.evaluate` 直接跑 `_audit_render_states.js` 的 `PAGE_ANALYSIS_FN` 验证 4 页归 0），不要另写临时探针（临时探针缺豁免面 ⇒ 假阳）；③ 顺带检查同一判据的**其他形态**（本批同时清掉 invisible 触顶 10 条与 lowContrast 7 条）。⇒ 要点与纪律详见归档 E-305
