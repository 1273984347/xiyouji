### CSS / 视觉渲染（27 条）

- **「零引用」判定不能按 `.class` 搜**（W1019 实证）：判断 CSS 类是否有人用时，初版在 HTML 里 grep `\.btn`——但 HTML 写的是 `class="btn"`（**不带点**），于是 **78 个在用类被误判零引用**（含 `.btn`/`.badge`/`.kpi-grid`），差点整批删除。⇒ 正确口径：解析 `class="…"` 属性后按 token 分词比对，再并上 JS 里的 `querySelector('.x')` / `classList.add('x')` 字面量；**任何「删零引用」动作前，两种写法各搜一次取并集**。

- **批量正则改 CSS/JS 后必须验证括号/引号平衡**（`check_structure.py`）。
- **批量关键字扫描/门禁必须穷尽同义变体**（W550）：可视化缺陷扫描的关键字要覆盖同义写法（如 饼图/环形图/圆环图/Pie Chart/Donut Chart）——「圆环图」变体曾致漏网；命中后以「可见措辞 × 实现签名（d3.arc/pie/treemap 计数）」双条件定错配，禁止单关键字定性。
- **SVG 标签量测四坑**（W553）：① `getBBox()` 是元素局部坐标系，跨 `<g>` 比较文本 bbox = 幻影重叠（W550 audit-contentavoid 曾据此单页 display:none 65 个未重叠标签——「行标签缺失」类缺陷根因是补丁遮蔽非布局），跨组比较必须 `getBoundingClientRect()`；② tspan 显式 `x=0` 在「x 属性定位」的 text 中是 g 原点绝对坐标，随节点定位的 text 折行须让 tspan 显式继承同一 x；③ d3 `selection.text()` 覆写 textContent 会抹掉子元素——先 text() 后 append('title')；④ 行宽量测禁用 canvas.measureText 字体串拼装（比真实渲染窄约 9%），用 svg 内隐藏探针 text 的 `getComputedTextLength()`。修复图表 svg 挂 `data-audit-skip` 即可让隐藏型 audit 补丁（axisfix4/contentavoid/labelavoid/labelavoid-all）在 svg 级循环跳过（旋转型 axisfix1/2/3 不识别该属性，维持 W550 已验收外观）。W557 全站复审实证该类缺陷在其余 15 页持续发作（页面级豁免≠类绝迹），已全局根治：20 页 contentavoid 补丁内 `getBBox()`→`getBoundingClientRect()`（探针验证行标签复活），data-audit-skip 保留为页面级豁免机制。
- **标记与 CSS 演化脱节查「基类是否还在」**（W557）：全站复审 30+ 页同现「KPI 统计条纵向裸排」，根因是页面只用 `.kpi-card.alt-*` 变体而基类 `.kpi-row/.kpi-card` 布局规则在历史批次丢失——「同文案多页同病」信号应立即查共享 CSS 基类；修法为对缺失页注入基类（纯 token 引用，禁裸色回退防 token 覆盖率门禁）。
- **CSS 缺分号 = 整条声明静默丢弃**（W558）：`: var(--xxx)` 后无分号直接换行跟下一属性，CSS 解析把两条并为一条非法声明整体丢弃（每处丢 2 个属性）——全站 130 页 1006 处实测（ethics-consumption 21 处/narrative-experiment 22 处恰为视觉 FAIL 重灾页）；机械修复用 `: var(--x)
 prop:` 形态正则补分号（_w558_fix_semicolons.py）。与基类丢失同属「属性静默丢失」族，排查视觉缺陷时优先扫描。
- **全局批量规则前置「设计惯例三查」**（W571）：对 tokens/system 级全局 CSS/JS 规则或正则批量修复，落规则前必查——① 页内注入机制盘点（style 块/id 标记，如 #audit-halo 光晕）；② 页内双轨设计（码/标签、光晕、fill=none）；③ 规则带豁免条件（如 :not(:has(#audit-halo)))+ 实拍复验。实证：W569 v2 文字反白一刀切误伤 168 光晕页（墨字+白晕本双主题可读，W571 :has 豁免修正）。
- **改 tokens.css/system.css 后必跑 `python scripts/inline_css.py --force` 分发**（W571）：与 generate_csp 同级必要——精修 tokens 规则后漏跑，:has 豁免只存在于源、未分发到 226 页内联副本（hardship-heatmap tick 实测 #F2EBDC 揭示）；分发后须实拍/样式探针复验。**--force 会按源重建 INLINED 块——历史批次追加在该块*内部*的页面私有规则会被静默洗掉**（W694 实证：四页 10 行〔语义网中英双页暗色 YlOrRd 重映射 + criticism-history 中英双页 reduce-motion〕被吞，暗色门禁 invisible 0→1 拦截后回灌）——运行 --force 后必须核对当批 diff 删除行是否仅标记行；页内私有规则一律写独立 `<style>` 块，禁追加进 INLINED 块内部。
- **d3.select 静态快照空选区族**（W575）：`d3.select('#x')` 在元素声明前执行、元素根本不存在、或把选区方法调在自建门面对象（仅 show/hide）上，均为永久空选区/静默 no-op——tooltip 类功能**桌面鼠标同样失效**且常无报错（一报错反而是 `node().offsetWidth` 型 TypeError）；修法三态=惰性取用/按 W460 形态补元素（必须置于捕获脚本之前）/门面补齐缺失方法。静态扫描「select 行号 vs 元素 id 行号」即可穷尽（W575 四例三型，81-hardships/ecology/global-pattern/cross-time-danmaku）。
- **触屏 tooltip e2e 三坑**（W575）：① tooltip 显隐多带 CSS transition，合成派发后同步读 `getComputedStyle().opacity` 恒为过渡起始值——探针以「预清空 tip 内容→派发→内容非空」同步信号判定，并 stash/restore 防污染页面；快照键不可含显隐态 class（visible 翻转致键漂移跨快照失配），用 id 或顶层序号；② Chrome 在 touchend 后把 hover 同步回真实鼠标位置并补发 mouseout——e2e 中一旦先动过真实鼠标，后续 tap 的 compat mouseout 会杀掉 tooltip 显示态（浏览器行为非页面缺陷），触屏断言序列须全部先于鼠标动作完成；③ 泛选择器 `[class*="tip"]` 会误伤 `small-multiple`（子串撞车）与 tooltip 内层元素（容器 opacity:0 隐藏时内层 computed opacity 仍 1）——精确化（tooltip 子串/tip 结尾）+ 顶层容器过滤；常显换内容型面板（prismTooltip 类）无隐藏态，隐藏断言以「触屏≡鼠标」经验对照替代硬编码 hidden 期望；④（W581）d3.drag 的 touchstarted 会 stopImmediatePropagation——document 冒泡层 touch 委托收不到可拖拽节点的触摸事件，注入须挂 document 捕获阶段（capture:true·先于目标阶段·免疫下游拦截）；⑤（W581）touchscreen.tap 的 tooltip 显隐在 Playwright 由 compat 事件随机承载（注入派发与断言错位·tap 式 PASS 可能是 compat 代劳）——断言改合成 TouchEvent 与取点同 tick 派发（兼顾力导向节点漂移），并以事件流取证甄别派发真身。
- **力导向图的边渲染在 canvas 层·SVG line 只是样式载体**（W551 族图谱 36 页实证·W902 自 Agent 记忆固化入仓）：力导向关系图「边看不见」先查 svg 背景是否不透明/边是否 zero-opacity——真正的命中判定画在 canvas 覆盖层，SVG line 元素仅承载 hover 样式与事件代理；改边视觉若只动 SVG 属性则画面不变。排查口：devtools 里 canvas 元素与 svg 元素并存且同 bbox 即此架构。
- **素材出图 prompt 里器物的「形状类别」比「数量计数」更要紧**（W974 实证·E-07/D-10）：写「金铙」二字 ⇒ 模型画成**圆环**（读作手镯/环）——形状类别错会**误读成别的题材**（须重出）；改写成「**倒扣的金钵 · 半圆盘 · 钵面一圈回纹 · 绝不是圆环或手镯**」一次画对。⇒ 描述器物必须给**几何形状 + 排除项**（「是 A·不是 B」），禁只给器物名；数量级偏差（星点数/环数）不误读则记取舍不重出（承 W942 紧箍儿九倒刺、W948 芭蕉扇叶形两先例）。
- **素材选题前先验「落位页存在且尚无题图」**（W974 实证·E-08）：原定「虎力大仙」在 people 库**无独立页面**（只有「车迟国三国师」这类合并页）⇒ 出图完成后才发现无处可放，浪费一次生成。⇒ 开工前做「题材 × 落位页」双向核对（存在 + 无题图）；同一 stem 只能对应一个母版，禁两套提示词。

- **素材出图：服饰的「固有色词」会被模型直接填成实心色块，而机器判据抓不到**（W983 实证·E-01）：母版段明写「无实心色块填充」，但主体段一旦写「黄袍」「玄色宽袖帝服」「乌纱帽」这类带颜色词的服饰，模型会把整片衣料涂成实色（实测第 27 张「披发黄袍的道士妖王」黄袍整片实心、第 26 张「玄色宽袖帝服」帝服整片实心黑）。⇒ **J6 实心块判据只统计「暗像素」，彩色实心块（黄/赭/黑）完全逃逸**（第 26 张 J6 = 0.203 却满是黑块）⇒ 机器判据全绿不等于画面合规。⇒ 修法：主体段对每件带颜色的衣物显式写「只用墨线勾出衣纹·通体不涂任何实心色块」；并把「逐张放大看是否平涂」列为硬人工关。
- **素材出图：器物表面的「字」同样违反「不得出现任何文字」禁项，且额外引入第二处朱砂**（W983 实证·E-02）：「官印」这类本体承载文字的器物，模型会默认在印面刻上篆字（实测第 36 张官印印面有红色篆字），违反母版段「不得出现任何文字/书法/印章」；那点朱红又打破「画面中仅有一处朱砂红点睛」口径（J5 只查朱砂像素 > 0，查不出「有几处」）。⇒ 器物若本体是「承载文字」的（印/牌/卷/旗/碑），主体段必须显式写「表面完全留白·不刻任何字迹·不涂朱砂色」。

- **成批接入存在「插入」与「替换」两种动作 ⇒ 判据要按动作分支建模，并各自留负样本**（W984 实证·E-01）：一批里若同时有「页原本无题图要插入」与「页已有题图要换图源」两类目标，**单一插入检查会把替换页误判为冲突**（已有 chapter-plate ⇒ 报「已有题图」）；而替换检查若只留一个拒绝分支，**负样本自证会误判「检查恒真」**——本次负样本误选了 `people/如来.html`（该页已插本批线描题图 ⇒ 触发的是「非浓墨版」分支而非「无题图可替换」分支），⇒ 修正为**每个拒绝分支各配一个负样本**（INSERT×已有题图页 / REPLACE×非浓墨题图页 / REPLACE×无题图页·3/3 自证通过）。
- **换图源必同步换可访问性属性（装饰图 ↔ 内容图）**（W984 实证·E-02）：存量图常是装饰语义（`<figure class="chapter-plate" aria-hidden="true">` + 空 `alt`），而新图带真实描述 ⇒ **只改 `img src` 而保留 `aria-hidden` ⇒ 读屏用户永远听不到题图内容**（图在 DOM 里、可访问性树里被隐藏）。⇒ 替换动作必须同步：移除 `aria-hidden` + 写入真实 `alt` 文本（alt 文本要描述画面内容，不只是标题）。

- **同角色同范式的第二张图，观感必然重复——机器判据与拼图趋势都发现不了**（W984 实证·E-05）：同一画幅 + 同一母版段 + 同一构图范式（完整全身立像 + 核心物）下，**同一角色第二次出图**（悟空 / 唐僧 / 沙僧 / 白龙马）⇒ 读者看到的是「同一张图换了个道具」；J1–J10 **全绿**、缩略拼图也看不出问题（拼图只判趋势）⇒ **只有用户目视能判定**（W984 实测：6 张线描重出版被用户判「一般算不上好看」，而判据与拼图全程无异常）。⇒ 选题阶段就要问「这个角色/主题此前有没有同范式的图」，有 ⇒ **换主体或换构图范式**，而不是换道具再出一张。
- **资产族必须归族登记：同族两套命名 + 全部 0 引用 = 「事实闲置但无人知道」**（W987 实证·E-08）：仓库里长期存在、未被引用的视觉资产时，**闲置规模极易被低估**——本批实测：`card-*` 27 张 + `chap-*` 6 张 = 33 张 1:1 水墨图，**全部 0 引用**（`card-*` 27 张同样从未上线），而用户只问起了其中 6 张 ⇒ 真实闲置面比感知大 5.5 倍。⇒ 做法：① 按「命名族 + 尺寸族 + 画风族」三个维度扫出成员；② 在**手写**导读里登记：成员清单 + 命名分歧 + 规范边界 + 引用状态 + 投放位置建议；③ 登记节写明盘点命令（可复算）。
- **不同画风族要靠「类名」而非「注释」隔开规范**（W987 实证·E-09）：同一站点并存两套画风/两套资产规范时（题图禁印章 vs 意境图带印章），若沿用同一个容器类名 ⇒ 后一族的资产会继承前一族的约束（或违反之）。⇒ 做法：① 新立独立类名（`.chapter-scene` vs `.chapter-plate`）并写独立样式块；② 规范差异写进资产导读的「规范边界」表；③ 验收项固定包含「同页两图各有 1 个且类名不混」。⇒ 本批实测：6 页题图与场景图并存 6/6 合规，题图母版段的「禁印章/禁文字」不被场景图继承。

- **沙箱/受限执行环境的三类「假缺陷」必须识别，否则会去「修」不存在的 bug**（W1014 实证·E-41）：① **`browserType.launch: spawn EPERM`**——受限模式下程序不能开命名管道，Playwright 的 `--remote-debugging-pipe` 必然失败（第 43 门禁整段崩）⇒ 不是代码缺陷，切完全权限复跑即绿；把这类判据登记为 `missing_warn` 降级（第 43/49 槽先例）而非改判据；② **`WARN V5 python-not-found`**——JS 侧 shell-out 用 `python` 在 PowerShell 侧是应用执行存根（exit 9009 无输出）⇒ 候选表要含 `py -3`/`python3`/`sys.executable`（`scripts/lib/py_launch.js` 已收敛单一实现）；③ **写锁/建目录 `PermissionError`**——受限令牌写 `.locks` 被 OS 拒，工具应**降级 + WARN 不抛**（tmpe_tidy R2），而不是让整工具在受限会话里不可用。判据：「同一条命令在完全权限下复跑是否仍红」——仍红才是项目缺陷。

- **报告目录的登记编号是「全局 max+1」，分区篇数须等于该区行数**（W1014 实证·E-42）：`docs/11-方案报告/README.md` 的编号列**跨六个分区共用**一个序列（各分区标题括号里的「N 篇」只是该区行数）⇒ 新报告取 **全局 max+1**（W1014 落报告时全局 max=47 ⇒ 取 48，而非按所属分区数数）。两处易错：① 按分区自数会**撞号**（分区内已有重号遗留）；② 加行后忘改分区标题的「N 篇」⇒ 声明≠行数（W1014 实测原声明「11 篇」而该区实有 12 行·已一并订正为 13）。另：§一 表内混入过 2 行指向 `计划方案/` 的错挂登记（历史遗留），新行只加指向本区的链接。

- **「死门控」：配置项或分支位置让判据永不可达**（W1014 实证·E-43·W999 同族泛化）：判据/告警写在代码里但**运行条件永不成立**时，它会长期「静默地不存在」而所有自测仍绿。W1014 一次体检抓到两例：① `tmpe_tidy.write_report` 的 `_misc 超额告警`——`_misc` 在 `policy.exclude` 内 ⇒ `scan()` 恒跳过该桶 ⇒ `agg["_misc"]` 恒空 ⇒ 告警永不触发（实测把 93 件误推进 `_misc` 到 555 件/9.8MB 破阈值却零告警）；② `check_archive_health` 的 `BATCHES_SEG` 常量**定义即弃**（全文件零读取）+ T2 只验「段是否被提及」从不核段级计数 ⇒ W1006 批 16 件未登记仍「0 待办」。前置形似先例：W999「C4 判据原嵌在 `HANDOVER>45KB` 分支内，HANDOVER 瘦身后永不执行」。**侦察法**：对每个告警/判据问「什么输入会让它成立」，再问「那个输入在当前配置下是否可能被产生」；配置项（`exclude`/`ignore`/分支早退）是最高危处。
- **派生脚本里的「期望值」也必须按当批实算，不能沿用上一批**（W1015 实证·E-36）：落位验收脚本由上一批程序化派生 ⇒ 其期望值（缺口 68 / 有配图 32 / 通用 og 66）仍写死上一批基线 ⇒ 本批实跑判红 3 项，而**实际基线已被其他批次推进**（有配图 32→44、缺口 68→56）⇒ 判红是**期望值过期**不是产出错。⇒ 修法：① 派生时**期望值必须重算**（当批开工前实算基线 + 本批增量）；② 尽量让脚本**现算**而非写死；③ 验收判红先查「期望值是不是上一批的」再查产出。
- **派生脚本要逐项核对「路径常量」；重出件的下载必须先删旧件**（W1015 实证·E-37）：① 派生下载器时只改了 manifest 名与批号串，**漏改 DEST 目录常量**（仍指上一批目录）⇒ 12 张原件全落错目录 ⇒ 成品处理报「无出图原件」；② 下载器幂等逻辑「已存在且 ≥MIN_BYTES ⇒ SKIP」⇒ **重出后旧件不会被覆盖**⇒ 复验的是旧图（判据全绿也是假绿）。⇒ 修法：① 派生后**逐项列出与目录/路径相关的常量**（DEST/RAW/OUT/SET_DIR…）逐个核对；② 派生脚本自带**残留断言 + 路径常量清单**；③ 派生后**立即端到端跑一次**（下载 → 成品处理）而不只 dry-run；④ **重出流程必须先删旧原件再下载**。

- **工具的「取值优先级」与「是否产生变更」不得耦合在同一个 `is None` 判断里**（W1042 实证·E-38）：`scripts/ledger_backfill.py` 的 `--from-git` 分支写成 `if args.status is None: args.status = auto; changes.append(...)` ⇒ **显式传了 `--status` 时既不取机器反填值、也不记录 change** ⇒ 显式参数被**静默吞掉且不报错**（帮助文案写着「显式 --hash/--status 仍可覆盖」⇒ 假绿）；同族缺陷：`--cascade` 只在 `else` 分支处理 ⇒ `--from-git --cascade X` 同样被吞。实证：W1015 批收官回填时状态列没写上，只能绕走 `--from-git` 之外的分支才写进去。⇒ 修法：把两条路径的取值统一到一个**决议层**（显式值优先·显式缺失才用机器反填·两者皆无则不产生变更），并让 status/hash/cascade 三列共用同一套语义；⇒ 自证：注入假提交索引跑「显式 --status」，断言状态列写入显式文本且**不是**自动反填文本（回退旧行为必须判红）。推广：任何「显式参数 + 自动反填默认值」双来源的 CLI/函数，都要问一句「显式值是否真的走到了写盘路径」——静默吞参数不报错，是最难发现的一类假绿。
- **自测汇总里的用例数禁硬编码**（W1042 实证·E-39）：`ledger_backfill.py --self-test` 末行写死「3 正例绿 + 4 负例红」，本批补进 4 正例 + 1 负例后**实测为 12 条正例断言 + 5 条负例断言** ⇒ 汇总数字自己成了「过期期望值」，且**没有任何门禁会红**（汇总只是打印）。⇒ 修法：用 `inspect.getsource` 取本函数源码，统计 `fails.append("正例…")` / `fails.append("负例…")` 的条数动态输出；⇒ 口径注意：统计的是**断言条数**不是用例数（一个用例可有多条断言）⇒ 文案要写「N 条正例断言绿」而不是「N 正例绿」。推广：凡「自测/覆盖率/统计类汇总数字」，若它由人手写进输出文本，就会在下一次加用例时失同步；要么机器算，要么就别印。
- **覆盖「新增/存量」分支应替换「判定开关」而不是整仓根替身**（W1042 实证·E-40）：第 48 门禁的 pytest 原先把 `ROOT` 整个换成 tmp 目录 ⇒ 读盘字节来自替身 ⇒ **「真实仓内路径 + 真实文件字节 + 真实 open()」这条新增件链路从未被单测走到**；而新增件分支的唯一开关只是 `head_text()` 返回 None（路径不在 HEAD 提交树）。⇒ 修法：只 monkeypatch 这一个判定函数，**读盘仍走真实仓根与真实文件**；缺项负样本用**绝对路径**写进 tmp（`os.path.join(ROOT, 绝对路径)` 仍取绝对路径）⇒ 不必改 ROOT 也能拿到真实字节的缺项件。⇒ 推广：替身越粗，覆盖越虚——**替身粒度应对齐判据的分支开关**，而不是对齐整个文件系统。
- **编排文件里的完成提示必须归属到正确目标**（W1042 实证·E-41）：`Makefile` 的 `==> ci 完成` 落在 `cross-line` 目标的命令体内（tab 缩进）⇒ 单独跑 `make cross-line` 会打印「ci 完成」⇒ **编排输出的归属被错报**，而 `make ci` 自己反而不打印完成提示。⇒ 修法：把该行移回 `ci` 目标末尾。⇒ 推广：Makefile/批处理脚本里，**「本目标完成」的提示必须与目标同名缩进块同层**；跨目标误归属属静默失真（不报错·但会让读日志的人误判整条流水线状态）。

- **跨行删改的危害是三要素的交集：可跨行 × 真删 × 结果被消费**（W1042 实证·E-42）：本批把全仓 `[^…]*` 改写面逐处人工复核（43 处）后坐实——单看任一要素都会误判。① **可跨行**：排除符不含 `\n\r` 的字符类会吃掉换行；② **真删**：替换为固定串/空串（而非回引匹配组）才删内容；③ **结果被消费**：写回磁盘 / 返回给调用方并被后续使用才算真危害（只打印或一次性比较 ⇒ 无害）。实证：5 处真缺陷全部是「剥标签」形态（`<[^>]+>` / `!\[[^\]]*\]\([^)]*\)`）——标签跨行时会把**标签之间的正文**一并删掉；实测 `<[^>]+>` 在仓内真实中文语料上跨行命中 **833 处**。⇒ 判据升级：扫描器新增**替换语义**维度（fixed / backref / unknown），「可跨行 × 固定串」判高危候选、「可跨行 × 回引」判可疑；⇒ 真危害仍须人工确认第三要素。
- **「有尾锚点 ⇒ 不跨行」是错判：尾锚点只约束匹配末端，不约束匹配内部**（W1042 实证·E-43）：`[^X]` 只排除 X，**不排除换行**；尾锚点（`)` / `]` / `"` 等）只限制匹配的**结束位置**，对匹配**内部**能否含换行毫无约束。实证：`build_reader.py:205` 在 832 个 md 上确有 1 处**真实跨行匹配**（只因替换回原内容才无害）；同形态 `<[^>]+>` 在中文语料上跨行命中 833 处。⇒ 危害：把「有锚点」当安全依据，会让扫描器把**真删型跨行改写**整体归入「可疑」⇒ 全仓「高危 0 处」成为**假结论**（W1015 批即如此报告）。⇒ 正确分界是**替换语义**，不是锚点有无。
- **静态判据有两层边界：扫描域与判据层级，各会漏一截**（W1042 实证·E-44）：① **扫描域**：扫描器 `SCAN_DIRS` 原只含 `ROOT/scripts` ⇒ `archive/scripts/`（617 个 .py）**整域未被扫**（W1042 扩域后 archive 域另有 38 处候选）；② **判据层级**：AST 能判到「可跨行」与「替换语义」，但**判不出「替换结果是否真被消费」**（需数据流分析，超出可靠边界）⇒ 这最后一轴只能靠**人工复核 + 现场实测**（影子对照法：用「排除符补 `\n\r`」的修法版本跑同一输入，diff 输出；差异 0 ⇒ 现场无害）。⇒ 配套：门禁改为**基线制**——已复核确认无害的候选入 `scripts/cross_line_baseline.json`，门禁只对**基线外的新增候选**判红；基线是「已复核」的显式登记，不是偷偷豁免。
- **机制改了·单测契约也要同批改，否则留下长期红的孤儿用例**（W1042 实证·E-45）：并行 W1014 批（61ea60b5）把 `archive_segments.plan()` 的「段数 == keep ⇒ 断言失败」改成「未超窗 ⇒ 返回 `(None, [])`」（未超窗本是正常状态，断言失败会让级联回窗误报 FAIL），**但配套单测仍守旧契约** ⇒ 该用例在 W1014 收官后长期红 ⇒ 全量 pytest 与 CI 持续阻塞，且因「是别人的批」而无人认领。⇒ 修法：同批改用例断言到新契约，并补同族形态（keep > 总段数同样返回无迁移）；⇒ 推广：改机制与改其判据/测试要**同批**；跨会话遗留的孤儿红灯，发现即收口（并在提交信息里写明代收原因）。

- **判据用「整串字面量」匹配 CSS 规则 ⇒ 排版一改就误判**（W1043 实证·E-46）：落位验收的暗色隐藏规则判据写作 `DARK_RULE = 'html[data-theme="dark"] .chapter-plate { display: none; }'` 并用 `in` 匹配 ⇒ 页面 CSS **多行排版**时整串不连续 ⇒ **8 个明明含该规则的页面被判「缺暗色隐藏规则」**（实测 ch090/ch071/ch086/ch095/ch029/ch085/ch097 等）。⇒ 修法：改用**容忍空白的正则**（`html\[data-theme="dark"\]\s*\.chapter-plate\s*\{[^}]*display:\s*none`）⇒ 排版变化不影响判定。推广：凡判据要「某条 CSS 规则存在/生效」，**禁整串字面量匹配**——用「选择器片段 + 声明片段」两段正则或按结构解析（与 W1019 的 INLINED CSS 标记配对同类）；另：判据误报时**先查判据**（puti-shouye 第 6 条：先读 FAIL 原文 + 读判据源码）。

- **豁免登记的「键」必须同时覆盖「内容」与「定位」**（W1045 实证·E-47）：跨行扫描器的基线键改过一次仍漏拦——**纯「文件:行」键**：该行**原地**被改成危险删除型（行号不变）⇒ 静默豁免；**纯内容指纹键**（文件+模式+repl 三分类）：① 同文件**新增同模式调用点**⇒ 键碰撞漏拦 ② 替换串**语义变更**（`""` → `"REPLACED"`）而三分类不变 ⇒ 键不变漏拦 ③ 模式 >160 字符**显示截断**后参与计算 ⇒ 不同模式撞键。⇒ 正解：键 = `sha256(文件 | 完整模式 | 完整替换串 | 行号)` 前 12 位，且**显示截断只用于展示、绝不进键**；行号漂移亦换键 ⇒ 报「基线外新增」（**宁可多报·安全侧**：人确认一次比静默豁免真缺陷便宜得多）。⇒ 配套：键格式必须有**回归锁**（逐输入变化必换键 + 同输入必同键），否则下一次改判据又无人发现口径漂移。
- **豁免登记会随源码演进而失效 ⇒ 必须有「失效项清理」机制**（W1045 实证·E-48）：键一旦绑定源码事实（文件/模式/替换串/行号），代码一改键即失效 ⇒ 基线里会**堆积**指向已不存在代码的条目（实测清出 6 项）⇒ ① 基线越虚高，越容易淹没真正的漏拦；② 门禁提示「基线中已不存在的条目 N 项（可清理）」若无人处理，提示会变成背景噪音。⇒ 修法：门禁**持续提示失效项**（已实现）+ 定期跑一次清理（实测 50 → 44 条）；⇒ 推广：凡「登记式豁免/白名单/基线」类机制，都要有**失效检测 + 清理**的闭环，否则它会同时变成「假绿来源」与「噪音来源」。

- **判据里「排除符含 `\n`/`\r` ⇒ 不跨行」是不完整的——`\s` 同样排除换行**（W1045 实证·E-51）：字符类的排除符若写 `\s`（= 空格 + 制表 + 换行 + 回车 + 换页 + 垂直制表）⇒ 该类**也不匹配换行**；只识别 `\n`/`\r` 的实现会把这类**误判为可跨行**（archive 域 129 处复核实测命中一处：`[^\s]*` 实不可跨行却被判可跨行 ⇒ 假阳）。⇒ 修法：`_can_cross_line()` 的「不跨行」判定改为「排除符含 `\n`/`\r`/`\s` 之一即不跨行」（`_has_tail_anchor()` 同步改，否则两函数口径不一致）；⇒ 配套：自测加一例「排除符含 `\s` ⇒ 判不跨行」。⇒ 推广：字符类「排除哪些字符」的判据要**穷举**（`\s` ⊃ `\n`/`\r`/`\f`/`\v`），凭直觉列几种是最常见的漏法。

- **剥标签类正则要按「标签语法」约束，不是靠「不跨行」规避**（W1047 实证·E-52）：`<[^>]+>` 的起点只要是 `<` 就当标签 ⇒ **JS 比较符 `<=` 被当标签起点** ⇒ 匹配段跨行时把**标签之间的正文整段吞掉**（实测 `site/data/perf-canvas-rendering.html` 吞掉 `n.x <= viewX1 && … n.y >= viewY0` 一整段多行 JS；`site/data/game-webnovel.html` 吞掉「灰<6.5」；en 版同两处）。⇒ 而朴素修法「排除符补 `\n\r`」会伤**多行合法标签**（`site/data/ai-dialogue.html` 的跨行 `<input>` 剥不干净）⇒ 两难。⇒ 正解：**按标签语法约束**——`</?[A-Za-z][A-Za-z0-9:._-]*(?:\s[^<>]*)?/?>`：标签名必须**字母开头** ⇒ `<=` 不匹配；属性段允许跨行 ⇒ 多行合法标签仍剥净。⇒ 影子对照实测（857 页）：相对旧法**修复** 5 页误吞，且**零漏剥标签**（新法输出残留标签的页 = 0）。⇒ 推广：正则「按语法收紧」优先于「按行/跨行收紧」——后者只是把误伤从一种形态挪到另一种形态。
- **多类非文本层的剥离顺序：注释必须优先**（W1047 实证·E-53）：判据剥 HTML 可见文本时若顺序是 script → style → 注释，则**注释里的 `<script>` 字面量**会触发 script 剥离 ⇒ 一路吞到后面真正的 `</script>` ⇒ 注释自己的 `-->` 被吞掉 ⇒ 注释剥离失配 ⇒ 注释残留（实测 `site/_template.html` 的「脚本区」注释即此形态）。旧式 `<[^>]+>` 恰好把这段残片当标签吞了 ⇒ **掩盖了缺陷**（旧判据「看着对」）。⇒ 正解：**注释优先**，再 script、style、标签。⇒ 推广：多层剥离有**顺序依赖**时，某一层会「吃掉」另一层的终止符；看似冗余的一层可能正好掩盖了下一层的失配 ⇒ 改顺序前先做影子对照。
- **出图接口有「单批上限 10 张」的硬限，且 9 张批会瞬时失败——3–5 张/批最稳**（W1049 实证·E-54）：一次请求 12 条直接被拒（`code:400 requests may contain at most 10 entries`）；改成 9 张/批时**整批瞬时失败**（`connector_tool_error`·latency_ms=0），但**单张**探测立刻成功 ⇒ 失败与「批大小」相关而非服务端全面不可用。⇒ 拆批到 **3–5 张/批**后 4/4 批全成；单张仍可能瞬时失败（`err_code:500`·同一批内其他张成功）⇒ **失败件单独重试**而非整批重发（重发会重复消耗已成功件的生成额度）。⇒ 推广：任何「批量生成/调用」接口都要先**探一次单件**确认连通性，再定批大小；批内部分失败要按**件**重试而非按**批**重试。
