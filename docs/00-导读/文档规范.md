# 文档规范

> 本文件是项目文档的**元规则**（rules for rules）：定义每份文档「写什么、怎么写、写到多大、何时归档、如何机器校验」。
> 适用对象：所有更新本项目文档的人与 AI 代理（含 Web Agent「写作助手」角色）。
> 创建于 2026-08-03（W336 文档瘦身复盘）；2026-08-09 按业界标准（Keep a Changelog / SemVer / Conventional Commits / Diátaxis / awesome-readme）重构。
> 配套门禁：`scripts/verify_delivery.py`（pre-commit 强制）·归档区：archive/（W734 统一——文档类 archive/docs/：CHANGELOG-ARCHIVE.md / STRUCTURE-ARCHIVE.md / HANDOVER-ARCHIVE.md / file-index-ARCHIVE.md / AGENTS-ARCHIVE.md；脚本类 archive/scripts/）。

## 1. 设计目标

| 目标 | 含义 | 对应机制 |
|------|------|---------|
| 单一事实源 | 每个事实只有一个权威文档，其余只放指针 | §3 角色表（禁止列） |
| 防膨胀 | 每份文档有写入上限与归档触发，控 token 成本与 diff 噪音 | §5/§8 |
| 可机器校验 | 核心约束由 pre-commit 门禁强制，不依赖人工自觉 | §8 |
| 可跨 session 接续 | 新 session 5 分钟内能定位当前进度与下一动作 | HANDOVER.md |
| 可追溯 | 每个变更可回溯到 W### 与 commit | CHANGELOG + file-index + §6 |

## 2. 对齐的业界标准

| 标准 | 适用范围 | 本项目落地 |
|------|---------|-----------|
| [Keep a Changelog](https://keepachangelog.com) | CHANGELOG.md | 六类变更标记 + Unreleased 段（§5） |
| [SemVer](https://semver.org) | 版本号 | vMAJOR.MINOR.PATCH：破坏性变更升 MAJOR，新功能升 MINOR，修复升 PATCH |
| [Conventional Commits](https://www.conventionalcommits.org) | git commit message | `<type>(<scope>): <subject>`（§6） |
| [Diátaxis](https://diataxis.fr) | 文档组织 | 四象限定位（§3 角色列） |
| awesome-readme 精神 | README.md | 项目是什么 → 怎么用 → 贡献（§3） |

Diátaxis 四象限速查：**Tutorial**=教学上手（学概念）·**How-to**=操作指南（解决问题）·**Reference**=权威参考（查事实）·**Explanation**=背景解释（理解为什么）。

## 3. 文档角色与单一事实源

| 文件 | Diátaxis 角色 | 职责 | 每个 W### 写入量上限 | 禁止写入 |
|------|--------------|------|---------------------|----------|
| CHANGELOG.md | Reference | 施工日志（唯一允许写细节的地方） | 10-20 行（来源/文件/验证/状态四件套） | 无限制，但超过 30 行需自问是否必要 |
| README.md | Explanation + Reference | 项目是什么 + 怎么用 | 0 行（仅更新版本号） | 禁止写 W### 细节 |
| STRUCTURE.md | Reference | 目录结构说明 | 0 行（仅版本号 + 新增目录） | 禁止写 W### 细节 |
| 项目说明.md | Reference | 项目状态快照 | 0 行（仅版本号） | 禁止写 W### 细节 |
| file-index.md | Reference | 文件→W 反向索引 | 每文件 1 行（文件名 + W### + 一句话） | 禁止写验证过程/subagent 报告 |
| HANDOVER.md | Explanation | 跨 session 交接 | 每个里程碑 3-5 行摘要 | 禁止复制 CHANGELOG 完整条目 |
| 术语表.md | Reference | 术语唯一释义 | 按需 | 禁止解释性论述（指回引用处） |

判据：想写一段内容时，先问「哪个文件是它的唯一事实源？」，不落在该文件 → 只放指针或交给 CHANGELOG。

## 4. 写作规则

### 4.1 Markdown 基础

- 标题层级 ≤ 3 级（`#` 文件标题 / `##` 章节 / `###` 小节），避免深层嵌套
- 代码块必须标注语言（` ```python ` / ` ```json `），便于高亮与 lint
- 仓库内链接用相对路径；外部链接用绝对 URL；链接文本要能自解释（禁止「点这里」「此处」）
- 行宽 ≤ 120 字符；版本描述行 ≤ 200 字符（门禁实测值）
- 引用 W 用三位数 `W###`（如 `W413`）；版本用 `vX.Y.Z`（如 `v2.3.28`）

### 4.2 版本描述规则（README / STRUCTURE / 项目说明）

- **格式**：`> 当前版本 vX.X.XX（日期）：一句话概括项目规模 + 最近 1-2 个里程碑关键词。详细变更见 CHANGELOG.md。`
- **长度**：≤ 200 字符
- **禁止**：在版本行中列举所有历史 W### 的内容（历史见 CHANGELOG）
- **更新**：由 `scripts/bump_version.py` 从 `site/dukou-engine.html` 页脚读取 v/W 一键同步

### 4.3 术语一致性

- 首次使用术语时链接到 [术语表.md](术语表.md)；同一概念全文用同一词（如「渡口问津」「心猿」不混写别名）
- 避免同义词漂移：一处用了「待办」，别处不要再引入「TODO/下一步事项」指同一概念

### 4.4 命名规范

- 文档文件名：语义名（中文或 kebab-case），**不**含版本号（版本写在内容头部）；既定英文名（README / STRUCTURE / AGENTS / CHANGELOG / HANDOVER / DESIGN / CLAUDE）沿用不改；既定英文名（README / STRUCTURE / AGENTS / CHANGELOG / HANDOVER / DESIGN / CLAUDE）沿用不改；既定英文名（README / STRUCTURE / AGENTS / CHANGELOG / HANDOVER / DESIGN / CLAUDE）沿用不改
- 引用版本段格式：`### vX.Y.Z（日期）：W### 一句话主题`
- 归档文件名：`<原名>-ARCHIVE.md`（后缀统一大写 ARCHIVE·W681 起）+ **统一存放 `archive/`**（W734 起·按类归置：文档类 → `archive/docs/`、脚本类 → `archive/scripts/`，其余类别以此类推一类一子目录）·头部标注归档范围；**现役文件超限内容必须移入 ARCHIVE 版，不得滞留现役文件**

### 4.5 轨标体系与准入

- 轨标是文档开头第一条 `> 轨标：X` 行（现役轨标以此为准）；文末历史元数据块中的旧轨标是版本追溯记录，**不得修改**。
- 轨别定义：
  - **学术研究**：以可核查引用（论文 / 专著 / 版本 / 理论框架出处）支撑的严肃分析（引用池见 `source/引用与网络解读/学术论文索引.md`）；仅凭原著文本证据（关联回目 / 数据指标）不构成引用
  - **跨界趣谈**：把现代学科或生活概念作为趣味透镜套用到《西游记》的联想型文章（如 西游与经济学、八十一难风险管理学），不声称学术贡献
  - **教学讲解**：面向普通读者的普及讲解（逐回解读、人物介绍）
  - **个人创作**：文学性创作（外传、深读随笔、方向二深化）
  - **大众普及**：面向大众的普及文章（当前暂无存量，保留轨位）
  - **外部分享**：S3 方法论外部分享
- 准入规则：
  1. 标「学术研究」必须至少有一条可核查引用（论文 / 专著 / 版本 / 理论框架出处），否则应降为「跨界趣谈」或「教学讲解」
  2. 「跨界趣谈」不得以「学术研究」身份对外宣传，也不得出现在「学术研究者」目标读者说明中
  3. 新增文档必须先定轨别再写作；轨别修改走常规 W### 变更流程
  4. 「学术研究」文档头部必须含 `> 引用：` 行，显式链接 `source/引用与网络解读/学术论文索引.md`（W452 起由 verify_delivery 机器校验）
- 历史：W450 将 33 个「现代学科趣味透镜」文档从 学术研究 批量改标为 跨界趣谈（清单见 CHANGELOG W450）；W451 引用审计将 9 个无引用文档从 学术研究 降为 教学讲解（清单见 CHANGELOG W451）；W452 为全部 105 篇现役「学术研究」补齐 `> 引用：` 显式链接并纳入机器门禁

### 4.6 元信息块 v2（血缘 + 核验状态 · W501）

- 适用范围：W501 起 docs/01–06 的**新增**文件；存量 611 篇由基线清单 `scripts/output/frontmatter-baseline.txt` 豁免（核验状态字段由 W504 统一补标）。
- 新文件在轨标块（或「W 溯源」块）之后**必须**追加以下 4 行 blockquote：

| 字段 | 格式 | 取值规则 |
|------|------|---------|
| 生成来源 | `> 生成来源：X` | skill 生成填 `<skill短名>@<commit短哈希>`（如 `xiyouji-character-content@aa410f9`）；人工撰写填 `人工撰写` |
| 生成模型 | `> 生成模型：X` | 执行 agent 能可靠自报的模型名；无法自报**必须**填 `未记录`（禁止编造模型名）；人工撰写填 `不适用` |
| 生成日期 | `> 生成日期：YYYY-MM-DD` | 内容产出日期 |
| 核验状态 | `> 核验状态：X` | 三值枚举：`未核验`（初始值）/ `引文已核验`（引文行 ≥ 3 且对 `dataset/text-search.json` 命中率 100%，由 `scripts/check_citations.py` 验证）/ `专家已核验`（人类专家确认）。**空真防护：0 条引文的文档禁止标 `引文已核验`** |

- 机器门禁：`scripts/check_frontmatter.py`（verify_delivery 第 18 门禁，W501 挂载），只扫描不在基线清单内的新文件；缺字段、枚举非法、日期格式错误 = FAIL。
- 设计依据：2026-08-24《内容可信度与溯源体系》方案（archive/docs/plans/2026-08-24-content-trust-provenance-w501-w505.md）W501。

### 4.7 术语一致性（机器可读库 + 锚定门禁 · W502）

- 单一事实源：`docs/00-导读/术语表.md`（人类可读）→ `scripts/check_glossary.py --generate` 逐行解析生成 `dataset/glossary.json`（机器可读，禁止手改）。改术语表后必须重跑 `--generate`。
- C1 双向同步：术语表.md 与 glossary.json 逐组逐条核对，diff = 0（防两侧漂移）。
- C2 规范词锚定（仅「一、人物称谓」组）：文档含某变体称谓（心猿/行者/金公/木母/黄婆/意马/唐僧/唐三藏/圣僧/弼马温/齐天大圣）但其规范词（指代，含传递归一：圣僧→唐僧→玄奘）出现 0 次 = 违规。复合词掩码：心猿意马/金公木母黄婆 先遮盖再扫描，避免子串误报。
- 基线豁免：存量违规 303 篇 383 条冻结于 `scripts/output/glossary-baseline.txt`（2026-08-24 实测），门禁只拦**新增**违规。
- 已知局限：CJK 子串匹配无词边界；新文档被误报时应在正文补规范词（而非改门禁）。
- 机器门禁：`scripts/check_glossary.py`（verify_delivery 第 19 门禁，W502 挂载）。

### 4.8 原著引文语法（精确命中 · W503）

- 引文行格式（单行，blockquote）：`> 原文引文（第N回）：“……”`——N ∈ 1–100，全角括号与全角引号。
- 命中规则：引文必须是 `dataset/text-search.json` 中 `chapters[N-1].text` 的**精确子串**；比较前双方去除全部空白（`re.sub(r'\s+','')`，兼容原文换行），除此之外逐字精确，不做任何标点/异体字宽容。
- 禁止省略号节引：需节引时拆成多条引文行，每条独立命中。
- 使用要求：方向二深化 / 深化专题 / 学术轨新文档须含 ≥ 3 条引文行（见 xiyouji-character-content skill）；`核验状态：引文已核验` 的前置条件即引文行 ≥ 3 且命中率 100%。
- 机器门禁：`scripts/check_citations.py`（verify_delivery 第 20 门禁，W503 挂载，`--dir docs` 全量）；任何文档任一引文行未命中 = FAIL（存量锚定引文行实测为 0，无历史豁免）。

### 4.9 写作可验证纪律（可判定表述 · W664）

> **总判据**：写给其他多 Agent、跨 session 或其他读者的方案/验收/交接文字，读者无需额外解释即可准确理解内容与执行方式。速查层入口：根目录 `CLAUDE.md`（W664 起，宿主自动加载）。

- **禁模糊措辞**：「适当、尽快、酌情、相关、必要时、尽量」等无判定标准的词禁入验收句与步骤句；量化描述必须带单位与比较符（如 ≤60s、计数=0、≥4.5:1），不得写「性能良好」「基本完成」类不可复算表述。
- **验收标准必须含期望输出**：给出命令 + 可复算判据（exit code / grep 计数 / 逐字基线）；新门禁落地必须附负样本自证（违例必红、恢复必绿，留证文件）。
- **交付文档自包含（头五要素）**：版本 / 日期 / 来源 / 状态 / 读者；执行体无需回看会话历史即可执行与复算。
- **框架类交付物必须落进仓内目录并登记索引（W858 · 用户 2026-10-21 明令）**：凡按《任务计划、执行与经验沉淀系统提示词（AI Agent 专用版）》框架产出的交付物（含其中的《执行前计划》），**必须**落盘到 `docs/11-方案报告/计划方案/`，文件名 `T0N-任务计划执行与经验沉淀报告-YYYY-MM-DD.md`（N 取框架编号空间 `T-0N` 的下一个空闲号，与 W 批次号无关联），并在 `docs/11-方案报告/README.md` §二「计划方案」登记行 + 同步该节篇数；同批重跑 `scripts/stats.py`（刷新 `report_docs` 计数）与 `scripts/_gen_search_index.py`（站内搜索索引；因改内联脚本，**必须**再跑 `scripts/generate_csp.py`）。**禁**只在会话答复里给出框架报告而不落盘——用户 2026-10-21 明言「以后记住不要每次都让我提醒你」。
- **数字当批现测**：写进文档的基线数字先实测再落笔（acceptance_snapshot.py / 命令实跑），禁从上一批文档复制；「当前态」与「历史叙述」分离，历史段不改写（E1 铁律同源）。
- **新增当前态声明须同步纳管**：新引入会过期的文档声明（总数/编号/门数/口径字面量）必须二选一——纳入 doc-sync 句式白名单（第 31 门禁）或改为引用式表述（指针化不写字面量）；裸露的现役值字面量禁入现役治理文档（W667 扩面评估结论：近 10 批漂移实例 10/10 已有防线·零裸露·报告 docs/superpowers/plans/2026-10-05-doc-sync-coverage-evaluation.md）。

正反例：

- 反例：「尽快修复相关页面的视觉问题」——无对象清单、无时限、无验收判据，三个维度全部不可执行。
- 正例：「`python scripts/check_doc_sync.py` exit 0（0 FAIL）且 `--self-test` 7/7 通过后，W664 方可提交；负样本＝临时改 README 抬头版本行必红。」——对象、判据、命令、负样本齐备。

### 4.10 聚合数字书写规范（磁盘可计算量 · W703）

聚合数字（页数/篇数/门禁数/类数等可从磁盘实算的量）的书写纪律（第 31 门禁 C5 落地）：

- **唯一基准**：`scripts/output/stats.json` 由 `python scripts/stats.py` 从磁盘实算生成（随批入库·CI 可复现）；CHANGELOG 头部「全站页数口径」块是全站页数的对外叙述权威，其数值与各治理文档中的同类句式一并受 C5 对账。
- **现役叙述面句式对账**：README/STRUCTURE/AGENTS/项目说明全文 + CHANGELOG 口径块行，命中 `check_doc_sync.py` 句式表（「HTML 共 N 页」「N 项自动化门禁」「共 N 篇」「已建 N 篇〔方法论语境〕」等 18 式）即与 stats.json 实时对账，不一致 = FAIL；改口径的批次须**同批**重跑 stats.py 并刷新受影响文档（与双源重灌同纪律）。
- **新增聚合量走登记制**：引用新的聚合量优先指针化（「见统计口径说明」）；确需手写现役值字面量，必须同批把键加入 `scripts/stats.py` 与句式表（否则 C5 不覆盖=漂移无防线），并补 self-test 负样本。
- **时点值豁免边界**：CHANGELOG 版段（历史记录）与 AGENTS 版本脚注不在 C5 扫描域；正文中的基线/首跑时点值（「首跑 N」「基线 N」形态）靠句式表设计豁免——新增时点实况叙述**禁复用现役句式形态**（防误对账），必要时用行级 `<!--doc-sync:exempt 原因-->`。
- **数字实体化（W704）**：治理文档现役关键数字写作 `N<!--stats:KEY--> 单位`（数字紧贴标记；HTML 注释在 GitHub 与 site/reader 渲染均隐藏=视觉零损，纯文本阅读时可反查身份）。stats.json 为实体形态：每键 {value, domain, generator, introduced_by, last_changed_by}；变更史=scripts/output/stats-changelog.json（stats.py 重跑 diff 旧值自动追加·--w 记批次）→ scripts/output/stats-index.md 反向索引（W→stats key·与 file-index 同构，均自动生成禁手改）。
- **C5 三层分工（W704）**：C5b 标记数字=权威锚点（失配/未登记键=FAIL）；C5a 句式表=兜底网（未标记的已知句式照对账）；C5c 裸聚合数字=NOTE 报告型（起步策略——内容描述数字〔板块篇数/维度数/表格计数〕允许长期 NOTE 在案；现役口径数字应实体化或入句式表；NOTE 清单收敛后评估转 FAIL）。

### 4.11 编号空间与标识符纪律（W706 · 用户方案四五阶段元规则）

- **编号空间字典**（各空间互不混用·生命周期各异）：W=变更批次（单调永不复用·唯一对账键）；S=skill-creator 任务卡；B/BL=Backlog 登记项；A=复盘行动项；E=经验条目；P=问题登记；SC=高优场景；WF=工作流；FAM=复发问题族。叙述中引用必须带空间前缀，禁裸编号。
- **v/W 双键元规则**：v 号=内容阶段标签（定性），W 号=批次编号（定量·单调）；**时间点查询以 W 号为准**——v 号在合并段/并行批次区间不单调（v2.3.262〔W661〕列于 v2.3.261〔W666〕后的 W659-W667 区间实证）。v 号形态演化（方案 D 阶段标签化）**已实施（W711·盘点 docs/superpowers/plans/2026-10-11-version-space-inventory.md·8791 处/826 文件+硬耦合 9 项·v2 修正版）**：自 W711 段起 CHANGELOG 段标题与治理文档抬头去 v（批次键唯一）·历史段保留 v 形态。
- **范围词汇定义**：「全量」在门禁语境=verify full 45 段（--scope 分面见 AGENTS §4.3），在扫描语境=叙述面清单（第 27 门禁）；「现役」=CHANGELOG 顶段三元组 ∪ 对账表现势；「版本」四语义=vX.Y.Z 发布批次（方案 D 过渡中）/W### 变更编号/frontmatter 文件版本（§4.6）/dataset 数据版本——叙述须写明指哪一种。
- **标识符禁令**：叙述引用实体用**标题/键锚点**（如「方法论 README 索引中《报告-2026-10-11》条目」），禁行号（插入一行即全链失效；存量「索引第 N 行」写法为历史形态不回改）；新增聚合量按 §4.10 登记制。
- **裁决记录形态**：用户裁决落点=CHANGELOG 段「来源」字段+对账表登记行（双处·primary source）；撤销=新批次裁决反转并引用原段（禁改历史段）；「登记不开工」=交接 Backlog 登记。
- **外部输入裁决流程**（W722 成文·S-27 落点·两轮挑刺+review 实战沉淀）：逐条「定位主张→对仓取证→三态裁决（采纳/事后应验/驳回）+证据（文件:行 或实测输出）」矩阵输出；驳回必附实测证据；「内容丢失类」主张配指纹对账实跑（_w712_fingerprint.py 先例）；主张不可证伪时标【待验证】不入裁决。
- **处置自查扩面五项**（W722 成文·S-30 落点+E-10 工具化·S-28 例行化并入·用户裁决 1A/5A）：每轮外部输入处置收尾时，对同域执行反向机械扫——①同型数字全仓 grep；②同族正则/解析面枚举（含 self-test 基线·E-04）；③git status 未跟踪件盘点；④锚点/指针语义 git 行为对拍设计意图（E-12）；⑤漏 add/漏登记流程面。自查发现与报告项同格式并入裁决表；基线=自查发现占落地项 25%（W713-W719 三批 8/32·小样本 n=3）。
- **技能卡降级/重启契约**（W722 成文·S-26 先例）：降级须并列「不再受保护的路径清单」与「重启触发条件」（可量化·如事故 ≥1 次/月或单次 P1），禁无条件关闭；降级理由禁用「使用频率低」（低频高危更要机器化）。

### 4.12 演绎内容标注（原创虚构叙事 · W737）

- **判定**：凡人物对白、场景、细节为作者再创作而非原著文本的内容（如逐回解读「深度解读」区的 SD### 系列与小说化小节），必须在节首插入标记行：`> 【文学演绎】本小节为基于原著的原创虚构叙事……不构成原著文本……`（模板见 scripts/check_citations.py 的 `FICTION_MARK`）。
- **语义**：标记小节内凡未以「原文引文（第N回）」规范语法（§4.8）标注的引号内容，一律视为再创作——读者与机器（check_citations.py 归属对白核验）均以此为豁免依据。
- **门禁**：`check_citations.py`（第 20 门禁）对 `X道：「……」` 归属对白行做全书精确命中核验；命中区=全文减去「原文全文」照录区与【文学演绎】标记区；未命中即 FAIL（无历史豁免）。
- **作者评点**（格言/术语的引号使用，如「延伸思考」问答中的自撰短语）不属演绎——但不得使用角色归属形态（`X道：「」`），避免与原文对白混淆。

### 4.13 源-产物同修原则（W742 · PRE-28）

- **原则**：凡存在「生成物/派生物」的内容体系（docs → reader 页面、EMBEDDED 数据、CSP、stats 派生件），修复必须溯源——修产物前先 grep 源文件；**只修产物不修源 = 债务展期**（实证：红蟒精「稀柿同」案——W691 手工修提交版 reader 而 docs 源藏残留，潜伏 46 批至 W737 重建才暴露）。
- **操作**：修产物必查源；修源后跑全链重建四连（build_reader → inline_css → generate_csp → chapter-stats EMBEDDED 重灌·规程见 docs/agent/gates.md 第 8 门禁 PRE-26 注）。

## 5. CHANGELOG 写法（Keep a Changelog 化）

- **头部**：`## [Unreleased]` 段 + W### 编号规则说明行
- **版本段**：`### vX.Y.Z（日期）：W### 一句话主题`，段内四件套（来源/执行/验证/状态）逐条 `> - **键**：值`；「文件」行（W723 起 C4-f 对账源）必须写 **repo 相对路径全量列名**（含手工编辑件·剥括号注释后逐 token 入库对账），禁纯描述性列举（如「六文档级联」「8 门禁脚本」——无可解析 token 即 NOTE）
- **六类变更标记**（借鉴 Keep a Changelog，按需标注在四件套内）：

| 标记 | 含义 | 示例 |
|------|------|------|
| Added | 新增 | 新增 SEC-005 扫描规则 |
| Changed | 修改行为 | save-env-config 改为禁运行时覆盖 |
| Fixed | 修复缺陷 | 修复 TS2802 Map 迭代 |
| Security | 安全修复 | 密钥轮换、XSS 转义 |
| Removed | 移除 | 移除 exec 死代码 |
| Deprecated | 弃用 | 旧端点标记弃用 |

- **处置收尾**：回退/删除/清理/审查类操作（如 workflow 删除、报告归档）同样必须记入对应 W 段的「处置收尾」字段——不因「非新功能」而跳过
- **行数**：10-20 行/段；> 30 行需自问是否可拆分或归档
- **归档**：> 50KB 或 500 行 → 迁移最早版本段至 archive/docs/CHANGELOG-ARCHIVE.md
- **二级归档（W513）**：archive/docs/CHANGELOG-ARCHIVE.md / archive/docs/file-index-ARCHIVE.md / archive/docs/HANDOVER-ARCHIVE.md 任一超 **1MB** → 触发二级归档：最老块迁移至 `archive/docs/<原名>-tier2.md`（如 CHANGELOG-ARCHIVE-tier2.md），archive 保留较新段 + 头部指针；tier2 文件须登记进 verify_delivery `ARCHIVE_DOCS`（W513 已入例）；tier2 历史段同受 §11.2 禁改约束
- **归档根与分类（W734 统一）**：全部归档件统一归入仓库根目录 `archive/`（与 docs/scripts/site 并列·W734 自 docs/archive 与 scripts/archive 迁入）；按文件类别归置子目录——文档类（.md/.txt 等）→ `archive/docs/`，脚本类（.py/.js 等）→ `archive/scripts/`，来源成组时可带来源子目录（如 archive/docs/w550-shot-review/）；触发条件二选一：① 文件被取代/退役（无论体积）；② 现役文档超限（本条及上一条阈值）；归档件只追加新归档段、禁止回溯修改（§11.2）

## 6. Commit Message 规范（Conventional Commits）

格式：`<type>(<scope>): <subject>`

本项目 type 集：

| type | 含义 | 示例 |
|------|------|------|
| fix | 修复 | `fix(w413): 仓库文件策略审查 — …` |
| feat | 新功能 | `feat(rag): provider 化 Base URL` |
| docs | 文档 | `docs(w413): 六文档同步 v2.3.28` |
| chore | 杂务/门禁 | `chore(ci): 移除过期 cache` |
| refactor | 重构（无行为变化） | `refactor(site): 抽取 escapeHtml 工具函数` |
| perf | 性能 | `perf(rag): 索引缓存` |
| security | 安全 | `security(mcp): 路径白名单` |

规则：
- `scope`：子系统名（rag/mcp/site/api/ci）或 W###（`w413`），可省略
- `subject`：祈使语气、≤ 60 字符；英文首字母小写
- 正文（可选）：`- ` 条目式列要点；破坏性变更用 `BREAKING CHANGE:` 前缀
- 提交体关联 W###（如 W413），便于 git log 与 CHANGELOG 双向追溯

## 9. 文档变更评审流程（docs-as-code）

1. **变更前**：查单一事实源是否已存在该信息（§3），存在则不重复
2. **变更中**：遵守 §4 写作规则与 §5/§6 格式；改历史段前按 E2 判据区分「历史事实（保留）」vs「现役描述（更新）」
3. **变更后**：跑 `verify_delivery.py`（提交门禁）确认 v/W 一致性与无范围漂移
4. 文档随代码走同一 commit/PR，禁止「只改文档不验证」；关键路径（版本/计数/W 范围）须 Grep spot-check 落地（E1 铁律）

## 10. 违反后果

文档膨胀/失配会导致：
- 新 session 加载上下文消耗大量 token（300KB 的 CHANGELOG ≈ 75K token）
- git diff 噪音淹没真正的代码变更
- 多 agent 协作时 Edit 冲突概率急剧上升（并行 Edit 竞态）
- 接手者阅读 HANDOVER 时信息过载，无法快速定位关键信息
- commit 被 pre-commit 门禁阻断（v/W 缺失或范围漂移），返工成本

### 11.3 接手速查（新 session / 新 Agent 首读）

1. 读 HANDOVER.md「零、当前阻塞」+「一、当前进度」→ 定位 HEAD 与下一 W 编号
2. 读 本节 11.1 → 明确本次 W 完成后必须同步的文件清单
3. 读 本节 11.2 → 明确禁止擅自修改的文件（历史段/密钥/门禁/归档）
4. 动手前查单一事实源（§3）：想写的内容归属哪个文件？不重复写
5. 提交前双重门禁：任务清单（TaskCreate 系列）逐项勾选 11.1 + pre-commit 自动跑 `verify_delivery.py`；临时跳过用 `git commit --no-verify`（不推荐）
6. 每个文件修改后：Grep spot-check 验证落地（E1 升级版铁律·声明≠落地）

## 12. 交付自检（10 项）

> 来源：由已退休的 `handoff-checklist.md`（8 项）+ `validation-checklist.md`（6 项）合并提炼（W797·原件入 `archive/docs/templates/`）。适用于任何文档/代码交付，含主代理与 subagent 两种角色。

| # | 检查项 | 判据 | 执行方式 |
|:---:|:---|:---|:---|
| 1 | 元信息完整 | 标题 + 作者/生成来源 + 日期 + W### ID 齐备 | 肉眼/头部三行核对 |
| 2 | 双索引一致 | CHANGELOG 的 W### 段 ↔ file-index 的本文件条目互相匹配 | Grep 双向 |
| 3 | 文件命名规范 | `主题.md` 或 `YYYY-MM-DD-主题.md`；目录归属正确 | 肉眼 + STRUCTURE 目录表 |
| 4 | 写作风格一致 | 与双轨写作表（大众普及/学术研究/教学讲解/个人创作）一致且贯穿全篇 | 抽读开头与结尾 |
| 5 | CHANGELOG 四件套 | 来源/文件/验证/状态 四字段齐全 | Grep W### 段 |
| 6 | INDEX 同步 | `python scripts/docs_index.py --check` 通过（如适用） | 跑命令 |
| 7 | 无占位符 | `Grep "<!-- TODO"` 交付物 0 命中 | Grep |
| 8 | 关联链接有效 | 所有相对链接指向实际存在的文件 | `python scripts/lint_links.py` |
| 9 | 内容命中 | 任务要求的关键术语在交付物中 ≥2 处命中 | Grep 关键术语 |
| 10 | 复核闭环 | 主代理核对：文件存在 + 声明与实物一致；失败 ≥3 项直接接手修复并记方法论 | 人工 + 证据留存 |

**处置规则**：10/10 通过=接收；任一项失败=退回修复并附证据；失败 ≥3 项=任务理解偏差，主代理 fallback 接手并在复盘登记。

**注**：第 1–9 项由交付方自检，第 10 项由接收方复核；机器可判项（2/5/6/7/8/9）应直接跑命令，不以口头声明代替证据。
