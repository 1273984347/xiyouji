# 文档规范

> 本文件定义项目文档的写入规则，防止文档膨胀。所有 agent（包括 AI 代理）在更新文档时必须遵守。
> 创建于 2026-08-03（W336 后·文档瘦身复盘）

## 核心原则

**每个文档有且仅有一个职责，不重复其他文档的内容。**

## 文件职责与粒度

| 文件 | 职责 | 每个 W### 写入量上限 | 禁止写入 |
|------|------|---------------------|----------|
| CHANGELOG.md | 施工日志（唯一允许写细节的地方） | 10-20 行（来源/文件/验证/状态四件套） | 无限制，但超过 30 行需自问是否必要 |
| README.md | 项目是什么 + 怎么用 | 0 行（仅更新版本号） | 禁止写 W### 细节 |
| STRUCTURE.md | 目录结构说明 | 0 行（仅更新版本号+新增目录） | 禁止写 W### 细节 |
| 项目说明.md | 项目状态快照 | 0 行（仅更新版本号） | 禁止写 W### 细节 |
| file-index.md | 文件→W 反向索引 | 每文件 1 行（文件名 + W### + 一句话） | 禁止写验证过程/subagent 报告 |
| 交接文档.md | 跨 session 交接 | 每个里程碑 3-5 行摘要 | 禁止复制 CHANGELOG 的完整条目 |

## 版本描述规则

README / STRUCTURE / 项目说明 的"当前版本"行：

- **格式**：`> 当前版本 vX.X.XX（日期）：一句话概括项目规模 + 最近 1-2 个里程碑关键词。详细变更见 CHANGELOG.md。`
- **长度**：不超过 200 字符
- **禁止**：在版本行中列举所有历史 W### 的内容

## 归档触发条件

| 文件 | 触发条件 | 动作 |
|------|---------|------|
| CHANGELOG.md | 超过 50KB 或 500 行 | 将最早的版本段迁移至 CHANGELOG-ARCHIVE.md |
| file-index.md | 超过 50KB 或 500 行 | 将最早的条目迁移至 file-index-archive.md |
| 交接文档.md | "已完成里程碑概要"超过 100 行 | 保留最近 5 个版本摘要，其余删除（CHANGELOG 有完整记录） |

## "6 文档同步"的正确执行方式

旧做法（导致膨胀）：
> 每个 W### 完成后，在 6 个文档中各写一段完整描述。

正确做法：
1. **CHANGELOG.md**：写完整四件套（来源/文件/验证/状态），10-20 行
2. **file-index.md**：每个新建/修改文件加 1 行索引
3. **README / STRUCTURE / 项目说明**：仅更新版本号字符串（如 v2.2.87 → v2.2.88）
4. **交接文档**：在"已完成里程碑概要"顶部加 3-5 行摘要

## pre-commit hook 兼容

`scripts/verify_delivery.py` 要求 README / STRUCTURE 中包含上一个版本号字符串（如 "v2.2.86"）。更新版本号时，在版本描述中保留对前一版本的引用（如 "W334（v2.2.86）设计系统"），不要删除所有旧版本痕迹。

## 违反后果

文档膨胀会导致：
- 新 session 加载上下文时消耗大量 token（300KB 的 CHANGELOG ≈ 75K token）
- git diff 噪音淹没真正的代码变更
- 多 agent 协作时 Edit 冲突概率急剧上升
- 接手者阅读交接文档时信息过载，无法快速定位关键信息
