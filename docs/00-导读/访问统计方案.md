# 访问统计方案（GoatCounter 升级路径）

> 本文档说明本项目（GitHub Pages 静态站）访问统计的现状、Umami 与 GoatCounter 的选择对比，以及切换到 GoatCounter 的具体升级步骤。
> 关联：`site/js/visit-log.js`（localStorage 基线）· `site/visit-viewer.html`（本地查看页）· `scripts/inject_goatcounter.py`（全站注入脚本，W403 已就绪）

---

## 一、现状与约束

- **托管**：GitHub Pages，纯静态，**无法运行任何服务端进程**（Node.js/数据库都不行）。
- **已有基线（W403）**：`visit-log.js` 将每次访问写入浏览器 localStorage（上限 500 条 FIFO），`visit-viewer.html` 可查看/导出。**局限**：仅本浏览器可见，统计不了真实跨访客读者量。
- **目标**：在零服务器 + 不牺牲隐私的前提下获得**真实的跨访客访问统计**。
- **演进路径**：Umami 自托管（需独立服务器，排除）→ 零服务器方案 → GoatCounter（托管版免费、无需自建，首选）→ localStorage 自建基线（当前，作为兜底与降级）。

---

## 二、Umami vs GoatCounter 对比

两个都是开源、隐私友好的 Google Analytics 替代品，核心差异在于**部署复杂度**与**功能丰度**。

| 维度 | **GoatCounter** | **Umami** |
|---|---|---|
| 开源协议 | AGPL-3.0 | MIT |
| 托管版 | **免费**（捐赠支持，合理公共用量——个人站/小中站点免费，百万级 PV/天除外） | **Hobby 免费**：10 万 events/月·最多 3 站点·6 个月数据保留·社区支持；Pro $20/月（100 万 events·20 站点·2 年保留）·Business $200/月·Enterprise 定制 |
| 自托管难度 | **极低**：单二进制 + SQLite，无外部依赖 | **较高**：需 Node.js + PostgreSQL/MySQL，多服务运维 |
| 脚本体积 | ~3.5 KB，极轻量；支持无 JS 像素追踪、日志导入 | 稍重；标准 script 加载 |
| 数据保留 | 取决于自托管策略；托管版长期可用 | 免费档仅 6 个月；付费档 2-5 年 |
| 功能范围 | **克制**：PV/访客/来源/浏览器/位置/屏幕/活动；突出简洁 | **丰富**：漏斗、留存、UTM、目标、用户旅程、自定义事件、实时看板、API、会话回放（Business） |
| 隐私合规 | 无 cookie、不存唯一标识、无需 GDPR 弹窗 | 无 cookie、无个人数据、GDPR/CCPA 合规、无需 cookie banner |
| 数据所有权 | 可导出、可随时取消、可自托管 | 可导出、无锁定；Cloud 数据在 US/EU 服务器 |
| 无障碍 | 高优先级（读屏友好） | 常规 |
| 本项目适配 | **命中所有约束**：免费、无需服务器、单 script 即插、隐私友好 | Cloud 需注册且免费档有额度/保留期限制；自托管超出本项目能力 |

**结论**：本项目流量小、要求零服务器、不想注册付费，**GoatCounter 托管版是唯一同时满足"免费 + 零服务器 + 真实跨访客统计"的方案**。Umami 更适合：需要漏斗/留存等深度分析、团队协作、或有服务器可自托管、且愿意接受事件额度与保留期限制的场景。

## 三、GoatCounter 升级方案（具体步骤）

### 第 1 步：注册并获取站点代码

1. 打开 <https://www.goatcounter.com/signup>，注册账号。
2. 创建站点（Site），获得一个站点代码（site code），如 `xiyouji`。
3. 得到追踪地址：`https://xiyouji.goatcounter.com/count`（页面集成用）与后台地址 `https://xiyouji.goatcounter.com/`。

### 第 2 步：配置注入脚本

`scripts/inject_goatcounter.py`（W403 已就绪）会在每个 `site/*.html` 的 `</head>` 前注入：

```html
<script data-goatcounter="https://xiyouji.goatcounter.com/count" async src="//gc.zgo.at/count.js"></script>
```

两种配置方式（任选其一）：

```powershell
# 方式 A：命令行参数
python scripts/inject_goatcounter.py --site xiyouji

# 方式 B：项目根 .env 写入 GOATCOUNTER_SITE=xiyouji 后直接运行
python scripts/inject_goatcounter.py
```

- 脚本幂等：已含 `goatcounter` 的页面自动跳过，可重复运行。
- 未配置 site 时以 `--check` 运行只报覆盖率，不写入。

### 第 3 步：注入前检查（可选）

```powershell
python scripts/inject_goatcounter.py --check
```

确认扫描文件数与待注入数符合预期（当前 160 个 HTML）。

### 第 4 步：CSP 兼容（部署到 Netlify/Cloudflare 时）

**W424（2026-08-12）已通过每页 `<meta http-equiv="Content-Security-Policy">` 落地严格 CSP**（159 页·script-src 白名单 d3js/cdnjs + 680 个内联脚本 SHA-256 哈希·script-src-attr 'none'·生成器 `scripts/generate_csp.py`·改内联脚本必须重跑，verify_delivery 有漂移门禁）。GitHub Pages 直接生效，无需 `_headers`。

`site/_headers` 仍保留 Netlify/Cloudflare 平台层 HTTP 安全头（W268 设计），其 CSP 白名单已同步（d3js/cdnjs·本地 RAG `127.0.0.1:8777`）；**GitHub Pages 不消费 `_headers`**。若未来部署到 Netlify/Cloudflare Pages，需在 `_headers` 的 CSP 中把 `gc.zgo.at` 加入 script-src / connect-src：

```http
/*
  Content-Security-Policy: ... script-src 'self' 'unsafe-inline' https://d3js.org https://cdnjs.cloudflare.com https://gc.zgo.at; connect-src 'self' http://127.0.0.1:8777 https://api.github.com https://gc.zgo.at ...
```

### 第 5 步：验证统计生效

1. 注入后 push，等待 GitHub Pages 部署（或本地 `python -m http.server` 预览）。
2. 浏览器打开站点任意页 → DevTools → Network 面板 → 应看到对 `https://xiyouji.goatcounter.com/count` 的请求。
3. 打开 GoatCounter 后台，应出现实时 PV / 访客 / 来源数据（首次访问有秒级延迟）。
4. 用无痕窗口访问确认可统计（不依赖 cookie）。

### 第 6 步：数据流与降级路径

- **正常路径**：`count.js` 上报 → GoatCounter 云端统计 → 后台看板。
- **降级路径**：`visit-log.js` 的 localStorage 基线**保留不删除**——无网络 / 脚本被拦截时仍记录本机访问；两者互补。
- **回退**：若需移除 GoatCounter，删除各页注入的 script 标签即可（`git revert` 或脚本反向清理），localStorage 基线不受影响。

### 第 7 步：数据导出（可选）

GoatCounter 支持导出全部数据（CSV），后台提供导出入口；也可随时取消账号，数据归自己所有。

## 四、升级后建议

- 观察 1-2 周真实 PV/访客数据：**有流量 → 继续内容生产与分发（S2/S4 方向）；无流量 → 按既定决策停止内容生产**。
- 若未来需要漏斗/留存等深度分析且愿意付费/自托管，再评估 Umami Cloud Pro 或自托管。
- 保留 `inject_goatcounter.py --check` 作为 CI 或手动门禁，防止未来新增页面漏注入。
