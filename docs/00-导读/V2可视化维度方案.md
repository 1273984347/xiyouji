# V2 可视化维度详细方案

> 定位：V 方向（可视化深化）下的 V2 阶段。本文档为详细规划，落地时每项单独走 W 批次 + verify_delivery 门禁。
> 更新时间：2026-08-14（配合英文站全量英文化 W445 收官后的下一阶段规划）

## 一、背景与现状

V 方向整体分四层：

- V1 现有页面内容深化（dashboard KPI 更新、交互增强）
- V2 新增可视化维度（本方案主题）
- V3 跨页面导航增强（footer 关联链接、标签云、智能推荐）
- V4 移动端体验（375px 视口、触摸交互、竖版图表）

当前 site/data/ 已有 86 张可视化页，且英文站 site/en/ 已全量英文化（W445 收官，232 页 CSP 0 漂移、3930 链接 0 broken）。

## 三、详细方案

### 方案 A（全新·优先）：西游地理 3D 可视化

**目标**：把取经路线从二维地图升级为可旋转、可缩放、带真实地形的 3D 场景，直观呈现「从东土大唐到西天灵山」的地理纵深。

**技术选型**：
- 首选 **Three.js（r128，CDN cdnjs）**：项目已有多处 Three.js 内联页面经验，且 file:// 可运行（Cesium 依赖外部瓦片服务，file:// 下不可用，不满足项目「双击可用」约定）。
- 地形数据：不引外部 DEM，用程序化生成的示意地形（Perlin 噪声山体 + 河流曲线），避免大体积二进制资产。
- 路线数据：复用 `journey-map-interactive.html` 已有的关键节点坐标（长安/两界山/鹰愁涧/高老庄/火焰山/通天河/女儿国/灵山等）。

**页面设计**（建议文件名 `journey-geo-3d.html`）：
- 顶部：标准 topnav/hero（沿用现有模板，含中文 back-link）。
- 主体：Three.js 场景，含示意地形、取经路线折线、关键节点标记。
- 交互：鼠标旋转/滚轮缩放、点击节点弹出章节与地点信息、可切换「路线高亮 / 地形透明」。
- 图例：节点分类着色（人间/妖界/天庭/灵山）。
- 性能：按 perf-canvas-rendering 经验做节流（rAF 批量更新）、节点数控制（关键节点 ≤ 40）。

**数据来源**：新增一份 `scripts/output/data/` 下的路线坐标 JSON（或内嵌 EMBEDDED 回退，遵循「fetch + EMBEDDED fallback」约定）。

**验收标准**：
- file:// 双击可开、fetch 失败自动回退 EMBEDDED；
- 无外部网络依赖（地形程序化生成）；
- 若出 EN 版，须过 `_validate_en.py`（chrome whitelist + script CJK=0）；
- 过 generate_csp / lint_links / verify_delivery。

### 方案 B（深化）：人物关系动态网络

**现状**：character-dynamic-network.html（85 chrome + 212 script 字面量，已英化）+ character-relationship-3d(-view).html。

**深化方向**：
- 时间轴播放：按回目推进关系边出现/消失的动画（复用 cooccurrence 时间线数据）；
- 角色过滤：点击角色只显示其邻域子图；
- 边权重视觉：关系强度映射线宽/透明度（现为颜色映射，可加粗细）。

**验收**：交互不破坏现有 hover tooltip；性能满足移动端 60fps（rAF 节流）。

### 方案 C（深化）：八十一难难度热力图

**现状**：hardship-difficulty-heatmap.html（难度 × 回目热力图）+ hardship-heatmap.html。

**深化方向**：
- 难度-结局交叉联动：点击单元格钻取该难的「结局类型 / 是否搬救兵」；
- 回目双向联动：热力图 ↔ 八十一难清单表同步高亮；
- 排序维度切换：按「难度 / 章节 / 结局」重排热力图。

### 方案 D（深化）：取经路线时间-空间双轴

**现状**：journey-spacetime.html（时空双轴）+ journey-map-interactive.html（交互地图）。

**深化方向**：
- 双轴真正联动：鼠标在时间轴滑动，地图路线节点同步高亮；
- 回目导航：路线节点直接跳转 A1 对应回目解读页（docs/01）；
- 距离/时长可视化：叠加每段路程耗时/距离的辅助刻度。

## 五、风险与依赖

- **Three.js 版本**：项目约束 r128（Cloudflare CDN），不要用 r142+ 的 CapsuleGeometry 等 API。
- **file:// 约束**：3D 地理不可依赖外部瓦片/远程纹理，必须程序化生成或内嵌。
- **CSP 内联哈希**：任何新页改动脚本后必须重跑 generate_csp.py。
- **英文站一致性**：若新增 EN 版，须复用现有 EN 模板 + 角色名对照表 + _validate_en.py。
- **移动端**：Three.js 场景在 375px 视口需降级（降低地形面数 / 关闭阴影）。
