# 统计口径说明

> 本文件是项目所有对外数字的**唯一口径来源**：定义每个数字的算法与边界，防止 README / 首页 / 交接文档各说各话。
> 适用对象：所有更新项目文档与站点的人与 AI 代理（含 Web Agent）。
> 创建于 2026-08-16（W450·统计口径统一）。

## 1. A1-A6 内容篇数 = 611 篇

**算法**：`docs/01-全书逐回解读`、`docs/02-人物深度分析`、`docs/03-主题与情节专题`、`docs/04-文化与历史背景`、`docs/05-诗词歌赋`、`docs/06-个人随笔` 六个板块目录**顶层** `.md` 文件数之和，**排除**各板块自身的 `README.md`。

**边界**：不递归子目录；不含 00-导读、07-09 及 docs 目录外文件。

**分板块**（与 `scripts/verify_delivery.py` 的 `A_AREAS` 一一对应）：

| 板块 | 目录 | 篇数 |
|---|---|---|
| A1 逐回解读 | docs/01-全书逐回解读 | 100 |
| A2 个人随笔 | docs/06-个人随笔 | 44 |
| A3 人物分析 | docs/02-人物深度分析 | 211 |
| A4 主题专题 | docs/03-主题与情节专题 | 209 |
| A5 文化背景 | docs/04-文化与历史背景 | 34 |
| A6 诗词歌赋 | docs/05-诗词歌赋 | 13 |

**校验**：`scripts/verify_delivery.py` 强制 README 声明 `共 611 篇` 与真实计数一致，漂移即 FAIL。

## 2. 可视化页面 = 86 页

**算法**：`site/data/` 目录**顶层** `.html` 文件数 = 86（含 `-view` 3D 视图页与内部模板 `_shell.html`）。

**校验**：`Get-ChildItem site/data -Filter *.html` 计数；README 与 site 文案（index / dashboard / tag-cloud）必须与口径一致写 86。

## 3. 数据维度 = 133 维（含趣味实验）

**算法**：README「数据维度全景」Phase 1-7 各阶段维度数之和：42 + 28 + 43 + 8 + 11 + 1 = 133。

**语义**：133 是**维度清单**计数，不是页面数；其中含趣味跨界实验维度（MBTI、卡牌、职场黑话等）。

**宣传口径**：首屏/英雄位不把 133 维作为主指标（避免「维度注水」误读）；确需展示时标注「含趣味实验」。

## 4. 学术引用 = 55 条

**算法**：`source/引用与网络解读/学术论文索引.md` 编号条目行数（V/C/A/S/T/P/M/N 八类合计 = 6+6+13+3+11+6+4+6 = 55）。

**说明**：该索引是「学术研究」轨文档的引用池；新增引用时同步登记并保持编号连续。

## 5. 版本号口径

- `vX.Y.Z` 是**内容发布批次编号**，不适用 SemVer 兼容性承诺：MAJOR/MINOR 对应内容阶段（v2.x = 内容体系成熟期），PATCH 随每次发布（一个 W### 条目）递增。
- 唯一持有者：`site/dukou-engine.html` 页脚；其余文档经 `scripts/bump_version.py` 同步。
- 判断「某版本改了什么」一律查 CHANGELOG.md，不要从版本号推断兼容性。

## 6. 维护规则

1. 任何对外数字（README / site/index.html / dashboard.html / 交接文档）引用前，先在本文件查口径。
2. 计数口径变更必须先改本文件，再同步所有引用处；禁止只改宣传文案不改口径。
3. 发布前运行 `scripts/verify_delivery.py`（611 / 209 强制校验）与 `scripts/lint_links.py --internal`。
4. 历史误值（首页 625 / 80 等）已在 W450 统一为 611 / 86 / 55；如再发现不一致，按本文件口径修正。
