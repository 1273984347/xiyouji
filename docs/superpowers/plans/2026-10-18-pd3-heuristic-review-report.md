## 一、范围与方法说明

1. **两态**：file://（离线双击）与 http（`python -m http.server`）——两条独立覆盖面，截图逐张记录 pageerror；
2. **双主题**：`prefers-color-scheme: dark` 模拟夜读态；
3. **滚动显现机制（W488）**：两页均用 `reveal-in` + IntersectionObserver 入场（js-reveal 类守卫·reduced-motion 直达终态·fail-open）。**全页截图对视口外未触发的段落呈 opacity:0 空白——这是截图工艺现象，不是用户缺陷**（真实浏览滚动即现）。本报告不把截图空白记为 finding（探针纪律：先排除工艺伪影再下判）；
4. **低分辨率误读排除**：走查中三处「疑似乱码/错字」（搜索提示行/DATA 介绍句/人物关系卡片）经原尺寸回读均为**清晰正确的正文**，未记 finding——记录在案以防同类误判复现。

## 五、与既有门禁的关系（为什么这些没被门禁抓到）

第 12/13/16/26 门禁覆盖一致性/标准/错误预防的机械面（链接/head/CSP/内容加载），但**页面文案中的聚合数字与版本徽标不在任何扫描域**（C5 只扫六文档+口径块，不扫 site 页面）。本报告的 F-03/F-04/F-05 正是该门禁盲区的实例化——是否给 site 文案加门禁（B-101 附带议题）需权衡：页数 336，全量扫聚合数会引入大量白名单，建议只对「页脚/版本徽标/搜索卡文案」三类高危位置做定点断言，而非全页扫描。
