## 3. 功能详细设计

### 3.1 四项出处检查（v1.1 校准判据）

**功能描述**：对范围内每页，检查四项并产出 通过/不通过+原因码。
**用户故事**：作为接手仓库的 Agent，我希望新增/改坏可视化页出处区时被逐检查点拦截并告知缺哪项，以便一次修对而非 CI 三连红。
**优先级**：P0

**扫描区定义（新增·判据生效前提）**：
0. **主区** = `<div class="notice" id="dataSource">…</div>` 的静态内容 **∪** JS 中赋给该元素的字符串（形如 `'数据源：实时加载自 <code>json/xxx.json</code>…'`，两态都要收）。
   **辅区** = 页内含 `数据源|数据出处|数据来源` 文案的其它可见元素。
   **排除区** = 内联 CSS/JS 头注释（`tokens.css —`/`inline_css.py`/`w334_font_subset.py` 所在注释块）、阅读延伸区 blob 链接、`<script>` 中的 fetch 变量名。

| # | 检查项 | 通过判据（存在性·静态扫描） | 已实测边界与原因码 |
|---|--------|--------------------------|-------------------|
| **C1** | **数据文件路径 + 版本** | ①扫描区内出现 `.json` 路径且**解析到磁盘真实存在**（相对 `site/data/` 解析；EMBEDDED 单源页以明示"嵌入式数据/内嵌数据"声明替代路径）；**且** ②含版本标识（生成日期 `YYYY-MM-DD` / `W###` 批次 / git sha / 快照日 任一） | 缺路径→`no-path`；路径不指向真实文件→`ghost-path`；fetch 路径越出 `site/`→`fetch-escape`（W554 反例）；有路径无版本→`no-version`（**预期主因·仅 3/86 有版本**） |
| **C2** | **生成脚本 + 参数** | 扫描区内出现 `scripts/**/*.py` 且**不在构建工具排除表**（`inline_css.py`、`w334_font_subset.py`），并含参数/口径说明（同句出现"生成/参数/口径/run_all/阈值/样本"任一，或脚本路径含分析类目前缀如 `AD_商业模型/`） | 无脚本→`no-script`（**预期 74/86**）；仅构建工具→`build-tool-only`（v1.0 假阳性源·已排除）；脚本磁盘不存在→`ghost-script` |
| **C3** | **引用格式呈现** | 三者其一：①`<cite>` 元素 ②含"引用/Citation/引文格式"语义的可见区块 ③扫描区内含站点规范 URL（`1273984347.github.io/xiyouji/...`） | 全无→`no-cite`（**预期 85/86**）·**不要求 APA/MLA/BibTeX 三式齐全**（那是第二步组件职责·见 §9 D2 裁决） |
| **C4** | **下载入口** | ①`a[download]` 属性 或 ②扫描区内指向所引 `.json` 的链接 或 ③EMBEDDED 单源页的"内嵌数据声明"（与 AGENTS §6-5 回退铁律对齐） | 全无→`no-download`（**预期 70+ 页**·现仅 graph-explorer 有 download 属性） |

4. 四项相互独立、逐项判定；单页总分 = 通过项数（0-4），**不加权**（W638"分级未经验证"教训）。
5. **分级呈现于报告**（§9 D2 裁决的落地形态）：C3 按 L0 无 / L1 有站 URL / L2 有引用区块 / L3 有 `<cite>` 或结构化引用文本 分四级记录，**门禁判据仍按"任一锚点即过"**，分级只服务于第二步排期。

**豁免机制**：
6. 页内注释 `<!-- citability-exempt: C2 理由≤80字 -->` 可豁免指定单项（参照 e-track-exempt 形态）；**豁免注释禁含 W 号**（W645/W621 漂移教训预防性写入）。
7. 无注释=无豁免；注释语法非法（缺项号/缺理由）=不生效并报 `bad-exempt`。

**异常处理**：

| 异常场景 | 处理方式 | 提示 |
|---------|---------|------|
| 基线文件缺失/损坏 | 门禁判 **FAIL**（堵 W631"报 100% 实为空真"静默跳过盲区） | `baseline missing — refuse to pass` |
| 页面 HTML 解析失败 | 该页判 `parse-error`，计入违规面（不静默跳过） | 附行号 |
| 无 `id="dataSource"` 锚点（31/86 页） | C1/C2 以**辅区**判定；辅区亦无 → 报 `no-anchor`（不直接 FAIL 整页，交由各项分别反映） | 报告单列 |
| 数据文件位于 gitignore 生成物区（`scripts/output/data/`） | C1 磁盘存在性以**部署副本 `site/data/json/`** 为准 | `gitignore-target` |
| 新页未入基线且四项全缺 | 4 项均基线外 FAIL 阻断 | 逐项原因 + 指向九问清单 |

### 3.2 基线冻结与只增语义

**功能描述**：首跑全量扫描生成 `scripts/output/citability-baseline.txt`，冻结存量缺口；此后只对**基线外**违规判 FAIL。
**优先级**：P0

**业务规则**：
1. 基线行格式：`页名|检查项|状态(missing/exempt/ok)|快照日`——逐页逐项一行，**344 行起步**（含 ok 行，便于收紧对账）。
2. **"只增即 FAIL"准确语义 = 违规集合单调不增**：基线中 missing 项修复后允许删除该行（**收紧**）；基线外新 missing = FAIL。防僵尸豁免膨胀。
3. 基线文件纳入第 17 门禁式新鲜度关注（改动随批登记 file-index）。
4. 生成与检查同一脚本两 mode（`--generate-baseline` / `--gate`），与 check_content_consistency 同构。

### 3.3 WARN 报告产物（第二步整改地图）

**功能描述**：每次运行输出机读 JSON + 人读摘要表。
**优先级**：P1

**业务规则**：
1. `scripts/output/citability-report.json`：逐页逐项 `{status, reason_code, grade?, exempt}`；
2. 摘要四格统计：C1-C4 各自通过率（**首跑预期 C1≈3% / C2≈14% / C3≈1% / C4≈19%**，如实报告，不为凑通过率放宽判据）；
3. 报告与基线冲突时以基线为准，冲突行显式报出。

### 3.4 verify_delivery 挂载与六文档联动

**功能描述**：作为第 28 门禁并入 `scripts/verify_delivery.py`，WARN 起步（同第 22 门禁 W518 起步策略）。
**优先级**：P0

**业务规则**：
1. 挂载即改 AGENTS.md §4.2 第 28 条（结构性编辑·维护契约②就地并入禁止尾部追加）；
2. **基线外违规=当场 FAIL**（挂载即硬）；**存量 WARN 面转 FAIL 的时点 = 基线 missing 收敛到阈值以下**（§9 D4 裁决），不预设日期；
3. CI 覆盖：verify.yml Delivery Gate 自动带入（无 workflow 改动）；
4. registry 须记 **B-6 裁决反转**（"登记不开工"→"第一步批准开工"·日期+理由），不留暗账；
5. 六文档同步、file-index 登记；本门禁不改页面 → generate_csp 预期零漂移（AC-09 机判保障）。
