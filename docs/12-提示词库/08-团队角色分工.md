## 一、角色清单（原文）

> 项目经理、产品经理、UI/UX 设计师、后端开发、前端开发、技术经理、数据库管理、数据分析、审查测试、运营客服

## 二、角色职责

| 角色 | 职责 | 原文评述（逐字保留） |
|:---|:---|:---|
| 产品经理 | 定义做什么、为什么做；PRD、用户故事、优先级 | office-hours |
| 后端开发 | 服务器、数据库、业务逻辑；API、数据模型、服务端架构 | — |
| 前端开发 | 用户界面、交互实现；网页/App 界面、组件库、用户体验落地 | — |
| UI/UX 设计师 | 界面好看、操作顺畅 | 前端只能抄竞品，体验拼凑感强 |
| 测试工程师 | 找 Bug、保障质量 | 上线后用户帮你测，口碑崩坏 |
| 技术经理 / Tech Lead | 技术决策、代码质量、团队成长 | 资深后端或前端兼任 |
| 项目经理 / PMO | 排期、进度跟踪、跨部门沟通 | 产品经理兼任（但易分心） |
| 运营 | 拉新、促活、内容维护 | 没人用的产品只是代码 |
| 数据分析师 | 埋点、用户行为分析、迭代依据 | 没数据 = 凭感觉决策 |
| 客服 / 用户支持 | 收集反馈、处理问题 | Bug 之外的需求来源 |

## 三、领域扩展角色

| 业务形态 | 扩展角色 |
|:---|:---|
| 电商 / 支付 | 风控工程师、合规专员 |
| AI / 算法产品 | 算法工程师、数据标注管理 |
| 软硬结合 | 嵌入式工程师、硬件产品经理 |
| 企业 SaaS | 解决方案架构师、客户成功经理 |

## 四、团队骨架（原文五条）

1. 三核打底（PM + 后端 + 前端）；
2. 设计测试保质量（UI/UX + QA）；
3. 运维上线不断线（DevOps）；
4. 运营数据让产品活（运营 + 数据分析）；
5. 按需增加领域专家（算法、风控、嵌入式等）。
