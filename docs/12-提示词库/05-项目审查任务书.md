| R-1 | Git 仓库历史 | 热点文件、贡献归属、历史密钥泄露 | 热点清单 + 归属分析 + 泄露扫描结果 |

## R-1 Git 仓库历史分析

- 深度分析 Git 历史：识别**高频变更的热点文件**；
- 分析**代码的实际贡献归属**关系；
- 扫描历史提交中的**密钥泄露**等安全隐患。

## R-2 全项目代码审查

对全部文件做全面审查，识别技术问题、性能瓶颈、安全隐患、代码质量问题及架构缺陷。重点方向：

1. 未处理的异常情况；
2. 内存泄漏风险；
3. 代码重复与冗余；
4. 性能优化空间；
5. 安全漏洞（XSS、CSRF、SQL 注入等）；
6. 依赖项安全更新；
7. 兼容性问题；
8. 文档缺失或过时；
9. 测试覆盖率不足；
10. 命名不规范；
11. 架构设计不合理。

输出：详细问题描述、风险等级评估、改进建议——重点发现「不易察觉但影响稳定性/可维护性/安全性」的潜在问题。

## R-3 前后端系统检查

- **前端**：UI/UX 兼容性、响应式布局异常、JavaScript 错误、资源加载性能、跨浏览器兼容性、表单验证逻辑、API 调用错误处理；
- **后端**：接口响应时间、数据库查询效率、错误处理机制、安全漏洞（SQL 注入、XSS 攻击）、权限控制、服务器资源占用、日志记录完整性。

输出：问题分类整理 + 严重程度分析 + 问题描述 + 复现步骤 + 初步解决方案建议。

## R-4 外部参照学习（GitHub）

- 到 GitHub 上学习：哪些内容对现有工作内容有用；
- 判断是否需要下载安装；
- 输出：可用项目/资料清单 + 引入判断 + 引入方式。

## R-5 现有 UI 美化升级

目标：提升整体视觉高级感。要求：

1. **配色**：优化色彩搭配，采用符合现代设计趋势的配色系统；
2. **排版**：提升层次结构，选用更具质感的字体组合与字号比例；
3. **层次**：通过阴影、渐变等效果增强视觉深度与立体感；
4. **动效**：优化交互反馈，添加细腻的过渡动画与微交互；
5. **组件**：统一组件风格，确保设计语言一致性与专业性；
6. **响应式**：提升多设备适配，保证不同设备上的视觉体验。

验收：简洁、精致、现代、有专业高级感，同时保持良好体验与功能可用性。

## R-6 已完成工作审查

- 检查范围：功能缺陷、逻辑错误、代码规范、性能瓶颈、安全隐患（原文此处有笔误「安wsl全」，已修正）；
- 具体维度：已实现功能的完整性与正确性 / 代码实现的规范性与可维护性 / 测试用例的覆盖度与有效性 / 文档的完整性与准确性；
- 输出：审查报告（问题 + 优先级 + 每项的具体改进建议）；
- **放行条件**：所有关键问题解决并验证通过后，方可进行后续工作。

## R-7 全项目潜在问题识别

检查方向：

- **代码质量**：重复代码、未使用变量、不规范命名、注释缺失；
- **性能隐患**：资源未释放、循环效率低下、不必要的计算；
- **安全漏洞**：输入验证不足、敏感信息暴露、权限控制缺陷；
- **兼容性**：跨浏览器/设备适配、依赖版本冲突；
- **可维护性**：模块化程度、耦合度、文档完整性；
- **业务逻辑缺陷**：潜在逻辑漏洞与边界问题。

输出：问题描述 + 所在文件位置及行号 + 按严重程度排序。
