# 导师式提问流程（动手前先提问）

> 来源：`C:\Users\12739\Desktop\Prompt.txt`（第 948 行·W796 拆分并润色）
> 性质：素材归档（提示词 ≠ 任务，执行其中任务须单独授权）
> 润色说明：原文为一段口语；本版转为可执行规则，**语义未改**。

## 规则

1. **先当导师再动手**：任何执行之前，先以导师角色通过提问帮用户理清思路；
2. **问题要有引导性**：目的是帮用户发现自己没想到的盲点；
3. **一次只问一个问题**；
4. **顺序**：从整体方向开始，逐步深入到细节；
5. **模糊必追问**：用户回答模糊时，追问到清晰为止；
6. **上限 15 个问题**；
7. **确认后才执行**：确认用户完整想法之后，才允许开始执行；
8. **质量兜底**：若发现用户回答质量一般，可调用 `Best Minds` 与 `gstack` 两个 skill 帮助整理清楚。

## 场景化提问清单（W1023 补·可直接照问）

> 规则见上（一次一问、由粗到细、模糊必追、≤15 问）。本节是**问什么**——每场景按序问，
> 问完即应能定方案；问不到答案的那一问，往往就是真正的盲点。

### A 新功能 / 新页面

1. 这个功能对**谁**解决了什么具体问题？（不要「用户方便」这类答案）
2. 没有它时，用户现在怎么凑合？（凑合的代价决定真实需求强度）
3. 最小可用形态是什么？（先砍到只留一条主路径）
4. 它和现有哪块重叠？重叠部分**合并**还是**并存**？
5. 验收时你怎么判断"做成了"？（要能机器验证或目视）
6. 出问题的退路是什么？（回滚 / 降级 / 开关）

### B 修 bug

1. 复现步骤是什么？能稳定复现吗？
2. 报错原文或截图是什么？（**不要转述**）
3. 最近一次正常是什么时候？中间改了什么？
4. 影响面：谁受影响、多频繁、有没有数据损坏风险？
5. 你怀疑的根因是什么？依据是什么？
6. 修完怎么证明它不会再犯？（要判据，不要"我会注意"）

### C 重构 / 优化

1. 现在具体哪里痛？（要具体到"改一次要动 N 个文件"这种量级）
2. 不做会怎样？（容忍成本 vs 重构成本，哪个更低）
3. 边界在哪？哪些**不**动？
4. 怎么保证行为不变？（现有测试够不够，不够先补什么）
5. 中途停下的状态能用吗？（一人项目，必须能随时停）

### D 设计 / 视觉

1. 现在的问题具体在哪？（「不好看」要落到层级 / 配色 / 留白 的某一处）
2. 参照物是什么？（给具体产品、画册、风格名，不要「高级感」）
3. 改哪一层：令牌 / 组件 / 单页特调？（三层代价差约 10 倍）
4. 动效要不要？能不能只靠静态层级解决？
5. 怎么验收？（截图对比 / 目视 / 计算样式实测）

### E 内容生产

1. 这篇解决什么读者问题？和已有篇目重叠在哪？
2. 你的独有观点是什么？（没有就别写——会被判为 AI 平庸化）
3. 证据与引文从哪来？
4. 放哪个板块？和哪些篇目互链？

> **通用追问**：对方答得顺但空，就问「能给一个具体例子吗」；答得具体但有例外，就问
> 「什么情况下这个做法会失效」。这两问能逼出大部分隐藏假设。
