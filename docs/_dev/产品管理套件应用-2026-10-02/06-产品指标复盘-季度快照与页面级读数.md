## 二、增长分析（口径先行）

- **uv7 = 1**（total=2−events=1·窗口 09-24~09-30）· **uv30 = 24**（total=31−events=7·窗口 09-01~09-30）——`fetch_gate_stats.py` API/UTC 口径；后台仪表盘同窗显示 35 visits（时区+语义差·W629 口径备注在案，本报告一律以 API 为准）。
- **DAU 不可得**（GoatCounter 日粒度可推 ≈0.8/日但方差主导）· **DAU/MAU 粘性比无意义**（n<30 时该指标统计失效，拒绝计算——防"指标凑数"）。
- **用户构成（新增/留存/回流）不可得**：GoatCounter 为 cookie 口径，无跨期用户 ID。**需要的升级**：若真要留存分析，须引入带首访时间戳的访客级数据（后台 Visitors 页 UA 明细人工可查·W629 备注在案）——低流量下人工逐条读反而可行（24 人/月，10 分钟读完），**这是本项目独有的"全量即抽样"优势**，列入行动。

## 八、关键洞察（汇总）

1. **双轨指标体系不对称是结构性问题**：工程轨 27 门禁日检、读者轨 1 个数月检——"复盘"在读者侧实为"巡检"。本报告首次给出页面级读数，即因基线从未建立。
2. **归档判据在低流量区分辨率不足**：24 vs 阈值 30 vs 分发线 200——一次偶发转发即可穿越归档线造成裁决翻转。**阈值不是问题，单轨才是**（→判据多轨化 I10）。
3. **读者行为与外部评审结论首次对账成功**：Top 页面 5/6 可视化 = "核心资产在数据层"获独立佐证（来源三角·中可信度——行为样本 n=24）。
4. **性能/无障碍等护栏指标当前是"无受害者的完美"**：LH 0.96 值得保留（解冻时不欠债），但复盘时不应因工程绿而放松读者红。
