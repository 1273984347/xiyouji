## Top 3 推荐创意

### 创意 1：I11 · 分发脉冲实验（先证伪"归档前提"，再谈维持归档）
- **描述**：不生产任何内容，只做 3 次分发动作——① GitHub Topics/描述位完善 + awesome 系清单提交 2 个；② D3 可视化画廊提交 1 个代表作（relationship-3d 或 hardship-heatmap）；③ RSS 源挂入 1 个聚合器。每渠道附 3 行现成简介（复用 README/统计口径说明原句，不新写文案）。观察 2 周。
- **解决的痛点**：W626 归档判定隐含"再投入也无读者"，但 W648 同时证明"从未测过分发"——**判决建立在未检验假设上**。
- **预期效果**：判定性指标单一——referrer 占比从 0%（W648 基线）是否破零；若 2 周后仍 0 外部来源，归档裁决从"假设"升级为"实证"，此后执行更心安；若破零，解锁 I10 多轨判据讨论。
- **实现路径**：纯操作项 ≈ 0.5 批（含提交表单与回执留档进 docs/10 复盘 §一 同目录）。
- **验证方式**：实验自带验证（GoatCounter Top referrers + W648 已打通的 DevTools 手工注入取证法可直接复用）。
- **风险**：提交失败率高（清单有准入门槛）→ 选 5 投 2；中文社区渠道可能要求内容授权 → 先英文索引。

### 创意 2：I10 · judge_gate 判据多轨化（修复"用网站流量指标判学术资产死刑"）
- **描述**：在 W626 阈值分发逻辑中，除 uv30 外并列一条"高意图信号"通道：外部引用（Google Scholar 收录 S4 后计数）、Zenodo 下载量（若 I13 成行）、fork/star、mailto 反馈计数（页脚入口已有）。判据从 `uv30≥200` 扩为 `uv30≥200 or intent≥N`，N 起步可设 1（出现第一条即值得重审）。
- **解决的痛点**：Why5a 根因——项目真正的价值兑现通道（学术引用/方法复用，即 B-5/B-7 线）在现行度量中权重为零。
- **预期效果**：让"归档/维持/解冻"三分支判定与项目双轨价值（网站+数据方法）对齐。
- **实现路径**：judge_gate.py 单函数改造 + 取数脚本扩展；改前**必须先给"意图信号"清单与取数口径草案供 Owner 裁决**（防自造折中冒充规范——用户红线）。
- **风险**：多轨判据可能被读成"给解冻找借口"→ PRD/文档措辞强调"测量公平性"而非"放松标准"。

### 创意 3：I13 · Zenodo DOI + dataset/ 版本化存档（归档态唯一能打的"永久价值锚"）
- **描述**：给 dataset/ 结构化 JSON + scripts/output/data 快照在 Zenodo 建概念性 DOI，版本=发布批次号（v2.3.x），license 依 CC BY-NC 4.0；站点与 README 挂徽章。质疑 registry 把 Zenodo 排在"B-5 重启后子项"的既定序——**存档=登记既有资产，零新内容，不触发冻结**。
- **解决的痛点**：GitHub Pages 无版本语义（main 即一切），外部引用无法指向"某个时间点的 133 维数据"；资产半衰期风险（8 个月零备份叙事）。
- **预期效果**：项目从"一个可能消失的网站"变成"一条可被引用的永久数据资产"；同时为 I10 提供下载量信号源；S4 论文修订版可加数据存档引用。
- **验证方式**：Zenodo draft 先建不发布，核验 license 选项与上传流程后再正式 release。
- **风险（诚实标注三条）**：① 上传=**不可逆公开动作**，必须 Owner 明示授权；② **CC BY-NC 4.0 与 Zenodo 的 license 枚举兼容性需先核对**（Zenodo 支持 CC BY-NC 系但部分下游索引只认 BY 系——可能需要在"存档可达性"与"非商用坚持"间裁决）；③ 存档内容若含分回原文衍生数据，须复核原著公版+演绎 NC 链条无断点（项目双协议本已覆盖，但 Zenodo 条目描述要写清）。
