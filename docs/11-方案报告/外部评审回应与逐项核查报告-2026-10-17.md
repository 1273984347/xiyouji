## 二、评审方法论评估：信息缺口的用法

评审的收尾论断是「六项的关键实现文件在公开索引中不可见……信息缺口本身就是最严格的那根刺」。这一论断把**检索不到**直接当作**不存在**的证据，方向性是反的：

1. GitHub 代码搜索索引不到 ≠ 文件不存在。本仓库 772 个提交、四层架构（source→docs→site→scripts），大量脚本位于 `scripts/` 子目录（`A_文本基础/`、`B_人物/`、`rag/` 等 40+ 个业务子目录），公开索引的召回率对这类结构本就有限。
2. 评审自己列出了「严格判断」与「搜索结果」两栏——多数栏位的「搜索结果」是通用工程模式讨论而非本仓库证据，却据此下了仓库级结论。
3. 但方法论缺陷不抵消评审的独立价值：两轮机制层批评（§5）不依赖源码细节即可部分成立，且其「七项核查清单」恰好构成一份有用的外部审计提纲——本项目已按此提纲完成第一次逐条复核（§3/§4），这就是本报告。

## 三、评审索要的四项材料——仓库实况

### 3.2 测试与覆盖率配置段

- `pytest.ini`：testpaths=tests；`--ignore=tests/e2e`（浏览器 E2E 默认排除，原因见文件内注释：CI 的 pytest-unit job 不装 Playwright，浏览器套件由 screenshots-regression job 覆盖）

- 位置：`xiyouji-agent-web/server/`（Express 5 + better-sqlite3 + 自研 OpenAI-compatible 引擎 server/engine/）

## 四、七项工程指控逐条核查

### 4.1 依赖锁定——指控不成立

指控：「依赖管理分散且不透明，不可见即不可信」。
证据：`scripts/requirements.txt` 精确钉版（`jieba==0.42.1` / `Pillow==12.3.0` / `markdown==3.10.2` / `ruff==0.16.9` / `pytest==9.1.1`），且每处钉版附带 CVE 驱动的更新记录（PYSEC-2026 系列·Pillow 11.3.0→12.3.0 消 25 个漏洞）；CI pip-audit 实测 26 漏洞归零。前端依赖在 `scripts/package.json`（pixelmatch 5.3.0 等）与 agent-web `package.json` 分治，各有 lock 语义。
保留意见：`fonttools>=4.66.0` / `brotli>=1.2.0` 为开发依赖用区间——可接受但不完美。判定：**不成立**。

### 4.2 门禁数字——指控不成立（数字过期）

指控：「43 项门禁的数字需要被拆解」。
证据：现势为 **44 槽 / verify 实跑 49 段**（评审的「43」是 W753 挂载第 43 槽时的旧数）；且「拆解」正是本项目已制度化的要求——gates.md 逐槽全量定义（口径/豁免/实证）、AGENTS §4.2 摘要层、stats gate_count 计数、test_ci_wiring 三方对账断言，四者必须一致，漂移即红。评审要求的事情已经由机器强制完成。判定：**不成立**。

### 4.3 视觉回归覆盖盲区——部分成立，已分层

指控：「像素比对无法覆盖可视化语义」。
判定：**部分成立**。像素 diff（tests/e2e/ 10+ 版本化 PNG 基线·pixelmatch）的职责本就是「防样式/渲染回退」，不宣称覆盖语义。语义正确性由另一层承担：第 43 门禁 `check_chart_values.js` 的 V1–V5 运行时断言（pageerror / 图表容器非空 / 数据量级自洽 / KPI 可复算 / 数据源四要素），对 87 个可视化页逐页「渲染值 ↔ 源数据」复算——这恰是评审所说「像素比对覆盖不了」的那一层，本项目以独立门禁覆盖。残余盲区（诚实声明）：V3/V4 对 na 页（缺数据源/缺视图意图）不判，覆盖缺口计入报告而非静默跳过。

### 4.4 agent-web 安全边界——指控不成立

指控：「攻击面存在，但回归证据不可见」。
证据：W752 Agent 安全加固批（对账表可查）+ 三套安全单测（§3.3）+ W757 D2 修复把 `test:server` 接进 CI 并由 test_ci_wiring W2 断言「删除即红」+ W757 D3 把 agent-web 纳入 security_scan 发现面（.ts/.tsx/.mjs）。判定：**不成立**。（攻击面「存在」本身不是缺陷——任何 Web 服务都有攻击面；问题是回归证据，证据在且被机器守护。）

### 4.5 测试覆盖率数字——成立

指控：「测试覆盖率：数字缺席本身就是信号」。
判定：**成立**。仓库无 coverage 配置，602 passed 不含行覆盖率。且本项目的测试是双轨制（pytest 单元/门禁 + Playwright E2E·后者默认排除于 pytest 由 CI 独立 job 覆盖），任何单一覆盖率数字都会失真。处置：不硬凑数字，登记为后续候选项（§7）。这一条是七项中唯一完全成立的。

### 4.6 脚本膨胀——部分成立（数字失实）

指控：「45 个归档脚本是事后治理的证据」。
证据：`archive/` 实收 **235 个 .py**（全历史归档，非 45）；且归档目录按 AGENTS §3 明确定位为「一次性/诊断脚本·不入库门禁、不参与 CI」——它是治理的**输出**而非失序。事前收敛机制：tmpe 临时区 TTL 桶（用后即弃）+ W751 根级脚本覆盖门禁（第 42 槽：根级脚本必须有测试或被显式登记不可单测）。判定：方向性批评（先写后治）**部分成立**，数字与归因失实。

### 4.7 sync_docs.py——部分成立（设计使然）

指控：「sync_docs.py 是事后对账，不是事前预防」。
判定：**部分成立**。六文档同步的语义就是「一致性校验」——一致性只能在多文件写完后校验，这是语义决定的，不是懒惰。但「事后」的窗口已被压到提交前：该脚本挂 pre-commit + verify 第 1 槽，不一致即阻断提交。评审建议的「编辑器模板约束层」部分存在：`docs/_templates/` 提供内容模板，新文档从模板建。判定：批评的完整形态（CI 补救层）不成立；其精神（更多事前约束）已部分落地。

## 五、两轮机制层评审的回应

以下四项不依赖源码细节，整体成立。逐项说明项目立场。

### 5.1 AI 内容质量方差与「平庸的废话」——成立，人的战场

评审：「43 项门禁可以防止 AI 生成虚假引文，但无法防止 AI 生成平庸的废话。」
判定：**成立，且项目从未宣称相反**。门禁的职责边界是机械保真：引文逐字比对（第 20 槽·415 条 100%）、六文档同步、数据双源一致。「解读是否有洞见」由人工审定 + 对抗性审查批承担（W737/W760 两轮全量对抗审查·19 篇现役报告归档于 docs/11-方案报告/）。这一分工是本项目的明示设计，不是盲区。评审的贡献在于把这句话说得足够锋利，值得写进后续内容生产的自检清单。

### 5.2 工程化 overhead——成立，是一次主动权衡

评审：「维护成本畸高，可持续性存疑；开发者体验凌驾于读者体验。」
判定：**成立（作为权衡被接受）**。项目的现实约束是「一人工作室 + 四条产品线并行」：W### 批次、双索引、49 段门禁的首要目的不是表演，是**断点可恢复性**——任何会话中断后，HANDOVER + 对账表 + 门禁体系让「新 Agent 可接管」成为可执行事实。代价评审说得对：贡献者曲线陡峭、维护者精力转移则机器停摆。缓解：公开仓库 + CI + 全文档化；承认这是负债，但去掉它的代价（历史多次「报告已同步但实际漂移」）更高。

### 5.3 单点故障——成立，无解但已缓解到可转让

评审：「存续建立在单点故障之上。」
判定：**成立**。数字人文个人项目的常见失败模式（机构支持短期化、劳动不被晋升路径承认）本项目全中。缓解仅限：把「维护者本人」的依赖度降到「任何合格 Agent + 文档可接管」。这是现实约束，不是设计选择——评审此处无改进建议可落地，记录在案。

### 5.4 可视化叙事脱节——部分成立

评审：「87 个可视化可能是数据维度堆砌，结论常识性。」
判定：**部分成立**。项目对可视化的纪律是「数字为真」（第 43 门禁复算、双源同步、色盲安全），**不宣称「洞见为深」**——133 个数据维度中确有常识性结论的页面，这是量产策略的已知代价。评审的风险提示（边权重定义、数据来源透明）已在部分页面落实（口径说明.md·统计口径说明），全量审查是内容轨的持续工作，非工程轨可一次性关闭。

## 六、评审的独立价值与本批实证

本轮 W775 批次本身提供了一个恰到好处的实证：在落地外部产出的 JS 门禁重构时，受控对拍（旧版快照 vs 新版重跑·五维矩阵）发现 **check_data_drift.js 自 W536 安全加固起就潜伏一个引号腐蚀 bug**——`jsLiteralToJson` 的字符串归一化分支因引号字符被腐蚀为空串比较而沦为死代码，导致含单引号 EMBEDDED 块的两个页面（timeline / journey-geo-semiotics）五年批次间被静默跳过（「无内嵌块」）。新版修复后两页纳入深比对且全绿（可比 57→59 页·exit 0）。

这个案例与评审结论互为镜像：**工程流程能抓住机械腐化（对拍抓到了），抓不住意义空转（评审说对了）**。两类防线都需要，且都不能替代对方。
