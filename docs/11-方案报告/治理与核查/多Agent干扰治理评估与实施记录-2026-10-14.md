## 0. 核心结论

**touches 机制能拦「计划阶段已知的共享文件交集」，但拦不住两件事**：

1. **并行会话在你认领前已经改完**（T 问题）——W739 当日活体实证：本会话两次 git 调用之间，并行会话完成了 W738 主提交+chore+推送，本会话读到的「W738 未提交」状态在写任何东西前已失效。对策是可见性（agent_start `--since` 候选 P1），不是更多锁。
2. **对账表自身格式漂移导致解析失效**——狗粮实证：收官行状态列的 Markdown 加粗 `**已收官**` 击穿 `startswith` 判定。已修（W739 fix）并于 W741 升级为全星号剥离 + 回归测试固化；失效方向是双向危险（收官误判在途→拒绝误报；在途误判收官→拒绝漏报）。

**这两条说明 touches 上线不是终点，而是暴露了「T 可见性」和「解析鲁棒性」两个下一层缺口**——前者进路线图 P1 触发条件，后者已由本批加固闭环。

### 1.2 N × p × T 实测（本轮最大洞察）

- **N = 2，有实证**（并行 Agent 会话 并行会话·W726-W728 撞号险情·W739 当日 W738 抢跑），但非常态。
- **p 分层**：收官级联面 p≈1（每批必写 CHANGELOG 头/六文档/对账表/AGENTS 脚注/dukou 页脚）——**但已被 batch_cascade 收敛为单写路径**；内容面 p 很低。
- **T = 小时到天级**：会话跨天，agent_start 无 --since，漂移不可见。
- **推论**：batch_cascade 解决了 p，safe_commit 解决了 commit 瞬间的 N——**剩下暴露的主要是 T**。这把 write_receipt 和 agent_start `--since` 的定位从「加锁」纠正为「**让窗口与漂移可见**」——可见性压缩 T，比锁便宜且不破坏并行。

## 3. touches 机制的边界与加固

- **拦得住**：计划阶段已声明的共享文件交集——两个批次都想手工改 AGENTS/pitfalls/表结构时，后认领者被 preflight 拒绝。
- **拦不住（一）认领前的并行改动**：T 问题，机制上无解（窗口不可能为零），只能靠可见性压缩——agent_start `--since` 是候选（P1·按两周日志观测触发）。
- **拦不住（二）对账表自身格式漂移**：解析层对自由文本 Markdown 的鲁棒性。本次加固链：startswith → replace("**") → **re.sub(r"[\s*]+")**（全星号+空白剥离）——单星 `*已收官*`、多星、空白前缀变体全部防御；回归形态固化于 `test_inflight_with_bold_status_variants`（7 断言）。**下一次排版美化不会再静默击穿它**。
- 更彻底的「状态字段固定 token（[DONE]/[INFLIGHT]）」方案因破坏 92 行历史数据不采纳（用户裁定）。
