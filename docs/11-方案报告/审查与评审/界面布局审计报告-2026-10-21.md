## 2. 静态站 `site/` — 四维审计

### 2.1 信息层级

#### S1 · 首屏塞满 3 个并列英雄区，内容入口在 1081px 外

**现状取证**（首页 @1440×900，探针实测）：

```
masthead   top=81   h=416   ← 品牌 + 100 回 mega 数字
svg 山脉   top=497  h=100   ← 纯装饰
ask-hero   top=597  h=341   ← 站内搜索卡片
stats      top=950  h=139   ← 首屏之外（900px 视口刚够不到）
「从哪一回读起」page-wrap  top=1081  h=774
```

首屏 900px 内共 52 个元素，**内容入口数量 = 0**；`stats` 数字区从 950px 才起步，差 50px 没进首屏。

**问题判定**：首屏被「品牌 + 装饰 + 工具」三块等权占满，用户落地后必须先滚 1.2 屏才能遇到「这里有内容」。首屏既没有唯一主 CTA，也没有明确的次级出口。

**建议调整**：首屏只保留 **1 个主 CTA + 1 个次 CTA**——主 CTA 保留 masthead 里的「开始阅读 · 第 1 回」，次 CTA 保留站内搜索；把装饰 SVG 移出首屏（并入 masthead 底部或作为区块转场），把 mega 数字从「右侧独立大数字」降为「与 tagline 同行的计量标签」。

**理由**：层级不成立时通常靠字号硬撑，但字号撑出来的层级会随屏宽崩塌（见 S3）。**用「占位」建层级**（谁在首屏、谁不在）比用字号建层级更抗缩放。

**可判定验收**：@1440 与 @375 两档下，首屏（视口高）内可见的 `<h2>` 数量 ≤ 2，且至少 1 个是内容类标题；`stats` 区 top ≤ 900px。

#### S2 · 字号层级倒挂：占满首屏的标题比下方内容标题小 12px

**现状取证**：@1440 标题序列 = `h1 56px`（详解西游记）→ `h2 28px`（想查点什么？·搜索区）→ `h2 40px`（从哪一回读起）→ `h3 20px`（卡片标题）。

**问题判定**：占满整屏的搜索区标题（28px）比它下面的内容区标题（40px）**小 12px**。眼睛在首屏读到的最大标题是 28px，而往下滚看到的区块标题是 40px —— 视觉主次与空间主次相反。

**建议调整**：搜索区降级为**工具条**（不再占用 h2，标题字号降到 18-20px 或改为无标题的纯输入区 + 占位文案）；内容区块标题统一到 v4 排版角色 `--type-title`（24px）与 `--type-subtitle`（18px）两档，首页四个区块共用一套。

**理由**：把工具和内容放在同一标题级，等于宣布「这里没有主次」。工具可以很大、但不必用标题强调它。

**可判定验收**：首页标题序列中，搜索区标题字号 < 内容区标题字号，且二者不属于同一标题级；`check_structure.py` 对首页标题级差判绿。

#### S3 · 手机端层级坍塌：搜索 h2 与卡片 h3 同为 20px

**现状取证**：@375 标题序列 = `h1 28px` → `h2 20px`（想查点什么？）→ `h2 24px`（从哪一回读起）→ `h3 20px`（灵根育孕源流出…）。

**问题判定**：**h2（搜索）= h3（卡片标题）= 20px**，h1=28px 只比 h3 大 8px。语义层级在 375px 下完全退化——同一屏里所有标题看起来一样大，层级信息归零。

**建议调整**：把「层级靠语义 + 靠留白」固定下来，字号只表达档位不表达层级：`h1` / `h2` / `h3` 三档分别锁在 ≥28 / ≥24 / ≥20px，且**任意相邻两级差 ≥4px**；差额用字号差 + 上下间距差双杠杆表达。

**理由**：屏幕越小越要靠**空间**表达层级；纯靠字号的方案在 375px 下必然坍塌（本次实测即坍塌）。

**可判定验收**：任一页面在 375px 下，`h2` 与 `h3` 的 computed font-size 差 ≥4px（探针脚本加一条断言即可机检）。

#### S4 · 首页 9 个顶层区块全部同级，无主任务分组

**现状取证**：首页 `<main>` 直系子节点 9 个 —— `section.masthead` / `svg` / `section.ask-hero` / `section.stats` / `div.page-wrap`×4 / `section.dark-band`，**无 h2 分组容器**，读者自 4 类任务（读回目 / 找专题 / 看数据 / 用工具）平铺在同一视觉层。

**问题判定**：9 个同级区块 = 9 个等权入口 = 没有主任务。首页实际承担 4 类完全不同的用户意图（初访者要「开始读」、研究者要「查资料」、回访者要「回到上次那页」、作者要「用写作引擎」），现在被压成一条线性长页（@375 高 8,138px ≈ 10 屏）。

**建议调整**：把首页重组为 **3 个任务区**（① 读回目 ② 查资料 ③ 看数据与工具），每个任务区一个 h2 标题 + 一组入口；原「精选必看 9 卡」与「全卷索引」合并为「查资料」区（索引表 + 精选卡二选一呈现，按屏宽切换）。总区块数从 9 降到 6。

**理由**：线性长页把「浏览」成本转嫁给用户；按意图分组能让每个区块回答一个问题，首屏之外的选择成本从 9 降到 3。

**可判定验收**：首页 `<main>` 直系子节点 ≤ 6；三个任务区各含恰好 1 个 h2；区块顺序与用户意图优先级一致（读 → 查 → 看）。

### 2.2 区块分布与留白

#### S5 · 间距无刻度：29,285 处硬编码，仅 43.3% 落在 v4 刻度

**现状取证**（全站 857 页扫描 `padding|margin|gap: Npx`）：

```
总出现次数            29,285
实际取值种类              33 种
命中 v4 刻度            11 种（0,2,4,8,12,20,24,32,40,48,64,80,96 中的子集）
命中刻度的次数占比        43.3%
刻度外 22 种 · 高频：10px×3650 · 6px×2532 · 14px×2258 · 18px×1466 · 16px×1266 · 34px×1244 · 3px×990 · 5px×650 · 9px×654
```

**问题判定**：v4 刻度（13 级）已经落地（`site/tokens.css`），但页面层仍在写刻度外字面量，且 **10px 是全站第一高频间距**（3,650 次）——它根本不在 v4 刻度里（v4 只允许 4 的倍数 + 2/10 半格里的 2 与 10 档，10px 对应 `--space-3`? 实为 8px 档；10px 无对应档）。即：**新刻度与旧字面量没有交集**，留白节奏实际由「随手写的 px」决定。

**建议调整**：分两步走 —— ① 共享层（`system.css` / `tokens.css`）先把自己的间距全部换成 `var(--space-*)`；② 页面层按 v4 §6 迁移清单逐批替换，替换时**允许 10px→8px 或 12px 的语义映射**，但必须写进批次的「视觉差异说明」。

**理由**：留白节奏差 = 多个区块间距互不成比例（相邻区块 40 / 72 / 96 / 120 混用）。刻度化之后，「区块间距 = 2 个档」才能被机检，而不是靠眼力。

**可判定验收**：迁移批完成后，页面层刻度外间距字面量计数 = 0（复算命令见 §7.1）。

#### S6 · v4 令牌已落地却 0 消费：容器 / 排版 / 语义 gap 三族引用数皆为 0

**现状取证**（857 页引用统计）：

```
var(--space-*)      330 页（38.5%）
var(--container-*)    0 页
var(--type-*)         0 页
var(--gap-*)          0 页
```

**问题判定**：W851 已把 v4 的 34 个新名（间距 13 + 语义 gap 6 + 容器 3 + 栅格 2 + 排版 9 + accent-text 1）落进 `tokens.css`，但**页面层一个新都没用**。令牌层与页面层之间缺一层「消费」，于是：容器宽度各自为政（S7）、排版字号各自为政（S2/S3）、语义留白各自为政（S5）。

**建议调整**：把「消费」写进迁移批的验收判据 —— 每批不仅删字面量，还要**用 `var()` 替回**，且替回后 computed 值必须与迁移前一致（视觉零变化，沿用 W851 探针的对拍方法）。

**理由**：令牌只有被消费才是「规范」，否则只是注释。零消费是设计体系落不了地的第一道坎，也是本仓 W851 之后的实际卡点。

**可判定验收**：每个迁移批结束时，`var(--container-*)` / `var(--type-*)` 引用页数 > 0 且递增；消费页 computed 样式与迁移前逐属性对拍零差异。

#### S7 · 四套容器宽度并存（1440 满宽 / 1320 / 1267 / 1536）

**现状取证**：

```
site/index.html   .masthead 满宽 1440（padding 86.4px）· .page-wrap maxw 1320 · .ask-hero 实测 1267
site/dashboard.html  .container maxw 1536（v4 裁决 3 要求降档至 1320·现役未降）
site/data/*.html  .page-wrap maxw 1320
site/reader/*.html .reader-wrap maxw 760
```

**问题判定**：同一个站点里同时存在 4 种内容宽度。读者在首页看到的正文起点（masthead 内文 86.4px）、在看板看到的起点（0px）、在阅读页看到的起点（1440−760)/2=340px）三者都不一致 → 跨页跳转时内容左缘「跳动」。

**建议调整**：落地 v4 容器三档（760 阅读 / 1120 内容 / 1320 宽版）并**逐页归并**：① dashboard 1536 → 1320（v4 规格已定，只差执行）；② masthead / ask-hero 等满宽区块的**内容内缘**统一到 1320 档的左缘（内部用 `max-width` + `margin:auto` 包裹内容，而不是改区块自身宽度）；③ reader 760 保持（已达标）。

**理由**：容器宽度不是审美问题而是**跨页一致性**问题——用户翻页时内容左缘不动，才形成「同一个站点」的连续感。

**可判定验收**：全站实测容器宽度取值集合 = {760, 1120, 1320} 三种；同一站点内相邻页面内容左缘差 ≤ 1px（探针加断言）。

### 2.3 操作动线

#### S8 · 目录页在手机上是 37 屏长单页，无搜索 / 无分页 / 无跳章

**现状取证**（`site/reader/index.html`）：

```
@1440  全页高 15,785px（= 17.5 个 900px 视口）· 单页交互元素 617 个
@375   全页高 30,333px（= 37.3 个 812px 视口）· 同一页 617 个交互元素
       「逐回解读（100）」一组即占 4,648px（= 5.7 屏）
```

**问题判定**：这是全站最严重的动线断点。用户的目标是「找到第 N 回」或「找到某人物专题」，但页面提供的只有一条 30,333px 的线性流：**目标越靠后，代价越高**（第 100 回 = 滚 37 屏）。页面上 617 个链接在视觉上完全等权，没有任何分组导航或检索。

**建议调整**：目录页补三层检索 —— ① **分组跳转条**（7 个分组的锚点，sticky 在顶栏下）；② **回目快捷定位**（输入回号直达，如「42」→ 第 42 回，键盘可达）；③ **人物/主题搜索**（复用站内搜索索引，对目录 617 条做过滤）。三者是叠加关系，不是替代。

**理由**：目录页是「列表页」不是「文章页」——列表页的价值在于**定位速度**。30,333px 的文档顶对 100 回正文是必要的，对目录是灾难。

**可判定验收**：@375 下从落地到「第 100 回」的点击数 ≤ 2；目录页提供 ≥1 个即时过滤输入框（可输入回号/人物名）。

#### S9 · 目录页顶部「主题专题导航 hub」是普通段落，不是可点导航

**现状取证**：目录页第一个顶层块是 `<p>主题专题导航 hub（209 篇·按族分组）</p>` —— 探针读取该节点 `tag = p`、无链接。

**问题判定**：这是一句**指向别处的提示语**，却出现在一个「本页已经列了 209 篇专题」的页面上 —— 用户被告知「专题在 hub 里」，但本页也在列专题，信号互相打架；而且这句话本身不可点。

**建议调整**：二选一并保持全站一致 —— ① 若 hub 是专题的权威入口，则本页只保留该链接（改为真链接 + 箭头 + 数量徽标），不重复列出 209 条；② 若本页就是专题索引，则删掉这句提示，改为分组标题。

**理由**：**同一目标的双入口**是动线噪声；一句话指向别处却不给出动作，是死信号。

**可判定验收**：该节点或为真链接（`<a>` 且有 href），或整句删除；不允许两者并存。

#### S10 · 87 个可视化页在顶栏只有 6 个入口，深挖要靠滚

**现状取证**：首页顶栏 7 项（导读 / 阅读 / 逐回 / 人物 / 专题 / 数据看板 / EN）。87 个可视化页（`site/data/`）与 622 个阅读页、138 个 en 页均无直接入口，只能经首页「精选必看 9 卡」「全卷索引表」或看板二级进入。

**问题判定**：首页「精选必看」只有 9 个入口覆盖 87 页（覆盖率 10.3%），其余 78 页的发现路径是：首页 → 全卷索引（滚动 2,815px 处）→ 找到板块 → 进入。即 **78 页的平均到达成本 ≥ 3 次点击 + 约 2 屏滚动**。

**建议调整**：把入口从「精选式陈列」改为「**可检索清单 + 精选留白**」：顶栏「数据看板」改为承载 87 页的**全量清单**（分主题/分族的筛选列表），首页只保留 6-9 个精选 + 一句「全部 87 页 →」。现有 `dashboard.html` 的 TOPICS 区（51 个专题页 / 37 大类）已具备雏形，扩成全量清单即可。

**理由**：精选解决「推荐谁看」，清单解决「我要找的那个在哪」。两者都得有，但清单不该藏在滚动深处。

**可判定验收**：任一可视化页从首页出发到达的点击数 ≤ 2（顶栏 → 看板清单 → 页面）；看板清单覆盖 87 页且可按族筛选。

### 2.4 多屏适配

#### S11 · 断点值只有 768/640/480 三档且全在 ≤768，桌面侧（≥1024）零分支

**现状取证**：

```
site/tokens.css    @media 计数 = 0
site/system.css    @media：768px×3 · 640px×1 · 480px×1（+ prefers-reduced-motion×3）
v4 tokens.css 注释声明的断点常量：640 / 768 / 1024 / 1280 / 1536（最小验收 375）——仅是注释，无 CSS 断点
```

**问题判定**：全站响应式只有 3 个断点值（768 / 640 / 480），且**全部 ≤768** —— 桌面侧 **1024 / 1280 / 1536 三档没有任何样式分支**。这正是 S13（宽屏行长失控）和 S12（KPI 不收缩）的共同根因：桌面端没有档位，页面只能按 1440 一直拉伸到 1920/2560。

**建议调整**：建立四档断点体系并写成常量（`--bp-md:768 / --bp-lg:1024 / --bp-xl:1280`），每档绑定明确职责：**375-767 单列** · **768-1023 双列** · **1024-1279 三列 + 限制行长** · **≥1280 四列 + 宽版容器**。断点值写进 `tokens.css` 并在 `system.css` 中统一引用（禁各页自写数字）。

**理由**：档位缺失 = 桌面端只有「一路拉伸」这一种行为。补齐中间档才能同时解决「手机挤」与「宽屏散」。

**可判定验收**：`system.css` 中出现 1024 与 1280 两个断点分支；全站 CSS 裸断点数字（`max-width: NNNpx`）计数 ≤ 6（仅共享层）。

#### S12 · 可视化页 KPI 区不随宽度收缩，手机首屏被它吃满

**现状取证**（`site/data/chapter-structure-graph.html`）：

```
@1440  kpi-row  top=553  h=799  w=1147  → 第一个真正的图表 section 在 top=1352
@375   kpi-row  top=522  h=799  w=327   → 第一个真正的图表 section 在 top=1321
```

**问题判定**：**KPI 区在 375px 与 1440px 下高度完全相同（均 799px）** —— 它不随视口收缩，只是从多列变单列。手机上它从 522px 一直铺到 1,321px，**首屏 812px 里剩下的 290px 全是 KPI 卡，真正的图表一张都看不到**。

**建议调整**：KPI 区在 ≤768 档降为 **2×2 紧凑网格 + 数字缩档**（`--type-number` 32px→24px，去掉描述行），把高度压到 ≤320px；或改为「首屏只留 1 个主 KPI + 「查看全部」链接」，其余下沉。

**理由**：KPI 是**摘要**，摘要在首屏的价值是「概览」，不是「读完」。摘要占满首屏，等于逼用户滚屏才能看正文。

**可判定验收**：@375 下 KPI 区高度 ≤ 320px，且第一个图表 section 的 `top` ≤ 812px（首屏内可见至少一张图）。

#### S13 · 宽屏行长失控：可视化页 ≈78 字/行（阅读页 39 字/行是对的）

**现状取证**（段落实测）：

```
可视化页 @1440   段宽 1147px · 字号 14.72px · 行高 29.44px  →  ≈78 字/行
阅读页  @1440   段宽 666-728px · 字号 17px · 行高 32.3px      →  ≈39-43 字/行
```

**问题判定**：中文正文可读行长通常 ≤40 字/行。**阅读页是全站唯一达标的正文区**，可视化页的说明段却在 1147px 宽度上排 78 字/行——这是「同一站点两种正文纪律」。根因是可视化页没有正文容器（只有图表容器 1320/1147）。

**建议调整**：可视化页的**文字块**（图表说明、结语、引用块）套用 `--container-read`（760px）或在文字块上设 `max-width: 70ch`；图表本身保持宽版容器，不受影响。

**理由**：行长问题只影响文字块，不该拖累图表宽度 —— 两者本来就该用不同容器档（这正是 v4 容器三档的设计意图，现役没落地）。

**可判定验收**：可视化页所有 `p`（长度 >60 字）的实测宽度 ≤ 760px；探针可机检。

#### S14 · 手机端卡片仍 2 列，且 13-16 个触达目标 < 32px

**现状取证**：

```
首页 curated-grid：@1440 4 列 · @768 2 列 · @375 2 列（每列 ≈151px）
首页触达目标 <32px：@1440 13 个 · @375 6 个
阅读页触达目标 <32px：@1440 16 个 · @375 15 个（示例 28×25、24×17）
可视化页：@1440 13 个 · @375 8 个
```

**问题判定**：① 手机上卡片保持 2 列 → 单卡宽 ≈151px，卡片标题（20px 字号）与描述被压到 3-4 字宽，是「挤」的真实来源（**不是溢出**，11 组实测 overflowX 全 false）；② 多个可点元素尺寸 <32px（`28×25` 属导航/工具条小字链接），移动端低于 44px 的可点尺寸下限。

**建议调整**：① ≤480 档卡片改 1 列（横向滑动卡保留 2 列时须露出下一张 12px 以示可滑）；② 触达目标统一 ≥44×44（视觉尺寸可小，用 padding 撑开热区）。

**理由**：在 375px 下保留 2 列，省的是「滚动次数」但花掉的是「可读性」——后者对内容站更贵。

**可判定验收**：@375 下首页 `.curated-grid` 计算列数 = 1；全站可点元素中 width<32px 或 height<32px 的计数 = 0（探针机检）。

## 3. 应用 `xiyouji-agent-web` — 四维审计

> 取证说明：源码面（`src/` 全树）+ 真机渲染（vite 5173 + API 3000 实跑，6 组 × 4 档宽）。

### 3.1 信息层级

#### A1 · 侧栏会话条目是工具调用原文，无会话语义

**现状取证**：侧栏列表渲染的是 `session.title`；实跑库中该字段是工具调用原文 —— 截图里 8 条连续显示「请写入 .git/hooks/pre-commit」「EVIL-TEST 请读取 ../.env」「读取 CLAUDE.md 并总结」等**指令串**，而非人能认出的会话名。

**问题判定**：侧栏是应用的**一级导航**，但它的 60% 屏宽里装的是机器指令文本。用户无法用视觉扫读区分「我刚才那个会话」——导航失去导航功能。

**建议调整**：会话名生成规则改为「**用户首条提问的摘要（≤16 字）+ Agent 徽标**」，指令串不再直接展示；同时给侧栏加**分组**（今天 / 本周 / 更早）与相对时间。

**理由**：列表项的默认语义是「我做过的事的索引」，不是「日志」。摘要是最低成本的修复（不需要新表）。

**可判定验收**：侧栏任意 10 条中，长度 >20 字符的条目数 = 0（探针可机检）；条目右侧显示相对时间。

### 3.2 区块分布与留白

#### A2 · 新对话页说明与输入框之间约 400px 纯空白

**现状取证**（@1440 截图量取）：新对话卡（`max-w-lg` 512px）底边 ≈440px，输入框（`max-w-3xl` 768px）顶边 ≈770px → 中间约 **330-400px 纯空白**；卡片本身居中于 1180px 主区，两侧各 ≈334px 空白。

**问题判定**：桌面端首屏被三段空白切碎：卡片上方（header 之下约 250px）、卡片左右（334px×2）、卡片与输入框之间（≈400px）。用户视线要「读卡片 → 跳到最底 → 输入」，中间无任何内容承接。

**建议调整**：① 空态时把新对话卡**垂直居中到「卡片 + 输入框」的整体中心**（输入框紧跟卡片下方 ≤48px），而不是卡片居中、输入框钉底；② 或把输入框上移成卡片的一部分（一张卡：Agent 选择 + 输入框 + 高级选项折叠区）。

**理由**：空态页只有一个任务（开聊），任务组件应当**相邻**；把它们分置页面两端，是在用距离表达「没关系」。

**可判定验收**：@1440 下「卡片底边 → 输入框顶边」间距 ≤64px。

#### A3 · 两套令牌并存：24 条 `--color-*` 声明全树 0 消费

**现状取证**：`src/index.css` 的 `:root` 与 `.dark` 各 12 条 shadcn 风格 `--color-*` 变量（`--color-background` / `--color-foreground` / `--color-primary` …），合计 **24 条声明**（12 个唯一名 × 明暗两套）；全 `src/` 树检索 `bg-background|text-foreground|border-border|bg-muted|bg-card|bg-primary` → **0 命中**。实际生效的是 TDesign 的 `--td-*`（同文件另 64 条声明 / 37 个唯一名）。

**问题判定**：同一文件里躺着两套互不相干的令牌体系，其中一套完全没人用。它不只是冗余 —— 它是**误导**：后续改版者可能去改 `--color-background`，以为改了背景，结果什么都没发生（这与本仓 W830 记录的「脚本自建即自曝」是同一类静默失效）。

**建议调整**：删除 24 条零消费声明（或在迁入 TDesign 体系后统一为一处），并在 `src/index.css` 顶部留一行来源注释说明「令牌唯一权威 = TDesign `--td-*`」。

**理由**：**未被消费的设计决策等于负债**——它持续占用认知带宽，并在改版时制造「我改了但没生效」的排查成本。

**可判定验收**：`src/index.css` 中 `--color-*` 声明计数 = 0；或全部有消费点（机检：每个 `--color-*` 名至少 1 处 `var()` 引用）。

### 3.3 操作动线

#### A4 · 开聊前必须先选 Agent + 可选目录 + 权限模式，三控件平铺

**现状取证**（`NewChatView`）：Agent 选择卡（含整段说明文字）→ 「工作目录（可选）」输入框 → 权限模式选择器 → 然后才是输入框。三个设置**同权平铺**，无主次、无默认值标注（除 Agent 默认 `default`）。

**问题判定**：新用户第一次打开面对 3 个配置项，其中「工作目录」是可选的、「权限模式」是高级项 —— 但它们与 Agent 卡等重。**开聊 = 读一段说明 + 选 3 项**。

**建议调整**：① 默认值全部预填（Agent=default、工作目录=项目根、权限模式=默认），让用户**可以直接输入并发送**；② 「工作目录 / 权限模式」折叠进「高级设置」；③ Agent 说明文字压成 1 行 + hover 展开。

**理由**：配置项的成本应该由「需要非默认值的人」承担，而不是由每个新用户承担。**默认值是给多数人的**。

**可判定验收**：新对话页首屏（@1440 900px）内可见的输入框 = 1 且可立即输入发送；折叠区默认收起；无任何必填空输入。

#### A5 · 权限模式两处重复出现

**现状取证**：权限模式选择器同时出现在 `NewChatView`（新对话页设置区）与 `ChatInput`（输入框左下角，与模型选择器并排）。

**问题判定**：同一语义控件在两个地方出现，且两处默认值都来自同一 state。新对话页那处是**开始前的设置**，输入框那处是**进行中的切换** —— 动线上互斥的场景不该共用一个位置。

**建议调整**：新对话页那处并入「高级设置」折叠区（A4）；输入框左下角保留为**唯一常驻**入口（会话进行中可随时切换，符合 TDesign 聊天框惯例）。

**理由**：重复入口既占空间又制造「两个都生效吗」的疑问。

**可判定验收**：任一屏内权限模式控件出现次数 ≤ 1（常驻那处除外）。

### 3.4 多屏适配

#### A6 · 零断点：侧栏恒 260px，手机上主区仅剩 115px

**现状取证**：

```
src/ 全树：@media 计数 = 0 · sm:/md:/lg:/xl:/2xl: 前缀计数 = 0（仅 6 处静态 max-w-*）
实测侧栏 / 主区宽度：
  @1440  aside=260  main=1180
  @1024  aside=260  main=764
  @768   aside=260  main=508
  @375   aside=260  main=115   ← 主区只剩 31%
```

**问题判定**：`Sidebar` 的宽度是内联 `style={{ width: sidebarOpen ? 260 : 0 }}` + `flex-shrink-0`，**不随视口变化、不可收缩、无遮罩**，且 `sidebarOpen` 初始值 = `true`。结果：手机上首屏 69% 被会话列表占据，主区 115px —— 截图实测：标题「西游记·渡口问津」竖排 3 行、Agent 说明被裁、输入框只剩半截、模型选择器 `default-model` 被切边。设置页同样只剩 115px。

**问题判定（补充）**：根容器是 `flex h-screen w-screen`（100vh），移动端浏览器地址栏收放时 100vh ≠ 可见高度（需 `100dvh`）；`html/body` 全局 `overflow:hidden` 使页面不能整体滚动，纵向溢出只能由内部区域承担。

**建议调整**：① ≤1024 档侧栏默认收起（`sidebarOpen` 初始值改为按视口宽度判定）；② ≤1024 档侧栏改为**抽屉**（遮罩 + ESC + 点击遮罩关闭，模式可复用站点 W492 已有的抽屉实现）；③ `h-screen` → `h-[100dvh]`；④ 抽屉打开时锁定 body 滚动。

**理由**：固定侧栏是「桌面优先」假设的残留。应用要能在手机上用，最小改动是**默认收起 + 抽屉化**，而不是把侧栏压窄（压窄后长会话名一样不可读）。

**可判定验收**：@375 下主区宽度 ≥ 320px（侧栏收起时）；侧栏打开时有遮罩；`100vh` 在 `src/` 中的使用计数 = 0。

7. 任一可视化页 @375 首个图表 section `top` ≤ 812px；文字块宽 ≤760px。

## 7. 复算命令

### 7.1 站点侧（静态扫描 · 零依赖）

```powershell
# ① 间距字面量总量与刻度命中率（期望：29,285 处 / 命中 43.3% / 刻度外 22 种）
$scale = @(0,2,4,8,12,20,24,32,40,48,64,80,96)
$files = Get-ChildItem D:\xiyouji\site -Recurse -File -Filter *.html
$vals = @{}
foreach ($f in $files) {
  $c = [IO.File]::ReadAllText($f.FullName)
  foreach ($m in [regex]::Matches($c,'(?:padding|margin|gap)\s*:\s*(\d+)px')) {
    $v = [int]$m.Groups[1].Value
    if (-not $vals.ContainsKey($v)) { $vals[$v] = 0 }
    $vals[$v]++
  }
}
$all = $vals.Keys | Sort-Object
$on = $all | Where-Object { $scale -contains $_ }
"取值种类 $($all.Count) · 命中刻度 $($on.Count) · 刻度外 $($all.Count - $on.Count)"
"总次数 $(($vals.Values | Measure-Object -Sum).Sum) · 命中占比 $([math]::Round((($on | ForEach-Object { $vals[$_] } | Measure-Object -Sum).Sum) * 100 / (($vals.Values | Measure-Object -Sum).Sum), 1))%"
```

```powershell
# ② 令牌消费计数（期望：--space-* 330 页 · --container-* 0 · --type-* 0 · --gap-* 0）

  "{0,-10} {1} 页" -f "--$k-*", $n

```
