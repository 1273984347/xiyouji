## 一、竖版图表专项

### 1.1 判据（五类真实渲染事实）

探针 `scripts/_w1331_chart_portrait_probe.py` 逐页在窄视口（375×812 / 320×812，file:// 加载）量：

| 类 | 口径 | 说明 |
|---|---|---|
| A 载体 | 可见 svg（≥60×50）与 canvas 清单 | 排除图标/装饰 |
| B 压缩比 | 渲染宽 / viewBox 宽（scale） | <0.75 记 WARN |
| C 有效字号 | svg 内 text 最小 computed font-size × scale | **<8px 判 FAIL**（竖屏不可读）；8–9.5px 记 WARN |
| D 标签越界 | text 渲染 rect 超出 svg rect >6px；其中横向越出视口且无滚动祖先 = 不可达 | 越出视口判 FAIL |
| E 不可达裁切 | 载体右缘越出视口且无 `overflow-x:auto/scroll` 祖先；页面级横向溢出 | 判 FAIL |

判据修正留痕：初版用 `text.getBBox()` 直接与 `viewBox` 比较，因 getBBox 是元素局部坐标系（未含祖先 transform）产生系统性误报（单页 46 处）；改为渲染 rect 与 svg rect 比较后归零（E-236 同族：探针坐标系必须先自证）。

### 1.2 基线（修复前 · 375）

165 页：OK 54 · WARN 64 · **FAIL 47**。压缩类共 **159 个 svg / 69 页**（151 个有静态 id；40 个无滚动容器）；文字越出视口 11 个 svg / 11 页（越界量 6–194px）。

典型读数（修复前）：

| 页 | svg | 渲染宽 / viewBox | scale | 有效字号 |
|---|---|---|---|---|
| data/journey-route | #timeline | 343 / 1120 | 0.306 | 3.1px |
| data/character-appearance | #chart-timeline | 319 / 1000 | 0.319 | 3.2px |
| data/concept-device | #prismSvg | 241 / 900 | 0.268 | 2.7px |
| data/pilgrim-team-psychology-arc | #cohesion-svg | 319 / 720 | 0.443 | 4.4px |
| en/text-evolution | #evolution-tree | 343 / 343 | 1.0 | 标签越出视口 194px |

### 1.3 根因（三类）

1. **假滚动**：父容器已有 `overflow-x:auto`（`.chart-wrap` / `.chart-block`），但 svg 自身无 `min-width` ⇒ `max-width:100%` 把它压进容器宽，横向滚动无内容可滚（典型 40 页）。
2. **无滚动轴**：svg 直接挂在 `section` 等无语义容器下，窄屏既压缩又无滚动可达。
3. **绘制层标签越界**：svg 自身 1:1，但 d3 绘制的标签坐标超出 svg viewBox（T112「SVG 文字越出视口」族），越界 6–194px。

### 1.4 修法（窄屏注入块 · 幂等）

对每页在 `</head>` 前注入独立块（标记 `data-w1331="1"`，仅 `@media (max-width:768px)` 生效，桌面零影响）：

```html
<style data-w1331="1">
/* W1331 chart-portrait v1 */
@media (max-width: 768px) {
    *:has(> #sankey) { overflow-x: auto; }   /* 父容器不可滚时补滚动轴 */
    #sankey { min-width: 1100px; }           /* min-width = viewBox 宽 ⇒ scale=1，横向可滚 */
    #evolution-tree { overflow: visible; }   /* 绘制层标签越界：放开裁剪 */
}
</style>
```

- 选择器优先级：静态 svg id → svg class → 父容器 class（`.parent > svg`）；无锚点不猜（记 skipped）。
- 无滚动祖先时用 `*:has(> 选择器)` 精确给直接父补滚动轴（不用宽泛的 `section{overflow}`）。
- 幂等：重建前继承旧块规则（`/^    .*;$/`），分阶段修复不丢前一次成果（本批曾因 `strip()` 误判丢过 criticism-history 的 scalpel 规则，已修并回归）。
- 微压缩不强行加宽：`effFs 8–9.5px` 只记 WARN；仅 FAIL 线（<8px / scale<0.6）注入，避免给「运行时按容器重设 viewBox」的响应式小图强加 min-width（320 实测该类 vbw≈容器宽，注入无效且破坏节奏）。

覆盖面：**81 页 / 222 条规则**（data 38 页 + en 43 页）。

## 四、经验与边界

1. **探针坐标系先自证**：SVG `getBBox()` 是元素局部坐标，不能直接与 `viewBox` 比较（E-236 同族）。
2. **「有滚动容器」≠「可滚动」**：容器 `overflow-x:auto` 但内容无 `min-width` 时滚动条无内容可滚，图表仍被压扁——判据必须量 scale/有效字号，不能只看容器样式。
3. **分阶段注入必须继承旧规则**：重建块只按「当前报告问题项」生成会丢前一次成果（本批实证并修复）。
4. **响应式重设 viewBox 的 svg 不能用 min-width 修**：其 vbw≈容器宽，min-width 无效；此类只登记 WARN。
5. 本批未动绘制层 d3 参数与公共层 CSS（避免 866 页分发）；标签重叠与暗色对比度留 L-13。
