## 2. 新增发现详述

### 2.1 N-01（P1）全站搜索结果无行内链接——主路径在最后一步断裂

**问题**：首页搜索表单（`#askForm`）提交后跳 `data/search.html?q=…`（`site/index.html` 内联脚本：`window.location.href = 'data/search.html?q=' + …`）。该页实为 W338 的**数据集检查工具**（类型/标题/分类/摘要表格 + 导出 CSV/JSON 按钮），结果行是纯文本 `<td>`，**没有任何一行含 `<a>`**。

**访客后果**：搜「孙悟空」得 23 行结果，行内无一可点（0/23）；唯一出口是点行弹 Drill 层再点「打开」的两步路径，且 doc 类目标仍是 GitHub blob（出站）。页面顶部还挂着「W338 数据 API 接入 · 在线跨 42 数据集递归检索（/search）」的开发者口径横幅。

**证据**：`rows: 23, rowsWithA: 0`（Playwright 实测）；截图 `tmpe/w1070/w1070/shots/`（搜索页）。

**建议**：结果行「标题」格加 `<a>`——`reader/index.html` 目录已建立文档→站内页映射，复用之；无站内页的条目退化为纯文本。数据集工具用途与读者搜索用途解耦（后者可指向 `data/text-search.html` 的实时检索）。

### 2.2 N-02（P1）`/datasets` 绝对路径 + 永不兑现的在线模式

`site/dashboard.html:675`：`fetch("/datasets",{cache:"no-store"})…`；`site/data/search.html:1300`：`apiFetch("/datasets")`。两处均为**根绝对路径**——项目站真实前缀是 `/xiyouji/`，且静态托管不存在该 API ⇒ 两页每次加载必发一个 404 请求再降级（实测 console）。UI 文案同时向访客宣传「在线命中『数据集 + 片段』」模式，该模式在纯静态部署下**永远不会上线**。

**建议**：静态构建移除在线分支或按 hostname 特性检测；文案改为「离线目录检索：覆盖全部研究文档与站点页面」（此句页面已有，保留即可）。W926 的维度 D 判据「fetch 有 catch 即健壮」对本类缺陷失明——catch 在、降级在，但**功能承诺与部署形态不符**，属判据盲区（与 §3 判据自纠同族）。

### 2.3 N-03（P1）`data-gsap` 属性文本泄漏 ×4 页

字节级根因（4 页同型）：**属性被写在开标签 `>` 之后**成为文本节点——

```
site/guide.html        <div class="paths-grid"> data-gsap="cards" data-gsap-target=".path-card"
site/reader/index.html <main class="reader-wrap"> data-gsap="cards" data-gsap-target=".reader-idx a"
site/reader/essays/index.html / site/reader/themes-hub.html   同型
```

双重后果：① 读者在路径卡/目录区上方直接看到一行代码文本；② 原设想的卡片入场动画**从未生效**（选择器挂在文本上而非属性上）。W926 的可见文本泄漏扫描（R-02）只统计批次号词面，未覆盖此类——判据盲区第二例。

**建议**：属性移回标签内（4 处机械修改）；第 38 槽（内嵌残留标记门禁）加 `>data-gsap=` 判据防再犯。

### 2.4 N-04（P1）100 个章回页「返回导读」出站

`grep -l "00-导读/阅读指南" site/reader/ch*.html | wc -l` = **100**。链接指向 `https://github.com/1273984347/xiyouji/blob/main/docs/00-导读/阅读指南.md`——站内阅读动线中途把读者送去 GitHub 文件查看器。

**建议**：生成器模板改为 `../guide.html`（站内导读页），一次重渲全量生效。

### 2.5 N-05（P1）阅读器目录页零出口

`site/reader/index.html`：banner=0 / contentinfo=0 / h1=0 / 唯一 `navigation` 是 6 个分类筛选签 / 622 个链接中无「首页」「返回」「取经录」任何一个。从首页「阅读」进入后无站内回程；搜索引擎直达用户滞留。移动端实测同样无 chrome。与 R-03（hub 无入口）互为镜像：一个是「进不来」，一个是「出不去」。

**建议**：套用站点标准 shell（页头导航+页脚），补 h1；单文件改造。

### 2.6 N-06（P1）首页计数自相矛盾

同一张首页并存：搜索区「**616** 篇解读文档（A1-A6）」/ 概览区「**615** 篇 · 研究文档」/ 看板卡 meta「**86** PAGES」/ 标签云卡与概览「**87** 个」；`site/reader/index.html` 工具行「全部 **615** 条」同族。`scripts/output/stats.json` 现值：`a1_a6_docs=616`、`visualization_pages=87`、`site_data_html=88`。「86」不对应任何现役键；615 为旧值残存。谱系：W855 曾发现同页 772 vs 834 漂移，W1058 做过计数链订正——本组字面量位于对账扫面之外。

**建议**：字面量对齐 stats（615→616 或标注口径；86→87），并把首页概览卡 / 看板卡 meta / reader 工具行纳入计数链对账扫面。

## 3. 判据自纠与撤销（本轮 4 条）

1. **IAB 输入事件伪影（最重要）**：browser-use 内置浏览器里，指向 JS 绑定控件（夜读开关/「问」浮钮/轮播圆点/askForm 回车）的合成点击与回车**全部不触发页面处理器**（元素命中正确、命令无报错、无效果），而链接导航正常——初判「全站交互死透」为**环境伪影**。经真实 Chromium 对照重放，4/4 控件全部正常，相关「发现」全部撤销。教训已固化入 Agent 记忆；建议坑表收一条（另批）。
2. **W854 快照过期两例**：S2「搜索 h2 28px < 内容 h2 40px」与 S3「@375 h2=h3=20px」复测现值分别为 **40/40** 与 **24/20**——两条在现势不成立（可能已修或口径不同），引用 W854 时须以本轮订正为准；S6 订正为「主要内容页（index/guide/curated）仍 0 消费，dashboard/dukou/rum-viewer 各 1 处边际」。
3. **index-row 悬停首测伪影**：首测报告「无反馈」，专测复测 `:hover` 生效（`site/system.css:631` 的 color-mix 背景，实测近纸色）——以专测为准，撤销该发现。
4. **轮播圆点 pressed 竞态**：DOM `aria-pressed`=第 9 张而截图红点在第 7 位——自动轮播推进的时序现象，非缺陷，撤销。
