## 2. 发现分级

### F1【中高】preflight touches 交集为字面字符串比对——通配/带注记声明恒不命中（假绿族·W897 同族残余）

- **位置**：`scripts/preflight_check.py` `touches_conflict()`（L158-160：`set(inflight) & set(mine)`）。
- **实证**：W900 认领行 touches 含字面 `docs/11-方案报告/**（22 文件移动 + README 重构）` 与 `CHANGELOG.md`。若并行批次声明 `docs/11-方案报告/README.md` 或该目录下任一具体文件，与 `docs/11-方案报告/**（…）` **字面不等 ⇒ 交集为空 ⇒ 判「无冲突」放行**——恰好挡住最该挡的目录面撞车。尾注「（…）」同样破坏命中。精确路径形态（如 `CHANGELOG.md`）不受影响。
- **定性**：W897 修的是「分隔符不识别」（整串一项恒空集）；本条是「形态不归一」（每一项都可能是无效模式）——同一家族的语义面残余。防护存在但覆盖不全，属「假绿」族（比漏检更危险·给已核对的错觉）。
- **修法（待批·管控件）**：`_split_touches` 产物归一化三步——① 剥条目尾部「（…）」注记；② `X/**` 与 `X/` 展开为前缀匹配（对方任一元素以 `X/` 开头即命中）；③ 双向对称应用。加负样本单测（通配 vs 具体文件必须报冲突）。
- **佐证**：W825 批台账自述「解析层修复曾被并行会话整仓提交覆盖丢失」、W893 批台账自述「认领行被并行提交 +3/-1 替换消失」——两起真实撞面事件均未被机器拦下（当时分隔符 bug 与本条共同作用）。

### F2【低】第 45 门禁 FAIL 提示语缺「先 add 再 refresh」顺序（W900/W901 连续两批踩中）

- **位置**：`scripts/check_folder_docs.py` FAIL 消息「重跑 python scripts/gen_folder_docs.py --refresh 刷新」。
- **实证**：W896 起生成器按 Git 索引（已跟踪+已暂存）收集——**refresh 跑在 `git add` 之前必然漏掉本批新件**，照提示做仍红。W900 与 W901 各踩一次，均靠自行排查发现正确顺序（add → refresh → 再 add）。
- **修法（待批·管控件）**：提示语改为「先 `git add` 新件再重跑 refresh（生成器按 Git 索引收集·W896 口径）」。一行文案，不动判定。

### F3【流程·本批闭合】§8 干扰日志窗口内两起真实覆盖事件未登记

### F5【已落地·W906】C4-f 把「他方批次登记行纯追加残留」误判「本方漏 add」——多 Agent 并行误拦
