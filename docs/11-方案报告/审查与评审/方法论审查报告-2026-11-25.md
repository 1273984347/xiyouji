## 三、P0 发现

### P0-1 三 skill 闭环在声明退役后仍给出可执行指令

- **证据（A）**：`三skill闭环.md` L5「三者均属已退役协议层（W562 随 skills 治理整体退役）」；但 §五 L97-101 仍写「实际触发三 skill 闭环时…如发现跳过某 skill：视为闭环断裂，立即补跑被跳过的 skill」，L105-106 还要求「先 Read DRL SKILL.md §0 提取…」。实测 `deep-review-loop`/`mem-wrap-up` 全局路径均不存在（子代理 Glob 实测 MISS）。
- **风险**：读者按现役口径执行会卡在已失联的 skill 路径上；与「载体退役必须同步退役其门禁与同步工具」的既有纪律相悖。
- **建议**：全文顶部加「历史档案·勿执行」封条；§五/§七/§九 的可执行指令改为「历史记录」；或直接归档 `archive/docs/`，在 README 保留指针。

### P0-2 前端诊断 SOP 的「样式生效」覆盖声明失实

- **证据（A）**：`前端显示问题诊断SOP.md` L61 把 `_diag_style_assert.js`/`_p1_viz_audit.js`/`_smoke_batch.js` 列为「非门禁槽·手动取证脚本」，L66 称「其覆盖职能已由第 24/43 槽 + `check_screenshot_gates.js` 承接」。实测 `check_screenshot_gates.js` 仅 L119 一处 `getComputedStyle(next).backgroundColor`（G5 画布遮挡分支），无全局「body 背景非透明 / 主 style 块 cssRules>1」断言；第 24 槽为图表静态自洽、第 28 槽为可视化可引用性，均非运行时样式生效。
- **风险**：真实的「样式裸奔」问题会被误判为已有门禁覆盖，形成假绿。
- **建议**：把 L66 改为「样式生效目前仅由渲染基线对比间接覆盖，无专门判据」；若要闭环，另批新增运行时断言并挂槽（需用户批准）。
