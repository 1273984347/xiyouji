## 2. 信息基础与检索口径

### 2.1 检索口径定义

- **纳入**：仓库名或描述明确指向《西游记》原著（文本 / 人物 / 情节 / 回目），或指向其明确衍生 IP（西游 MUD、造梦西游、幻想西游、西游 OL、大话西游、梦幻西游、黑神话：悟空、PS1《西游記》、花果山场景）。
- **排除**：同名异物（`Code Monkey King` 国际象棋引擎、`MonkeyKing` 社交发帖工具、西邮 `XiyouLinux` 兴趣小组、`verification_code` 验证码研究）、政治宣传库、纯泛用工具。
- **噪声规模**：867 个去重唯一仓库中，**471 个（54.3%）** 被排除；396 个进入粗筛核心池；再经人工核定得到 **72 个核心条目**。

### 2.2 GitHub 检索行为差异（实证，影响可复现性）

| 现象 | 实测 | 影响 |
|:---|:---|:---|
| **中文 `in:name` 返 0，英文 `in:name` 正常** | `西游记 in:name` → **0 命中**；`journey-to-the-west in:name` → 50 命中 | 纯中文名仓库**只能靠 `in:readme` 或拼音兜底命中**，否则系统性漏检 |
| **多词 AND 检索对中文失效** | `西游记 全文` / `西游记 文本` / `西游记 数据` / `knowledge graph 西游记` / `西游记 命名实体` / `西游记 自然语言处理` → **全部 0** | 中文复合查询必须**拆成单关键词 + 域限定**再靠本地聚合 |
| **`in:readme` 反而能捞到中文** | `西游记 in:readme` → 50 命中（轮询上限） | 中文有效路径是 `in:readme` + 本地正则二次筛 |
| **`--json topics` 字段不存在** | `gh search repos --json topics` → `Unknown JSON field: "topics"` | topics 只能走 `gh api repos/<r>` 单独取 |
| **Code Search 对中文与 `path:` 限定近乎失效** | `西游记 path:*.txt`、`"孙悟空" path:*.md`、`"西游记" path:*.py`、`"西游记" path:*.jsonl` → **全部 0**；`filename:xiyouji` → 40 命中 | 中文语料文件**只能靠 filename 反查**，不能靠内容检索 |

**结论（可复用）**：中文古典题材在 GitHub 上的可发现性路径唯一可靠形态是 **多语系别名 + `in:name`/`in:readme` 双通道 + 本地去噪**，任何单语言单通道检索都会漏掉一半以上的仓库。

### 3.2 两处方法失误与修正

**P-1　字段假设错误（已修正）**：首次 `gh search repos --json ...,topics` 全组失败，错误信息为 `Unknown JSON field: "topics"`（search 与 repo view 的字段集不同）。修正：search 侧去掉 topics，topics 改走 `gh api repos/<r>` 单独补齐。影响：无数据损失（51 组查询重跑后命中量与首跑一致）。

### 10.3 经验沉淀（可复用，跨项目适用）

**E-1　中文题材在 GitHub 上的可发现性需要"多语系别名 + 双通道 + 本地聚合"三件套，单一检索语法必然漏检。**
适用边界：任何非英文主流语言的题材调研。复用条件：调研目标是"某主题在 GitHub 上的全貌"。量化效果：本轮 51 组查询 vs 若只用 `中文 + in:name`（0 命中），可发现仓库数差 ≥ 1 个数量级；两个正面同赛道项目（`moli-knowledge-base`、`suhaihan/xiyouji-knowledge-base`）**只**出现在 `in:readme`/角色名通道中。
证据来源：§2.2 四项实测（`西游记 in:name`=0 / `西游记 in:readme`=50 / 6 组多词=0 / `--json topics` 报错）。

**E-2　"某主题没人做"这个结论，在正则分桶之前说出来是不可信的。**
本轮粗筛池 396 项中，人工读 README 后剔除的 324 项里，包含 3300★ 与 168★ 的高星伪相关；而**真正的核心项目里，有 2 个直接与本项目正面重叠且都在 2026 年**——它们在正则分桶里分别落在"弱相关"和"游戏"桶，若以正则桶出结论就会丢失。⇒ 调研结论必须建立在"读过 README 的最小可信单元"上，仓库数不是充分统计量。
