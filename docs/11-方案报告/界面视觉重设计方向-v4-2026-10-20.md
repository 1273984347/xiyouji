## 1. 执行摘要与五轴决策

### 1.1 一句话方向

**不换风格，换秩序**：保留「宣纸 · 墨骨 · 朱砂单点强调」的项目气质不变，把当前**靠 857 页各自手写**形成的视觉一致性，改造成**由一套令牌 + 一套组件 + 两套版式语法**保证的一致性；功能结构、DOM 类名、数据链路、交互逻辑一律不动。

### 1.2 五轴决策表

| 轴 | 现状（2026-10-20 实测） | v4 决策 | 收敛判据 |
|:---|:---|:---|:---|
| **视觉层级** | 三套首屏语法（首页 masthead / 数据页 hero / dashboard container）；三种区块标题形态（`.section-head h2` / `.section-title` / `.chart-block h3`） | **页级五段式 + 区块三段式**两套固定语法；层级靠「留白 / 墨色深浅 / 朱砂单点」三杠杆建立，不靠字号堆叠 | 全站区块标题形态 ≤ 2 种；首屏段序 100% 合规 |

## 2. 现状取证：五处可指认的缺陷

> 全部数据取自本批一次性只读脚本 `scripts/_w819_design_audit.py`（2026-10-20 实跑，输出 `scripts/output/_w819_design_audit.json`）。口径：**公共层** = 页面内 `<!-- INLINED CSS -->` 标记块（`tokens.css` + `system.css` 的内联副本）；**页面层** = 其余 `<style>` 块（页面私有样式）。

### 2.1 缺陷一：视觉一致性靠「每页自写」，不靠系统

| 观察 | 实测值 |
|:---|:---|
| 全站 HTML | 857 页（data 88 / en 138 / reader 622 / 根 9） |
| 含公共层的页 | 330 页 · 公共层总计 15,425,481 B · 单页最大 47,808 B |
| 页面层总计 | 3,264,180 B |
| **页面层自建同名核心组件** | `.kpi-card` **119 页** / `.chart-block` **98** / `.insight-box` **79** / `.hero` **58** / `.section` **35** / `.table-wrap` **25** / `.empty-state` **25** / `.card-grid` 8 / `.badge` 6 / `.btn` 6 / `.chart-tooltip` 5 / `.card` 4 / `.kpi-grid` 4 / `.stat` 2 / `.topnav` 1 / `.filter-tab` 1 |

结论：**核心组件的实际外观由「谁的页面层写在后面」决定**，而不是由设计系统决定。`.chart-tooltip` 的 5 处页面私有实现同时违反 DESIGN.md §5.4「禁止页面私有 `.tooltip{}` 盒样式块」的现行契约。

### 2.2 缺陷二：同一组件在站内有两套异形实现

以站点主入口 `site/dashboard.html` 为例，其页面层自建了 `.kpi-card`、`.filter-tab`、`.search-box`、`.category-badge` 四个**与 `system.css` 同名**的组件，与公共层实现的关键差异：

| 位置 | `.kpi-card` 数值 | 视觉差异 |
|:---|:---|:---|
| `site/system.css`（公共层） | `padding: 20px` · value `32px` / `--ink` · `border-top: 3px solid var(--accent)` | 顶部朱砂横条、数字墨色 |
| `site/dashboard.html`（页面层） | `padding: 22px` · value `34px` / `--accent-deep` · 无顶部横条 | 无横条、数字朱砂 |

`site/dashboard.html` 恰是全站「数据看板」主入口，其卡片外观与其他 119 页不同——这是「组件样式统一」在当前最直观的破口。

### 2.3 缺陷三：规范有、代码无

- `.insight-box`：DESIGN.md §4.8 给出完整规范（渐变底 + 4px 朱砂左边框 + 20/24 内边距），**公共层实现 0 处**（`site/system.css` + `site/tokens.css` 命中 0）→ 79 个页面各自实现，视觉各不相同。
- `.stat`（首页四数字概览）公共层无实现 → 首页与 rum-viewer 各写一套。

### 2.4 缺陷四：间距没有刻度，栅格没有档位

- `site/tokens.css` 中 `--space*` 令牌命中 **0** —— 全站没有间距令牌层。
- 页面层间距字面量 Top25 合计 20,201 处，其中**六类刻度外值**合计 **2,760** 处（占 Top25 的 13.7%）：`9px` 666 · `34px` 1,247 · `26px` 641 · `22px` 91 · `5px` 63 · `30px` 52。
- 容器宽度四种并存：`760px`（reader 阅读宽）/ `1200px`（DESIGN.md §3.1 规范值）/ `1320px`（`system.css .page-wrap`）/ `1536px`（dashboard `.container`）。
- 网格间距三种并存：`gap: 16px`（`system.css .kpi-grid`）/ `20px`（`.card-grid`）/ `24px`（`.chart-block` margin-bottom）。

### 2.5 缺陷五：暗色适配靠 hex 补丁表，被复制 330 份

`site/tokens.css` 的暗色适配段是 **约 200 条** `html[data-theme="dark"] svg [fill="#xxxxxx" i] { fill: #yyyyyy }` 规则。公共层裸 hex 实测 **72,934** 个 / token 引用 90,090 个 —— 意味着暗色适配占了公共层 hex 的 97% 以上，且随 330 页内联复制。

代价有二：**维护面**（新增一个图表色就要在补丁表加一行，且要同时改浅色值与暗色值）；**体积面**（每页公共层 47,808 B，是 `site/data` 单页均值 107.9 KB 的 44%）。

## 3. 方向 A · 视觉层级：两套固定版式语法

### 3.1 问题定性

当前层级不弱，弱在**没有共同语法**：首页首屏是「kicker → 主标 → 英文副标 → tagline → meta → mega 数字」，数据页是「breadcrumb → kicker → h1 → 英文副标 → tagline」，dashboard 是「container → kpi-row → filter-bar」。三套顺序、三个标题形态、六种标签措辞并存 —— 每页都得重新发明首屏。

### 3.2 决策 A1：页级五段式（Page Frame）

所有页面首屏按此顺序，缺项可省、**顺序不可乱**：

| 序 | 段名 | 角色令牌 | 内容要求 | 示例 |
|:--:|:---|:---|:---|:---|
| 1 | 眉标 `eyebrow` | `--type-eyebrow` | 等宽 · 全大写 · 朱砂 · ≤ 12 个拉丁字符或 8 个汉字 | `数据可视化` / `CHAPTER GRAPH` |
| 2 | 主标 `title` | `--type-display` | 宋体 · 一句话即页面主张 | `回目结构图谱` |
| 3 | 导语 `lead` | `--type-lead` | 1 句 · ≤ 62 字符 · ink-soft | `百回对仗回目…` |
| 4 | 元信息 `meta` | `--type-caption` | 等宽 · ink-faint · 数据源/日期/引用数 | `数据源：EMBEDDED 快照 2026-10-04` |
| 5 | 动作 `action` | 按钮规格卡 | **全页唯一主动作**（朱砂实底），次要动作用描边 | `进入看板 →` |

配套：**元信息上移**。现状数据页顶部有一条独立的「数据来源」提示条（脱离导航、脱离版式、整行铺满），v4 归位为第 4 段 `meta`，与主标同栏，不再单独占一条横带。

### 3.3 决策 A2：区块三段式（Section Frame）

| 序 | 段名 | 规格 |
|:--:|:---|:---|
| 1 | 区块标题 | 宋体 22–28px + **统一的 3px 朱砂左竖线**（全站一处，替代现状「2px 朱砂下划线」「顶部横条」「无标记」三态并存） |
| 2 | 区块说明 | 黑体 15px · ink-soft · ≤ 60 字符宽 |
| 3 | 区块内容 | 12 栏栅格内的卡片/图表/表格 |

### 3.4 决策 A3：层级三杠杆（而非字号堆叠）

1. **留白**：section 96 → block 32 → item 16 → meta 8（刻度见 §6）。
2. **墨色**：`--ink-1` 标题与正文 → `--ink-2` 说明 → `--ink-3` 元信息；数据数字用 `--ink-1`。
3. **朱砂单点**：**每页至多 3 处朱砂实底**（主按钮 / 当前态 tab / 关键 KPI 数字），其余朱砂仅以字色或 4–6% 淡底出现。

> 朱砂实底限额是本方案最强的一条纪律，也是与现状差异最大的一条：现状朱砂实底出现在导航指示条、卡片顶部横条、kpi 数值、徽章底、链接下划线等多处，收敛后页面会更安静，层级反而更清楚。

## 4. 方向 B · 配色：四族角色 + 色阶 + 色板驱动暗色

### 4.1 决策 B1：四族色彩角色

| 族 | 角色 | v4 取值 | 用途 |
|:---|:---|:---|:---|
| **纸** | `--surface-0/1/2/3` | `#FAF7F0` / `#FFFFFF` / `#F1EBDD` / `#E8E0CE` | 页面底 / 卡片 / 内嵌块 / 压深块 |
| **墨** | `--ink-1/2/3/4` | `#23201A` / `#6B6455` / `#9A9280` / `#E5DFD0` | 正文 / 说明 / 元信息 / 发丝线 |
| **彩** | `--accent` + `-soft/-deep`、4 数据色、4 语义色 | 朱砂 `#C8463A` 等 | 单点强调 / 图表 / 状态 |
| **夜** | `--night-1/2` + `--night-text` | `#221D16` / `#2B2419` / `#F2EBDC` | 深色节奏段 / 夜读模式底 |

**派生统一**：每族三档一律用 `color-mix(in srgb, …)`（现状仅 3 处使用，其余为手写 hex）——新增族色时不再手写第三个数。

### 4.2 决策 B2：图表色板双组（替代 200 条 hex 补丁表）

```
浅色组：--chart-1..6  #C8463A #3A6B8C #C9A063 #6B8E5A #D8CFBC #8A6D3B
暗色组：--chart-1..6  #E0604F #7FA8C9 #C9A96B #9DB98A #6E6656 #C9A96B
```

- 图表 SVG 填充一律写 `fill="var(--chart-N)"`（生成器 `scripts/` 侧改一处，全站受益）。
- 暗色模式只需在 `html[data-theme="dark"]` 覆盖 6 个变量，**补丁表整体删除**。
- **预期收益（待阶段 1 实测复核）**：公共层 hex 72,934 → 估算 ≤ 800；`tokens.css` 体积 20,799 B → 估算 ≈ 8 KB；330 页公共层各省约 12 KB。

### 4.3 决策 B3：对比度硬指标（可机检）

| 用途 | 指标 | 现状取值 | 判定（W822 实算 · WCAG 2.1） |
|:---|:---|:---|:---|
| 正文 `--ink-1` on `--surface-1` | ≥ 7:1 | `#23201A` / `#FFFFFF` | **16.24:1** ✅ |
| 说明 `--ink-2` on `--surface-1` | ≥ 4.5:1 | `#6B6455` / `#FFFFFF` | **5.87:1** ✅ |
| 元信息 `--ink-3` on `--surface-1` | ≥ 3:1 | `#9A9280` / `#FFFFFF` | **3.09:1** ✅（v1.0 估算判「需加深」**已撤销**·保持现役取值） |
| 朱砂 `--accent` on `--surface-1` | ≥ 4.5:1 | `#C8463A` / `#FFFFFF` | **4.78:1** ✅ |
| 朱砂 `--accent` on `--surface-0`（页面底） | ≥ 4.5:1 | `#C8463A` / `#FAF7F0` | **4.47:1** ❌ → 新增 `--accent-text: #C7463A`（4.50:1） |
| 交互边界 | ≥ 3:1 | `--accent-soft` `#E9B885` 实测 **1.80:1** ❌ | 交互边框改用 `--accent`（4.78）或 `--accent-deep`（5.86）；`--accent-soft` 降为纯装饰 |
| 图表 `--chart-3` 赭金 | ≥ 3:1 | `#C9A063` 实测 **2.42:1** ❌ | 图表专用深档 `#B38F58`（3.01:1） |
| 图表 `--chart-5` 米灰 | ≥ 3:1 | `#D8CFBC` 实测 **1.55:1** ❌ | 仅作底色/填充，禁作数据边界 |
| 暗色 `--accent` on `--surface-1` | ≥ 4.5:1 | `#E0604F` / `#2B2419` 实测 **4.35:1** ❌ | 暗色组上调至 `#E46250`（4.50:1） |

> **v1.1 订正（W822）**：上表原为估算值，现已被 W822 实跑数据取代（`scripts/_w822_contrast_audit.py`）。三项结论变化：① `--ink-3` 现役值**已达标** → 撤销「加深至 #8A8271」；② 新增 `--accent-text`（朱砂落页面底时专用）；③ `--accent-soft` 降为纯装饰、禁作交互边界。逐项订正与全部取值见《界面视觉重设计细化规格-v4-2026-10-20.md》§3.1 / §8。

### 4.4 决策 B4：语义色四件套固定

`ok / warn / danger / info` 各自绑定「底 / 边 / 字」三件套（现状已有 `--ok-bg` 等，v4 补 `--*-border` 缺项），供徽章、提示条、空态复用。

## 5. 方向 C · 字体体系：三族分工保留 + 九个排版角色

### 5.1 决策 C0：项目气质资产不动

**宋（标题）/ 黑（正文）/ 等宽（数字与拉丁标记）三族分工保留** —— 这是 v3 已确立、DESIGN.md §4A.4 明文、且与「数字刻本」隐喻一致的部分。v4 不改分工，只补「角色层」。

### 5.2 决策 C1：九个排版角色

| 角色 | 族 | 字重 | 字号 | 行高 | 字距 | 颜色角色 | 用途 |
|:---|:---|:---|:---|:---|:---|:---|
| `display` | 宋 | 600 | `clamp(34px, 4.4vw, 56px)` | 1.15 | -0.02em | ink-1 | 页主标 |
| `title` | 宋 | 600 | 22–28px | 1.30 | -0.01em | ink-1 | 区块标题 |
| `subtitle` | 宋 | 500 | 17–20px | 1.50 | 0 | ink-1 | 卡片标题 |
| `lead` | 黑 | 400 | 16–18px | 1.75 | 0 | ink-2 | 导语 / 说明 |
| `body` | 黑 | 400 | 15px | **1.80** | 0.01em | ink-1 | 正文 |
| `label` | 黑 | 500 | 13px | 1.50 | 0.02em | ink-2 | 卡片标签 |
| `caption` | 黑 | 400 | 12px | 1.60 | 0.03em | ink-3 | 来源 / 元信息 |
| `eyebrow` | 等宽 | 500 | 12px | 1.40 | **0.12em** | accent | 眉标（大写） |
| `number` | 等宽 | 500 | 28–36px | 1.10 | 0 | ink-1 | KPI 数字（`tabular-nums`） |

- 与现役 `--text-step-0…5`（1.25 比率）的关系：**步阶保留为刻度，角色表是语义层**。角色 → 步阶 + 字重 + 行高 + 字距 + 颜色，语义与刻度解耦，后续调刻度不必改 857 页。
- **字重预算**：本地无衬线子集只有 400/500 两档（`NotoSansSC-Regular.subset.woff2` / `NotoSansSC-Medium.subset.woff2`），角色表的黑体侧只用 400/500，**禁 600/700 黑体**（浏览器合成伪粗体）；宋体为可变字重（200–900），可用 500/600/700。

### 5.3 决策 C2：CJK 专项

- 正文行高 1.80（现 1.75）——中文方块字面需要更大行距。
- 标题字距收紧（display −0.02em），正文微松（+0.01em），中文标点不另作处理。
- 等宽字体只用于数字、编号、拉丁标记；**正文中出现的中文数字不用等宽**（现状 `.kpi-card .value` 套 mono 导致「第 41 回」这类中文值也走等宽，是字体分工的越界）。

## 6. 方向 D · 间距栅格：4px 基准十三级 + 容器三档

### 6.1 决策 D1：间距刻度（新增令牌层，现状完全缺失）

```
--space-0  0px     --space-5  20px    --space-10 64px
--space-1  2px     --space-6  24px    --space-11 80px
--space-2  4px     --space-7  32px    --space-12 96px
--space-3  8px     --space-8  40px
--space-4  12px    --space-9  48px
```

（`2px` 为发丝微调档，`8px` 与 `12px` 为半格档，其余为 4 的倍数。）

语义别名：`--gap-tight 8px` / `--gap-base 16px` / `--gap-loose 24px` / `--gap-block 32px` / `--gap-section 64px` / `--gap-hero 96px`。

### 6.2 决策 D2：容器三档（现状四档收敛）

| 档 | v4 | 适用 | 现状来源 |
|:---|:---|:---|:---|
| 阅读宽 | `--container-read: 760px` | reader 长文、摘要 | `.reader-wrap` 760px ✅ |
| 内容宽 | `--container-content: 1120px` | 数据页、专题页 | DESIGN.md §3.1 的 1200px **归并至此** |
| 宽版 | `--container-wide: 1320px` | 看板、大网格 | `.page-wrap` 1320px ✅；dashboard 1536px **降档至此** |

### 6.3 决策 D3：12 栏栅格

- 12 栏 · gutter 24px（桌面 ≥1024）· 16px（≤768）· 栏间距归入刻度。
- 卡片网格最小单元：内容宽档 3 栏、阅读宽档 1 栏、宽版 4 栏（现状 `minmax(200/240/280px)` 三套并存 → 统一为栏宽倍数）。

### 6.4 决策 D4：收敛判据

| 指标 | 现状 | v4 目标 |
|:---|:---|:---|
| 页面层间距字面量种类 | 25+ | ≤ 14（等于刻度级数） |
| 刻度外值出现次数 | 2,760（Top25 内） | **0** |
| 容器宽度档数 | 4 | 3 |
| 网格 gap 取值种类 | 3+ | 2（24 / 16） |

### 7.2 决策 E2：每个组件一张「规格卡」

五要素缺一不可：**用途 / DOM 结构 / 令牌 / 五态（default·hover·active·focus-visible·disabled）/ 禁改项**。五态的 focus-visible 一律双层 ring（沿用现状 `outline: 2px solid var(--accent)` + `outline-offset: 3px` 口径）。

### 7.3 决策 E3：页面层禁改核心组件（新增第 47 槽门禁）

- 判据：页面私有 `<style>` 中出现核心组件选择器（`.kpi-card` / `.chart-block` / `.hero` / `.section` / `.insight-box` / `.table-wrap` / `.empty-state` / `.chart-tooltip` / `.filter-tab` / `.search-box` / `.badge` / `.btn`）且带属性块 → **FAIL**。
- 历史豁免：当前命中 119+98+79+58+35+25+25+6+6+5 页（去重后约 250 页），按批逐步清零，豁免清单落 `scripts/output/` 可机读。
- 负样本自证：还原任一历史形态 → 门禁必须变红；恢复 → 变绿（留证文件随批入库）。

### 7.4 决策 E4：DOM 类名不动

用户硬约束「保留原有功能结构不乱动」优先：**现有类名一律保留为规范类名**，不重命名、不改 DOM 层级。新增组件才采用 BEM-lite（`{block}` / `{block}__element` / `{block}--modifier`）。历史别名（如 `.filter-tab` 与新 `.pill-tab`）以别名共存，退休另批。
