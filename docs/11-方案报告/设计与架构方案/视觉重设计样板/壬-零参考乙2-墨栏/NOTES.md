## 1. 一句话立场

**设计语言 =「墨栏」**：用木刻本版的**栏线与界**搭骨架、用拓片**墨分五色**做色阶、用纸做底，把《西游记》这部"有物质感的古籍"的质地放回版面里——但只放在**能报出信息的地方**，不放装饰。

签名元素 = **鱼尾对版标**（长文页版心眉），与线装书**每半叶中央的版心鱼尾**同源：它在木版印刷里是**上下两半叶的对版规矩**，在本站是**回数与叶码的定位尺**。

## 2. 为什么落到"栏线 + 墨阶"，而不是另外三条路

BRIEF-B 已排除三种窠臼，我逐一说明自己为什么不在那儿，以及最终站在哪：

| 被排除的路 | 它的问题 | 我的处置 |
|---|---|---|
| 暖色宣纸 + 毛笔插画 + 朱砂点缀 | 那是"关于传统的装饰"，不是版面；且朱砂点缀会把长文页变成海报 | 纸色做成**冷灰纸**（#F3F3EE，不是米黄）；朱砂只留作语义色（--danger）与文末落款印；**没有毛笔插画** |
| 深色终端 + 等宽字 + 网格背景 | 与"读长文"相反：等宽字读散文极累；网格背景是分心的噪声 | 等宽字只进数据与代码；正文宋体；暗态是"灯下的纸"，不是"终端"（无网格、无扫描线） |
| 米白 + 极细线 + 大留白 + 无装饰的极简杂志风 | 会落回通用极简，和"数字人文"这个题材无关；且细线+大留白让旁注失去依附 | 我保留**双线分节**（文武边）与**墨阶五色**，把材质感做在**工艺痕迹**上（版框、界栏、鱼尾、落款印），而不是做在纹理上 |

于是第三条路 = **把传统的"工艺结构"抽出来当界面骨架**：刻本有版框（界）、有界栏（栏线）、有版心（鱼尾）、有叶码（进度）、有刻工的对版规矩（校准）。这五样都能在屏幕上找到对应物，且都能报出信息。

## 3. 删掉了什么（逐条，可对照文件核对）

**内容层**

1. 纸纹噪点 / 做旧滤镜 / 水墨背景贴图 —— 材质进内容层即干扰，且长页上噪点会放大疲劳感。
2. 引文块的"引用卡片"写法：重底色 + 彩色左边条 + 图标 → 改为楷体 + 暖纸底 + 中性发丝线。
3. 长文页的一切入场动画（js-reveal 只留给落地页与数据页）——"内容自己出现"是阅读干扰。
4. 长文页的目录侧栏 / 面包屑 / 浮动工具条 —— 用旁注 + 上下回导航替代，视线不必横拉。
5. 正文中的评论区、点赞、分享浮层 —— 与"读完一篇再读一篇"的沉浸相斥。
6. 正文里的彩色热力图与仪表盘 —— 数据归数据页；长文页只留一张**线描**示意图（取经队伍编制）。
7. 首页的"滚动展开大图 / 开始探索"动画 banner —— 首页的任务是分流，不是炫技。

**装饰层**

8. 渐变与发光（代码里 linear-gradient 0 命中）。
9. 烫金边、卷轴造型按钮、仿古纹样。
10. 圆角卡片 + 彩色左边条的模板卡片组合（卡片统一 2px 直角 + 发丝描边）。
11. emoji 与彩色 unicode 符号当图标（14 枚手绘 24×24 描边 SVG 替代）。
12. 图标的 transform 凑合对齐（几何精确，不靠位移对齐）。

**工程层**

13. 图表库与任何外域脚本 —— 图表是内联 SVG + vanilla 手绘。
14. 本地存储以外的任何状态依赖 —— 主题偏好写入 localStorage 且 try/catch 兜底（file:// 下可能不可用）。

## 4. 契约冲突与裁决（本批最花心思的部分）

### 4.1 「视觉应与内容同源」× 「禁装饰性仿古」

**冲突**：既要纸墨朱印的质地，又不许装腔。
**裁决**：把"同源"限定在**材料与结构**，排除**造型与特效**。
- 结构层：版框双线、界栏、版心鱼尾、叶码、落款印 —— 这些是刻本真的有的东西，且都能报出信息。
- 造型层：卷轴、烫金、云纹、仿古按钮 —— 一律不做。
**判据**：任何视觉元素，问"它报出了什么？"答不出就不做。鱼尾答得出（我在第几回第几段），烫金花边答不出。

### 4.2 「禁现代 UI 库默认紫」× 「不忌讳绛紫/紫檀」

**裁决**：主强调取**石青**（矿物蓝，#1F5A86 / #6FA8D6），不用任何 SaaS 紫蓝；绛紫只保留两处语义——序列槽 5 与 --rebel（妖异/反叛），且都是暗而浊的传统绛紫（#6E3350 / #B078A0），与 #8B5CF6 一类的高饱和紫不是一档。
**机器判据**：_audit.py 扫描 #6366F1 / #8B5CF6 / #818CF8 / #A78BFA / #7C3AED / #4F46E5 / #A855F7，0 命中。

### 4.3 「禁材质/模糊进内容层」× 「要感到纸的质地」

**裁决**：**纸色本身就是底色**（--bg / --paper），不是"贴在内容上的材质"；质感由**工艺痕迹**提供（双线、界栏、墨阶、楷体、朱印），而不是噪点纹理。模糊只允许出现在功能层（topnav 的 backdrop-filter，用于吸顶导航的可读性），已核对未进入正文区。

### 4.4 「签名元素只做一处」× 「三页要统一」

**裁决**：统一的是**语言**（纸、墨、栏线、双线、字阶），**签名只给读者页**。理由：签名元素要"同时是内容与仪器"，仪器只该出现在它工作的那个面上；把它复制到仪表盘上，它就退化成装饰，违反"只做一处"。

### 4.5 「明暗两套独立取值」× 「暗态不是反相」

**裁决**：暗态色板由**亮态同一批颜料统一上移 ΔL×23** 推导（_palette_search.py 的 derive_dark 阶段），因此两态色相同源、关系一致；排版度量（字号、栏宽、行高、间距、圆角、层级 z-index）两态**逐项相等**；色值类令牌两态**必不相同**（_audit.py 双向校验）。

### 4.6 「八支序列色全 ≥3:1」× 「色盲安全」——被机器打回来的一处

**约束冲突**：八支序列色同时要满足"对近白底 ≥ 3:1"（把 Y 压到 ≤ 0.2583，L* 约 58 以内）和"两两在三种色盲模拟下可分"。亮度带被压窄后，明度差用尽，只能靠色相。
**裁决顺序**：① 先守住 3:1 与模拟 ΔE00 ≥ 8；② 常视 ΔE00 阈值取实测可达的 ≥ 12（实测上限约 14），并在 SPEC 写明为什么不是 15；③ 演示图表实际同时只用 3 色（石青/朱砂/赭黄，两两常视 ΔE00 ≥ 30），另配图例与直接标注作冗余编码。
**已知代价**：暗态朱砂 #A36457 偏闷——它是约束边界上的解，再提鲜就会与檀褐在 deutan 下收敛。

### 4.7 「_audit 的『明暗两块令牌集与值逐项相等』」口径解读

原句有歧义。我的裁决（已写进脚本注释）：
- 两个暗态块（[data-theme="dark"] 与 prefers-color-scheme: dark）的**令牌名集合逐项相等、取值逐项相等**；
- 亮/暗两块：排版、字号、间距、字体、动效、圆角、z-index 类令牌**取值相等**；
- 亮/暗两块：色值与阴影类令牌**取值必不相同**（防止把暗态写成反相或漏改）。

### 4.8 「禁圆角卡片 + 彩色左边条的模板卡片」

**裁决**：卡片 2px 直角 + 发丝描边、无投影；引文块虽用左侧线，但取**中性** --ink-tint 而非强调色，且上下另有发丝线，避免"色条 + 卡"的模板观感。

## 6. 探针全绿但页面是坏的（这一条最值钱）

_audit.py 与 _palette_check.py 全部 PASS 的同一轮，截图里仍然有三处缺陷，**只有看图才能发现**：

1. **「正在载入出场统计…」一直显形**：.chart-loading 的 display:flex（后定义、同权重）压过了 .hidden 的 display:none。探针只查"类名存在、令牌存在"，查不出层叠顺序。修法：.chart-loading.hidden { display: none; }。
2. **图例里「合计 2,692 次」误用了一个序列色块**，读起来像第四个类别。修法：改为无色块的说明文字（.legend-note）。
3. **375px 下版心眉折行破碎**（"详解西游记"被断成三行）——探针只测 scrollWidth，不测排版。修法：≤768px 隐去书名、回目单行省略、叶码 nowrap。
4. 另修：落地页「精选导读」的摘要与标题挤在同一行（span 默认 inline），修法：.read-title / .read-desc 改 block。

## 7. 已知弱点 / 我没有验证的东西（诚实清单）

1. **字体只在 Windows/Chromium 上验证**：截图机有 SimSun / 微软雅黑 / 楷体；macOS 的 Songti SC / STKaiti、Linux 的 Noto Serif CJK 未实测，跨平台字号与行距可能需微调。
2. **"读 30 分钟不累"未做真人验证**：本页只有 11 段、约 2,700 字；我没有做读者测试，疲劳结论是基于版式度量的推断而非实测。
3. **色觉评估只覆盖三种二色型**：Machado 2009 矩阵 + CIEDE2000；未覆盖单色盲、低视力、屏幕反射环境，也未做 APCA / 印刷打样。
4. **暗态朱砂偏闷**：受 4.6 的约束边界所限，我用图例与直接标注做了冗余编码，但没有找到既鲜艳又色盲安全的解。
5. **旁注浮排依赖负边距**：1025px 以上用 float + 负 margin-right 把旁注推进右侧栏；这一手在 1024px 断点处回落为行内注，中间没有更细的断点，极窄窗口（1000–1024px）观感是"行内注"，不是"右侧栏"。
6. **数据页数值是演示集**：2,692 次等数字由 BRIEF 给定，页面上已明确标注"演示样例 / 演示集"，但**未与站方真实统计口径逐项核对**（例如"首次出场回"的取舍是否与站内算法一致）。
7. **未做屏幕阅读器实读**：已给图标加 aria-hidden、给 tooltip 加 aria-live、给表格加 caption、给状态加字形标记，但没有用 NVDA / VoiceOver 实跑。
8. **英文版未涉及**：本方向只做中文排版；138 页英文版需要一套拉丁正文字体策略，不在本次交付范围。
9. **875 页的落地成本未估算**：token 与 class 接口已冻结，但"把读者页版式铺到 636 页"还涉及导航改造、旁注锚点与打印样式（print CSS 未做）。

## 8. 若继续推进，建议的下一步（三条，按优先级）

1. **把鱼尾抽成共用 SVG symbol**：目前只在读者页内联；铺到 636 页时应做成一处定义、全站引用，并保留"只出现一处"的纪律。
2. **旁注改为锚点定位**：float + 负边距在窄区间不理想；改成每段带 id、旁注用 position absolute + 锚点，可支持"点击旁注跳段"与打印时的批注位置。
3. **补一版高对比度模式**：Windows 高对比度 / forced-colors 下，纸墨栏线会整体失效；需要一套 forced-colors 兜底（边框改用 CanvasText、系统色），并把该模式纳入 _palette_check.py 的复算矩阵。
