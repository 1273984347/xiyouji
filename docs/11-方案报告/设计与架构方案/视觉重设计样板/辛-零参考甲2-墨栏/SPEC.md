# 详解西游记 · 设计系统正本
## 「墨栏 / INK-RULE」——纸为面、墨为字、朱砂只标「要看这里」

> **方案**：甲案（优先服务数据探查与快速判读）
> **交付目录**：`design-A2/`；令牌与类名为冻结接口，本文件只描述规则，不改名字。
> **所有对比度与色盲 ΔE 均为机器实测**：由 `_palette_check.py` 复算 `tokens.css` 得出；本文数字即该脚本输出，可重跑复核。

## 0. 三个必答题

### 0.1 一位读者在 3 秒内能读懂这张图说了什么吗？

版面按「结论前置、数据居中、解释随后」排布，四类信息的视觉权重自高而低：

| 序 | 信息 | 位置 | 视觉手段 |
| --- | --- | --- | --- |
| ① | **量级与结论** | 首屏 KPI 账簿行（4 卡） | 34px tabular 数字 + 上下通栏墨线；主角一项用朱砂 |
| ② | **形状与走向** | KPI 下的拓片概览条 | 100 格墨条，密度即走势，无需读图例 |
| ③ | **主体图形** | 主图区 | 条形长度唯一编码量值，数值右端直标 |
| ④ | **解释与口径** | 图下（洞察框、口径块） | 墨色正文，朱砂只标关键数字 |

具体纪律：

- **图面里不放标题**。图题写在图外左上（`.section-title`），量程写在右上（`.section-head__aside`，随筛选变化并显示真实数字）。
- **数值一律右端直标**，不靠刻度反查；刻度只作参照。
- **每张图上方必有一行元信息**：数据口径 / 更新日期 / 核校状态徽章。读者先知道「这数怎么来的」，再看数。
- **结论必须落成文字**（洞察框），用加粗 + tabular 数字标出 2–3 个承重值，而不是让读者自己总结。
- 3 秒内还要能判断「这是不是异常」：主图内置 **百次基准线**（墨色虚线），线以下即低于百次量级。

### 0.2 签名元素是什么？

**「百回拓片条」**（`.ink-strip`）：100 格墨条 = 《西游记》一百回逐回的主角出场密度。

- **它同时是内容与仪器**：
  - 内容——它是这本书的「指纹」。一眼可见第 31–40 回的低洼与第 51–70 回的高脊，峰值为第 59 回 42 次（朱砂标出）。
  - 仪器——它是主图的概览导航：悬停任一格弹出该回读数（「第 N 回 · 悟空出场 X 次 · 第某段」），同时联动下方「八十一难」十回段柱图高亮对应段。
- **它与《西游记》的具体事物同源**：**拓片（碑帖传拓）**。拓片是把刻在石头上的字迹蘸墨拍下、拓成一纸影像；这里把一百回的登场痕迹「拓」成一条墨带——载体是纸，痕迹是墨，密度是数据。
- **只出现一处**：仅在数据可视化页出现一次，落地页不出现，避免稀释签名。

### 0.3 明暗两态是同一套设计还是两种不同的设计？

**是同一套设计的两种照明，不是两套设计。** 三条依据：

1. **结构同源**：栏线、账簿 KPI、拓片条、墨块带在两态中一一对应，DOM 与类名完全一致，只有取值不同。
2. **物理隐喻一致**：亮态＝日读（纸为底、墨为字）；暗态＝夜读（墨为底、纸为字）。关键证据是 `--dark` / `--dark-text` 在暗态**互换角色**——亮态的「墨块带」在暗态变成「纸块带」，因为夜里翻书看到的是反白的字，而不是把黑条换成灰条。
3. **但取值独立撰写、不是反相**：机器判定见 §2.3——57 项颜色令牌暗值与亮值逐项不等；朱砂与 6 色序列色的色相漂移均 ≤ 30°（反相会使色相整体翻转 180°）；明暗各自的「字比面亮/暗」关系各自成立。暗态朱砂由印泥红 `#B23A2B` 变为透纸亮朱 `#E0705A`，是「夜里朱笔透纸更亮」的独立判断，而非机械提亮。

## 1. 设计语言

**核心隐喻：明代刻本的「栏线」。** 刻本用栏线把一块版面切成可扫读的单位；本系统把那条线原样搬进数据页：

- **分节＝一道通栏墨线**（`.section` 上边框 `--border-strong`）。
- **指标＝账簿式竖栏线**（`.kpi-grid` 四格以竖发丝线分隔，像账簿的栏）。
- **表格＝横栏线分行**（`.table-wrap` 行间发丝线，表头墨线压顶）。
- **强调＝朱砂只标一处**（当前栏目、主角、峰值、洞察框的承重数字）。

三条配色纪律（贯穿全站）：

1. **纸色系承载表面**：亮态是麻纸底色阶（`--bg` → `--paper` → `--surface-raised`），暗态是墨底色阶（`--bg` → `--surface-raised`）。全站**零渐变、零发光**，纸靠色阶而非特效成立。
2. **墨色承载文字层级**：`--ink`（焦墨）→ `--ink-soft`（浓墨）→ `--ink-faint`（淡墨）→ `--ink-tint`（清墨）四级，配 `--text-primary/secondary/tertiary` 三级正文色。
3. **朱砂是唯一强调色，且语义唯一**：朱砂＝「**要看这里**」。它出现在且只出现在——主角标记、拓片峰值、当前导航项、洞察框承重数字、主按钮。**朱砂不做装饰**，因此站上任意一屏，朱砂的面积应当 < 3%。

数据序列色取自**传统矿物颜料**（石青、赭石、胭脂、松绿、藤黄、绛紫、黛、檀），而非现代 UI 色板；全部经色盲模拟调校（§2.3）。

## 3. 字阶与字体策略

**字体策略（三套栈，零外部依赖）**

| 令牌 | 栈 | 用途 |
| --- | --- | --- |
| `--font-display` | `"Songti SC","SimSun","Noto Serif CJK SC","Source Han Serif SC",serif` | 标题、回目、引文 |
| `--font-text` | `-apple-system,"SF Pro Text","Segoe UI",system-ui,"PingFang SC","Hiragino Sans GB","Microsoft YaHei",sans-serif` | 正文（占站点 636 页长文） |
| `--font-data` | `"Avenir Next","Helvetica Neue",Arial,"PingFang SC","Microsoft YaHei",sans-serif` + `tabular-nums` | 数字 |

**display 层为什么用衬线（宋体）**：站点一半篇幅是「逐回解读 + 原文全文」的长文阅读，原文本身是宋刻本；标题与引文用宋体是**与内容同源**的排版事实（读者在屏幕上看到的刻本气息应与引文一致），而正文用黑体是**可读性事实**——宋体在 16px 屏上连续读 3,000 字会糊，黑体不会。因此：标题/回目/引文＝宋体，正文＝黑体，数字＝无衬线 tabular。数字不用等宽字体，避免落入「终端/科技风」；对齐靠 `font-variant-numeric: tabular-nums`。

| `js-reveal` / `hidden` / `visible` | 滚动揭示：`.js-reveal` 初始 opacity 0 + translateY(10px)，命中后 `.visible`；无 JS 时由 `<noscript>` 兜底显示 |

## 6. 动效

| 场景 | 时长 | 缓动 | 动什么 |
| --- | --- | --- | --- |
| 反馈（hover / focus） | 150ms（`--dur-fast`） | `--ease-out-quart` | 仅 transform |
| 状态（tooltip 显隐） | 150ms | `--ease-in-out-soft` | 仅 opacity |
| 入场（条形生长、行揭示） | 360ms（条）/ 200ms（行） | `--ease-out-expo` / `--ease-out-quart` | 仅 transform + opacity |
| KPI 数字滚动 | 900ms（白名单） | `--ease-out-expo` | 文本内容，非布局 |

纪律：

- **只动 transform / opacity**；颜色、宽度、位置一律瞬时切换（hover 变色不加过渡）。
- **零无限循环动画**；全站无 `@keyframes`。
- **reduced-motion 双守卫**：CSS 侧 `@media (prefers-reduced-motion: reduce)` 全局停帧；JS 侧 `const RM = matchMedia('(prefers-reduced-motion: reduce)').matches` 短路——条形直接落终态、KPI 直接显示终值、揭示元素直接可见。
- KPI 终值精确还原：HTML 里终值文本本来就在，滚动结束写回同一字符串（含千分位）。

## 7. 无障碍

- 正文 ≥ 4.5:1，图形要素 ≥ 3:1（实测见 §2.3）。
- 触控目标 ≥ 44×44px（按钮、标签页、搜索框均满足）。
- `:focus-visible` 全局 2px 朱砂焦点环 + 2px 偏移。
- 状态不只靠颜色：数据状态徽章同时带圆点与文字（「已核校」/「演示样例」）。
- 色盲安全：序列色经 Machado 三型模拟，亮暗两态最小 ΔE 均达标（§2.3）。
- 图表序列色**永不单独承载含义**：分组同时见于图例与 tooltip 文本；表格提供等价的文本读法。
- 图表提供 `aria-label`；tooltip 容器 `role="status" aria-live="polite"`；表格 `scope="col"`。
- 空状态有文字说明与可操作按钮，不靠视觉留白传达。

## 9. 签名元素详述：百回拓片条

- **形态**：100 个等宽墨条，底端对齐，条高与墨浓度双编码该回主角出场次数（15–42 次）；峰值（第 59 回，42 次）用朱砂。
- **版位**：数据页页首元信息行之下、KPI 之上——读者第一眼拿到「全书形状」，第二眼拿到「总量」。
- **仪器行为**：悬停 → 浮出该回读数（次数 + 所属十回段）；同时下方「八十一难」柱图中对应段转为主色并加墨色基线，跨图联动。
- **刻工**：条底压在 2px 墨线上（碑座），左右端标「卷一 / 卷一百」；条间隙 2px 即拓片行款。
- **纪律**：全站只此一处；落地页不出现；不得复制为其他装饰性条形。
