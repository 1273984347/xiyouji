# 设计决策记录 · NOTES
## 「墨栏 / INK-RULE」甲案（优先服务数据探查）

> 配套文件：`SPEC.md`（正本）· `tokens.css` · `system.css` · `sample-landing.html` · `sample-dataviz.html` · `_palette_check.py` · `_audit.py` · `_shoot.py`

## 1. 为什么是「栏线」，而不是纸墨谱系、印谱拓片、线装版式

三条同源路径都试想过：

| 候选路径 | 想到的形态 | 为什么没有选它 |
| --- | --- | --- |
| **纸墨谱系** | 纸色底 + 墨字 + 朱点 | 只剩颜色，没有**秩序**；90 个可视化页会退化成「换了底色的仪表盘」 |
| **印谱** | 朱印作头像/页徽 | 印是「身份」，而本站的核心行为是「读数」；且印会变成装饰 |
| **线装版式** | 界行/鱼尾/书口 | 最接近，但线装是**竖排**；本站是横排数据页，直搬会得到仿古 |
| **墨栏（采用）** | 取线装的**栏线**这一条规则，移植到横排数据版面 | 它是一条**可执行的排版规则**，不是一种纹样——既能承载 875 页，也能承载 90 张图 |

结论：视觉语言不落在「画什么」，落在「**怎么分区、怎么对齐、什么才被强调**」。于是得到三条可机器验收的纪律：分节用通栏墨线、指标用账簿竖栏线、强调只用朱砂且语义唯一。

**同源但不做仿古**：本站的「物质感」来自三处，全部是**规则**而非贴图——纸色底阶（表面）、墨色四级（文字）、朱砂唯一强调色（注意力）。全站**零渐变、零水墨背景贴图、零卷轴造型**。读者感到的是「一本被仔细编排的书」，不是「贴了古籍滤镜的网页」。

**与数据优先的方向如何不打架**：甲方向要「读数字」，传统气质要「同源」。裁决是——**气质放在结构与材料上，数据放在几何与数字上**。刻本气质由栏线/墨色/朱砂承担；数据可读性由 tabular 数字、值右端直标、基准线、量程明示承担。两者不共用一个视觉通道，因此互不稀释。

## 2. 三个关键取舍

### 2.1 朱砂只做一件事：「要看这里」

最初想让朱砂兼做「品牌色 + 主角色 + 装饰点」，结果全站朱砂面积约 8%，读者无法判断朱砂意味着什么。改为**单一语义**：朱砂＝注意力落点，且只出现在五处——主角标记、拓片峰值、当前导航项、洞察框承重数字、主按钮。落到实际页面，朱砂面积 < 3%，读者一眼就知道「红的地方是作者要我看的」。

### 2.2 序列色用矿物颜料，但明度按色盲模拟反推

没有直接抄 Okabe-Ito：Okabe-Ito 的黄（`#F0E442`）与橙（`#E69F00`）在浅纸底上对比度不足 3:1，且其蓝/紫在 deuteranopia 下靠明度差拉开、与本页纸色底不搭。改以矿物颜料定色相（石青/赭石/胭脂/松绿/藤黄/绛紫/黛/檀），再用 Machado 三型模拟反推明度，搜索出**明暗两态各自**的最优组合（脚本 `_build/opt_colors.py`）。最终最弱两两 ΔE：亮态 12.49（deutan，石青/绛紫）、暗态 12.18（tritan，赭石/胭脂），均过线。

### 2.3 数字不用等宽字体

等宽数字天然对齐，但整套数字用等宽会立刻变成「终端/科技风」，与本方向冲突。改用无衬线的 `tabular-nums`（等宽数字特性）：对齐效果等同等宽字体，气质仍是印刷品。数字字体栈单独给 `--font-data`，与正文分开，便于 90 个可视化页按需换。

## 3. 删掉了什么（以及为什么）

| 删掉 | 原因 |
| --- | --- |
| 卷轴造型按钮 / 烫金花边 | 装饰性装腔：把「古籍」当贴图，而非当排版规则 |
| 渐变 hero / 发光 / 双段紫蓝 | 现代 SaaS 语汇，且与纸色平面体系冲突；全站改成纯色阶 |
| 圆角卡片 + 彩色左边条 | 模板卡片签名，且会与「朱砂＝注意力」抢语义 |
| emoji 图标 | 一律换成 24×24 栅格、1.6px 描边、`currentColor` 的内联 SVG（16 枚族） |
| 材质/模糊进入内容层 | 契约明令：只许功能层。故 `backdrop-filter` 仅 `.topnav`，`box-shadow` 仅 `.chart-tooltip`（由 `_audit.py` 机器判定） |
| 水墨/宣纸背景贴图 | 贴图＝仿古；纸感改由色阶承担 |
| 正文用宋体 | 636 页长文在 16px 屏上宋体连续阅读发糊；宋体只用于标题、回目、引文 |
| 数字用等宽字体 | 见 §2.3 |
| 「好感度」型柔和配色 / 圆弧曲线 | 与数字阅读无关，且降低对比 |
| 在页面上放装饰性拓片/印章图案 | 签名元素只做一处，且必须是仪器而非贴图 |

## 4. 契约冲突怎么裁决

| # | 冲突 | 裁决 |
| --- | --- | --- |
| 1 | §5 说「两页 × 明暗 × {1280, 375}」= 8 张，§6 却要求 12 张 | 加第三档 **768**（契约本身的响应式断点）凑满 12：2 页 × 2 态 × {1280, 768, 375}。`_shoot.py` 断言数量必须为 12 |
| 2 | §4 给出「629 篇解读文档」，六类篇数合计只有 616 | **不在页面上写任何合计**：落地页只列六类篇数与「相对篇数（以人物谱系 215 篇为满格）」；629 作为独立统计出现在 KPI 位。差额属源数据问题，在本文件 §6 记录，不在页面上编解释 |
| 3 | 「暗色不是亮色反相」如何机器判定 | 三条判据（见 SPEC §2.3）：① 颜色令牌暗值与亮值逐项不等 ② 朱砂与 6 色序列色色相漂移 ≤ 30° ③ 明暗各自「字/面」关系成立。反相会让色相整体翻转 180°，必被第②条拦下 |
| 4 | tooltip 契约要 150ms，但令牌表里 `--dur-fast` 自定 | **令 `--dur-fast = 150ms`**，两者同源，避免两套时长口径 |
| 5 | 「材质/模糊只许功能层」边界模糊 | 判定规则写死：`backdrop-filter` 只允许出现在 `.topnav` 规则块内，`box-shadow` 只允许 1 处（`.chart-tooltip`）；`_audit.py` 计数校验 |
| 6 | §3 禁「装饰性仿古」 vs §1 要求「与内容同源」 | 判定标准：**纹样＝装腔，规则＝同源**。我保留的是版式规则（栏线/墨阶/朱砂语义），删除的是纹样（卷轴/烫金/贴图） |
| 7 | 冻结类名表里没有签名元素的类 | 允许新增类（`system.css` 条款明写「+ 你新增的类」），自建 `ink-strip` / `insight` / `meter`，**未改动任何冻结名** |
| 8 | 「禁 transform 凑合对齐」 | 16 枚图标全部按 24 栅格直接画几何路径（圆心坐标为整数或 .5），无任何位移补偿 |
| 9 | 表格 sticky 表头 + 375px 不得横向滚动 | 表格改为**容器内横滚**（表 `min-width:560px`，外层 `overflow-x:auto`），页面本身 `scrollWidth == clientWidth`；图表面同理（`min-width:520px`） |
| 10 | 「签名元素只做一处」的计数口径 | 落在**页面实例**而非 CSS：拓片条只出现在 `sample-dataviz.html`，落地页不出现；`_audit.py` 对去内联样式后的标记层做断言 |

## 5. 机器可复算的验收面

三份脚本互为独立证据，不共用结论：

- `_audit.py`：读**源文件**（tokens.css / system.css / 两页 HTML 标记层）判定契约——令牌 109 项齐备、明暗键集逐项相等、两个暗态映射块各自覆盖全量令牌、41 个冻结类既有样式又在样板页出现、禁项（8 个 SaaS 紫 / 渐变 / emoji / lorem / tailwind / scale 对齐 / 无限动画）、动效（过渡只含 transform-opacity、CSS 时长 ≤600ms、reduced-motion 双守卫、tooltip 钳制、KPI 终值还原）、自包含（无外域资源、内联 CSS 与源文件逐字节一致）。
- `_palette_check.py`：独立实现 WCAG 与 Machado/CIE76，不读 `_audit.py` 的结论；对比度与 ΔE 全部实算。
- `_shoot.py`：走 node + `require('D:/xiyouji/scripts/node_modules/playwright')`，`colorScheme` 与 `data-theme` 双路驱动；除字节数外还比对两态 `--bg` 计算值（字节数只能证明「两张图不同」，计算值才能证明「暗态真的生效」）。

**重建方法**：

- 令牌改值 → 改 `_build/gen_tokens.py` → `py -3 _build/gen_tokens.py`（生成 `tokens.css`）
- 样板页同步 → `py -3 _build/build_samples.py`（把 tokens.css + system.css 原样内联进两页 HTML）
- 全量复算 → `py -3 _audit.py`；`py -3 _palette_check.py`；`py -3 _shoot.py`

`_build/` 只含生成脚本与页面模板，**交付物本体是上列 9 个文件**；样板页是 `tokens.css` + `system.css` 的逐字节内联产物，任何一处改动都会被 `_audit.py` 的「内联一致」检查拦下。

## 6. 自觉薄弱 / 无法验证之处（诚实清单）

1. **629 与 616 的差额没有解释**。§4 的六类篇数合计 616，与「629 篇解读文档」差 13 篇；来源不明。我选择不在页面上编解释，但站点若要长期展示这两组数字，必须先厘清差额口径。
2. **拓片条的 100 格数值是生成的演示值**（确定性生成、总和严格等于 2,692、峰值第 59 回 42 次），形态与真实《西游记》出场分布无关。它验证的是「概览条作为仪器」这一交互，不是真实分布形态。
3. **暗态最弱色对 ΔE 12.18（tritan，赭石/胭脂）**，虽过 10 的线，但若同一张图里赭石与胭脂同时出现且面积接近，仍可能难以分辨——真实页面中已避免（主图只用石青/藤黄/胭脂三色，赭石与胭脂不同时出现）。
4. **只验了 Chromium**。Playwright 的 chromium 内核已过全部断言，但 Safari / Firefox 对 `color-mix()`、`backdrop-filter`、`font-variant-numeric` 的支持与渲染未实机核对；本系统已为 `color-mix` 写了降级声明（先写 `background: var(--paper)` 再写 `color-mix`），但未做跨浏览器截图。
5. **375px 下主图与副图需在卡片内横滚**才能看全（契约允许「图表容器横向可滚而非压碎」）。首屏观感因此依赖用户横向滑动，代价是「3 秒读懂」在手机上要退到「3 秒知道大概量级」。这是被契约允许、但我自觉不够理想的一处。
6. **宋体在部分 Windows 环境回落到 SimSun**，笔画较粗，`letter-spacing: .08em` 可能显得偏松；未做多机字重对比。
7. **落地页的六类占比条以最大类为满格**，没有给出「占全站 629 篇」的比例——因为分母本身有争议（见第 1 条）。
8. **两页样板的章节结构是「为演示而设」**：真实站点的 875 页各有其骨架，本样板只给出可视化页与落地页两套骨架，其余 88 个可视化页与 636 页长文页需按 SPEC §10 的规则另行落地。
9. **未做真实浏览器里的键盘走查与读屏软件验证**；无障碍结论全部来自数值判据（对比度、ΔE、触控尺寸、语义标签），非辅助技术实测。
10. **icon 族的 16 枚只覆盖本样板所需场景**（搜索/关闭/箭头/索引/书/路线/网络/热力/时间线/表格/柱状/日/月/引用/勾）；站内若扩展到网络图、时间线、地图等 90 页，可能还需补充 4–6 枚同族图标。
