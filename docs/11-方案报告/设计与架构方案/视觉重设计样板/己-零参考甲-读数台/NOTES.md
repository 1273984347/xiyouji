# 详解西游记 · 设计决策记录（NOTES）

> 配套文件：SPEC.md（正本）· tokens.css / system.css（实现）· _palette_check.py / _audit.py / _shoot.py（机器复算）。
> 本文只记录「为什么这么做、放弃了什么、契约打架时怎么裁」，不重复正本里的数值。

---

## 一、方向判断

BRIEF-A 的落点要求是「读者打开数据页的第一反应是这数据讲得很清楚，而不是这页好看」。因此整套设计的**评价标准不是好不好看，而是读不读得懂**：

1. 数值必须是版面上最重的东西：KPI 数字用全页最大字号，条形末端直接写数值，表格数字右对齐等宽。
2. 结论必须由图形推出，不能另起一套话：洞察框里的每个数字都能在图上找到出处。
3. 装饰一律让位：没有渐变、没有发光、没有材质模糊（除顶栏与浮层这类功能层）、没有大圆角卡片、没有 emoji。
4. 颜色是最稀缺的资源：全站同一张图内最多三色，颜色只用来编码数据与状态。

按这条标准反推，最先被砍掉的不是装饰，而是「好看但无用」的信息：首页不再放概念图，改放**卷首索引**（真实的回目 + 篇目），因为它比任何插画都更能说明「这是一本可以逐回读的书」。

## 二、关键决策

### D1 明暗两态：同一套设计，两套独立取值

- **决策**：令牌名、结构、栅格、字阶、动效完全一致；但 109 项中 63 项取值独立设计，暗态不是亮态反相。
- **理由**：浅底上强调色必须更深才够对比（5.69:1），深底上必须更亮（8.69:1）。反相会同时毁掉两态的可读性。
- **代价**：tokens.css 里同一组值要写两遍，靠 _build.py 的单一数据源保证不漂移（审计会检查两态令牌集逐项相等）。

### D2 衬线做标题，无衬线做正文与数字

- **决策**：display / title / subtitle 用衬线栈；正文、说明、全部数字用无衬线栈。
- **理由**：中文衬线在 13px 说明文字下发虚，而无衬线在 28px 以上的标题里缺少「书」的重量。分工后，标题负责「进入阅读」，数字负责「读数」。
- **代价**：Windows 上「Songti SC」不存在，会回落到 SimSun（横细竖粗）。这是可接受的——但要求机器上装有宋体，否则标题会退化为雅黑，标题与正文的质感差会消失。

### D3 签名元素「十回尺」，全站只做一处

- **决策**：以「回」为单位的刻度尺（100 格 + 难数齿 + 读数窗），只出现在数据可视化页。
- **理由**：它同时是内容（齿数就是真实的 81 难分布）与仪器（读数窗给出段 / 难数 / 占比），符合「只做一处，且必须同时是内容与仪器」的要求。
- **取舍**：落地页曾经想用同一把尺做「百回概览」，最终删掉——同一个构件出现两次，读者会把它当成版式模板而不是签名。落地页改用**卷首索引**承担「这是逐回结构」的表达。

### D4 色盲判据 = 同图共现子集可分

- **决策**：可分性按「实际同图共现的颜色集合」判定，而不是要求 6 个序列色两两可分。
- **理由**：这是实测结论，不是偷懒。用 Machado 2009 模拟 + CIEDE2000 搜索过固定色相下的全部可行解：白底且满足 3:1 图形对比度时，**色盲安全的彩色上限约 5 色，且必须放弃灰**。若强行要求 6 色两两可分，唯一解是彩虹化的饱和蓝紫绿（搜索最优解为 #287AEE / #3F9813 / #750EA9），与「明代器物釉色」的气质完全冲突。
- **落地**：彩色池 = 青釉 / 窑变褐 / 靛青三色（这既是实测可行解，也正好是数据页真实需要的三个身份组）；chart-4..6 改为中性/扩展位，仅用于单序列场景，声明不得与彩色池同图共现。
- **冗余编码**：条形末端直接标数值、身份组写进 tooltip 文字、筛选标签带文字与计数——即使完全看不到颜色也能读懂。

### D5 直角 + 发丝线，不用彩色左边条

- **决策**：卡片 = 3px 微圆角 + 1px 发丝边框 + 表面色差；KPI 行用 1px 间隙底色做格线；引证块用暖纸底而非彩色侧边条。
- **理由**：契约明令禁止「圆角卡片 + 彩色左边条」的模板卡片，而中文语境里引证块的默认写法就是左侧竖线——若照惯例做，既踩禁令，又把颜色预算花在结构上。
- **代价**：暗色态下 KPI 的 1px 分隔线最初几乎不可见（已在目视检查中发现并把间隙底色从 hairline 改为 subtle）。

### D6 动效：只动 transform / opacity 的裁决

- **契约原文**：「只动 transform / opacity，禁 width/height/top/left 参与动画」。
- **裁决**：**布局类属性（width/height/top/left/right/margin/padding/font-size/flex/grid）一律不参与动画**；颜色类属性（background-color / border-color / color / fill）允许过渡，但归入「反馈档 ≤150ms」，因为颜色不引起重排、不触发布局抖动。
- **落地**：_audit.py 逐条扫描 transition 声明的时长与属性名；白名单只有三处：入场 600ms（js-reveal / bar-anim / table-anim）与 KPI 数字滚动 900ms（JS 侧）。

### D7 中文限宽用 em，不用 ch

- **决策**：所有中文段落的 max-width 用 em（按字数），不用 ch。
- **理由**：ch 基于数字 0 的宽度，中文里换算结果只有预期的一半，导致每行只有十几个字，断行位置还很难看。目视检查时这一条最先暴露。

### D8 落地页 hero 用「卷首索引」而不是可视化缩略墙

- **决策**：hero 右栏是 8 条真实回目（回目名 + 所属板块），不是数据图表。
- **理由**：落地页的第一任务是回答「这是什么」，回目索引同时回答了「内容形态（逐回）」与「真实内容（回目名）」；图表缩略墙留在了下方「精选可视化」区，那里才是它的正确位置。

## 三、删掉了什么（以及为什么）

| 删掉的东西 | 原因 |
|---|---|
| 全部渐变（含 hero 背景） | 渐变在这套语言里没有语义，只会稀释读数；契约也禁紫蓝双段 hero 渐变 |
| 卡片阴影堆叠 | 层次交给表面色差与发丝线，阴影只留给 tooltip / 抽屉这类真正浮起的东西 |
| 大圆角 + 彩色左边条卡片 | 契约明令禁止，且与「仪器」语气冲突 |
| emoji 图标 | 契约禁止；改为 16 枚 24×24 / 1.7px 描边的手写几何图标族 |
| 图表库 | 契约要求 vanilla + 内联 SVG；也避免 file:// 下的外域依赖 |
| 落地页的第二处刻度尺 | 签名元素只做一处（见 D3） |
| 卷首索引的「更多回」占位按钮 | 无真实链接就不该出现（禁占位文案） |
| 悬浮大标题 / 视差 / 无限循环动画 | 无限动画与注意力争夺在数据页是负资产 |

## 四、契约冲突的裁决记录

| 冲突点 | 冲突双方 | 裁决 |
|---|---|---|
| 6 个序列色 vs 色盲安全 vs 白底 3:1 | 三者不可兼得 | 判据改为「同图共现子集可分」，灰色位隔离到单序列场景（D4） |
| 「只动 transform / opacity」vs 颜色过渡 | 字面禁止 vs 反馈需要 | 布局属性一律禁；颜色过渡限 ≤150ms 反馈档（D6） |
| 触控目标 ≥44px vs 筛选标签密集 | 44px 下 7 个标签会换行 | 保留 44px，标签组 flex-wrap 换行；480px 下标签等分铺满 |
| 禁主强调用靛蓝/紫罗兰 vs 数据序列需要冷色 | 契约只禁「主强调」 | 主强调是青釉；chart-3 的靛青是数据编码色，且与主强调不同色相、不同明度 |
| 签名元素只做一处 vs 落地页也想用尺 | 一处原则 | 落地页改用卷首索引（D3） |
| 零外域依赖 vs 图标与图表 | 需要图形 | 图标用 symbol/use 同文档内联，图表用内联 SVG，字体用系统栈 |

## 五、目视复核中发现并修掉的真实缺陷

机器探针全绿不等于页面没坏。以下问题均来自逐张读图：

1. 卷首索引「第 01 回」断成两行（列宽 42px 不足）→ 列宽改 68px + nowrap。
2. 中文段落限宽用 ch 导致每行只有十几个字、断行难看 → 改 em。
3. 375px 下 4 张 KPI 卡单列，首屏几乎只剩 KPI → 480 断点改 2 列并收紧字号。
4. 暗色态 KPI 的 1px 分隔线几乎不可见 → 间隙底色 hairline → subtle。
5. 375px 下卷首索引的「逐回解读」列挤压回目名 → 480 断点隐藏该列。
6. 480 断点 KPI 卡左内边距被误设为 0 → 改回对称内边距。
7. 窄屏「出场次数排序」标题与单位说明折行打架 → chart-wrap-head 在 480 下改为纵向堆叠。
8. hero 副标题的破折号落到行首 → 用 nowrap 包裹「——一部原著，」。
9. 图标族里一处 y1="7. " 的坐标笔误导致浏览器 console error → 修正后 console 零错误。

（另有一处误报：375 截图里「卷首索引」右侧像是多了一根竖线，放大到 6 倍并用元素探针核对后确认是「引」字本身的右竖画，非缺陷。）

## 六、已知薄弱点（诚实记录）

1. **Windows 上的衬线回落到 SimSun**：标题笔画偏细、横竖对比强，与 macOS 的 Songti SC 观感不同。若目标环境不含宋体，标题层会退化为雅黑。缓解：标题字重已设为 600。
2. **三色池对更复杂的可视化不够**：90 个可视化里若有需要 5–6 个身份组同图的页面，必须引入形状/图案/直接标注的冗余编码，或回到「同图 ≤3 色」的约束重新分配身份组——不能简单加色。
3. **tritan（蓝色盲）余量最小**：亮态彩色池在蓝色盲下最小 ΔE00 为 7.6（阈值 6），靠数值直标与图例文字兜底，但不如其他三类余量稳。
4. **数据页的十个「回」段标签在 375px 下降到 8px**，已属可读下限；若再窄，需要改成悬停读数而非常驻标签。
5. **样板页为静态演示**：KPI 数字滚动、tooltip、筛选为真实可交互，但数据是演示值，不接真实统计接口。
6. **未做长文阅读页样板**：本次只交付落地页与数据可视化页两页样板，长文侧（42rem 阅读宽、逐回连续阅读）的组件规则只在 SPEC 文字里约定，未出可运行样板。
