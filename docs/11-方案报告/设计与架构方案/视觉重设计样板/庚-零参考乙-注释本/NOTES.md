# NOTES · 设计决策记录（方向乙 · 校注体）

> 记录三件事：**为什么这么设计**、**删掉了什么**、**契约冲突怎么裁决**。
> 与 `SPEC.md` 配套阅读；SPEC 写"是什么"，本文件写"为什么"。

---

## 0 · 立场

方向乙的第一读者是**长文连续阅读者**：636 页逐回解读是站内最重的使用场景。因此整套系统的评价标准只有一条——
**读者在一篇解读上停 30 分钟，版面上有没有东西跟他抢注意力。**
视觉上的"好看"排在后面，且必须服从这一条。落点：读者打开长文页的第一反应应是"读起来不累、层次清楚"，而不是"这页好看"。

## 1 · 关键决策与代价

| # | 决策 | 为什么 | 代价（诚实写明） |
|---|---|---|---|
| 1 | 正文栏 40em + 旁注栏 15rem 的双栏校注版式 | 中文长读的舒适行长是 35–40 汉字；旁注把出处/口径/版本说明从正文里剥出去，读者随时能查、但不被正文打断 | 1024–1200px 之间旁注偏窄；单栏回退时旁注变成段下小注，层次弱一档 |
| 2 | 段首缩进 2 字符、**段距为 0** | 中文书籍的段落节奏靠缩进；加了段距再缩进就变成两套信号，读者每次都要重新判断段落从哪起 | 长段落在窄屏上显得密；靠行高 1.95 兜住 |
| 3 | 内容层零阴影、零大圆角、分隔靠 1px 发丝线 | 阴影与圆角是模板化"卡片"的两个签名，去掉之后版面秩序全部交给线与字号层级，安静度大幅提升 | 层次感弱一些，需要靠 `.section-head` 的眉题短横与段落留白补足 |
| 4 | KPI 做成"被线隔开的数字带"而不是四张卡 | 站点的气质是编目而非促销；数字带读起来像表格，像"数据的目录" | 视觉上不如卡片"跳"，首屏下不一定第一眼抓住 KPI |
| 5 | 单一墨青强调色，面积 ≤5% | 长读场景里大面积色彩是噪音；一个颜色承担"当前/可交互/关键数字"三类语义已经足够 | 深青在暗色态必须换成亮青并把按钮文字反转为深色（两态明度角色相反） |
| 6 | 衬线只用在两处：引文与回目/章节标题 | 宋体在屏幕上小字号最舒服，用作长引文能立刻与正文分开；标题用衬线给页面"书"的骨架。刻意避开"宣纸 + 毛笔"的古典质感 | Windows 落到 SimSun（发丝笔画偏细），大字号标题略显轻 |
| 7 | 签名元素＝**百回刻度尺**（内容 + 仪器，且只有一处） | 一格一回是这部书真实存在的结构；同时它是长文流里的回次定位尺（点哪一格就读哪一回）。只做一处，避免"每页一枚印章" | 100 个刻度的可访问名目前只到"第 N 回"，未带回目名 |
| 8 | 明暗是**同一套语言、两套独立取值** | 按钮上"谁压谁"在两态相反（亮色是深青块配白字，暗色是亮青块配深字），说明不是反相滤镜；暗底需要更亮的边界而不是更深的墨 | 维护成本翻倍：每次改色要在 `_gen_tokens.py` 里改两处，脚本会核对 |
| 9 | 序列色**机器调校**：Paul Tol / Okabe-Ito 出发，机器搜最小 ΔE | 手调色板对"色盲安全"只能凭感觉；把"最差色对 ΔE"变成可优化目标后，才谈得上安全 | 分类槽只剩 6 个（对比度与色觉的物理上限），8 个槽位改成 6 分类 + 2 功能 |
| 10 | 入场显现**渐进增强**：`html.js` 才启用 | JS 失效时内容若停在 opacity:0，整页就是白纸；这是真实站点的可用性底线 | 需要在每页脚本首行加 `classList.add("js")` |

## 2 · 删掉了什么（以及为什么）

明确不做（BRIEF-B §B3 已列的三条方向，本系统一条都没沾）：

- **东方古典质感**：没有做旧纸色、没有毛笔插画、没有"朱砂点缀"。宋体只作为**排印工具**出现（引文、回目），不作为气质道具；纸面是冷灰（`#F7F8F5`），不是暖米黄。
- **终端科技风**：没有等宽字堆砌、没有网格背景、没有发光边框。等宽字只在数字与代码语义上使用（`--font-mono` / `--font-code`）。
- **无装饰极简杂志风**：没有"米白 + 极细线 + 大留白 + 零信息"那套模板。本系统的极细线是用来**承载信息**的（分节、分行、分组），不是装饰。

另删：

| 删掉的东西 | 理由 |
|---|---|
| 渐变 + 发光的首屏 | 合约明禁；且长读站点的首屏不需要"哇" |
| 圆角卡片 + 彩色左边条 | 合约明禁；内容层零圆角 |
| emoji 当图标/装饰 | 合约明禁；改用 24×24 描边 SVG（15 枚图标族） |
| 悬浮目录 / 悬浮工具条 | 跟随滚动会持续制造运动刺激；回次定位交给刻度尺 |
| 无限循环动画 | 合约明禁；连加载态都不用循环（静态占位） |
| 材质/模糊进入内容层 | 只许功能层（顶栏、浮层）使用；实际本系统连顶栏都没用模糊 |
| 暗态"亮色取反" | 直接导致墨青变亮、按钮文字失去对比；改为两套独立取值 |
| KPI 数字滚动放进长文页 | 读长文时数字在眼前跳是典型干扰；只留在数据页 |
| 首屏 600ms 入场动画（白名单项） | 白名单是上限不是义务；首屏保持静止进场更利于长读 |
| 8 色全分类的序列色板 | ≥3:1 对比度把可用明度压到 L* ≤ 60，8 色在该带内必然互相混淆；改为 6 分类 + 2 功能槽并把规则写成机器判定 |
| ▲ 符号 | 属于装饰性 dingbat，靠近 emoji 灰区；改用墨青刻度 + 文字标注 |

## 3 · 契约冲突怎么裁决

| 冲突 | 裁决 |
|---|---|
| BRIEF §6 写"两页 × 明暗 × {1280, 375}"＝8 张，任务口径要求 12 张 | **取 12 张**：宽度集扩为 {1280, 768, 375}，多出的 768 正好覆盖中段断点（主导航收起、KPI 两列、图表内部滚动）。375px 的四项断言一项不减。 |
| BRIEF §2.2 里 `--text-step-0` / `--text-step-3` 在"文本"与"字号"两组各出现一次 | 同名令牌只定义一次，归入"字号/行高/间距"组（它们是字号不是颜色）；两组引用的是同一个名字，冻结名不增不减。 |
| 8 个序列槽 vs "必须色盲安全" vs "图形要素 ≥3:1" | 三者不可同时最优化。裁决：**分类槽 6 个**（两两 ΔE：常视 ≥15、模拟 ≥12，且实测优于 Okabe-Ito 基线），**功能槽 2 个**（参考线/合计，不与分类槽同屏比较，规则写进 `_palette_check.py`）。 |
| 冻结类必须全部"按新语言重新设计"，但"样板页必须真实呈现"清单里没有 `.card` | `.card` 在 `system.css` 有完整样式与规则；样板上承担卡片位的是 `.viz-card` / `.kpi-card`（同为发丝线、无阴影），未为了"凑类名"而塞一个空卡片。 |
| 引文必须真实，但本任务禁止读仓内文件（也就用不了仓内 `_cite_probe.py`） | 只选通行本里高确定性的两句（"一日为师，终身为父"第三回 / "皇帝轮流做，明年到我家"第五回），并在旁注里标出版本口径；**上线前须按仓内引文探针复核一次**（这是本方案唯一未闭环的事实风险）。 |
| 动效白名单给了 hero 600ms | 白名单不是义务；本系统首屏无入场动画，实际时长最高为条形生长 580ms 与 KPI 滚动 900ms。 |
| "禁 emoji"与"需设计 10–16 枚图标族" | 图标族 15 枚，全部为几何精确的描边 SVG（`stroke: currentColor`，1.7–1.9px，24×24 栅格），不用任何字符代替。 |

## 4 · 已知弱点与后续动作（自觉薄弱处）

1. **字体环境差异**：本机为 Windows，实测落在 SimSun / 微软雅黑；macOS 会落到 Songti SC / 苹方，字面宽度、行高观感与气质都会变。正式上线前需在目标环境复核首屏标题与引文的行断。
2. **引文未过仓内探针**：见 §3。两条引文来自通行本通行记忆，标点参照中华书局本整理，**未经仓内脚本复核**。
3. **数据可视化页的数值为演示值**（BRIEF 指定为演示样例）：2,692 次等数字是演示口径，页面已用 `data-status-badge` 明确标注"演示数据"，不可当作真实统计发布。
4. **长文页本体不在本次交付**：本次只交付落地页与数据可视化两页；签名元素在真实长文页的"进度态"（读到第几回）尚未实现，双栏旁注在 636 页上的批量接入也未做。
5. **刻度尺的无障碍名偏薄**：100 个刻度目前只报"第 N 回"，没有回目名——因为回目名需逐条核对，不愿凭记忆写入。
6. **1024–1200px 窄档**：正文 40em + 旁注 15rem 在此区间略挤，靠 page-wrap 的 padding 缓解，未做第三档断点。
7. **未做打印样式**：本方向的自然延伸是"打印成注释本"，尚未实现（@media print）。
8. **暗态只做了色值层**：暗色下没有单独的排版微调（如行距补偿），两态字号阶完全一致。

## 5 · 文件清单

**交付物（9）**：`SPEC.md`、`NOTES.md`、`tokens.css`、`system.css`、`sample-landing.html`、`sample-dataviz.html`、`_palette_check.py`、`_audit.py`、`_shoot.py`

`_build_inline.py`（把 tokens+system 内联进两份样板页，幂等且可检测漂移）、
`_palette_optimize.py`（序列色机器调校，保留候选池与搜索过程）、
`_shoot_driver.js`（Playwright 驱动，由 `_shoot.py` 写出）、
`_report_numbers.py`（导出本文件与 SPEC 引用的实测色板数据）。

**运行顺序**：`_gen_tokens.py` → `_build_inline.py` → `_palette_check.py` → `_audit.py` → `_shoot.py`。
