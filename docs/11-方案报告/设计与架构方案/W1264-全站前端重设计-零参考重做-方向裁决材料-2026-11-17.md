### 3.1 乙方向的缺陷（本会话独立复现 → 根修）

**现象**：落地页从「个人随笔」到页脚之间约 600px 空白（目视发现）。
**探针**：6 个 .js-reveal 区块中 5 个停在 opacity≈0（html.js 已加但 IntersectionObserver 未触发）。
**根因**：`.js .js-reveal { opacity: 0 }` 依赖 IntersectionObserver 显现；而**全页截图 / 打印 / 爬虫抓取不会真实滚动** ⇒ 观察器永不触发 ⇒ 视口外内容永久隐藏。子代理自述称「已修复」，但在其自身截图流程内成立、在通用流程下复现。
**修法**（已落仓）：load 后 1.2s 兜底——仍未显现者强制落位（不影响正常滚动路径）。复验：1.6s 时 6/6 全显现。

## 5.1 落地成败的硬指标：类族覆盖率（实测·不利数据·必须知情）

「换皮能否终结拼贴感」不取决于设计多好看，而取决于**新语言的公共层能管住多少页面样式**。实测（875 页实际使用的 953 个 class 为分母）：

| 公共层 | 类数 | 覆盖 953 个实用 class | 占比 |
|---|---|---|---|---|
| 现役 site/system.css（宽口径·选择器） | 673 | 113 | **11.9%** |
| 甲 读数台 system.css | 143 | 59 | **6.2%** |
| 乙 注释本 system.css | 118 | 39 | **4.1%** |

> **两个口径都要说（避免给后来者埋坑）**：上表甲/乙为**宽口径**（CSS 全部选择器里出现的类名）；现役另有一个**窄口径** 91 / 953 = 9.5%（只数以 .class 形式出现的类定义）——两者都对，但含义不同。棘轮与门禁（第 76 槽）统一用**宽口径 11.9%**（更贴近「实际有多少页面样式被公共层接管」）。
**结论（不利但必须说）**：**两个新方向的公共层覆盖率都低于现役**。若直接用其 system.css 替换现役，**样式治理水平会下降**、拼贴感可能更严重。

**⇒ 落地批的硬性前置条件**（任一方向均适用）：
1. **类族覆盖必须补到显著高于 11.9%**（建议 ≥40%）⇒ 落地批需**逐族归并**页面私有类（现役 88.1% 的样式在页面私有层里），而不是只换一份 system.css；**首要目标＝reader 族 9 个高频类（reader-wrap / reader-topnav / reader-body / reader-toolbar / reader-progress / reader-feedback / reader-pn / fb-row / site-header）＋ grp(1258 次) ＋ legend-swatch(470 次)**；
2. 该指标应**做成门禁**（新增第 76 槽：公共层覆盖率下限 + 棘轮），否则下一轮改版又会退回拼贴状态；
3. **落地批次切分按页面族走**（reader 636 / data 91 / en 138 / root 10），每族独立验收、独立可回退。

**最硬的单点证据**（抽 site/reader/ch001.html 实测）：

- 该页共用到 **18 个 class**，其中只有 **7 个**（brand / is-active / nav-brand / nav-item / off / site-header / site-mainnav）来自公共层，**11 个 reader 专属类全是页面私有**；
- 该页**自带 73,679 B（≈72 KB）私有样式**（2 个 style 块）；
- ⇒ **reader 族 636 页（站点 73%）从来没有被公共壳管理过**，每页自带一份几十 KB 的私有 CSS。

这不是「某个页面没改好」，而是**站点结构性事实**：所谓「换一套皮肤」能改的只有那 7 个导航类，reader 族的主体样式（正文排版、工具条、折叠、进度、上下回导航、反馈条、旁注）**全在页面私有层**。⇒ 落地批若只替换 tokens.css + system.css，**reader 族 636 页几乎不会变样**；而 reader 族恰恰是读者停留最久的面。
### 5.2 落地可行性实验：换肤到底能不能穿透页面私有样式（实测·不改仓库·内存注入·两个方向各跑一次）

把甲 / 乙各自的 tokens.css + system.css **注入**现役 `site/reader/ch001.html`（内存态，不改仓库），实测前后：

| 读数 | 注入前（现役） | 注入甲后 | 注入乙后 | 判定 |
|---|---|---|---|---|
| body 底色 | rgb(245, 240, 228) 暖宣纸 | rgb(232, 235, 233) | rgb(228, 232, 229) | **穿透** |
| 正文墨色 | rgb(28, 26, 23) | rgb(20, 25, 27) | rgb(21, 26, 24) | **穿透** |
| 正文体 | Noto Serif SC | Songti SC | Songti SC | **穿透** |
| 标题体 | Noto Serif SC | Songti SC | Songti SC | **穿透** |

**结论（与本报告初版相反·已订正）**：**换肤能穿透页面私有样式**——颜色与字体都跟随新令牌生效。
（初版曾据「字体未变」得出「私有样式压住令牌」的结论，实为**读数截断假象**：按 `fontFamily.slice(0,40)` 取前缀时两个字体串前缀混淆；按 `split(',')[0]` 取**首个字体名**后，两个方向均确认穿透。此条已按复算结果订正。）

**但「穿透」不等于「统一」**——目视注入结果仍是同页两套语言并存：底色与标题字体已是新语言，**而版面节奏、栏宽、段距、工具条形态仍是页面私有的旧形态**（reader 页 11 个专属类 ≈72 KB 私有样式未被新 system.css 接管）。

**⇒ 落地批的工程结论（方向不变·手段更精确）**：

- **换肤在技术上可行**（令牌层是有效的统一点）⇒ 不必担心「改了令牌页面不动」；
- **真正的残余问题是「版面形态」**（布局/间距/组件形态仍在私有层）⇒ 落地批仍需**逐族归并页面私有类**（覆盖率 11.9% → 目标 40%+），否则只是「换色 + 换字体」的半成品；
- ⇒ **可验证的落地判据**：归并后重跑注入实验 + **目视**确认同页只有一套语言（探针测不出「混搭」）。
