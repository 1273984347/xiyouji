## 0. 一分钟速览（零前置知识可读）

### 0.1 这个项目是什么

**《详解西游记》** 是一个「一源多形 · 数字人文可视化解读《西游记》100 回」的开源项目。它把一部古典小说的文本研究，组织成四层产物：

| 层 | 产物 | 规模（2026-10-20 实测） |
|---|---|---|
| 文档 | Markdown 写就的逐回解读、人物分析、主题专题、文化背景、诗词赏析、个人随笔 | A1–A6 六板块共 **615 篇** |
| 站点 | 纯静态 HTML 站点，`file://` 双击即可打开（不需起服务器），同时部署在 GitHub Pages | **857 个 HTML 文件** |
| 可视化 | D3.js / Three.js 数据可视化页 | **87 页**（`site/data/` 88 个 HTML 减 1 个模板壳） |
| 可问询入口 | Web Agent「西游记·渡口问津」——自研 OpenAI-compatible 引擎，可对话、可检索文档、可跑脚本 | `xiyouji-agent-web/`（React 19 + Vite 8 + TypeScript + Express 5 + better-sqlite3） |

另有 Python 脚本层（`scripts/`，负责生成、校验、门禁、审计）与 100 回原文语料（`dataset/text-search.json`，本文件 §2 的引文全部出自此语料）。

**给 Agent 的一句话**：本项目的**内容真载体是 Markdown 文档**，站点与可视化页都是文档的派生产物；改内容先改文档。

### 0.2 本文档是什么、解决什么问题

**问题**：新接手的人或 Agent 打开仓库，看到的是 `scripts/` 里几十个 `check_*.py` 和一份 46 条的门禁清单，**不知道该由谁做什么**——谁施工、谁审查、谁收官、谁管编号、谁验证、谁沉淀方法。本项目已经用《西游记》的取经编制把这套职责讲得比任何通用工具目录都清楚，本文档把那份讲法固化下来。

**做法**：把每个**编制位**（一个职责位置）用《西游记》里的角色命名，并写清四件事——**这个位的项目职责是什么**、**挂载哪个工具/技能/Agent**、**怎么用**、**不能做什么**。共 **17 位**，分四组：

- **甲组 · 取经四众**（常驻流水线）：孙悟空、唐僧、猪八戒、沙悟净
- **乙组 · 天庭编制**（治理与供给）：玉皇大帝、太白金星、太上老君、观音菩萨、如来佛祖
- **丙组 · 旁证与方法**（验证、取证、沉淀，以及两个反面角色）：菩提祖师、千里眼·顺风耳、谛听、六耳猕猴、红孩儿、牛魔王
- **丁组 · 归档与工地**（两套仓内治理系统，V1.1 增补）：酆都判官崔珏（`archive/` 归档区）、扫地道人（`tmpe/` 临时区）

**这不是文学比喻游戏**：每个位都有仓内真实对应的脚本、门禁或文件，§1 总表最后一列给出该位当前是「在役」还是「位空」。

### 0.3 三条阅读路径

| 你要做什么 | 读哪几节 | 耗时 |
|---|---|---|

### 0.4 先认这 5 个词（本项目最小词汇集）

| 词 | 一句话解释 | 权威指针 |
|---|---|---|
| **W 批次** | 本项目的**发布批次编号**（如 W831）。**不是** SemVer 版本号——「现在什么状态」看 `CHANGELOG.md` 顶段 | `CHANGELOG.md` 头部「W### 编号规则」 |
| **门禁** | 提交前自动跑的校验脚本集合（46 条，清单在 `docs/agent/gates.md`），任一条红即阻断 | `docs/agent/gates.md` · `scripts/verify_delivery.py` |
| **认领行** | 开工前在批次编号对账表登记的一行，声明「这个号归我、我要碰哪些共享文件」 | `docs/00-导读/W批次编号对账表.md` 表头规则 |
| **共享面（touches）** | 多会话并行时会被同时修改的文件。动手前必须声明自己碰哪些，**跑 preflight 查交集**，交集非空即禁止并行 | `docs/agent/pitfalls.md` · `scripts/preflight_check.py` |
| **临时区** | 过程产物的唯一去处 `tmpe/`，按桶分类（`_shot/` 放截图与预览页、`_misc/` 放一次性脚本、`w###/` 放批次工作件）。**仓库根不得另建临时区** | `tmpe/README.md` · `tmpe/policy.yml` |

## 2. 编制卡（逐位展开）

每张卡回答五个问题：**谁**（原典来路）→ **在本项目负责什么** → **挂什么** → **怎么用** → **不能做什么**。
引号内均为《西游记》原文，**已用仓内 `scripts/_cite_probe.py` 从 `dataset/text-search.json` 实测提取并逐字比对**（复现命令见 §6.2）。

### 甲组 · 取经四众

#### 孙悟空 · 施工官

- **谁**：全书主力，72 变不是万能钥匙，是「一次只解一难」。
- **负责**：**一次只做一件事**。悟空的纪律是这一难只打这一难，旁的不碰——这正是本项目「最小连贯改动」「一批只动一面」的古典表述。
- **挂**：`worker` Agent（内置角色，负责有边界的产出）· `karpathy-guidelines` 技能（先想再编码、手术式修改、目标驱动）· 批次协议的一批一面纪律。
- **怎么用**：接一个**范围单一、验收标准明确**的批次；开工前先读 `docs/agent/pitfalls.md` 里与该面相关的条目。
- **不能做**：不做「顺手改一下」——改动越出认领的 touches 共享面即触发 preflight 拒绝。

#### 唐僧 · 持经人

- **谁**：肉身凡胎，权威却最高。他不生产内容，他定「什么算取到经」。
- **负责**：**目标与口径的唯一权威**。项目里同一位是文档规范与版本段：口径一旦定版即成历史段，只增不删、禁改——任何人的施工都不得回填它。
- **挂**：文档规范 · `AGENTS.md` §1–§8 铁律 · CHANGELOG 版本段纪律。
- **怎么用**：拿不准「该以哪个口径为准」时，问这一位；引用其原话作为**判定依据**而非装饰。
- **不能做**：不得擅改管控文件（`verify_delivery.py` / `check_doc_sync.py` / `bump_version.py` 等）——改动须经用户批准。

> 「与真悟空同象同音者，六耳猕猴也。」（第 58 回）

#### 猪八戒（俗名猪刚鬣）· 挑刺官

- **谁**：天蓬元帅下界，资质极高但贪懒。
- **负责**：**敢说真话**。八戒的价值恰恰在敢当面说难听话；但要用对——八戒的毛病是懒，所以审查必须带证据清单与触发条件，不能凭印象发难。
- **挂**：`verifier` Agent（内置角色，独立复核、不改产物）· `code-review` 技能 · 仓内对抗性审查报告体例。
- **怎么用**：审查前先写清「交付物 + 验收标准」，让审查者**只做证伪**；结论按严重度排序并附文件路径与行号。
- **不能做**：不能一边审查一边改——发现者与修改者必须分离（这是 `verifier` 的硬性门禁）。

> 「我因有罪错投胎，俗名唤做猪刚鬣。」（第 19 回）

#### 沙悟净 · 收官官

- **谁**：流沙河挑担、任劳任怨、从不改口。取经路上那句标准回执——「大师兄，师父被妖怪抓走了」——正是项目里「收官回执 + 跨会话书面告知」的原型。
- **负责**：**把批次收干净**：跑全量门禁、补齐旁文档指针面、回填认领行状态、书面告知并行会话。
- **挂**：`scripts/verify_delivery.py`（交付门禁）· 收官回填 · 跨会话书面告知。**当前无专职 Agent，此位空缺**。
- **怎么用**：收官清单固定加一条「**旁文档指针面逐条核**」——因为别的批次一旦落段，你上批落的指针立刻过期，而这件事只有全量档才看得见（各批次自查只看自己 touched 的面）。
- **不能做**：不施工。收官位只做「验与补」，不碰内容。

> 「弟子向蒙菩萨教化，指河为姓，与我起了法名，唤做沙悟净，岂有不从师父之理！」（第 22 回）

### 乙组 · 天庭编制

#### 玉皇大帝 · 号牌官

- **谁**：玉帝极少亲自下场（原文仅 6 处直呼其名），但天庭的秩序全靠他定。
- **负责**：**只管号牌与秩序，不发活**。项目里同一位是 W 批次编号：谁取号、谁让号、顶段如何推进、preflight 如何按共享面交集拒绝。
- **挂**：批次编号对账表（认领行 + 递延登记）· 取号规则（**下一自由号 = 表内 max(W#)+1**）· `scripts/preflight_check.py`。
- **怎么用**：取号前做**四面扫描**（台账认领行 / 磁盘件 / spec 文件 / 源码行内批次号注释），确认目标号四面皆空；撞号时按**落地时序**让号（先落地者保留），并跨会话书面告知让号依据、共享面与写顺序。
- **不能做**：不得为「让门禁变绿」而改号——改 bullet 或补认领行会推高台账 max、反过来破坏级联取号。

> 「老孙自小儿做好汉，不晓得拜人，就是见了玉皇大帝、太上老君，我也只是唱个喏便罢了。」（第 15 回）

#### 太白金星 · 传令官

- **谁**：下界招安、上天请旨、两界往返。太白不动一砖一瓦，只把话带到。
- **负责**：**跨会话、跨 Agent 的告知通道**。项目里同一位是「让号依据 / 共享面 / 写顺序」的书面告知。
- **挂**：跨会话告知通道（**当前位空**）· `lark-cli`（官方飞书 CLI，已装、bot 已绑定；用户 token 已过期，个人身份操作须重新授权）· `gh run list`（查 CI 与并行增量）。
- **怎么用**：把「让号依据 / 共享面 / 写顺序」写到**仓外**通道（飞书消息或云文档），而不是共享 git 文件——写进共享文件本身就会制造并发冲突面，还会占号段、触发 preflight 交集拒绝。
- **不能做**：不通过共享文件做通知；不代替用户发对外消息。

> 「我是西方太白金星，奉玉帝招安圣旨，下界请你上天，拜受仙录。」（第 3 回）

#### 太上老君 · 器物官

- **谁**：丹炉里炼出金刚琢、紫金红葫芦、芭蕉扇——道家最硬的部分是「器」。

## 6. 自查与复现

### 6.1 本文档引文怎么复现

```powershell
py scripts/_cite_probe.py --kw 谛听 --chap 58-58 --min-len 12 --max-len 100
py scripts/_cite_probe.py --kw 六耳猕猴 --chap 58-58 --min-len 12 --max-len 100
py scripts/_cite_probe.py --kw 菩提祖师 --chap 1-1 --min-len 12 --max-len 100
```

- **必须用完整句模式**（不加 `--frag`）：碎片模式输出的是「关键词 ± 前后字」的上下文窗口，不带句读。
- **`--max-len` 不要调小**：碎片模式的输出窗口固定为「词长 + 60」字，`--max-len` 小于 64 会把全部候选筛掉且**退出码仍为 0**（静默失败，看上去像「原文里没这个角色」）。默认 100 是安全值。
- 探针保证「候选句是语料正文的精确子串」，但**排版会破坏该保证**：把内层 `“…”` 改成 `‘…’` 即不再是精确子串。故引文须**整段复制语料原样**，需要外框时用 `「」` 而非改内层引号。

### 6.2 引文逐字一致性自查

把本文档每条**块引行的原文引文**（`> 「…」` 形态）逐条比对语料，命中数须 == 引文条数；**行内强调引号（如「用户令」「一批一面」）不是原文引文，不参与比对**。

> **V1.1a 勘误（W838 审查实证）**：V1.0/V1.1 的自查脚本用宽正则 `「([^」]+)」`，把全文 75 处强调引号一并计入「引文」——实跑 94 条 vs 命中 19，按本节判据（两者须相等）**在自己的文档上不过**。真实原文引文（块引 15 条）实则 15/15 全命中，实质无误、发布口径错，此版已修正为正则限定块引行。

```python
import json, pathlib, re
ROOT = pathlib.Path(r"D:\xiyouji")
plan = (ROOT / "docs/11-方案报告/取经编制表-工具与技能挂位-2026-10-20.md").read_text(encoding="utf-8")
blob = "\n".join(c["text"] for c in json.load(open(ROOT / "dataset/text-search.json", encoding="utf-8"))["chapters"])
quotes = re.findall(r"^> 「([^」]+)」", plan, re.M)   # 只取块引行的原文引文（强调引号不计）
print(len(quotes), sum(q in blob for q in quotes))   # 两者须相等（当前应为 15 15）
```

### 6.5 为什么本文档不用 `<!--stats:*-->` 标记

`docs/11-方案报告/` **根层**的 `.md` 属第 31 门禁 C5b 扩展面：文中若出现 `<!--stats:KEY-->` 标记，标记前数字必须等于 `stats.json` 中该键的当前值。`report_docs` 是**递归**计数（`docs/11-方案报告/**/*.md`），任何新增或删除报告都会让它变化——而本文件是一份**编制说明**，其内容与报告篇数无关。

故本文档：**不使用**任何 `<!--stats:*-->` 标记，并把全部数字标注为「2026-10-20 实测快照」+ 给出复现命令。

⚠️ **改动者请勿擅自添加 `<!--stats:*-->` 标记**：加了就得连带刷新 `stats.json` 并同步订正其他文档中同一键的标记值，否则 C5b 立刻红。
