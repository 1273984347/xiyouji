## 0. 为什么推翻现设计语言

现设计语言 = 「古典宣纸风」（§1.1）+ v3「纸感轻立体」（§4A）+ Name That UI 组件语言（§1.3）。它的问题不在审美偏好，而在**执行层面已经造成可测量的后果**：

| 现设计的做法 | 造成的后果 | 本批实测 |
| --- | --- | --- |
| 全站正文用衬线体（§2.4「标题与正文统一使用宋体」） | 长文与图表说明的连续阅读负担；数据语境下衬线降低数字扫读效率 | 90 页正文全衬线 |
| Hero 用三色线性渐变 + `::after` 径向光晕（§3.3） | 装饰层抢注意力；暗色态需另写一套补偿规则 | 90 页 hero 渐变 |
| 纸纹噪点 / 纸感轻立体（§4A） | 「拟物」执行与「数字学术」内容错位；批量维护成本高（每次改版要重刷 INLINED 副本） | 内联 CSS 18.9 MB / 占站点 37% |
| 图表标签直接绘制无避让 | 标签被 svg 视窗裁切 / 相互重叠 | 87–108 页命中，裁切 162–302 处、重叠 252–637 处 |
| 图表内文字色未做对比度门槛 | 暗底浅字几乎不可读 | 112 处 < 3:1，最差 1.1:1 |
| 图标用 `transform="translate() scale()"` 缩放凑合栅格 | 笔画粗细/视觉边距逐枚不一致 | 45 枚中普遍存在 |
| 数据系列只用语义色（朱砂/靛/苔/赭），无灰阶层级 | 多系列图的「非数据色」与「数据色」混用 | — |
| EN 站 fetch 目标指向中文数据集目录 | 生产环境 EN 站数据区变中文 | 13 页 / 38 调用点 |

**结论**：现语言的文化身份主要落在「宣纸 + 朱砂 + 衬线」三个符号上，而**执行方式**（拟物、渐变、光晕、噪点、全衬线）才是成本与缺陷的来源。→ 新语言应当**保留文化符号、重做执行方式**。

## 1. 新设计语言的骨架（与方向无关的通用部分）

三个候选方向共享同一套骨架——**这部分是「推翻」的实质内容**，方向只影响色彩/字体/图形/版式四张面孔。

### 1.1 五条不可协商的原则

1. **数据优先于装饰**：任何视觉元素若不承载信息、不建立层级、不引导视线，删掉。（现站 hero 光晕、纸纹属此列）
2. **一套令牌，两个令牌集**：亮/暗各一套变量，**暗色不是亮色的反色**（现站为暗色另写补偿规则 + `fill` 覆写，是缺陷温床）。
3. **对比度是门禁不是审美**：正文 ≥ 4.5:1，图形与文字标签 ≥ 3:1，**逐页实测**（禁止目测）。
4. **标签零缺陷是准入条件**：任何图表上屏前，标签不得超出 svg 视窗（四向判定）、不得相互重叠（相交面积占比 > 0.3 判重叠）。
5. **一次声明，全站生效**：令牌与组件写在 `site/tokens.css` + `site/system.css` 单一事实源，页面只消费不重定义（现站 15 个令牌散落在页面私有声明里，是 W1105 已记录的口径缺陷）。

### 1.2 新令牌表结构（替代现 §2.1 的 12 色 + 15 页面私有令牌）

```css
:root {
  /* 语义层（唯一入口·页面只准消费） */
  --surface-canvas   /* 页面底 */
  --surface-raised   /* 卡片面 */
  --surface-sunken   /* 图表底/槽位 */
  --surface-inset    /* 内嵌代码/次级面 */

  --text-primary     /* 主文本 */
  --text-secondary   /* 次级文本 */
  --text-tertiary    /* 元信息/轴标签 */
  --text-inverse     /* 反白文本 */

  --border-subtle    /* 卡片边 */
  --border-strong    /* 输入/聚焦边 */
  --axis-line        /* 坐标轴线 */
  --grid-line        /* 网格线 */

  --accent-primary   /* 唯一强调色·全站唯一彩色 */
  --accent-muted     /* 强调的弱化态 */

  /* 数据序列（有序·第一序列=强调色·其余去饱和递降） */
  --series-1 .. --series-8

  /* 状态 */
  --status-pos / --status-neg / --status-warn / --status-info

  /* 排版 */
  --font-display     /* 标题 */
  --font-text        /* 正文 */
  --font-data        /* 数字/轴标签/等宽数据 */
  --size-hero / --size-section / --size-body / --size-label / --size-micro

  /* 间距与圆角（8pt 栅格） */
  --space-1 .. --space-12
  --radius-sm / --radius-md / --radius-lg
}
```

**与现设计的差别**：① 语义层 4 面（现为 2 面 + 纸纹叠加）② 灰阶层级 3 阶 + 边框 2 阶 + 轴线/网格线独立（现无轴线与网格线令牌 ⇒ 每页各写各的）③ 数据序列 8 槽有序（现为语义色 4 个 + 图表色 6 个，两套混用）④ 字体三分（display/text/data）⑤ 间距 12 槽（现约 29,285 处硬编码间距）⑥ 圆角 3 档（现 6 种）。

**令牌表的一条硬规矩**：每个颜色令牌旁**必须标注其对背景的实测对比度**（如 `--text: #E6EDF3; /* 对 --panel 13.1:1 */`）。理由：现站令牌表只有色值没有比值，于是「浅底深字还是深底浅字」全靠人记——这直接导致了 W1259 审查出的 112 处对比度不足（最差 1.1:1）。把比值写进令牌表本身，就是最便宜的防线。

**迁移成本的实测基线**（决定阶段 2 的排期）：

| 指标 | 实测 | 含义 |
| --- | --- | --- |
| `site/tokens.css` 现有令牌数 | **134** 个 | 令牌表已不小，但缺轴线/网格线/数据序列序等关键槽 |
| 10 页内联 hex 出现 | **2409** 次 | 令牌化率极低 ⇒ 改一次颜色要改上千处 |
| 10 页内联 rgba() 出现 | **933** 次 | 透明度写死 ⇒ 暗色态无法整体调 |
| 全站硬编码间距 | **29,285** 处 | 间距未进令牌 ⇒ 版式无法统一 |
| 内联 CSS 体积 | **18.9 MB**（占站点 37%） | 单一事实源被物理复制到每页 ⇒ 改版成本随页数线性增长 |

⇒ **阶段 2（令牌化 + 单一事实源）的工作量主要在这里**，不是「改几个颜色」。建议阶段 2 与阶段 3 分开排：阶段 2 只做令牌与公共壳（可脚本化批量替换），阶段 3 才做图形语言改造（需逐族实测）。

### 1.3 图形语言规范（替代现 §4B 只管「选型」不管「画法」）

现 §4B 有九族图型的**选型表**（什么数据用什么图），但没有**画法规范**（图怎么画才不撞标签、不糊、不压）——这是 87–108 页标签缺陷能长期存在的原因。新规范补九族画法：

| 族 | 画法定规 |
| --- | --- |
| 柱/条形 | 柱宽 ≥ 2px 且 ≤ 类别间距 60%；值标签**仅标极值与末位**；轴刻度按可用宽度抽稀（目标间隔 ≥ 标签宽 + 12px） |
| 折线/面积 | 线宽 ≥ 1.5px；线端不裁切（viewBox 留 2px 余量）；多系列 ≤ 4 条，超出改用分面 |
| 散点 | 节点半径 ≥ 2.5px；点标签仅对 top-N 或选中项；重叠点用抖动或半透 |
| 环形/饼 | 标签一律外置 + 引线；扇区 ≤ 8；单扇区 ≥ 3% 才独立标注 |
| 桑基 | 节点标签置于节点外侧且不压连线；连线透明度 ≥ 0.35 保证重叠可辨 |
| 弦图 | 矩阵外的轴标签必须留 ≥ 8px 间隙 |
| 力导向 | 节点标签仅对度数 ≥ 阈值的节点显示；标签加白色描边（paint-order）保证可读 |
| 树图 | 矩形内文字垂直居中且不换行超 1 行；小矩形不标注（改为 hover） |
| 热力图 | 色阶为**单调明度**（避免色盲不可辨）；单元格数值仅在色阶浅端标注 |
| 3D | 提供降级 2D 形态与静态回退图（file:// 不可用 WebGL 时） |

### 1.4 标签与碰撞的工程判据（**新增·可门禁化**）

```js
// 四向越界：文本 bbox 超出所属 svg 视窗任一边 > 1.5px ⇒ 裁切
// 重叠：同 svg 内两两文本 bbox 相交面积 / 较小者面积 > 0.3 ⇒ 重叠
// 规格必须写明的三项边界（缺一 ⇒ 换人复跑必然对不上）：
//   ① 越界方向（四向 / 仅水平）
//   ② svg 宽度下限（多窄的 svg 不参与判定）
//   ③ 是否需滚动触发 reveal 后再量
```

> 这一条直接来自 W1259 的教训：交付者按「仅水平」判定报 87 页，独立复算按「四向」得 108 页——**两个数字都对，差异来自判据宽窄**。规范必须把边界写死。

### 1.5 图标体系规范

| 项 | 规定 |
| --- | --- |
| 栅格 | 24×24 viewBox，图形光学中心居中，视觉边距 ≥ 2px |
| 笔画 | 1.5px（终端向 1.75px），`stroke-linecap/linejoin: round` |
| 颜色 | `fill="none" stroke="currentColor"`，由上下文色继承（禁硬编码色值） |
| 写法 | **坐标直接对齐栅格，禁 `transform="translate() scale()"` 凑合** |
| 尺寸档 | 24px（功能）/ 16px（紧凑）/ 32px（品牌） |
| 命名 | `<语义>-<变体>.svg`（如 `chart-line.svg`），纯装饰图标 `aria-hidden="true"` |
| 可及性 | 纯装饰 → `aria-hidden`；可交互 → 走 `role="img"` + `<title>` |

## 2. 三个候选方向（同一数据·同一结构·只换视觉语言）

样板页目录：`docs/11-方案报告/设计与架构方案/视觉重设计样板/<方向>/`

| 方向 | 一句话 | 底色 | 强调 | 字体策略 | 图形性格 | 版式性格 |
| --- | --- | --- | --- | --- | --- | --- |
| **甲 · Ink Editorial** | 刻本的气质留在排版里，不在材质里 | 冷白 `#FBFBF9` | 朱砂 `#C8463A`（唯一彩色） | 标题衬线 / **数据无衬线** | 实心柱 + 高光描边 + 直接标注 | 12 列栅格、卡片仅 1px 边、大留白 |
| **乙 · Terminal Dark** | 站点 = 可翻阅的数据终端 | 深墨 `#0D1117` | 青 `#2DD4BF` + 品红 + 琥珀 | 数据/标题等宽 / **正文无衬线** | 弱发光、交叉网格、低填充高亮边 | 面板化、等宽前缀、刻度尺感 |
| **丙 · Neo-Xuan** | 承认暖纸底，但换掉全部执行方式 | 暖纸 `#F5F0E4` | 朱砂 `#C0392B` + 靛苔赭 | 标题衬线 / **正文无衬线** | 几何规整、2px 圆角、chip 图例 | 竖向分隔线、大号章节序号、纯平面 |

**三方向的取舍（主会话初判，待用户裁决）**：

- **甲** 冲突最小：保留「数字学术出版」的严肃感，最贴近站点的内容属性（100 回文本的量化解读），暗色态需单独设计但不反直觉。代价：文化辨识度较现设计下降，需靠排版而非材质承载。
- **乙** 记忆点最强、与现站差异最大，夜间可读性好；但**与《西游记》的题材气质最远**，且终端风在中文长正文上极易翻车（必须正文换无衬线）。
- **丙** 文化资产零损耗、迁移成本最低；但「保留暖底」在用户选择的「推翻现设计语言」框架下，可能被视为**不够推翻**——若选它，需确保执行层确实全换（材质→几何、衬线正文→无衬线正文、拟物→平面）。
