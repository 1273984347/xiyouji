## 1. 为什么「推翻现设计语言」是有依据的判断（不是审美偏好）

现设计语言 = 「古典宣纸风」（DESIGN §1.1）+ v3「纸感轻立体」（§4A）+ Name That UI 组件语言（§1.3）。它的**文化符号**（宣纸 / 朱砂 / 衬线 / 刻本隐喻）是有价值的资产；但**执行方式**已经产生可测量的代价：

| 现设计的做法 | 可测量的后果 |
| --- | --- |
| 全站正文用衬线体（§2.4「标题与正文统一使用宋体」） | 长文与图表说明连续阅读负担；数字扫读效率下降 |
| Hero 三色渐变 + `::after` 径向光晕（§3.3） | 装饰层抢注意力；暗色态需另写补偿规则 ⇒ 缺陷温床 |
| 纸纹噪点 / 纸感轻立体（§4A） | 拟物与数字学术内容错位；每次改版要重刷全站内联副本 |
| 令牌表只有色值没有比值 | 112 处图表文字对比度 < 3:1，最差 **1.1:1**（近乎不可读） |
| 图表标签直接绘制无避让 | 87–108 页标签裁切/重叠，裁切 162–302 处、重叠 252–637 处 |
| 图标用 `transform="translate() scale()"` 凑合栅格 | 45 枚笔画粗细与视觉边距逐枚不一致 |
| 硬编码色值与间距不入场 | 10 页内联 hex **2409** 次 + rgba **933** 次；全站硬编码间距 **29,285** 处 |
| 内联 CSS 物理复制到每页 | 18.9 MB，占站点 37% ⇒ 改版成本随页数线性增长 |

**结论**：该保留的是**符号**（朱砂、衬线标题、刻本气质），该推翻的是**执行**（拟物、渐变、光晕、全衬线正文、无避让绘制、令牌失联）。新语言因此定义为：**保留文化符号 · 重做执行方式**。

## 3. 三方向取舍（主会话初判·待用户裁决）

| 维度 | 甲 Ink Editorial | 乙 Terminal Dark | 丙 Neo-Xuan |
| --- | --- | --- | --- |
| 底色 | 冷白 #FBFBF9 | 深墨 #0D1117（暗为默认） | 暖纸 #F5F0E4 |
| 强调 | 朱砂 #C8463A（唯一彩色） | 青 #2DD4BF + 品红 + 琥珀 | 朱砂 #C0392B + 靛苔赭 |
| 标题字 | 衬线 | 等宽加字距 | 衬线（字重对比更强） |
| 正文/数据字 | 无衬线 | 正文无衬线 / 数据等宽 | 无衬线 |
| 图形 | 实心柱+高光边 / 直接标注 | 弱发光 / 交叉网格 / 低填充高亮边 | 几何规整 2px / chip 图例 |
| 版式 | 12 列栅格 / 1px 边 / 大留白 | 面板卡片 / 等宽前缀 / 刻度尺 | 竖向分隔线 / 大号章节序号 / 纯平面 |
| 文化辨识度 | 中（靠排版气质） | **低**（离题材最远） | 高（暖底保留） |
| 迁移成本 | 低 | 高（暗为默认 ⇒ 亮色态需重做） | 中低 |
| 主要风险 | 文化辨识度下降 | 中文长正文易翻车（须正文换无衬线） | 可能被视为「不够推翻」 |

**主会话推荐**：**甲**。理由：站点的内容属性是「100 回文本的量化解读」（学术而非消费级），甲的学术出版气质最贴合；且文化身份可由**排版气质**（衬线标题、批注式旁注、章节批注号）承载，不必靠拟物材质——这正是「保留符号、推翻执行」的典型落地。反之乙虽然记忆点最强，但把《西游记》做成终端风，与内容属性的错位最大；丙若选，需确保执行层确实全换，否则不满足「推翻」的要求。

**裁决后即可开批**：方向 → 阶段 1（写定稿规范 + 新令牌双轨落地）→ 阶段 2（公共壳 + 令牌化批量替换）→ 阶段 3（十族图形改造 + 标签/对比度清偿）→ 阶段 4（45 枚图标替换）→ 阶段 5（W1259 数据层根修，可并行）。

## 5. 验收与复盘

### 5.1 样板验收判据（主会话用自有探针实测，不采信子代理自述）

- `file://` 双击可开、控制台 0 错误、4 张图均有图元
- 明暗两态各自截图存档，暗色非 filter 反色
- 标签裁切（四向 bbox 越界 > 1.5px）= 0、标签重叠（相交面积占比 > 0.3）= 0
- 正文对比度 ≥ 4.5:1、图形 ≥ 3:1（实测计算）
- 图标 24px / 16px 两档可辨、笔画不糊、居中不贴边
- 单页 ≤ 180 KB、单图标 ≤ 2 KB、零外域请求
- 三方向之间配色/字体/图形/版式四维度至少三项不同

### 5.2 本批复盘

**做对了**：① 先把「推翻」翻译成**可测量的执行层问题**（11 项代价表），而不是泛泛说「旧设计不好看」——这样设计方向的选择有客观依据；② 三方向共用同一数据与结构，保证对比的纯净性；③ 把与方向无关的 11 项缺陷提前解耦，避免整个工程被方向裁决阻塞。

**走错了**：① 首版设计契约文件用 run_code 模板字符串写入时因反引号/转义冲突连续失败三次——**长文档应用 write 工具落文件，不宜塞进 JS 模板串**；② 早期用「字符串计数」grep 报告数字时，把「38」这种高频数字误当成断言通过，属自检口径不严。
