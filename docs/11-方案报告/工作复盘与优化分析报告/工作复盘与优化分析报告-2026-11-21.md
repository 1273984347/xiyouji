## 2. 主题复盘一：判据锚点随上游重构漂移——「形态缺失」假红的两条 N 条

**现象**：N3 与 N4 的报错不是「数字不等」，而是「**断言形态缺失**」。

| 断言 | 旧判据形态 | 事实 | 根因 |
|---|---|---|---|
| N3 槽数 | AGENTS「内含 N 槽，五组」 | gates.md 编号条目 **83** 条、标题自声明「83 槽」 | §4.2 全量定义已于 **W1279** 迁入 gates.md，AGENTS 地图化后**不复述**槽数 |
| N4 坑位数 | AGENTS「N 条坑位按六主题迁」 | 六主题正本聚合 **419** 条 == stats `pitfalls_total` **419** | 该散文形态随 **W1279 地图化 + W1290 六主题拆分**一并退役 |

**关键区分**：这两条断言的**事实源本身是自洽的**（83==83、419==419）——如果当时只做「把 AGENTS 补回那句话」，就会造出**两份可漂移的复述面**（AGENTS 一份、gates/stats 一份），把一个单点漂移变成双点漂移。**正确修法是让判据锚移到同源事实面**：

| 断言 | 旧锚（退役） | 新锚（同源·有判别力） | 能抓住什么 |
|---|---|---|---|
| N3 | AGENTS 散文复述 | **gates.md 标题「（N 槽」自声明 == gates.md 编号条目实数** | 加槽忘改标题即红 |
| N4 | AGENTS 散文复述 | **stats.json `pitfalls_total` == 六主题正本「- \*\*」聚合实数**（另查 AGENTS 是否保留 stats 标记） | stats sweep 与正本脱钩即红（改正本忘 sweep / 改 sweep 忘改正本） |

N4 的新口径**不是恒真**：它把「stats 与正本必须同步」这一条**新的不变量**引入机器对拍——旧的 N4（对 AGENTS 复述）连「stats 漂移」都看不见。

**复用结论**：**判据的锚点是有生命周期的东西**。上游文档一改结构（地图化 / 拆分 / 迁出），依赖「散文复述形态」的判据就变成永久假红，而它的报错形态（形态缺失）与真实原因（事实源漂移）**不是同一件事**。⇒ 上游治理文件做结构性重构时，**判据锚点必须同批审**；判据锚应落在**机器可算的同源事实面**，而不是人写的复述句。

## 3. 主题复盘二：治理数字漂移是「面」的漏网，不是「点」的错

N1/N2/N5 点名了 5 处，但**每个断言面旁边都躺着同族陈旧数**：

| 文件 | 判据点到 | 同族漏网（实测） |
|---|---|---|
| `docs/00-导读/新Agent启动Prompt.md` | 623/89/90（判据 N5 三对） | **616 篇**（第 5 步「现役口径」行·判据当时不覆盖） |
| `docs/00-导读/统计口径说明.md` | （判据不覆盖） | A6 **13→19**、N=**615→629**、**88→91**、**87→90**、校验行 **87→90** |
| `docs/00-导读/文档规范.md` | 76→88 段 | **615==615 → 629==629** |
| `HANDOVER.md` | （判据不覆盖） | A5 **34→42 篇** |
| `docs/00-导读/协议边界速查.md` | A6 13→19 | — |

**最刺眼的一处**：统计口径说明.md **单文件内自相矛盾**——§2 标题「可视化页面 = 90<!--stats:visualization_pages--> 页」（stats sweep 已跟随到 90），而 §2 正文仍写「顶层 .html 文件数 = 88」「可视化页 87」。**同一文件、同一个数字、两个值**，且两者都「看起来权威」。

**根因**：治理数字的判据是**按断言点建的**（哪个文件哪个数），而漂移是**按面发生的**（一个口径源改了，它的**引用方集合**全部过期）。⇒ 判据覆盖的是**点**，漏网的是**面**。

**修法（两条，均已落地）**：
1. **覆盖面补齐**：N5 新增第 4 对（`真实计数：**N 篇**`），使同一文件内第 5 步的同族数也进对拍面。
2. **引用方清扫**：按「口径源 → 全部引用方」而非「断言点 → 单点」的关系扫一遍同族面（本批实扫 5 个文件、9 处）。

**复用结论**：**改一个口径源，必须枚举它的引用方集合**。仓内已有该关系的权威载体（统计口径说明.md + `stats.json` + `<!--stats:*-->` 标记），但**引用方集合没有权威载体** ⇒ 本批靠实扫补齐；后续应把「口径源变更 → 引用方清单」做成机器面（这与第 3 节同源）。

## 4. 主题复盘三：硬门禁在断言源缺失时静默降级——比红更危险的一类失效

**发现经过**：本批为修复 N5，改动了 `docs/00-导读/新Agent启动Prompt.md` 的篇数声明，随后跑 verify 发现 **A1-A6 计数段的状态是「WARN 跳过」而非「实跑对拍」**。查 `verify_delivery.py` 的判定链：

```
L1762  m_cnt = re.search(r"共\s*(\d+)\s*篇", readme_txt)   # ① README 声明
        if not m_cnt:                                        # ② 落空 → fallback
L1785      m_mark = re.search(r"(\d+)\s*<!--stats:a1_a6_docs-->", agents_txt)
L1799      # 仍落空 ⇒ ctx.rep.warn("...跳过 A1-A6 计数校验")
```

- ① **README 无「共 N 篇」字面**（README 用的是 `629<!--stats:a1_a6_docs--> 篇解读` 形态）⇒ 落空。
- ② fallback 找 **AGENTS 的 `a1_a6_docs` 标记**——而 **AGENTS §1「核心内容规模」段在 W1279 地图化时已被删** ⇒ AGENTS 里也没有该标记 ⇒ **落空 ⇒ 该段被跳过**。

⇒ **这道「A1-A6 磁盘计数 == 声明值」的硬门禁，自 W1279 起一直处于静默跳过态**（本批之前无人发现，因为它跳过时不红、不出声）。这正是 W1290 遗留清单里「N3/N4 判据未跟上 AGENTS 地图化」的**更深一层后果**：AGENTS 地图化不只让两条报告型断言假红，**还让一道 verify 硬门禁的断言源失联**。

**修法（不动禁改清单）**：`verify_delivery.py` 属文档规范 §11.2 禁改面 ⇒ 修法选在**断言源的承载面**——在 AGENTS.md 定位段补 `629<!--stats:a1_a6_docs--> 篇`（stats sweep 自动跟随），fallback 即刻恢复。

**实测**：修复前 `AGENTS §1 stats 标记` 分支走 WARN 跳过；修复后输出 `OK A1-A6 真实文件计数 629 篇 == AGENTS §1 stats 标记 629 篇` ⇒ **硬门禁从静默跳过回到实跑对拍**。

**复用结论**：**「门禁没有报红」不等于「门禁在跑」**。当门禁的判定链存在「找不到断言源 ⇒ 降级为 WARN」的分支时，**降级本身必须可见**（本次是靠人工追问 verify 输出才发现）。⇒ 判据设计纪律：**降级分支要么 fail-closed，要么把「本段被跳过」写进汇总行**，禁让降级无声。

## 5. 主题复盘四：豁免簿「只增不减」是防线自身的漏洞（T4 清偿）

**触发**：复盘触发器 T4「豁免簿 30 天未减（updated_at 停更）≥30 天」——`scripts/output/_w864_accent_exemptions.json` 的 `updated_at` 停在 **2026-10-22**，13 个分册 / **259 条**豁免只增不减。

**为什么触发器喊了没人动**：豁免簿是第 49 槽（朱砂实底）门禁的**扣减面**——每条豁免让某页少算若干处朱砂实底。**豁免越多 ⇒ 门禁越松** ⇒ 没有人有动力去减它（减豁免 = 自己给自己加约束）。而门禁自带的 `staleExempt` 判据（`exempted > measured`）**本可机械发现**，但没有任何环节要求「按它收缩」⇒ 触发器只负责喊，不负责罚。

**本批清偿（实测驱动·三阶段）**：

| 阶段 | 口径 | 结果 |
|---|---|---|
| v1 | 按原始登记键匹配 + 实测 `measured == 0` ⇒ 全删 | 259 → **7** 条（251 组删除） |
| v2 | 改按**实测同源归一口径**（剥每段中文批注「（…」+ 复合键按「 / 」分段）⇒ 对齐 `normalizeExemptCls` | 7 → **4** 条（3 组「族合计 > 族实测」下调至 0） |
| v3 | 该页实测 `perCls` 为空（**无任何朱砂实底**）⇒ 该页登记全属多余 | 4 → **0** 条（4 条删除） |

**自证（关键）**：收缩后**复跑第 49 槽**——**238 页 · 增量重扫 0 · 缓存命中 238 · 陈旧豁免 NOTE 清零 · 0 FAIL · EXIT=0**。⇒ 删掉 259 条豁免后门禁仍绿，**反证了这些豁免一条都不再需要**（若误删了仍需要的，第 49 槽会立刻 FAIL——这就是本次收缩的硬自证机制）。

**结论**：豁免簿「只增不减」的本质是**扣减面无收缩义务**——触发器有、判据有（`staleExempt`）、收缩动作却缺。⇒ 纪律：**任何「扣减型登记表」（豁免 / 白名单 / 基线）的维护义务必须与它的触发器同批落地**（触发器只是通知，**收缩动作要有明确责任人与批次归属**）。

**遗留**：审计文件 `scripts/output/_w1291_exemption_audit.json` 保留 v1/v2/v3 全部动作记录（原 count / 实测数 / 归一化差异）；`needs_review` 清单已清零（4 条带中文批注 / 复合键的登记在 v2、v3 分别按归一口径与空页口径处置）。

## 6. 经验沉淀

- **判据锚点随上游重构漂移**：上游治理文件做结构性重构（地图化 / 拆分 / 迁出）时，**必须同批审判据锚点**——依赖「散文复述形态」的判据会退化成永久假红，且其报错形态（形态缺失）≠ 真实原因（事实源漂移）。判据锚应落在**机器可算的同源事实面**（gates.md 自身声明 / stats.json / 生成器产物），而不是人写的复述句。
- **「数字对了」不等于「门禁在跑」**：verify 的 A1-A6 计数段自 W1279 起长期处于 WARN 跳过态（README 无「共 N 篇」+ AGENTS 无 stats 标记 ⇒ fallback 双重落空），无人发现。**门禁的降级分支必须可见**，否则「不红」会被读成「绿」。
- **口径源变更要枚举引用方集合**：治理数字判据按**断言点**建、漂移按**面**发生 ⇒ 改一个口径源必须扫它的全部引用方（本批 5 文件 9 处），否则同文件内会并存两个「看起来权威」的值。
- **豁免簿需要「收缩」这个动作入机制**：触发器只喊不罚 ⇒ 30 天零清偿；门禁自带的 `staleExempt`（`exempted > measured`）本可机械发现，但需把「按实测收缩」写进批的义务面。
