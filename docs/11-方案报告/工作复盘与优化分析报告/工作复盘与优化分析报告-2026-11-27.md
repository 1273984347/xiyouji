### 3.3 skill-creator 优化任务卡（【工具依赖】按仓内替代方案执行）

> 【工具依赖】本项目不引入外部技能包（且铁律 19 禁 CodeBuddy/WorkBuddy 品牌工具链）；「skill-creator 优化」在本仓的等价形态 = **脚本 + 门禁 + 单测 + 文档判据**四件套，由 `scripts/` 与 `tests/unit/` 承载。

**S-03 归档工具链**

- 技能边界：归档正本/一级/250 号宽分卷的写入、对拍、健康检查。
- 当前问题：清单判据面刚收窄；`--check` 只在手工/第 84 槽触发时跑；新人上手需读 30 篇手册。
- 优化目标：`gen_archive_manifest.py --check` 纳入第 84 槽或 pre_push_gate 常态（一次真实腾窗演练即验）；手册「六场景命令」逐条可复制执行率 100%。
- 规格要点：输入=归档目录实况；输出=清单 + exit code；约束=单一写入者表不破；异常=卷谱系断档/冻结卷被改 → exit 1。
- 验收：一次真实腾窗（迁 1 卷）后 `--check` 绿 + 第 84 槽绿 + 手册命令逐条 rc=0。

**S-04 登记账本**

- 技能边界：台账行、TODOS、遗留总账三账的登记/删除/回填。
- 当前问题：三账各自有「完成即删/当批翻状态」义务，但无统一判据；本区间实证三例滞后。
- 优化目标：把三账义务机器化——① TODOS 挂起行判据=文件已在 git 历史（可脚本检测）；② preflight 状态前缀表补终态词；③ 台账在途行 git 反查（已有 P-43-01 二分，可扩到「已收官+hash 空缺」外）。
- 验收：新增单测 ≥4 例；下一批复盘前 preflight 的 NOTE 类噪音 ≤1 条。

**S-05 复盘/审查编排**

- 技能边界：周期哨判据、报告体裁选择、登记面口径。
- 当前问题：登记面（T 报告）与目录面（复盘文件）双源；完整版模板对 26 批可用但对 3 批过重。
- 优化目标：在报告文件名或 README 行增加「复盘批角色」字段，使触发器只读一个面；模板按批次数自动选档（≤3 批 mini / ≥10 批完整）。
- 验收：下一轮 T1 触发时，preflight 不再报「登记面与目录面不一致」。

### 7.3 优化建议与量化

| 编号 | 改进 | 步骤 | 预期效果 | 验收 | 风险 |
|---|---|---|---|---|---|
| WF-10 | **回填笔与下一批首笔同车** | 下一批内容笔同时 `ledger_backfill --w <上批> --from-git`；上批状态在收官笔已翻「已收官」，仅 hash 延至下批首笔 | 每批省 1 轮 CI 等待（11–15 分钟）；26 批 ≈ 4.8–6.5 小时 | 连续 3 批：首笔含上批 hash 且 C4-g 绿 | 改变 E-311「第二笔回填」时序语义，须先改口径与判据 |

**量化模型（假设 H-02）**：批次周期 = 施工（可变，按 1.5–2 小时估）× 1 + 门禁固定成本（≈2–3 分钟）+ 推送等待（2 轮 × 11–15 分钟 ≈ 22–30 分钟）。WF-10 后周期减少 11–15 分钟 ⇒ 相对 1.5–2 小时周期，效率提升约 **9%–16%**（未达模板 20% 目标，如实标注）；若叠加 WF-11 消除的复发热灯返工（历史每 5–10 批 1 次，单次约 20 分钟），可达 **12%–18%**。剩余空间需削减施工面或 CI 平台侧并行（不在本仓控制范围）。

**本章结论**：七步流水线的唯一分钟级瓶颈是 CI 等待；WF-10 是唯一有量级收益的改动，但需先改 E-311 口径。
