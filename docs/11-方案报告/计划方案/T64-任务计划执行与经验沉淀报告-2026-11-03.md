## 0. 背景与结论速览

**一句话**：档 3 铺开第一批把三对同批页（character-sentiment-arc / concept-device / monster-victims-network，中英各一）的图表色常量改读 `var(--chart-N)`，并在过程中**自行发现并撤销了两处越界改动补偿机制的动作**（补偿收口属档 3 之后），补齐档 3 权威口径复算出的施工缺口，最终以「呈现色等效核档」证明**本批引入的真实回归为零**。

**四条结论**：

1. **铺开面**：6 页 · 60 行改动 · 档 3 权威口径（L2/L4/L5 互斥归类）复算残留 **10 处 → 0 处**。
2. **本批最大产出＝越界动作的自我纠正**：施工初稿照 W1108 原型批先例改写了补偿规则 LHS 并新增前缀规则，经 DOM 级取证判定**两处均越界**（与 W1100 工程次序定案冲突 + 破坏补偿表每页 112 条同源指纹），实测造成 22 处凭空 filter 差异 + 9 处补偿值互换（其中 8 处是暗色态变暗的真实回归）⇒ **全部撤销**，补偿机制原样保留。
3. **核档结论**：浅色态零差异 · 元素数 12 组零不一致（5512 元素）· 呈现色口径分档 OK 166 / WARN 114 / BLOCK 50 · **改后取暗色令牌值 330/330** ⇒ BLOCK 50 条全部是「改前裸浅色 → 改后暗色令牌」的**令牌口径差**（与站内既有口径对照读数一致）⇒ **我方引入的真实回归 = 0**。
4. **防线复用**：W1110 新增四槽在本批直接生效（第 56 槽兜 CSP 同步、第 57 槽兜 CSS 变量自引用、第 54 槽兜坑位撞号）。

**证据件**：`scripts/output/_w1113_delta.json`（呈现色逐元素核档 + 站内口径对照）· `scripts/output/_w1113_spec.json`（落段 spec）· 台账 W1113 行 · 坑表 E-133 / E-134。

### 2.3 越界动作纠正记录（本批最大产出）

#### （1）越界动作是什么

初稿按 W1108 原型批先例，对 6 页各做了两件事：

- **改写字面值型补偿规则的 LHS**：`html[data-theme="dark"] svg [fill="#3a6b8c" i] { fill: #7d99a9; }` → `[fill="var(--chart-2)" i]`
- **新增前缀型规则**：`html[data-theme="dark"] svg path[fill^="var("], … circle[fill^="var("], … rect[fill^="var("] { filter: brightness(1.12) saturate(1.05); }`

#### （2）为何判定为越界（三条依据）

| # | 依据 | 证据 |
|---|---|---|
| ① | **与 W1100 工程次序定案直接冲突** | 台账明文：「补偿表含调色板色条目且当前仍生效 ⇒ 先删会让 1412 处暗色变暗 ⇒ **补偿收口排在档 3 之后**」⇒ 铺开批本就不该动补偿机制 |
| ② | **破坏补偿表的站内同源指纹** | W1100 实测：330 页补偿规则**指纹仅 1 种**（每页 112 条一模一样）⇒ 改任一页的 LHS 即破指纹 ⇒ 破指纹本身就是越界信号 |
| ③ | **W1108 先例成立的前提在本批不成立** | chart-design 页的 SVG 喂色经 `--chain-color` CSS 变量中转 ⇒ fill **不落表现属性位** ⇒ 不受前缀规则影响 ⇒ 先例在那里安全；本批三页是 D3/echarts **直写表现属性位** ⇒ 前缀规则在此有完全不同的命中面 |

#### （3）实测代价（DOM 级规则命面对拍）

| 缺陷 | 机理 | 实测量 | 性质 |
|---|---|---|---|
| ① 前缀规则凭空加补偿 | 基线中**早已是 `var(--chart-1)`** 的元素（16 circle + 1 path + 5 circle）在基线**本就不吃**亮度补偿（`[fill^="#"]` 不匹配 `var(`）⇒ 新规则让它们首次获得补偿 | **22 处** filter 差异 | 副作用（非预期变亮） |
| ② 改写 LHS 后字面值元素失配 | 页内仍有字面值 `#3a6b8c` 元素（monster 页 `catColors` 数组未被施工覆盖）⇒ 不再命中任何字面值补偿规则 ⇒ 暗色态落回浅色原色 | **9 处**补偿值互换（其中 **8 处暗色态变暗**） | **真实回归** |

#### （4）处置与留证

## 4. 复盘

### 4.1 做对了什么

1. **没有停在「现象层」**：J2 对拍出现 31 条待判定差异时，没有按经验直接归类为「预期令牌跟随」，而是建基线 worktree 做 DOM 级规则命面对拍 ⇒ 才发现根因是**我方自己的越界动作**。若停在 computed 快照层，这 31 条会被误判为「既有机制失配」而放过。
2. **越界动作被撤销而非辩解**：发现与 W1100 定案冲突后，选择撤销并留证（记录机理、实测代价、撤销后读数变化），而不是论证「先例可类推」。
3. **核档用呈现色口径**：因裸 computed 值无法反映 brightness 补偿 ⇒ 补做 filter 叠加实算 ⇒ BLOCK 从「50 条假警报」被正确归类为「既有令牌口径差」。
4. **施工缺口用权威口径复算兜住**：不是靠肉眼看有没有漏改，而是用 W1100 归档的互斥归类脚本复算（10 → 0）。

### 4.2 待改什么

1. **施工脚本的正则覆盖靠人工枚举 → 应以权威盘点脚本的命中面为准**。本批首版脚本漏了对象内联字段 / 数组字面量 / `stop-color` 三类形态，共 10 处。⇒ 后续铺开批的脚本应**直接复用 `archive/scripts/batches/w1100/_w1100_layer3_pages.py` 的层正则**做命中断言，而非另写一套。
2. **越界检查应前置到开工前**：本批的越界是在施工后被取证抓出，代价是一轮重采 + 一轮重算 CSP。⇒ 铺开批开工前应先读「工程次序定案」并把「本批禁动的机制清单」写进 spec。
3. **J2 快照的采集面不含 DOM 属性** ⇒ 归因能力受限。⇒ 建议后续把「fill content attribute 值」纳入快照属性集（低成本、直接把归因从「另造探针」变成「现成读数」）。

### 4.3 交接口径（下一批可直接用）

- **档 3 铺开的既定口径**：改令牌值、不改补偿机制；补偿失配（filter 增减）属预期，令牌暗色值已上调部分抵消。
