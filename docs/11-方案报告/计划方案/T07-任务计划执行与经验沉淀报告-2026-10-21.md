## 一、执行摘要

**G-01 目标**：把公共站的交互流程缺陷收敛成可验证的修复批，并给根因加装可自动判红的预防措施。

**结论一句话**：公共站的**健壮性底子不差**（1915 处 fetch 调用只有 1 页整页零兜底、856 个内联脚本 0 个被 CSP 拦），但**少数几处关键代码被后续批次覆盖或退役**，导致 3 条 P0：一条**线上已生效**（渡口页交互全失效）、一条**访客闭环死路**（"问"浮窗 + 渡口页互为死胡同）、一条**主导航会被永久隐藏**（ESC / 窗口缩放）。

| 维度 | 量化结论 | 证据 |
|---|---|---|
| 审查覆盖面 | 857/857 页脚本化扫描；736 页含控件、2876 控件逐个对账 | `tmpe/_misc/audit_interaction_unbound_controls.py` |
| P0 数量 | 3 条（P-01/P-02/P-03），其中 P-01 线上已生效 | 见 §二 |
| "点了没反应"真阳性 | **1 页**（`site/dukou-engine.html`，6 个控件） | 同上 |
| 死法归因 | 3 类：重建覆盖脚本 / 内联被 CSP 拦 / 真没实现 | §八 E-03 |
| 健壮性正例 | fetch 整页零兜底 1/232 页；CSP 未放行 0/856 块 | 两个审计脚本 |

| 需用户裁决 | 2 项（开工授权 + P-02 产品口径） | §六 / 附录 E |
