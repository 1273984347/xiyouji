## 4. 复盘
**本章结论**：本章要求已逐项落实，明细见本章各表与第 3 节实测读数。

### 4.1 做对了什么

1. **先取证再取号**：占号前查清编号占用与对方改动面，避免踩「编号撞车」与「同文件并行改」两类坑。
2. **缺陷由真实操作证明**：没有停在单测绿——让号那一步就是 release 的真实使用场景，回读断言当场证明修复有效。
3. **让号写进回执**：把依据、共享面与写顺序一并告知对方，避免事后各说各话。

### 4.2 待改什么

1. **新写机制必须自带「假成功」防线**：本批 release 缺陷的表象是「打印成功而实际未删」⇒ 任何涉及状态变更的工具都该有回读断言，不能只看回执。
2. **合并语义与删除语义要在设计时就分开**：合并（本意不覆盖他人）与删除（本意必须消失）共用一条写回路径 ⇒ 必然有一方失效。
3. **归类门禁的「归属」必须先问「它归属的是本提交还是带入内容」**：凡按「索引态顶段/新增段集合」定归属的门禁，merge 场景都要显式处理。
4. **未处理项**：正本与归档并存的存量 W1001 段（须用户批准）；档 3 剩余可施工面近耗尽（排除 181 页豁免页后每页 ≤2 处，需先改消费方式）；批量写 .py 后强制 py_compile 尚未成为机器门禁。
