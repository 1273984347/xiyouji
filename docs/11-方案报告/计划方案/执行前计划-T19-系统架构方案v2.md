## 摘要

本批为**方案设计批**（只读盘点 + 新增文档），不改 `site/` 页面、不改 `xiyouji-agent-web/` 代码、不改管控脚本。核心工作是：在 W821 架构方案（2026-10-20）基础上，针对**新的规模与技术栈选型**（月活十万级 + TypeScript/Node.js 全栈 + PostgreSQL）产出一份**目标态架构方案 v2**，并补上既有方案完全缺失的**合规（等保）维度**。

**关键判断**：W821 明确裁定「不引入外部数据库」，其理由写的是「当前 DAU 百级、站点零服务端」——**该前提被规模改写**，且 W821 自己写明了升级触发条件（DAU > 5,000 或并发写会话 > 50 或需要多用户鉴权与租户隔离），新规模已命中。故 v2 不是推翻既有方案，而是**执行其档 2**，同时新增合规横切面。

**交付形态**：Markdown 方案正文（Mermaid 源码·事实源） + 零外域 HTML 可视化页（产物） + 6 张 PNG（产物）。

## 0. 任务背景（读者无需回看会话即可理解）

本项目是《详解西游记》数字人文平台：Markdown 文档为唯一事实源，经确定性加工层产出零服务端静态站（857 页），上层挂 Web Agent 问答（Express 5 + React 19 + TypeScript + better-sqlite3）。

2026-10-20 已有一份《系统架构方案（W821）》，覆盖分层、模块、数据流、存储、扩展、容灾、部署、监控八个维度。2026-10-25 用户提出新一轮架构设计需求，并确认了四项此前未定的条件：

1. **业务场景与规模**：内容/文档平台型 · 单机到 10 台 · **月活十万级** · 读多写少（W821 时期为「DAU 百级」）。
2. **技术栈**：**TypeScript/Node.js 全栈 + PostgreSQL**（W821 时期为「沿用现役栈」，即 SQLite）。
3. **硬约束**：① 私有化/离线部署（禁外域依赖）② 成本敏感（尽量少用托管服务）③ **合规等保（审计日志 + 数据分级）**——第三项在 W821 全文中无对应内容。
4. **交付形态**：架构图需 **HTML + Mermaid 源码 + PNG** 三件套（W821 时期为 Markdown + Mermaid）。

因此本批产出一份**增量修订版**方案 v2：保持 W821 的根本裁定，修订其存储裁定所依赖的规模前提，并新增合规横切面。
