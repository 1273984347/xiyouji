### 实跑抓出的真缺陷（静态审查看不见）

1. **注入脚本的标记注释形态恒为 JS 形态**：W1205 交付的 `inject_service_endpoint.py` 里，`inject_text()` 硬编码用 `MARKER_TEMPLATE_CODE`（`/* … */`），而 `marker_template_for()`（按类型选模板）**无人调用** ⇒ 注入 HTML 产物时该串不是注释 ⇒ **被浏览器当正文渲染到页面顶部**。而守卫豁免判定只找标记里的 `endpoint=` ⇒ **判据照样报绿**（属「判据绿但产物破」的静默形态）。⇒ 根修：`inject_text()` 接受模板参数、`inject_file()` 传 `marker_template_for(path)` 的结果；补 **1 例变异自证单测**（退回代码形态必红）。
2. **就绪响应泄露服务端本机路径与错误原文**（独立盲审 P1）：`auditDegradation()` 全量含 `markerPath`（服务端绝对路径）与 `lastError`（fs 错误原文），直接序列化会重开 W832 已收敛的信息泄露面。⇒ 根修：只投影 `degraded / failures / gapStart` 三字段 + 集成测试回归锁（键集合恰为三字段 + 响应体不含 `markerPath`/`lastError`）。
3. **降级标记只写不读回**（盲审 P2-1）：`audit.ts` 注释承诺「落标记文件 ⇒ 重启后仍可见」，实现却只在模块内保留 ⇒ 重启后 `/api/ready` 反报「未降级」（**声明 ≠ 落地**）。⇒ 根修：启动时读回标记回填 `degradation`（读不到/坏文件按「未降级」降级处理，不抛）。
4. **`needs_rag` 判定与注入顺序耦合**（盲审 P2-4）：判定若只看占位符文本，已注入产物再跑 `generate_csp.py` 会得到 `needs_rag=False` ⇒ 生成的 `connect-src` 丢掉 RAG 源 ⇒ 注入后的页面 fetch 被 CSP 阻断（脚本仍 rc=0）。⇒ 根修：判定改看服务基址载体。

## 四、复盘

### 做对的

1. **读判据源码而非猜口径**：`generate_csp.py` 的 `needs_rag` 判定与 `check_doc_sync.py` 的 C5e 口径，都是先读源码再改 ⇒ 没踩「两处字面量漂移」。
2. **占位符位置按下游约束设计**（而非「先替换上再说」）：先确认「内联脚本是哈希载体」⇒ 地址改由 `<meta>` 承载 ⇒ 部署期替换不动内联脚本 ⇒ 哈希不破。

### 做得不好的（风险与偏差记录）

1. **子代理派发实施任务失败**：派出的 worker 子代理做了 70+ 轮调研（读源码、探 Chrome 行为、核实生成源归属），**零文件落地**，60 分钟后被中止 ⇒ 纯浪费。根因是把「需要边读边判断的大范围改造」整包丢给子代理，而它把「读完再动手」当成终点。**偏差**：原计划「主会话派发实施 + 盲审并行」实际退化为「等待调研」；**改进**：此类改造由主会话自持实施，盲审才外包（窄范围、有明确验收清单与时间盒）。
2. **写文件脚本自伤**：`open(path, "wb")` 在**实参求值之前**就截断文件 ⇒ 我一个批量脚本因 write 实参类型错误抛异常 ⇒ `docs/11-方案报告/README.md` 被清空（291 行丢失，git diff 显示大量删除）。**改进**：所有批量写入脚本一律「先算完完整内容，最后才打开文件」；改前用 `git checkout` 快速复原。
3. **首次实证脚本口径不严**：把 `_template.html`（本就不入 CSP）与「注入后未带 `--expected-endpoint` 声明」误读为 E2 失败 ⇒ 实证脚本自身需与判据同源。
4. **grep 全仓未限路径**：`grep "318 条"` 命中 `site/data/search.html` 的搜索索引（79 万字符）⇒ 单次输出爆掉 ⇒ 全仓 grep 必须限 `path`。
