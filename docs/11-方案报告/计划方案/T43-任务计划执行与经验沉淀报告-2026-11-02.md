## 0. 背景与结论速览（执行摘要）

B1（W1076）收官时给出的程序重排建议是「先量 v4 剩余工作的真实形状」。本批就是这个量：**全站硬编码颜色的分类盘点**，产出「逐页清单 + 令牌映射 + 不可替换项」三件。

**四条结论（每条都有全站实数支撑）**：

1. **可逐页消费的量只有 1,066 处**（页内私有 CSS 401 + 内联样式属性 665）——占全站硬编码总量 77,580 处的 **1.4%**。
2. **不可替换项占绝大多数**：JS 字面量 **5,041** 处（`var()` 在 SVG/Canvas 属性位不生效）、共享副本消费 **57,090** 处（改它＝改共享层 ⇒ 级联全部内联页）、令牌定义面 **15,166** 处（不是消费面）、标记文本 312 处、SVG 表现属性 **0** 处（站点未在表现属性里写 hex ⇒ 无需改写法）。
3. **B2 十页的形状比预期更薄**：页内私有 CSS 仅 **13** 处 + 内联样式 **38** 处 = 51 处可消费；JS 字面量 **183** 处；容器**全部已是 `var(--container-wide)`** ⇒ 无容器归并对象；`--chart-3` / `--chart-5` 的**硬编码消费面为空** ⇒ defer「暗色 chart 新增」**不触发**。
4. **v4 剩余工作集中在两个跨批面**：① **图表色的 JS 侧令牌化**（需工程化：`getComputedStyle` 读令牌喂图表，或把图表配置改为 CSS 变量驱动）——它同时消解共享层 `tokens.css` 暗色块的 **111 行 SVG 旧色→替代色映射表**（共享副本里那 57,090 处 hex 的来源）；② **页内私有的零散项**（1,066 处）。**更正（W1079 开工实测）**：本报告初稿曾建议「共享层一次 spacing 令牌化 ⇒ 零视觉差异覆盖 857 页」，**该建议不成立**——共享源 `tokens.css`/`system.css` 的刻度内 spacing 字面量实测为 **0 处**（每页副本里那「55 处」全部落在 `clamp()/calc()` 内，按手术 8 口径本就不替换）⇒ **不存在「零差异的一次性大批」**；共享层颜色的正确路径是 JS 侧令牌化，且收敛必然带来**暗色视觉变化**（需 J2 证明 + 灰度）。

4. **全站盘点工具**（`scripts/_w1078_color_inventory.py`）：解析 tokens.css 浅/暗两套令牌值 → 建 hex→令牌索引 → 逐页按「定义面/共享副本/页内私有/内联样式/SVG 属性/JS 字面量/标记文本」七类归集 → 出 json + md 两件（40 KB / 1.5 MB）。
5. **判据自纠两处**：① 无暗色覆盖的令牌（如 `--dark`/`--rebel`）原被标成「暗色有意变化」⇒ 改为「暗色沿用浅色值（零差异）」；② 补 B2 专项小节（逐页明细 + 判定小结）。

## 4. 复盘

### 4.1 做对了什么

1. **先把「共享副本」与「页内私有」拆开**：不拆的话 B2 的结论会是「每页 55–60 处可换」⇒ 直接把逐页批误导成共享层改造（越裁决 5 + 级联全站）。这是本批最重要的技术判断。
2. **分类轴对齐「下一步动作」**（而不是「对象属性」）：七类里只有两类是「现在就能逐页做」，其余各有明确归口 ⇒ 盘点直接变成施工判据。
3. **零抽样**：857 页全量 ⇒ 结论不含「样本偏差」这层不确定性。

### 4.2 该改什么

1. **「B2–B10 逐批」的程序形状需要用户裁决**：按本盘点，data 页的页内可消费量已枯竭（B2 十页仅 51 处）⇒ 继续按 §6 表逐批做下去，多数批次会是「几处替换 + 一次 J2 全量采集」的低产出批次（每次采集约 30–50 分钟）。建议改为：**组件层批（共享层一次令牌化 + 一次传播，零视觉差异、覆盖 857 页）→ 图表色工程批（JS 侧令牌化，需设计）→ 逐页批只做真正的页内私有项**。
2. **J2 采集成本应被重新计价**：B1 实测 24 页 ≈ 40 分钟；B2 若要覆盖 27 页 ≈ 50 分钟/拍 × 2 拍 ⇒ 逐批一次采集成本高于其产出。⇒ 对**零差异**改动可改用结构化判据（字面量残留扫描 + 令牌同值断言）替代 computed style 全量对拍；但**共享层颜色收敛不是零差异**（暗色 SVG 映射表 ⇒ 图表色变化）⇒ 该批仍须 J2 暗色面证明 + 灰度。
