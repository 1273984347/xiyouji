## 0. 背景与结论速览（执行摘要）

**本批针对**：用户批准的三项后续工作的第 1 项——把「暗色补偿失配的可接受幅度」从人眼判断变成**可机读的实数**。上一批（W1100）已定案工程次序：ΔL* 判据（工具层·独立可做）→ 档 3 原型验证批 → 档 3 规模化 → 补偿收口。本批是次序的**第一站**，为后三步提供判据与前置清单。

**核心判定**：

1. **判据内核已落地**：新增 scripts/color_delta_guard.py —— sRGB → CIELAB（D65）→ ΔL*（亮度差）与 ΔE*76（总色差），三档分级（OK / WARN / BLOCK）且**阈值可配**，四个子命令：pairs（色对清单求 ΔL*）/ scan-comp（全站补偿表等效 ΔL* 分布）/ scan-tokens（令牌暗色覆盖体检）/ scan-palette（调色板 12 色双态体检）。
2. **阈值不是拍脑袋**：实测站内两套补偿机制的等效 ΔL* 分布落在**两个互不重叠的区间**——弱补偿（前缀型 filter: brightness(1.12)）**1.1~5.6**（59 个补偿原色全覆盖·中位 4.5）、强补偿（字面值型重映射）**14.7~55.1**（中位 24.2）⇒ 据此把三档定在 **OK ≤ 6**（弱补偿等效上限 5.6 的向上取整）/ **WARN 6~12**（两区间之间的自然间隙）/ **BLOCK > 12**（接近强补偿下限）。
3. **判据反过来暴露了档 3 的施工前置**：调色板 12 色双态体检显示——**浅色态 3 处 BLOCK**（#7FA8C9→#3A6B8C 的 ΔL* = 23.9、#C9A96B→#8A6D3B 的 22.9、#9DB98A→#6B8E5A 的 16.7）：这四个色**本身是暗色调色板值**，若在档 3 中被一刀切替换为 var(--chart-N)，浅色态会回落成浅色值而变深 ⇒ **档 3 必须按「原色是否暗色专用值」分类施工，不能一律替换**；**暗色态 1 处 BLOCK**（#8A6D3B→#C9A96B 的 17.5）+ **2 处暗色无覆盖**（--chart-3 / --chart-5 在暗色块未定义 ⇒ 沿用浅色值）⇒ **档 3 铺开前必须先补齐暗色令牌值**。
4. **判据自身的可信度靠异源锚点**：单测 29 例，锚点用 **CIE 标准参考值**（L*(#000000) = 0 · L*(#ffffff) = 100 · L*(#808080) = 53.585）而不是自算值 ⇒ 实现算错公式会被立刻抓住（自检式判据的通病是「用同一实现自证 ⇒ 口径漂移不可见」）。

**本章结论**：ΔL* 阈值判据已从「建议值 12」升级为「有站内经验分布支撑的三档可配判据」，并顺带产出档 3 的两项硬前置（补暗色令牌值 + 按暗色专用值分类施工）。
