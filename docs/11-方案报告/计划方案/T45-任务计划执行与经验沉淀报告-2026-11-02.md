## 0. 背景与结论速览（执行摘要）

W1080 与 W1082 两轮试点都改了 `site/en/global-pattern.html` 的 `renderTimeline` 两行颜色（分别用 `var(--chart-1)` 与「求值后的实际色值」），两轮都观测到同一症状：**该页可见元素数由 light 532 / dark 533 塌缩到 108 / 109**。W1080 据此判定「`.style()` 形态不能直接换 `var()` 令牌」并回退改动；W1081 给出机理（「`var()` 串进入 SVG 文本量测路径 → D3 量文本宽度取 0 → 避让算法把文本整批隐藏」）；W1082 换「读令牌喂图表」方案仍复现同一症状；W1083 自审发现「改动点在时间轴绘制处、塌缩消失的却是更早的卡片区 ⇒ 两者不同源」，把两批的证伪结论降级为「未证实」，并定案下一批 = 逐段渲染探针。

**本批结论（一句话）**：塌缩与颜色写法**毫无关系**——真因是**改了内联脚本未同步重算 CSP 哈希，导致该页整个内联 `<script>` 块被浏览器拒绝执行**，页面只剩静态 HTML。

证据链（四环相扣，每环均为实测）：

1. **塌缩态 = 页面只剩静态 HTML**：总元素数 586 → **150**，可见元素 532 → **108**（dark 533 → 109），卡片区元素 **8 → 0**，`#timeline` 子元素 **1 → 0**。
2. **不是渲染中断**：d3 顶层 API 抛错 **0** 条，`window.onerror` 与 `unhandledrejection` 与基线同数（唯一 1 条是探针自身在 `t=1` 的采样噪声）；`#pilgrim-grid` 的 `.pilgrim-card` 在 DOM 中**根本不存在**（`cards=0` 且 `cardsVis=0`）⇒ 既非「不可见」，也非「抛错后中断」。
3. **不是颜色写法问题**：console 抓��到唯一一条 CSP 违规 —— `Executing inline script violates the following Content Security Policy directive 'script-src 'self' 'sha256-rJcw5NpTQDIYWj9+…'`；同时 `inlineScriptLen = 36,730` 证明脚本**内容完整存在**于 DOM，只是**被拒执行**（连带 `loadData()` 从未调用 ⇒ console 无 `[INFO] Using embedded data` 一行）。
4. **因果闭环（三组对照，唯一差异是 CSP 是否同步）**：

   | 组 | 改两行颜色 | 同步 CSP 哈希 | light 可见元素 | dark 可见元素 | 卡片区元素 | CSP 违规 |
   |---|---|---|---|---|---|---|
   | A | 否 | — | 532 | 533 | 8 | 0 |
   | B | 是 | **否** | **108** | **109** | **0** | **1** |
   | C | 是 | **是** | **532** | **533** | **8** | **0** |

   B 与 C 的唯一差异 = CSP meta 是否同步 ⇒ 差异随 CSP 同步而消失 ⇒ **因果成立，不是相关**。

**对本仓铁律的复核**：CLAUDE.md 第 4 条与 `scripts/generate_csp.py` 的 docstring 都已写明「改内联脚本必跑 `python scripts/generate_csp.py`（哈希失配 = 整脚本被浏览器拒执行）」；`docs/agent/pitfalls.md` 行 91 与行 100 已两次记录同一坑（行 100 标注「W1073 实证·老坑复现」）。**本批是该坑的第三次复发**——前两次复盘写清了症状，未能阻止第三次复发，原因是「症状描述」不等于「10 分钟内可认出的识别信号」。

**对 v4 迁移程序的影响**（§3.4 详述）：档 1「`.style()` 形态直喂 `var(--chart-N)` 令牌」的可行性判据**从「已证伪」改判为「可行」**——同步 CSP 后元素数与基线**逐值相同**（532 / 533），其余内联色值与基线逐值相同，`tlStyles` 含 `var(--chart-1)` 证明注入生效。

### 3.3 根因结论与三重识别信号

**根因**：本仓以 `<meta http-equiv="Content-Security-Policy" content="script-src 'self' 'sha256-…'">` 逐页锁定内联脚本（`scripts/generate_csp.py` 按脚本块原文算 SHA-256）。改动任一页的内联脚本后若**不重算哈希**，该页内联 `<script>` 块**整体被浏览器拒绝执行**——不是抛错中断，而是整块不跑 ⇒ 页面只剩静态 HTML ⇒ 表现为「DOM 塌缩」。

**三重识别信号**（下一次遇到「改页面后元素数塌缩」，按此顺序查，10 分钟内可结案）：

1. **塌缩落在改动点之前渲染的区块** ⇒ 天然被误读为「改动致因」（本批：改动在时间轴，塌缩在更早的卡片区）。
2. **无任何 runtime error**（`onerror` / `unhandledrejection` / d3 抛错全为 0 或与基线同数）⇒ 被误读为「静默的可见性变化」。
3. **元素从 DOM 消失**（不是变不可见）⇒ 被误读为「渲染中断」。

**量化判据**：可见元素数塌到「只剩静态 HTML 的量级」（本批 108/532 ≈ **20%**）。

**取证第一步**：读 console 有无 `Executing inline script violates the following Content Security Policy` —— 本仓 `generate_csp.py --check` 即为漂移守卫（门禁已挂），但**试点批在跑门禁之前就下了结论**，这是流程缺口（§4.2）。

## 4. 复盘

### 4.1 做对了什么

1. **坚持「先取证据再下结论」**：W1083 定案「逐段渲染探针」后，本批没有直接改页面去「试一个修法」，而是先造能区分三种塌缩形态的探针 ⇒ 一次性排除了「不可见」「抛错中断」「数据未加载」三个假设。
2. **把「排查动作」升级为「受控自变量」**：把 CSP 同步做成探针的对照组变体（`var` vs `var_csp`）⇒ 结论从「相关」升到「因果」，且可被第三方按附录 A 复算。
3. **自造假象被当场识破**：首轮的「塌缩」一度可以写成「var() 致因」的第二个证据，但因 base 态读数与现役 J2 基线逐值相同、且 `tlStyles` 为空，才反查到传输层 ⇒ **探针自己也必须被判据复核**。
4. **结论订正做到逐条留痕**：前序四批的「成立/作废/降级」全部写明依据，不做静默覆盖。

### 4.2 该改什么

1. **流程缺口（本批最重要的发现）**：本仓已有铁律（CLAUDE.md 第 4 条）、已有脚本（`generate_csp.py`）、已有门禁（`--check`）、已有坑表条目（行 91 / 行 100），**四道防线全在，却仍被踩第三次**。原因不是「不知道」，而是「**判据不在施工动作的必经路径上**」——试点批改了页面后没有立即跑 `generate_csp.py`，而门禁是**提交前**才跑；两次试点都因为「塌缩」在提交前就下了结论。⇒ **改法**：把「改内联脚本 ⇒ 立即 `generate_csp.py` ⇒ `--check` 零漂移」写成**施工动作的前置步骤**（而非提交前的收尾步骤），并在探针/验收清单里加一条硬问句：「本批是否改过内联脚本？CSP 哈希是否已重算？」
2. **坑表条目的形态要改**：行 91 与行 100 写的是「现象 + 修法」，缺「**怎么在 10 分钟内认出它**」⇒ 本批补的「三重识别信号 + 量化判据（塌到静态 HTML 的量级）」才是可直接使用的形态。⇒ 后续坑表条目一律带识别信号与量化判据。
3. **判据须能区分同源与异源**：J2 现役只记元素数与可见性，本批被迫新造「元素存在数 vs 可见数」二分 ⇒ 建议把这两个读数并入 J2 现役口径，避免下一批再从零造。

### 4.3 交接口径（下一批 = W1086 档 1 施工）

1. **开工前置**：① 统一 `.style()` 色字面量口径（347 处/83 页 vs 28 处，§3.4）并写明取哪一版；② 先把「改内联脚本 ⇒ 重算 CSP ⇒ `--check` 零漂移」设为施工动作的必经步骤。

### A.2 判据口径

| 口径 | 定义 |
|---|---|
| 可见元素 | `display`/`visibility` 非 none 且 `getBoundingClientRect()` 宽高非全零（与 `scripts/visual_regression_probe.py` 的 J2 判据同源） |
| 元素存在数 | `document.querySelectorAll(sel).length`（不施加可见性过滤）⇒ 与可见数二分后即区分「渲染中断」与「可见性变化」 |
| 塌缩量级判据 | 可见元素数塌至基线的 20% 量级 ⇒ 指向「只剩静态 HTML」而非局部渲染问题 |
| CSP 违规读数 | console 消息中含 `Content Security Policy` 的条数 |
| `.style()` 色字面量面 | 正则 `\.style\([^)]*['"]#[0-9a-fA-F]{3,8}['"]`（W1084 口径，与 W1079 的 28 处口径并存待统一） |
