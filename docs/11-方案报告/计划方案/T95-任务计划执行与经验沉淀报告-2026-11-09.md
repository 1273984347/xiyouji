## 执行摘要

**一句话结论**：前批（W1194）对 Scorecard 安装命令面的修法方向错误——它要求「钉 hash」而非「钉版本」，前批钉的 7 处精确版本因此一条告警都未消解；本批读 Scorecard 判定源码（`checks/raw/shell_download_validate.go`）确证真实要求，把仓内全部 13 处 pip 安装点改为 `--require-hashes` + 新建的哈希化依赖清单（51 项完整闭包），全部 4 处 npm 安装点改为 `npm ci`（走 lockfile），并把仓内守卫 `scripts/check_install_pins.py` 从「钉版本」判据改为与 Scorecard 源码同源的判据（自证 14/14 通过）。

**核心判定（三条）**：

1. **前批的方向性错误已被合并后重跑实测证伪** —— 合并 PR #151 后手动 dispatch Scorecard（run `42736414215`），Code scanning open 由 20 降至 16，但**减少的是 Dockerfile digest 与 TokenPermissions 两条线的告警，安装命令面的 13 条 `PinnedDependenciesID` 一条未消**。这直接证明「钉精确版本」对 Scorecard 的该项判据无效。
2. **Scorecard 的 pip 面要求「钉 hash」，且 hash 必须在 requirements 文件里** —— 源码 `isUnpinnedPipInstall`：命令含 `--require-hashes` 即 pinned（直接 `return false`）；含其他参数即 unpinned。其中 `--hash=` 是 flag、被 `isFlag` 跳过 ⇒ 单包 `--hash=` 形式**不起作用**；而 `pip install pkg==1.2.3 --hash=...` 在命令行上被 pip 直接拒绝（`Invalid requirement`）⇒ 唯一可行形态是 `--require-hashes -r <哈希化清单>`。
3. **Scorecard 的 npm 面只认 `npm ci`** —— 源码 `isNpmUnpinnedDownload`：命令含 `ci` 即 pinned（走 lockfile，`ci` 会校验 lock 内的 integrity hash）；`npm install pkg@版本` 一律 unpinned。前批钉的 `playwright@1.63.0` / `@lhci/cli@0.13.0` 均属后者。

**本批产出**：① 新建 `scripts/requirements-hashed.txt`（51 项完整闭包：直接依赖 9 + 测试传递依赖 8 + CI 工具包与其传递依赖 34；每项列出该版本全部发布文件的 sha256）；② 全部 13 处 pip 安装点改为 `pip install --require-hashes -r scripts/requirements-hashed.txt`；③ 全部 4 处 npm 安装点改为 `npm ci`（3 处 `npm ci --prefix scripts` + 1 处 `npm ci --prefix scripts/lighthouse`）；④ 新建 `scripts/lighthouse/{package.json,package-lock.json}`（lhci 独立锁，348 包）；⑤ 删除 black 冗余安装（自 W400 起从未被执行）；⑥ 守卫 `scripts/check_install_pins.py` 判据改为与 Scorecard 源码同源，自证升级为 14 例；⑦ 坑表 E-215 入表与计数链同步。

**本章结论**：Scorecard 安装命令面的 13 条告警的真因已被定位到判定口径层并全面真修；判据与告警口径同源，防复发能力入库。

**待确认事项**：本批改动的 13 处 pip 安装与 4 处 npm 安装需由 CI runner 实跑验证（runner 为 Linux + Python 3.12，哈希清单已按全平台发布文件采集，含 Linux wheel）；合并后需再次 dispatch Scorecard 复查该面告警是否消解。
