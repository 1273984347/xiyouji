## 0. 任务背景（读者无需回看会话即可理解）

2026-10-20 用户在本仓提出「推荐适合我的工具/技能」。首轮回答给出的是**通用清单**（T0 缺口 + 技能匹配表），用户当场纠正：**本项目是西游记，工具推荐应当贴合项目自身的体系，而不是通用清单**。第二轮用户又纠正了过程产物的落位：仓内已有 `tmpe/` 临时区契约（`tmpe/README.md` 自称「唯一权威约定」·`tmpe/policy.yml` 自称「规则唯一权威源」），过程产物不得在仓库根另建临时区。

两轮纠正共同定义了本计划的任务边界：**推荐面必须以本项目自有的隐喻与体系为组织轴；过程产物一律进 `tmpe/` 桶。**

本计划把「取经编制表」从一次会话答复升级为**仓内可复用的项目级编制文档**，并给出三个空缺编制位的补全方案与验收标准。

### 0.3 本批针对的真问题

**问题陈述**：本仓的「方法论沉淀」已足够厚（`docs/agent/pitfalls.md`、`docs/agent/gates.md`、`docs/10-方法论沉淀/`），但**没有一件「项目自有隐喻下的工具编制表」**——新人接手时看到的是通用 Agent 工具目录，而不是「这个项目里，验证由谁做、施工由谁做、收官由谁做、号牌由谁管」。

**为什么本批值得做**：编制表一旦入库，就把「角色 → 职责 → 挂载载体」的映射从**人脑里的默契**变成**可检索、可评审、可复现的文档**，并顺带暴露三个至今无人认领的编制位。三个补全动作合计 **2 条命令 + 2 次创建**，成本低于一次方案审查。

## 5.8 决策记录与理由

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | 用「取经编制」而非通用清单组织本批 | 用户明确要求「贴合本项目」「按照西游记里面的角色人物」；且西游记隐喻与仓内既有体系一一对应（施工 / 宪法 / 审查 / 收官 / 号段 / 传令 / 工具 / 仲裁 / 框架 / 授业 / 取证 / 只验证 / 假收敛） |
| D-02 | 编制表落 **md + HTML 双件** | md 是检索与索引面（README 登记 + 门禁可查 + 可 diff），HTML 是视觉面（857 页站点的既有惯例：`docs/11-方案报告/v4-design-language-preview.html`） |
| D-03 | 仓外三动作与仓内落库**分离** | 仓外动作不占 W 号、不触 touches，但**必须在文档附录 A 留实测证据**——否则就是「声明≠落地」 |
| D-04 | 批号取 W831，**不抢 W827** | W827 已被站内阅读入口打通施工批预留；抢号会断号段链（W822→…→W831 必须连续） |
| D-05 | HTML 预览页**不加 `@font-face`** | 保持零相对路径依赖：落 `docs/11-方案报告/` 与留 `tmpe/_shot/` 两处均可 `file://` 直开；字体走系统栈（`Noto Serif SC` → `Source Han Serif SC` → `Songti SC` → `SimSun`） |
| D-06 | 编制表落**只读文档面**，不改任何现役页面 | 857 页站点的 `file://` 与零外域依赖是硬铁律，编制表不构成改页理由 |
| D-07 | 15 个角色中 2 个是**反面角色**（六耳猕猴 = 假收敛 / 牛魔王 = 失控面） | 反面角色对应项目里真实存在的失效模式，只写正面角色会丢掉最有价值的对照 |
| D-08 | 仓外动作 B（Agent + Skill）**默认不执行**，等用户逐项批准 | 建 Agent 会写 `~/.minimax/agents/`、建 Skill 会写 `~/.minimax/skills/`，均属用户环境改动 |
| D-09 | **并行避让优先于「自己把门禁刷绿」** | 共享工作区的第一性约束是「不互相覆盖」：`stats.json` 的计数漂移是**收敛性问题**（谁刷新都得到 39），而并发写同一文件是**破坏性问题**。故待刷项点名交底，不自行代劳 |
| D-10 | 编制表文档**不使用** `<!--stats:*-->` 标记 | `docs/11-方案报告/` 根层 md 属 C5b 扩展面，标记值须与 `stats.json` 实时一致；本文件是编制说明，其内容与报告篇数无关，用「实测快照 + 复现命令」代替实体标记，并在文内写明「改动者请勿擅自添加标记」 |
