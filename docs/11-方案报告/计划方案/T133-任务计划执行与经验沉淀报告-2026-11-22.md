## 六、经验沉淀

- **「数字对不上」先查清是哪套口径**：本批开局我以为「stats 少算 1」，实测发现 stats 的口径是**数行**（含该条）⇒ **上一批的判断本身是错的** ⇒ 真相是「本体 E 号集合（按形态识别）」与「条目行（按行首识别）」两套身份口径不一致。**口径不同的两个数字对不上时，先确认每个数字量的是不是同一件事。**
- **临时扩展要留退路**：W1299 为隔离连锁面而立的私有扩展正则，W1300 公共口径修好后**必须退役** ⇒ 否则「两份正则」会成为下一次漂移源（单一事实源原则的延伸：临时分叉要写明退役条件）。
- **改判据口径时先算清楚哪个数字会动**：本次连锁面比预想小（stats 取数面是引用不复制 + AGENTS 用实体化标记）⇒ **连载体是「同一实现引用」还是「各自实现」决定了连锁面大小** ⇒ 引用式 ⇒ 改一处即全体跟随；各自实现 ⇒ 逐面手改。
- **测试函数名可能是 API**：仓内 api_diff 判据把 tests/ 下 test 函数也当公开 API ⇒ 改判据时**只改断言、不改函数名**（名实不符以 docstring 说明）。
