## 执行摘要

本批把「7 天没做复盘」从一个问答变成**一篇数字全部机器可复算的复盘交付物**，并在过程中修掉了阻塞本批开工的真问题。

**做了什么**：① 新建取证脚本 `scripts/_w954_review_evidence.py`，把 CHANGELOG 现役面 + 归档面 + 对账表 + git 提交图四源合取，产出区间事实与**五类登记漂移**分类；② 据机器输出起草第 43 篇复盘（149 段 / 154 行 / 354 提交 / 12 组主题分组 / 8 条核心发现）；③ 按 git 事实回写台账 8 行并登记 W954 认领行，使 preflight 从 **8 条 FAIL 恢复到 EXIT=0**；④ 产出 T27 执行前计划与本件。

**最大发现**：**登记面（台账 / CHANGELOG 段状态字段）不是事实源**——CHANGELOG 段状态字段滞后 **91 批**、台账滞后 **7 批**。这不是文字瑕疵：它让 preflight 的 touches 交集拒绝**恒红**，把并发保护机制架空成本批开工的真实阻塞。根因是收官回填全程靠人工手写，没有机器回填与校验。

**次级发现**：① 只读现役 CHANGELOG 会漏 8 个批次（W795–W802 已归档）；② 段状态存在串行错位（W941 段的状态写的是「认领登记 W940」）；③ 素材线判据机器覆盖良好但「题材/形制」只能人眼，本期重出率 6/12；④ 用户二次追问（W947/W949）是有效的第四道门，但成本是两轮返工。

**沉淀**：本批框架内 **E-01~E-06** 六条经验（对应主报告全局编号 E-25~E-31）；主报告登记 **FAM-40~42** 三问题族、**WF-08/09** 两条工作流、**P-43-01~05** 五项改进项。
