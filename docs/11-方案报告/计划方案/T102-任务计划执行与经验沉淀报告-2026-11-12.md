## 执行摘要

W1212 把第 45 槽的失败明细并入汇总行后，PR #171 的新一轮 CI（head=fc2c3b9df）给出了本批的全部输入：
Delivery Gate 仍是唯一红项，**第 45 槽「目录文档新鲜度：6 FAIL / 214 目录」**，而这次日志里**首次看得见是哪 6 个目录**——
assets/promo、assets/promo/hero-set、assets/promo/hero-set/raw、assets/promo/hero-set/raw/round-w1005、
assets/promo/output、assets/promo/plate-set，判据一律是 **C2「INDEX.md 结构不合生成器模板（疑手改/旧版/截断）」**。

定位结果是一个**双因叠加**的链，每个环都有可复跑证据：

- **配置层**：W1209 做 LFS 迁移时，migrate 自动追加的排除行「**/*.md !text -filter -merge -diff」被同批**整行删除**
  （当时的理由是：!text 会压制 W993 立的 LF 规范化、-diff 会让 md 被当二进制）⇒ **排除语义连同 filter/merge 一起消失**，
  只剩「assets/promo/** filter=lfs」这一条 ⇒ 此后凡被 git add 的文本文件都走 LFS clean filter ⇒ 落成 LFS 指针。
  实测 8 个 md + 2 个 html 在 LFS 里。两版 commit 对拍坐实时序：改写后的 W1096 commit 里 assets/promo 下 12 个 md
  **全是普通文本**（说明迁移当时的排除确实生效），到 W1209 commit 时其中 8 个变成指针 ⇒ 落成发生在「排除行被删之后」。
- **机制层**：CI 的 actions/checkout **默认不拉 LFS 真身** ⇒ 工作树是指针文本 ⇒ 第 45 槽 parse_index() 返回 None ⇒ C2 判红。
  **本地恒绿**是因为 git lfs checkout 已把工作树恢复成真身——读磁盘永远读不到指针，这就是「本地绿 / CI 红」的分歧点。

修法遵循「改根因不改表象」：.gitattributes **逐项改写**恢复排除语义（-filter -merge diff text eol=lf），
而不是整行删除或整行照抄（前者重犯 W1209 的两个副作用，后者补回 !text/-diff）；
随后把 10 个已被托管的文本文件**重新入库为普通 blob**（git rm --cached + git add，**不做历史改写**）。
端到端反证双向成立：注入指针文本 ⇒ 第 45 槽实测 6 FAIL 且 6 个目录名与 CI 日志**逐字一致**；还原 ⇒ 0 FAIL。

教训转机器判据：新建 scripts/check_lfs_text_purity.py，采用**索引 blob 口径**（索引 = 将要入库的内容 = CI 干净检出的内容；
读工作树本地恒读真身 ⇒ 判据恒绿 ⇒ 只能等 CI 报红），接进第 45 槽 **C5 子项**（Delivery Gate 必跑 ⇒ 拦合并）与 ci_sim GATES（第 14 项），
并补 7 例单测（含「真仓 0 命中」回归锁）。此外修掉一处自伤：判据初版逐个起 git cat-file 子进程，
把第 45 槽从 0.9 s 拖到 **32.6 s** ⇒ 改批量（一次 --batch-check 取体量筛小件 + 一次 --batch 取内容）⇒ 实测 **885 ms**。

### 2.2 取证：6 个目录 ⇒ 6 个 LFS 指针

| 取证动作 | 读数 |
|:---|:---|
| git ls-files 全仓 INDEX.md 计数 | 139 个 |
| git lfs ls-files 中 md/html 计数 | 10 个（8 md + 2 html），路径全在 assets/promo/ 下 |
| git cat-file -p HEAD:assets/promo/INDEX.md | 首行 version https://git-lfs.github.com/spec/v1（size 809）⇒ **指针** |
| git check-attr 探针（临时追加 5 条 pattern 后还原） | 证明 gitattributes 的 ** 不跨层陷阱不成立（**/*.md 实测匹配 3 段路径）⇒ 排除规则失效**另有原因** |

**一一对应关系成立**：6 个失败目录 = LFS 内 6 个 INDEX.md 所在目录；其余 133 个 INDEX.md 均在普通存储。

### 2.3 根因定位：两版 commit 对拍坐实时序

对同一路径在两个 commit 上取 blob 首行：

| 路径 | W1096（改写后 commit 81d47fb81） | W1209（commit dfff13ecf） |
|:---|:---|:---|
| assets/promo/INDEX.md | TEXT（# 文件索引 · promo） | **POINTER** |
| assets/promo/hero-set/INDEX.md | TEXT | **POINTER** |
| assets/promo/hero-set/raw/INDEX.md | TEXT | **POINTER** |
| assets/promo/hero-set/raw/round-w1005/INDEX.md | TEXT | **POINTER** |
| assets/promo/output/INDEX.md | TEXT | **POINTER** |
| assets/promo/plate-set/INDEX.md | TEXT | **POINTER** |

结论：迁移当时的排除（**/*.md）**是生效的**（12 个 md 在 W1096 仍是普通文本）；变指针发生在 W1209——
该批删掉了 migrate 自动追加的排除行（连 filter/merge 一起），此后**凡被 git add 的文本文件都走 LFS clean filter**。
W1096 时 html 已是指针 ⇒ html 从未被 exclude 覆盖（排除只针对 *.md）。

### 2.4 根修：排除语义逐项改写 + 10 件重新入库

.gitattributes 末尾（W1209 原注释位置）改写为：

    *.md -filter -merge diff text eol=lf
    assets/promo/**/*.html -filter -merge diff text eol=lf

四个属性各司其职且**不重犯 W1209 的两个副作用**：-filter 清除 LFS clean/smudge（不再落成指针）、-merge 清除 merge=lfs、
**diff 覆盖 diff=lfs**（保留文本 diff——审计与改写面判据依赖它，而 -diff 会把 md 当二进制）、
**text eol=lf** 强制 LF（承接 W993 的行尾定形，替代被删掉的 !text）。
范围选择：md 全仓（文本本就不该进 LFS，且全仓仅一条 LFS 规则 ⇒ 全局排除零副作用）；html 仅 assets/promo（site 产物量大，本批不动）。

随后对 10 个被托管的文本文件执行 git rm --cached + git add（工作树内容保留，属性已 unset ⇒ 存普通 blob）。
落地读数：git check-attr 十个路径全部 filter: unset / merge: unset / diff: set / text: set / eol: lf；
索引内十个 blob 全部为 TEXT、指针 0；git lfs ls-files 中 md/html 残留在提交前仍为 10（该命令读 HEAD，提交后复核）。

### 2.6 防复发机器判据

新建 scripts/check_lfs_text_purity.py：
- **口径**：索引 blob（git ls-files -s 取 oid → cat-file 取内容），不用工作树文件；
- **圈定**：文本扩展名白名单（md/html/json/yaml/py/js/css/sh/xml/svg/sql 等 40 余项），二进制媒体（png/jpg/webp/pdf/zip）不在范围（留在 LFS 是正确用法）；
- **判定**：blob 体量 ≤ 512 B 且首行为 git-lfs 签名 ⇒ 判红；git 不可用 ⇒ fail-closed（exit 2，不 fail-open）；
- **挂载**：第 45 槽 C5 子项（目录文档层·Delivery Gate 必跑⇒拦合并）+ scripts/ci_sim.py GATES 第 14 项（全仓层·CI Sim job 必跑）；
- **性能**：初版逐个起 cat-file 子进程 ⇒ 第 45 槽 32.6 s ⇒ 改批量（--batch-check 取体量筛小件 + --batch 取内容）⇒ **885 ms**；
- **单测**：tests/unit/test_lfs_text_purity.py 6 例（指针识别正负 / 扩展名圈定 / 合成 git 仓命中 / **真仓 0 命中回归锁** / 汇总行形态）。

## 四、复盘

**做对的三件事**
1. **先补「看得见」再追根因**：W1212 把失败明细并入汇总行，本批一次 CI 就拿到 6 个目录名，省掉一轮 CI（一次 push ≈ 25 job）。
2. **归因靠对拍而不是推理**：用两版 commit 的同路径 blob 首行对比，把「迁移时排除失效」与「删除排除行后落成」两种假设分开，一击坐实时序。
3. **修法避开了前批的坑**：排除行不是照抄 migrate 的原文（会带回 !text/-diff 两个副作用），而是逐项改写并说明每个属性的职责。

1. **性能自伤**：判据初版逐个起子进程，把第 45 槽拖到 32.6 s——写判据时没有先问「批量读 blob 有没有一次性接口」。

## 五、经验沉淀

本批教训已入坑表 **E-228**（与 E-227「CI 侧零执行证据」同族的「观察面错位」族），要点：

1. **排除规则被「整行删除」时，排除语义会一起消失**——排除语义的载体是 -filter/-merge，删整行连载体一起没；
   正解是**逐项改写**（-filter -merge diff text eol=lf），既保住排除又不重犯 !text/-diff 两个副作用。
2. **判据必须读「索引 blob」而非工作树文件**——读工作树本地恒读真身 ⇒ 判据恒绿 ⇒ 只能等 CI 报红；
   索引 blob = 将要入库的内容 = CI 干净检出的内容 ⇒ 本地即可提前发现。
3. **批量读 blob 必须一次 --batch**——逐个起 cat-file 子进程把第 45 槽从 0.9 s 拖到 32.6 s。
4. **排查「本地绿 / CI 红」先问「CI 侧拿到的内容与本地是否同形」**——checkout 参数（拉不拉 LFS）与工作树状态是两个独立变量。

### 决策记录与理由

| 决策 | 理由 | 被否方案 |
|:---|:---|:---|
| 恢复排除语义用「-filter -merge diff text eol=lf」逐项改写 | 排除语义的载体是 -filter/-merge，整行照抄 migrate 原文会带回 !text（压制 LF 规范化）与 -diff（md 被当二进制）两个副作用 | ① 照抄 migrate 自动追加行——重犯 W1209 的两个副作用；② 只加 -filter 不管 text/diff——LF 规范化与文本 diff 会退化 |
| 判据读索引 blob 而非工作树文件 | 索引 = 将要入库的内容 = CI 干净检出的内容；读工作树本地恒读真身 ⇒ 判据恒绿 ⇒ 只能等 CI 报红 | 读工作树文件——本地永远绿，防复发目标落空 |
| 落点在第 45 槽 C5 + ci_sim，不新增 verify_delivery 槽位 | C5 随第 45 槽在 Delivery Gate 必跑 ⇒ 能拦合并；新增槽位须改管控脚本（规则 10 须用户批准） | 直接挂第 72 槽——越过审批红线 |
| 重新入库用 git rm --cached + git add，不做历史改写 | 向前修复只需改当前提交形态；历史改写不可逆且使全部 commit hash 变化 | git lfs migrate export——不可逆·超出本批授权 |
| 本批不动二进制媒体与 CI workflow | 二进制媒体留在 LFS 是正确用法；CI 拉 LFS 会拉 332 个对象（GitHub 免费 LFS 月带宽 1 GiB）极易爆额度 | 给 actions/checkout 加 lfs: true——引入新的 CI 慢因与额度风险 |
| 先补「看得见」再追根因（W1212 → W1214 两批制） | 一次 push ≈ 25 个 job；本批一次 CI 即拿到 6 个目录名 | 盲改配置试探——多轮 CI 成本高且无证据 |
