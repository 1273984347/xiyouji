### 1.2 目标与完成标准

#### 1.2.1 任务目标

把「写盘出错 ⇒ 语法错 ⇒ 坏件进提交」这类事故从「靠 CI 才发现」前移到「收官链当场拦停」，且不降低任何既有判据强度。

#### 1.2.2 不完成定义

① 只在提交前手动跑一次 py_compile 而不入链；② 门禁只查已暂存件而漏掉「改了就忘 add」的件；③ 用「打印警告后继续」代替中止；④ 触碰并行会话的共享面（坑表计数链 / batch_closeout 的 rebuild 步语义 / 级联面）。

#### 1.2.3 范围与边界

**做什么**：收官链新增 pycompile 步；三态清单收集本批改动的 .py；逐件 compile 并 fail-closed；顺序锁同步与新增单测；报告与 README 登记；落段与收官链。

**不做什么**：不新增坑表条目（本批教训暂写报告 §5，**计数链不动**，避与并行会话 W1125 未合并批对撞）；不改既有步的语义与判据强度；不碰级联面与页脚面；不做存量 .py 的全仓语法体检（只查本批改动面）。

**输入**：2026-11-04 早前的 8 文件语法错事故现场；收官链现状（已含 archive / rebuild / precheck / selfref / add / content_stage / docnums / regsurface / csp / cspcheck）；既有顺序锁单测（test_w1102 的行为锁、test_w1114 的版本面位置锁）。

### 4.1 做对了什么

1. **先做负样本再交付**：门禁类改动的价值全在「它会不会红」⇒ 造一个真坏件跑一遍，而不是只看单测绿。
2. **检查集合按三态并集**：把「改了就忘 add」这一事故形态直接纳入覆盖范围，而不是只查索引。
3. **只编译不落盘**：避免门禁自身污染工作树（不留 __pycache__ 残留进提交）。
4. **让号不拖延**：发现 W1127 被占即刻顺延，并用剩余预算把本批做完整，而不是僵持。

### 4.2 待改什么

1. **本批教训待入坑表**：「批量写 .py 的语法错此前无机器门禁 ⇒ 收官链 pycompile 前置门禁」应入坑表（拟 E-172 起），但需等并行会话 W1125 合并、计数链基线稳定后入，避免对撞。
2. **覆盖面仍有限**：本门禁只查**本批改动**的 .py；全仓存量 .py 的语法体检未做（可用一次性巡检脚本，不入收官链）。
3. **门禁只能拦语法错**：写盘事故的其它形态（截断、空文件、编码错）不在 compile 的判据内 ⇒ 若要覆盖需另加体量与编码判据。
4. **未处理项（跨批）**：正本与归档并存的存量 W1001 段已由并行会话 W1125 代办（用户已批准）；档 3 消费方式全量施工待其原型合并与口径重建后另批。
