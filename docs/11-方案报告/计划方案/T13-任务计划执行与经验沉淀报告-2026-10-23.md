## 一、执行摘要

**问题**：GitHub 仓库主页展示的不是项目门面，而是 `.github/` 目录导读。访客打开 `https://github.com/1273984347/xiyouji` 看到的是「.github 目录装什么 / 子目录 / 维护约定」——**根 README.md（在线体验 / 桌面版下载 / 615 篇解读 / 87 可视化页 / 普通读者专区）从未上过主页**。

**根因（两层）**：

1. **载体层**：GitHub 仓库主页的 README 查找优先级是 **`.github/` > 根目录 > `docs/`**。`scripts/gen_folder_docs.py:77-80` 的排除规则「排除全部点开头顶层目录」**唯独给 `.github` 开了例外**（注释理由只考虑了 `workflows/README.md` 是 batch_cascade 级联面），W779 批遂生成 `.github/README.md` → 抢占展示位。
2. **时间层**：Pages 部署源 = `main` 分支的 `site/` 目录（`.github/workflows/pages.yml:7`），而 `origin/main` 停在 **W794**、`origin/dev` 停在 W811、本地 dev 已到 **W888** → 展示层内容落后开发进度 **94 个批次**。

**本批动作（用户拍板三项）**：

- **① 载体复位**：`.github/README.md` → `.github/README-internal.md`（转人工维护件）；生成器加**精确单文件排除**；门禁 45 同源豁免；新增**防回归门禁**。
- **② 首屏重排**：根 README 首屏改为「项目定位 → 在线体验 → 下载 → 目录导航」+ 增补「30 秒上手」速览块；抬头四行（阅读契约 / 当前批次 / 版本号说明 / 维护契约）降噪入开发者专区。
- **③ 时间对齐**：推 dev → PR 合 `main` → Pages 重建；并补齐仓库元数据（topics / contactLinks / description / 社交预览卡）。

**不做**：根 README 内部术语行的「对外降噪改写」（本批只搬位置不改文案，desc 文本由 batch_cascade 每批自动写入，改文案须动 spec 契约）；桌面版签名与公证；仓库转公开以外的组织级治理项。

## 四、决策记录与理由

### D-1 `.github/README.md` 处置：改名 `README-internal.md`（用户拍板）

**备选**：① 删除并入 `index.md` ② 改名 `README-internal.md` ③ 改名 `github-README.md`。
**理由**：用户选 ②。② 保留独立人读导读（`.github/` 的用途约定），且 `README-internal` 语义直白；GitHub 社区通行解法（讨论 #163997 中 `alexeygnetko` 改为 `.github/README-internal.md`、`B-ki` 改为 `.github/github-README.md`）。
**代价**：文件树里多一个非标准名文件。**接受**——换取改动面最小（不需改写导读正文）。

### D-2 修生成器：精确单文件排除，而非整树排除

**理由**：整树排除会让 `.github/workflows/` 下的 `index.md` 停止刷新（目录清单与实况脱节），且 `workflows/README.md` 是 batch_cascade 的级联面（另一个脚本管），误碰会打架。**只排除 `.github/README.md` 这一个目标路径**——目录仍在生成范围，`.github/index.md` 继续刷新，级联面不受影响。
**同源要求**：排除清单定义在 `gen_folder_docs.py`（门禁 45 已 `import gen`），门禁侧**引用同一常量**而非复制一份，避免两处口径漂移。

### D-3 新增防回归门禁的判定口径

**备选**：① 根 README 在位时，`.github/README.md` 与 `docs/README.md` 必须都不存在 ② 只断言 `.github/README.md` 不存在 ③ 不加门禁。
**决定**：②。
**理由**：① 会让本仓**立刻 FAIL**（`docs/README.md` 现存且由 W779 生成器产出），而本批用户拍板范围只含 `.github/`；③ 违背「同一类坑要有防回归断言」原则。② 精准对应本批所修的坑，`docs/README.md` 的隐患以 NOTE 形式记录（根 README 在位时它不抢位；根 README 若消失则会上位）。

### D-4 首屏版本行：整行搬运，不改文案

**理由**：`batch_cascade` 每批自动重写该行的 desc 段（写入工程术语是**批次的既定契约**，改文案须动 spec 契约与三处锚点，属另一批的范围）。本批只解决「该行出现在哪儿」，不解决「该行写什么」——后者在首屏重排后自然降为次要问题（首屏已无内部术语行）。

### D-5 推远端时机：本批末一次推 + PR 合 main

**理由**：用户拍板。`origin/main` 独有 5 个提交均为 merge commit（dev 已含其全部内容）→ 预期零冲突。Pages 部署源是 `main` 分支 `site/` 目录 → 只有合进 main，读者才看到新站点。
