## 0. 背景与结论速览

**本批针对**：W1109 批的 CI 连续三次红项（第 45 槽 ×2 + CSP 漂移 ×1），三次都不是「内容错」，而是**生成链内部的隐藏耦合**：
- ① 生成器**按 Git 索引**收集 ⇒ 新增件必须**先 add 再 refresh**，否则漏件；
- ② **refresh 自身产出的新清单件又让索引变化** ⇒ **一轮不收敛**；
- ③ docs_index / 搜索索引生成会**改写搜索页内联脚本** ⇒ CSP 哈希失配 ⇒ **CSP 重算必须置于生成链最后一步**。

**本批产出**：把这套顺序从「靠人记的纪律」变成**脚本内建行为**，并让每一步都自带**判据 + 自证**：
1. **scripts/batch_closeout.py** —— 落段收官一键脚本，八步固定顺序：precheck → selfref → add → refresh(迭代至收敛) → 索引 → stats → csp → cspcheck；
2. **precheck 会中止并给修复指引**：台账「正本同号多行」（回窗工具的中止条件）与「行数超窗口」⇒ 不通过即停；
3. **selfref 步只引用不复制**：直接调用仓内既有的第 57 槽判据 `scripts/check_css_var_selfref.py`（主会话 W1110 落地）⇒ 全站单一事实源；
4. **7 例单测**锁定顺序与各步行为；**真实仓跑通取证**（见 §3.2）。

## 4. 复盘

### 4.1 做对了什么

1. **从红项倒推机制**：不把三次红当三个 bug，而是识别出同一个「顺序耦合」⇒ 一次工具化覆盖全部。
2. **只引用不复制**：selfref 步复用第 57 槽判据 ⇒ 避免两份实现漂移（与主会话抽 doc_areas 共享单一事实源同一手法）。
3. **预检带修复指引**：precheck 不只判红，还给「先跑 archive_ledger_rows --apply 腾窗」这类可执行下一步。

### 4.2 该改什么

1. **补丁脚本须自检 + 自动回滚**（已做）⇒ 应写成双方共用的补丁模板。
2. **单测须注入 lines/added**、不可依赖工作树状态（否则未跟踪文件让判定漂移）。
3. **断言「main 上仍存在 X」须带 ref 与时刻**（本批已犯一次并纠正）。

### 4.3 交接口径

- 后续各批的收官一律走 `python scripts/batch_closeout.py --spec scripts/output/_w<批号>_spec.json`；
- 写报告与 README 登记行**必须在调用脚本之前**（脚本内 add 早于 refresh ⇒ 索引含新件）；
- 判据新增类缺陷（基点/分组/豁免）由主会话 W1110 批统一根治，本批不再触碰该文件。

### A.2 判据口径

- **顺序**：precheck → selfref → add → refresh → index → stats → csp → cspcheck（csp 恒末位）；
- **precheck**：台账「正本同号多行」（回窗工具中止条件）与「行数超窗口」⇒ 不通过即中止并给修复指引；
- **refresh 收敛判据**：两次 refresh 后的索引快照（git ls-files）相同即收敛；
- **selfref**：调用 scripts/check_css_var_selfref.py（--gate）⇒ 只引用不复制；
- **add**：spec.rows + 显式 --paths；**禁 git add -A**。
