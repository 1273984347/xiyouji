## 0. 背景与结论速览

**本批针对**：W1109 批的 CI 连续三次红项（第 45 槽 ×2 + CSP 漂移 ×1），三次都不是「内容错」，而是**生成链内部的隐藏耦合**：
- ① 生成器**按 Git 索引**收集 ⇒ 新增件必须**先 add 再 refresh**，否则漏件；
- ② **refresh 自身产出的新清单件又让索引变化** ⇒ **一轮不收敛**；
- ③ docs_index / 搜索索引生成会**改写搜索页内联脚本** ⇒ CSP 哈希失配 ⇒ **CSP 重算必须置于生成链最后一步**。

**本批产出**：把这套顺序从「靠人记的纪律」变成**脚本内建行为**，并让每一步都自带**判据 + 自证**：
1. **scripts/batch_closeout.py** —— 落段收官一键脚本，八步固定顺序：precheck → selfref → add → refresh(迭代至收敛) → 索引 → stats → csp → cspcheck；
2. **precheck 会中止并给修复指引**：台账「正本同号多行」（回窗工具的中止条件）与「行数超窗口」⇒ 不通过即停；
3. **selfref 步只引用不复制**：直接调用仓内既有的第 57 槽判据 `scripts/check_css_var_selfref.py`（主会话 W1110 落地）⇒ 全站单一事实源；
4. **单测**锁定顺序与各步行为（计划态 7 例·终态 13 例·见 §2.3）；**真实仓跑通取证**（见 §3.2）。

### 2.5 W1114 订正（对 W1112 段「正面案例」的订正）

W1112 批把「precheck 当场拦下『台账正本 61 行超过窗口 60』并给修复指引」记为**正面案例**（§2.1 执行经过与 CHANGELOG W1112 段均有此表述）。W1114 批复核发现：该拦下是**口径缺陷导致的假阳**，并非真实超窗——

- **机理**：precheck 原用 startswith('| W') 逐行计数 ⇒ 台账**表头行**（形如「| W 号 | 批次标题 | …」）同样以「| W」开头 ⇒ 被计入 ⇒ 读数恒比真实**数据行**多 1。
- **唯一事实源**：scripts/archive_ledger_rows.py 的 ROW_RE（数数据行）+ --keep 默认 59（= 窗口 60 − 当批认领 1）⇒ 窗口 60 的真实语义是「**数据行 ≤ 60**」。
- **实测**（2026-11-03 22:2x·origin/main）：台账数据行 60 + 表头 1 = precheck 读数 61 ⇒ 误报超窗并**中止整条收官链** ⇒ 收官一键工具在本仓**恒判超窗、实际不可用**。
- **W1114 修法**：precheck 与同号多行判定改为**复用 archive_ledger_rows.ROW_RE**（单一事实源·不另写正则），并补负样本单测（数据行 60 PASS / 61 FAIL / 表头行不计入）。
- **定位**：W1112 段的**原文不改**（历史段禁改）⇒ 订正以本节留痕；CHANGELOG 侧同样以 W1114 段的留痕行记录。
