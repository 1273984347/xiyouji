## 一、执行摘要

素材做完六十一件之后，站内已入库的水墨素材共 **71 件 / 5.65 MB**，但**页面引用为零**——用户看完这一事实后连续两轮催办（「继续」22:50、23:24），本批执行缺口清单第 6 项：把已验收的素材真正接到站面上。

本批实际落了三件事：

1. **213 页**（site/data 82 页 + site/en 131 页）在 `.hero` 暗色带内挂一张**深底直显版**装饰插画，按页名映射四类母题（network/relationships/social-media → 根须网、heatmap → 墨点阵、radar → 放射线、timeline → 刻痕序列，其余默认墨点阵）；
2. **首页 `site/index.html`** 的浅色 `.masthead` 铺 hero-01 山河云海横幅，标题文字正落在图底部预留的空白带上；
3. 另出 **4 张深底直显版** viz 插画（`viz-dark-01..04`·640×640）供暗带使用——浅底宣纸图贴在暗色带上会成一块亮斑，暗带必须用深底版。

**两条实测结论（本批最有价值的产出，都不是推演出来的）**：

- **实测一**：`file://` 下 CSP 的 `style-src 'self'` 会拦掉外链样式表，页面实际生效的样式**全部来自每页的内联副本**（`inline_css.py` 从 `site/system.css` 注入的那份，每页约 55 KB）。首轮只改源文件 `site/system.css` → 浏览器实拍见装饰图撑成 990 px 方块盖住整页。**规则必须源与内联副本双写**：源保证下次 `inline_css` 重跑时仍被继承，内联副本保证当前即生效。
- **实测二**：深底方图贴在暖褐 hero 上有色差、可见方框 → 按亮度把深底映射为 alpha 渐变（近底色透明、笔触不透明），插画变成**悬浮的米白笔触层**，无方框且不依赖具体底色。

**验收**：浏览器实拍两页（数据页 + 首页）确认装饰插画为 240 px 角饰、落在右下不压标题不压正文，首页文字全部落在图的留白带上可读；全量门禁 54 段实跑首轮 1 FAIL（第 45 槽目录文档新鲜度）→ 执行门禁自带修复动作 `gen_folder_docs.py --refresh` → 复跑 0 FAIL；CSP 856 页 0 漂移。

**留白与缺口**：素材引用缺口实测表显示，71 件素材中本批之后**已接线 8 件、未接线 63 件**，引用总次数 1401。未接线的主体是 card 24 张与 post 6 张（卡片封面与竖版海报尚无消费位），chap 6 张百回母版因回目页由 `build_reader.py` 生成、接线须改生成器并重生成 622 页，本批不做。

**本章结论**：接线批已落库且门禁全绿，两条实测结论可复算，素材缺口已量化为「8 接 63 未接」的可执行清单。
**待确认事项**：① 63 件未接线素材的消费位排期（卡片封面配图 / 竖版海报 / 回目母版）待用户裁决；② `ink-mountains-hero.webp` 实测引用面 332 页与 W879 批记录的 848 页读数不一致，差额集中于 reader 子目录，原因未取实证，登记为待验证项。

## 四、决策记录与理由

本节汇总 §3.7 的 7 条决策中影响面最大的三条，其余四条（母题映射表维护、报告落盘、版段递延、回目页另批）见 §3.7 对应行。

1. **D-01 规则双写**——这是本批唯一一处「按直觉做会失败」的决策。直觉上改 `site/system.css` 就够了，但实测证明页面在 `file://` 下拿不到外链样式表，浏览器实拍直接见装饰图撑成 990 px 方块盖住整页。代价是接受「同一规则写两遍」的重复成本，收益是不用碰 `build_reader.py` 就能让 213 页立刻生效。**重复优于失效**。
2. **D-02 + D-03 暗底图的两步处理**——第一步选对底（深底直显版而非浅底合成），第二步处理接缝（按亮度映射 alpha 消除方框）。两步缺一不可：只做第一步会得一张发亮的方块，只做第二步则浅底图贴暗带本身就不成立。
3. **D-06 + D-07 共享面避让**——并行 W883 批正在推进 CHANGELOG 顶段与 `stats.json`，reader 622 页全量重生成又会触发 `inline_css --force` 回吞事故面；本批把两处都让出去，代价是 CHANGELOG 版段递延与 chap 母版暂挂，收益是零门禁红、零并行冲突。

**本章结论**：三条关键决策的取舍理由已完整留痕。
**待确认事项**：无。

**待确认事项**：A-04 / A-08 对应的接线排期待用户裁决。

## 九、经验沉淀

| 编号 | 经验 | 适用场景与边界 | 量化效果 | 证据来源 | 可迁移性 |
|---|---|---|---|---|---|
| E-01 | **file:// 静态站里 CSS 源不是生效源**：页面样式全部来自每页内联副本（`inline_css.py` 注入·每页约 55 KB），故新规则必须源与内联副本双写 | 适用于本仓全部 857 个页面；边界：不适用于走构建管线的项目；坑已在本批发生一次 | 只改源 → 装饰图撑成 990 px 方块盖住整页；双写 → 角饰 240 px 正常 | 浏览器实拍两轮 + `site/system.css` 与页面内联副本对读 | 高——任何 file:// + CSP `style-src 'self'` 的静态站都适用 |
| E-02 | **暗底装饰图必须用深底直显版，不能用浅底合成**：soft-light 在深底（亮度 0.115）上「源越亮越隐形」，浅底淡墨贴上去等于没贴 | 适用于深色带 / 暗色模式；边界：浅底版适合浅色区（如首页 `.masthead`） | 浅底淡墨合成后亮度跨度仅 0.0080（肉眼不可见）；改深底浓墨后 0.0718–0.0789（×9.0–9.9） | W879 批量测 + 本批实拍对照 | 高——深底配图的可复用判据 |
| E-03 | **深底方图接缝用 alpha 映射消解**：按亮度把近底色映射为透明、笔触映射为不透明，插画变成悬浮笔触层 | 适用于方图贴任意异色底；边界：需底色相对稳定，暗色模式切换时需复核 | 方框可见 → 消除；插画不依赖具体底色 | 本批实拍 + `_w885_viz_alpha.py` | 高 |
| E-04 | **共享工作区里刷新派生索引会吸入他方在途内容**：须逐条比对差异并把「源文件未入库者」的条目按 HEAD 版回退 | 适用于搜索索引 / 目录清单 / 文件索引类生成物；边界：源文件已入库则不回退 | 差异仅他方在途 1 条 → 回退后索引文件与 HEAD 逐字节一致 | `_w885_index_revert.py` + `git diff` 复核 | 高——多 Agent 并行仓库的通用处置 |
| E-05 | **新增文件必触发目录清单门禁**：门禁只给修复命令不自动执行，须显式跑 `gen_folder_docs.py --refresh` | 适用于任何新增文件的批次；边界：人工维护件自动跳过 | 首跑 1 FAIL → refresh 后 0 FAIL | 门禁两轮输出 | 高 |
| E-06 | **批次台账的分项数字要按磁盘实况回填**：spec 与台账写的分项（87+126）与实况（82+131）不符，总数却一致——只对总数会漏掉口径错 | 适用于任何批次的统计回填；边界：数字须能按文件级复算 | 差 5 页分布偏移·总数不变 | ASM-09 实测 | 高——「总数对不等于分项对」是易漏项 |
| E-07 | **素材做完不等于用上**：71 件 / 5.65 MB 素材可长期零页面引用；「产出—接线」应是同一条流水线的两段 | 适用于素材生产流程；边界：不适用于本就无需上线的实验件 | 接线前引用 0 → 本批后 8 件上线 / 引用 1401 次 | 缺口量测脚本两轮 | 高——本项目最可复用的流程纪律 |

**本章结论**：7 条经验全部带量化效果与证据来源，其中 E-01（CSS 源不是生效源）为跨项目通用性最高的一条。
**待确认事项**：E-02 与 E-03 的深底判据是否固化为仓内常驻检查（可考虑并入第 49 槽的同类门禁族），待用户裁决。
