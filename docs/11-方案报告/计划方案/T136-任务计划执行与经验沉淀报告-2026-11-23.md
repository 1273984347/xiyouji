### 风险与偏差

1. **偏差（已修）**：初判 `ledger_backfill.py --w W1306` 报错时误以为是工具缺陷 ⇒ 实为**参数格式**（要整数 `1306` 而非 `W1306`）⇒ 按工具 help 改正。

3. **风险（已处置）**：改**已入库**的历史批 spec（W1304）⇒ 触及 CHANGELOG 历史段 ⇒ 属**订正**而非擅改，已按惯例并入本批并在 §九 声明。
4. **风险（已处置）**：台账正本顶格 60 行 ⇒ 登记 W1307 前先归档已收官 W1243（不迁在途行）。
5. **风险（待观察）**：存量 409 件目录件清理时若生成器对某目录的人工内容处理有例外 ⇒ 会体现在 diff 中 ⇒ 下一批须抽样核对。

### 决策记录

| 决策 | 理由 | 依据 |
|---|---|---|
| 生成器**删日期**而不是改成「运行时动态日期」 | 动态日期会让每次 refresh 都改文件 ⇒ 产生新噪声；删掉日期并指向 git 提交时间 ⇒ **既无伪信息又幂等** | E-01 实测：改后二次 refresh 零 diff |
| L-11/L-12 **单独成批**，不并入本批 | 二者改收官链核心（`_run_backfill_prev_hash` 与链尾结构）⇒ 与「改判据 + 批量刷新」混批会让故障面不可隔离 | 用户口径「回填/订正类永不单独开 PR·但涉核心路径须独立批次」 |
| 回填用 `ledger_backfill.py` 而非手改台账 | 手改 = 无指纹锁 = lost update 风险（该工具的 docstring 明确要求独占回填） | 工具 design（指纹锁 + `--expect` + `--verify`） |
| 5 行他方悬空 hash 维持豁免、不代改 | 台账规则：只改本会话认领的行；且压缩推送的承载 commit 判定需谨慎 | C4-g 的存量豁免基线机制 |
