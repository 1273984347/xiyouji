## 执行摘要

**一句话结论**：前两批对 Scorecard 的核对面窄于告警面——只核了 `uses:` 引用（90 个全钉 40-hex SHA）就判「陈旧投影」，漏掉 Scorecard 同样检查的**安装命令**与**Dockerfile `FROM`** 两类对象；本批把三类对象逐面重核，得出**7 处安装命令未钉版 + 1 处基础镜像未钉 digest + 2 处写权限未最小化**的真实清单并逐项真修，同时把「镜像必须钉 digest」固化成仓内机器判据（`scripts/check_docker_pin.py`，含 5 例负样本自证）并接入 CI。

**核心判定（三条）**：

1. **告警定位行必须回读当前文件内容** —— SARIF 记录的是告警产生时的行号，后续文件改动会让行号漂移（本例多条指向空行）。逐条回读当前行内容后，真实对象与告警规则精确对上：`xiyouji-agent-web/Dockerfile:6` 的 `FROM node:22-alpine`、`screenshot-review.yml` 两处 `npm install playwright @playwright/test`、`ci-sim.yml` 的 `pip install --upgrade pip`。
2. **「核对面窄于告据面」是漏判的通用形态** —— Scorecard 的 Pinned-Dependencies 检查三类对象（action 引用、安装命令、镜像 `FROM`）。此前只核第一类 ⇒ 后两类 8 处真实未钉版项长期不被看见。本批建立三面扫描（`uses:` 91 个引用、安装命令 13 条、`FROM` 1 条）并把后两面收进判据。
3. **写权限要收进真正需要它的 job** —— `release.yml` 顶层 `contents: write` 覆盖了 preflight 与 build 两个不需要写权限的 job；`stale.yml` 的 job 级 `contents: write` 对 `actions/stale` 而言是多余的（它只需 `issues: write` + `pull-requests: write`）。前者改为「顶层 `contents: read` + 发布 job 级提权」，后者直接删除多余项。

**本批产出**：① 7 处安装命令钉精确版本（pip-audit / black / mypy / @lhci/cli / playwright / @playwright/test / pip 自身）；② 2 处写权限最小化；③ 新增 `scripts/check_docker_pin.py`（FROM 必须钉 `@sha256:`，5 例负样本自证）并在 `security.yml` 新增 `docker-pin` job（打印当前 tag 的期望 digest 供回填 + 跑严格判据）；④ 文档链：CHANGELOG 段 + 台账认领行 + HANDOVER + file-index + 本报告 + README 登记 108；⑤ **二轮产出**：digest 取值并回填（`0e1754758c2df…8202`，双代理 + 响应体哈希双证）+ 取值 step 改纯 HTTP 多源回退 + lock 的 26 条第三方镜像 `resolved` 归一（npm audit 500 根因真修）+ `scripts/check_install_pins.py` 扩展供应链面判据（lock 的 `resolved` 只允许官方注册表，新增 4 例负样本自证，可变异自证）。

**本章结论**：Code scanning 的 20 条告警已被拆解到具体对象并逐项处置——8 处真实未钉版项真修、2 处权限最小化、其余为行号漂移的陈旧投影（合并后随 Scorecard 重算消解）；4 条 Scorecard 整体评级项（CII / CodeReview / Fuzzing / Vulnerabilities）属组织级指标，仓内基础件已具备，外部登记动作登记在案。

**待确认事项**：`node:22-alpine` 的 digest 已于二轮取值并回填（值 `sha256:0e1754758c2df4cfa3e68d59e2e1b7374bb7fd9ea6328eaaacf15cc934af8202`，取值与自洽校验过程见 §2 AC-03 与附录 A）；合并后仍需复查 Code scanning open 计数与 Scorecard 重算结果。
> **【后续发现】（W1195）：本报告 V1.0 针对「安装命令面的修法方向错误**——前批认为 Scorecard 要求「钉精确版本」并对 7 处安装命令钉了版本；合并 PR #151 后重跑 Scorecard（run `42736414215`）实测：**该面 13 条告警一条未消**。读 Scorecard 源码（`checks/raw/shell_download_validate.go`）后才确认：它要的是「**钉 hash**」而非「钉版本」——pip 面必须含 `--require-hashes`（单包 `--hash=` 是 flag、被跳过⇒不作用），npm 面只认 `npm ci`。此判定误差与修法已在 W1195 批全面纠正（新增 hash 化清单 + 全部安装点改销可认形态）。
