## 执行摘要

本批是《系统架构方案 v2》§8.2 档 2 施工序里 **D-2 应用迁移批的第一子批（W934）**，把方案里的一句设计意图变成可运行代码：

> 「M12 PG 存储层：连接池 + 迁移 + 事务 + 健康探针」（方案 §5.1）

**做四件事**：

1. **M12 存储层抽象落地**——把现役 `server/db.ts`（SQLite 直连，356 行）拆成「接口 + 两个后端 + 一个工厂」：`server/storage/types.ts`（`StorageBackend` 接口）、`server/storage/sqlite.ts`（现役实现搬迁，行为逐字保留）、`server/storage/postgres.ts`（新增 PG 实现）、`server/storage/index.ts`（按环境变量选后端）。`server/db.ts` 降为**门面**，保留全部现有导出名 ⇒ **三个调用点（`chat.ts` / `routes.ts` / `index.ts`）零改动**。
2. **PG 三表 schema + 迁移器**——`deploy/pg/migrations/0002_app_tables.sql`（三表 + 索引 + CHECK + 外键）与 `deploy/pg/bin/migrate-sqlite-to-pg.ts`（SQLite → PG 一次性迁移 + 逐表行数与主键集合对账）。
3. **真实 PG 端到端实跑**——对 W928 已起的 PG 16.4 实例真实建表、真实迁移 70 会话 / 134 消息 / 4 反馈、真实对账。
4. **修掉 D-1 施工件在实跑中暴露的两处真缺陷**（授权模型），并把 D-1 留下的演练残留清理干净。

**本批不做**（明确留给后续子批）：双写对账期与切读停写（W935）· 检索层接入与静态产物服务地址注入（W936）· 容量实测（W937）· 合规批（D-3）。

**默认后端保持 SQLite 不变** ⇒ 现役应用行为与全部既有测试零影响，本批是**加法不是换法**。

### 0.3 本批开工前的实测发现（三条，全部有机器证据）

1. **D-1 授权模型有两处真缺陷**（W928 实跑遗留）：
   - `initdb-bootstrap.sh` 里 `ALTER DEFAULT PRIVILEGES IN SCHEMA public …` **缺 `FOR ROLE ${APP_USER}`** ⇒ 默认权限只挂在 `postgres` 名下 ⇒ **由应用账号创建的表不会被授予只读账号 SELECT**。
   - 引导脚本**先建 `schema_migrations` 再设默认权限** ⇒ 该表落在授权之前 ⇒ 实测应用账号读它报 `permission denied for table schema_migrations`。
2. **PG 库里留着 W928 的演练残留**：`sessions` / `messages` / `feedback` 三表是**桩结构**（`sessions` 只有 `id` / `title` / `created_at` 三列，与现役 6 列不符），带 6 / 50 / 20 条种子行；`schema_migrations` 的 `checksum` 是占位串 `w927-verify` 而非真实摘要。**这些行不是应用真实数据**，直接迁移会把演练残留带进正式库。
3. **`preflight_check.py` 的 touches 交集检查在真实撞面时假绿**：台账 touches 列里的路径带反引号，而 `_split_touches` 不剥反引号 ⇒ 与命令行传入的无反引号路径字面不等 ⇒ 交集恒空。**本批不依赖该检查判定安全**，改为自己按「行级纯追加」纪律管理共享面（已跨会话书面告知该批的机制 owner）。

> **注 1（AC-02 口径修订·实跑后）**：规划期写的是「三调用点**零改动**」，该假设在实跑中被**证伪**——PG 是网络库，Node 生态**没有同步 PG 驱动**（`pg` 的 socket 只有异步接口）⇒ `StorageBackend` 接口必然是异步的 ⇒ 调用点必须加 `await`。这不是「为了改而改」，而是**规划期的一个技术假设错了**；改法有二：① 造一个假的同步 PG 后端（内存镜像/阻塞自研协议栈）⇒ 否决；② 接口异步化、调用点加 `await` ⇒ 采纳（决策 D-10）。「业务逻辑零改动」这条仍然成立且已逐条核对。

**不完成定义**：

1. 只写接口与两个后端的**代码**而不把数据**真实迁进真实 PG 并对账**（本批的价值在「迁得过去且对得上」，不在「有代码」）。
2. 对账只比**行数**不比**主键集合**（行数相等但内容错位是假对账）。
3. 把「静态校验全绿」当作「迁移已验证」——本批必须给出真实 PG 上的实跑数字。
4. 改动**默认后端**让现役应用立刻切到 PG（本批是加法；切读属 W935）。
5. 触碰 `site/` 任何页面或任何管控脚本。
6. 把 W928 的演练残留（6 / 50 / 20 桩数据）当作应用真实数据迁进正式库。
