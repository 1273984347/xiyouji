## 0. 背景与结论速览

本批是**遗留清偿批**。它不新增站点能力，只把 W1096 收官时登记、W1105 批留待次批根治的**四项遗留**逐项清偿，并把每项的治本判据固化成**常驻机器门禁**。

**遗留①（d3 动效守卫实参 317 处）**——站内 reduced-motion 契约（DESIGN.md §5.3）要求用户开启「减少动态效果」时 d3 图表的 `.duration()/.delay()` 归零。既有判据只清零**裸数字实参**（BARE），**表达式实参**（EXPR）从未进违规面 ⇒ 317 处表达式实参长期不套守卫，reduced-motion 用户仍会经历动效与延迟。本批把 317 处统一改写为 `MOYUN_RM?0:<表达式>` 形态，改写规则与仓内既有 545 处写法逐字对齐（简单表达式不加括号 · 箭头函数与含逗号实参加括号）⇒ 调用点 **GUARDED 545 → 862 · EXPR 317 → 0 · BARE 0**，d3 页 **91/91** 声明守卫，违规调用点页 **0**。

**遗留②（tooltip 多行间距死规则 3 页）**——W1105 批把 EN 站私有 `.tooltip{}` 盒样式收敛为规范 `.chart-tooltip`，但 3 个 ZH 页遗留的 `.tooltip div + div { margin-top: var(--space-2); }` **类名不匹配 ⇒ 该规则从未命中**（运行层实测 ruleHits=0）⇒ tooltip 多行内容一直挤在一起。本批改为 `.chart-tooltip div + div`（tooltip 内为 3 个连续 div ⇒ 命中第 2/3 行）⇒ 全站旧类名残留 **0**；独立取证面（3 页 × 亮/暗 = **6 组**）改前 `marginTop=0px / ruleHits=0` → 改后 `4px / 1`，且 4px 精确等于 `--space-2` 解析值（tokens.css 实测 `--space-2: 4px`）。

**遗留③（design 目录清单整体过期）**——真凶**不是**生成物，而是 `assets/design/tools/build_assets.py` 的**模板常量自身过期**：整段目录树指向已废弃的一次性工作区 `tmpe/_reports/logo-explore-v2/`、引用两个磁盘上不存在的脚本、并把两张判废且磁盘不存在的概念稿写进 index.html ⇒ 站点图片 404。本批**改模板而非改产物**（逐条手改生成物会被下次生成原样覆盖）⇒ 并连带订正概念稿张数（**生成 18 张 · 入库 16 张（13 可用 · 3 判废）· 另 2 张判废稿未入库**）、**治本 Windows CRLF 污染**（生成器两处写盘补 `newline="\n"`）。

**遗留④（独立盲审 6 条可观察项）**——逐条处置表落 `docs/11-方案报告/审查与评审/设计文件审查报告-2026-11-02.md` **第九节**，并纠正 T56 §6.1 ④ 与 T56 §7 A-08 的**指针失准**（6 条真出处是独立盲审报告**第四节**，不是本报告第八节）。

**三条新常设判据挂槽**——`scripts/check_motion_guard.py`（第 58 槽·三档扫描 + 括号平衡宽口径 + 双守卫命名枚举）· `scripts/check_design_asset_manifest.py`（第 59 槽·反引号 + 目录树缩进栈 + 命令形态三来源）· `scripts/check_tooltip_spacing.py`（第 60 槽·运行层 playwright·亮/暗双主题）⇒ 门禁 62 → **65 段**，同步六处字面量（gates.md 标题 60 槽 + 分组行 27-60 · AGENTS 三处 60 槽 + §4.2 三条摘要 · 文档规范「现役 65 段」· verify 注册「第 58/59/60 门禁」+ 段数 62 → 65）。

**本章结论**：四项遗留**全部清偿**，三条判据**全部挂槽且 0 FAIL**，全量 pytest 与 CSP 均不因本报告变红。
**待确认事项**：0 项（本批全部读数以本报告 §3.2 与附录 A.3 命令复算为准）。

## 4. 复盘

**做对的**：

1. **先复算基线再动手**——用第 58 槽判据本身对 HEAD 树跑一遍，得到 GUARDED 545 / EXPR 317 / BARE 0、EXPR 分布 57 页，证实「317 处 / 57 页」这个登记值仍成立且判据口径与登记口径同源 ⇒ 改写面不会因口径漂移而错位。
2. **改写形态复用仓内既有样本**——不自创风格，而是按既有 545 处写法的既有规则（简单不加括号 / 箭头函数与含逗号实参加括号）逐处对齐 ⇒ 全站写法统一，改后可逐处评审。
3. **验证面选在运行层而非静态层**——tooltip 缺陷的本质是「规则在但从未命中」，静态 grep 证明不了命中 ⇒ 用浏览器读计算样式拿到 6 组独立读数（0px → 4px）。
4. **溯源到生成源**——design 清单过期没有逐条手改生成物（那会被下次生成覆盖），而是改模板常量再重跑生成器。
5. **父会话独立复核子代理产出**——worker 任务丢失后不靠自述判定完成，按目标文件绝对路径实读磁盘状态 + 自跑验收命令。

**做得不好的**：

1. **判据首版口径过宽**——design 清单判据首版误报 20+ 条（仓库根相对路径 / 通配占位 / 花括号展开 / 枚举合并写法），是「先按最严口径做，再按降级口径收敛」的顺序，增加了一轮返工。
2. **目录树层级一开始没解析**——只认反引号条目 ⇒ 代码块目录树（层级靠缩进表达）整段漏检/误检 57 条，须改为按缩进栈还原层级才拿到正确分母 201。
3. **worker 派发环节无独立验收闸**——第一次挂槽任务静默丢失（四文件零改动），若只读 worker 自述会把「未执行」误判为「执行中」。
4. **「全量」口径二义未在动手前澄清**——文档规范那处「全量」指执行段数（65），gates.md 标题指槽位数（60），两者不同源，若不实读确认会写错字面量。

**下次改进**：① 判据类脚本先枚举**实参/条目形态全集**再逐形态各做一例负样本自证，分类器本身不得留盲区；② 凡由脚本生成的文档，改动前先定位生成源，禁在产物上动手；③ 外包子代理的关键改动，验收证据必须由接手方自己产出；④ 引用「全量」「现役」「版本」等范围词汇前，先实读其定义所在的权威位置并写明指哪一种。
