## 四、经验沉淀

**E-86 · Windows 上「改文件名大小写」必须物理改名与索引登记两段都做**：`git mv` 只改 git 索引、不改物理名（`core.ignorecase=true` 时 git 认为路径未变）⇒ 提交会呈现「删旧增新」的零差异假 diff；正解 = 先用两步法（临时名 → 目标名）做物理改名，再 `git mv` 登记。

**E-87 · 判定「大小写冲突」类判据时，规范名迁移必须同步反转判据方向**：`case_collides()` 原语义是「规范名之外的大小写变体 = 冲突」；规范名从小写改为大写后若沿用旧判据 ⇒ 每个目录都命中 ⇒ 数百目录被整体跳过 ⇒ **门禁从"有判据"变成"无判据"且仍然报绿**（latent 三问的典型形态）。

**E-88 · 同名不同义的产物共存时，豁免必须是显式契约而非隐式副作用**：`docs/INDEX.md`（文档索引）与目录清单（`INDEX.md`）同名不同义；改名前靠「恰有 INDEX.md ⇒ 整目录跳过」的副作用豁免，改名后副作用消失 ⇒ 门禁误判。根修 = 把豁免写成显式契约（`INDEX_OWNED_ELSEWHERE`）并让生成器与门禁共用（单一事实源）。

**E-89 · 批量替换前必须先按语义分桶，且「历史叙述」单列**：1333 处 `index.md` 引用中，活导航指针（改了即活）与历史叙述（改了即篡改历史）方向相反 ⇒ 一律替换会造成 18 处历史事实被改写；一律不替换则造成死指针。分桶判据 = 该引用指向的是**活文件路径**还是**对过去的叙述**。

**E-90 · 多会话共享工作树时，`git add -A` 会反复扫进他方在途件**：本批被并行会话扫入 4 件（2 份 spec + 2 份临时件），对方逐次 `git restore --staged` 摘出；且其一次 `git checkout -f` 直接回退了我方全部工作树改动。正解 = 独立 git worktree 隔离施工 + 跨会话书面约定写顺序 + 提交一律用显式 pathspec（禁 `git add -A`）。
