### 1.2 根因分析（两项遗留的病根）

**遗留 A（补段工具单面判定）**
backfill_changelog 的立段判定集合 established **只从 CHANGELOG 面收集**（现役 + 归档两文件），完全不看 file-index 面。
⇒ 某批若 CHANGELOG 已立段而 file-index 未立段 ⇒ 该 spec 被判「已立段」⇒ **整批跳过** ⇒ file-index 段**永远补不上**。
连带缺陷：字段完整性检查挂在「已立段」判定之后，而「已立段」只看一面 ⇒ 一面已立一面未立的 spec，其完整性检查也一并跳过。

**遗留 B（级联插段非幂等）**
各插入型面**各自为战**，无统一的「本批号在本面是否已落内容」判定 ⇒ 行为分裂成两类：

| 面 | 原行为 | 危害 |
|---|---|---|
| 交接文档头链 entry | 无条件 prepend | **静默重复**（重跑即内容越滚越多，不报错） |
| 交接文档里程碑块 | 无条件插入 | **静默重复** |
| AGENTS 脚注条目 | 无条件追加 | **静默重复** |
| workflows 里程碑尾标记 | 无条件包裹 | **静默重复**（层层累积） |
| 页脚链 token | 无条件前插 | fail-closed（W724 去重断言炸） |
| CHANGELOG 段 | 「批次号 = 顶段+1」强断言 | fail-closed（降序位补段时必然失败） |

⇒ 共同后果：**落段后无法重跑级联**（W1117 R-01 原文登记）。
另一层根因：交接文档里程碑滚动（淘汰最老块）是**有状态**操作 ⇒ 即使把插入改成幂等，重跑仍会再淘汰一块（信息丢失）⇒ 必须一并守卫。

### 1.3 方案与判据

**方案一：幂等 upsert 原语（单一事实源）**
新增 scripts/cascade_idempotence.py，提供两个纯函数：

- upsert_entry(text, locate, build, insert_at) ⇒ (新文本, 状态)，状态 ∈ inserted / unchanged / replaced
  · 本批条目不存在 ⇒ **插入**（既有行为不变）
  · 已存在且内容一致 ⇒ **零变化**（可重复执行）
  · 已存在但内容不一致 ⇒ **替换**为新内容（重跑级联修正路径）
- locate_entry(text, start_re, end_re) ⇒ 通用区间定位（终点可指定；不指定时取行尾）

各面只提供各自的定位规则，判定逻辑单点收敛 ⇒ 行为一致性由结构保证，不靠逐面自觉。

**判据强度不降的说明**：原「已存在即断言失败」的 fail-closed 语义，由「内容不一致 ⇒ 替换」覆盖；替换后内容与 spec 逐字一致 ⇒ 不会留下 stale 内容。
唯一保留 fail-closed 的是 **CHANGELOG 段面**：段内容不一致时**拒绝插入**并指引 scripts/rebuild_section.py 重建（与 W1120 的 file-index 面同策略）⇒ 段面内容的修复职责归属重建工具，不在级联里两处实现。

**方案二：补段工具双面独立判定**
新增 collect_pending_faces() ⇒ 返回 [(W 号, spec, need_changelog, need_file_index)]；两面皆已立段 ⇒ 不在结果内。
collect_pending() 收敛为**薄委托**（返回形状与语义均不变 ⇒ 既有调用方不受影响）。
字段完整性检查按「写入去向」拆成两面所需字段（CL_FACE_KEYS / FI_FACE_KEYS）⇒ 该面缺字段仍 fail-closed，无关面的历史缺字段不再误伤待补面。

## 5. 经验沉淀

**落仓位置**：本节即仓内载体（docs/11-方案报告/计划方案/T74-…）· 坑表入表归集下一批（W1125）· 另同步 Agent Memory（跨项目通用教训）。

1. **「同一机制的多个实现点若无统一判定原语 ⇒ 行为必然分裂」**：六个插入型面各自判断「本批是否已落内容」，结果分裂成「静默重复」与「断言炸」两类 ⇒ 修法不是逐面加判断，而是抽出**单一事实源**的原语（判定逻辑单点收敛，各面只提供定位规则）。
2. **「幂等化的对象不止是插入动作，还包括有状态的配套操作」**：把插入改成幂等后，交接文档的里程碑滚动仍会在重跑时再淘汰一块 ⇒ 幂等边界必须覆盖「插入 + 配套副作用」，并把有状态部分挂在「首次执行」分支上。
3. **「立段/落段类判定若只看一面 ⇒ 另一面的缺口永远补不上」**：判定集合必须与写入面**一一对应**；且完整性检查要按「待补的那一面」校验，否则一面已立一面未立的件会既被跳过校验又被跳过补段。
4. **「兜底保护要先于自动补段」**：双面判定暴露历史缺口后，若默认自动补，会把老段插进现役降序位并撞体积窗 ⇒ 历史缺口（低于已立段 max）默认只提示、须显式确认才补。
5. **「多副本实现收敛到同一入口」**：collect_pending 收敛为 collect_pending_faces 的薄委托（形状与语义不变）⇒ 既有调用方零影响，同时消除双份判定逻辑。
