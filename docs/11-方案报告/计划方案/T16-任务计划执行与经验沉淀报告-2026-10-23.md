### 2.1 锚点版本的选择（本批核心技术决策）

仓内既有 30 张宣纸水墨图，锚点原文在 `tmpe/_misc/w852_hero_args_v3.json`。**但本批未直接复用 W852 原版**，原因：

### 2.4 定稿过程中修正的两个缺陷（自造 bug·被自己的探针抓出）

**缺陷一：缩放方向错误导致底部出现补边色带。**
初版 `fit_to` 按「缩放到目标**宽度**」缩放：源 2752×1536（实为 1.7917）→ 2560×1428，高度**不足** 12px ⇒ 走「补宣纸底」分支 ⇒ 底部多出一条色带（虽肉眼近乎不可见，但属交付污染）。
修法：改按「覆盖目标」缩放 `scale = max(tw/w, th/h)`，保证两轴均 ≥ 目标，再裁溢出量。修正后四种画幅均为「等比命中（无溢出）」或「裁顶/裁底（保主体或保净空带）」。

**缺陷二：`over_y == 0` 被误判为「高度不足」。**
1:1 档源 2048×2048 → 1200×1200，覆盖缩放后**恰好命中**（`over_y = 0`），但 `if over_y <= 0` 把它判成「异常·补底」分支 ⇒ 走补纸路径。修法：`over_y < 0` 才补纸，`over_y == 0` 直接裁到目标宽。

**验收佐证**：修正后底部 20 行的唯一色数为 2–17（宣纸自然纹理，非补边色带的单色带）。

### 2.5 裁切规则（主体不被切是第一原则）

顶部 96 行暗像素占比 < 0.05%（几乎全空）→ **裁顶**（底部净空带整条保留）；顶部有深墨（主体顶端正压在画幅上沿，如塔顶/山脊/旗杆）→ **裁底**（底部为纯宣纸带，裁之无痕）。

实际采用：16:9 三张与 1:1 三张「等比命中」；3:4 中 `post-07` 裁底（保古山主体）、`post-08`/`post-09` 裁顶；630 中 `og-13`/`og-14` 裁底、`og-15` 裁顶。

## 四、复盘与经验沉淀

### 4.1 本批真正解决的问题：不是「画什么」而是「四画幅并存时怎么仍然成套」

前三批都是单一画幅内的成套（16:9 一套、1:1 一套、630 一套）。本批第一次要求**四种画幅同批交付且风格一致**。做法是把「一致性」全部押在**提示词锚点同源**上：画幅差异不在提示词里体现，而在交付端机械处理（缩放 + 按「保主体/保净空带」规则裁切）。这样 12 张的 `art direction` 段与配色五色是**逐字同一份**，一致性不靠事后调色去凑。

### 4.2 读历史比重新发明便宜

W852 锚点原文在 `tmpe/_misc/` 下（不在 `scripts/output/`），第一轮搜 `FAF7F0` 只搜到文档没搜到原文。若凭印象重写锚点，很可能重犯 W881 的规则线错误——**那正是 W852 原版里的句子**。本批改为先读 `W852→W882` 的演进链，确认「哪一版是修好的」，再动手。

### 4.3 自造 bug 被自己的探针抓出（本批两处）

缩放方向与 `over_y == 0` 两处缺陷都是本批自己引入的，且都由**自己写的脚本**抓出（底色带自检、底色族统计），不是靠肉眼。教训：交付端机械处理（缩放/裁切）的正确性判据必须**独立于**目视——本批的「底部 20 行唯一色数」就是为此专门加的。

### 4.4 交付端裁切的第一原则：主体不被切

W878 已把裁切规则细化过，本批沿用并补一条：**顶部深墨「本就溢出画幅上沿」时裁掉看不出断口**（如 `og-13` 的山门屋脊）；但**主体顶端正悬在画幅内时一律裁底保主体**（如 `post-07` 的古山山脊）。净空带是叠字区、优先级高，但主体被切是更严重的缺陷。

### 4.5 顺带发现的一处门禁判据缺陷（未修·已交底）

```python
return {t.strip() for t in last.split(",") if t.strip()}   # 只认逗号
```
