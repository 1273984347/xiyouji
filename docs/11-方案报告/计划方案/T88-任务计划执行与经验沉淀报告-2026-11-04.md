## 4. 复盘

1. **「台账 max+1」不覆盖已预约未落地的号**——本批首次取号按台账 max(W#)=W1129 推出 W1130，若照做即与 ROGSTRIX 预约的 W1130 撞号（他方已占·先落地者保留）。正解：取号前必须跑 reserve_w.py list 实读**三个占用面**（台账正本 / 预约表 / 产物与脚本前缀），只查台账会撞号。该教训与坑表号段相邻但**不入本批坑表**（E-179 ~ E-182 四号已由 T80 报告入库声明归本批·取号教训入表需另行占号·留待下一批）。
2. **「重建某面」的脚本必须以该面原文为唯一基线，不能按行号猜测插入位**——D1 的根因正是「按行号 1 当作第 1 号登记行」。正解：重建类脚本的插入位必须由**内容锚点**（表头行 / 目标 token）定位，并以基线原文逐字取行。
3. **同名文件 + 一侧未改 ⇒ 合并静默覆盖**——D3 即此族（清理在 11e40b75 做过，两次 merge 后回灌）。正解：合并收尾除文件集差集外，还须逐字比对「不在本批应动全集内却与 main 不同」的文件（已入 E-172）。

4. **「同号两行」类重复不能靠补登记消除 ⇒ 撤销归位是唯一正解**（统筹裁定采纳·对应坑表 E-183）：§六 的 35/36 是**同号两行**而非「缺号」⇒ 补第三行只会变成三行同号（更糟）⇒ 补登记永远无法消除同号重复。正解：先判定重复的成因类型（同号两行 = 撤销归位；缺号 = 才补登记）⇒ 撤销本方引入的那行、恢复基线原状，真实缺口移交独立治理批（与 AGENTS §6-15「禁补丁加补丁」一致）。
5. **补登记他人历史交付物＝越权改他方登记行**（统筹裁定采纳·对应坑表 E-184）：T-29 两件属**他人历史交付物**（W974 批）⇒ 我方补登记违反台账表头规则②「不改他方行」⇒ 越权。正解：登记缺口只允许两种合法处置——① 本方产出的件由本方登记；② 他人产出的缺口登记为独立治理批（写清缺口清单 + 归属批次 + 处置方式），不得夹带进任何在途批的提交。
