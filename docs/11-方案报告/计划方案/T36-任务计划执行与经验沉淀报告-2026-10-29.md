## 0. 执行摘要

用户在看 `site/static/images/ink-mountains-hero.webp` 时指出「**内容不符合西游记·为什么有七个人**」。实查确认：那张图的档案早在 **W852 批**就写死了「山脊云海 + **七人单行**」⇒ **W879 批**原地替换该图时沿用了同一错误 ⇒ 与它同族的 `hero-01-xihai-yunhai.webp`（flyer 配图）同样是错的。

本批做两件事，第二件是第一件收官时被逼出来的根因修复：

| # | 轨 | 动作 | 规模 | 结果 |
|---|---|---|---|---|
| ① | 资产 | 两张 hero 水墨图人数修正 | 2 张（1792×1024 + 2560×1440） | 4 人形 + 1 匹白马；**331 个引用页零页面改动** |
| ② | 资产 | README 物料三图核查 + flyer A4 快照重渲染 | 3 图核查 / 2 PNG 重渲 | 静态快照已同步（1240×1756） |
| ③ | 工具链 | 级联改写面「行锚定」根因修复 + 防复发判据 | 4 正则 + 1 新判据 + 5 例单测 | 项目说明.md **103 行不变**；旧吞并被负样本复现并挡住 |

**关键取舍（三条）**：

1. **人物口径＝取经五人组 = 4 人形 + 1 匹白马**（唐僧·悟空·八戒·沙僧 + 白龙马）。白龙马是马不是人 ⇒ 「7 人」与「5 人形」两种读法都不合原著；本批按「4 人形 + 1 匹白马」出图并在图题层写死该口径。
2. **原地替换（同文件名同尺寸）**⇒ 引用该图的 **331 个页面零页面改动**（沿用 W879 批先例）——这是「修图」而非「改引用」的最小面路径。
3. **人数核对只走人眼硬关**：本批实测「深墨小簇计数」判据**不可用**——山水皴笔的碎点被计入（67 / 20），机器数不出可信人数 ⇒ 承坑表 E-18「人物数超限机器判据全绿」，人眼为硬关。

**根因（本批最硬的产出）**：`batch_cascade` 的项目说明「当前版本」列表行正则用 `[^·]*` 且**无尾锚点** ⇒ Python 字符类匹配换行符 ⇒ 匹配区间跨行 ⇒ `re.sub` 替换整个匹配区间 ⇒ **静默删掉一整行**。本批实测：匹配区间 1143..1342 跨 1 行 ⇒ 项目说明.md **103 行 → 102 行**，第 49 行「当前阶段」行首被删，而级联当时报「写后自检全部通过」。**反直觉点**：旧 desc **含**「·」时反而**安全**（`[^·]*` 止于行内）；desc **无**「·」（正是 C6 判据 W841 要求的形态）才触发吞并 ⇒ 两个判据在列表行上互为镜像。

## 附录 C：级联根因链与证据

```
用户问「README 图片更新了吗」
  └─ 收官级联 batch_cascade --apply
       └─ 断言 FAIL：项目说明头部版本行未变化
            └─ 根因 A（我方误伤）：手工修 C6 时整行无差别替换「·」→「、」
                 └─ 把结构性尾缀「·详细变更见」改成「、详细变更见」
                      └─ 级联正则 [^·]*·详细变更见 失配
            └─ 根因 B（脚本既有缺陷）：列表行正则 [^·]* 无尾锚点
                 └─ Python 字符类匹配换行 ⇒ 匹配区间 1143..1342 跨 1 行
                      └─ re.sub 整段替换 ⇒ 项目说明.md 103→102 行
                           └─ 第 49 行「当前阶段」行首被静默删掉
```
