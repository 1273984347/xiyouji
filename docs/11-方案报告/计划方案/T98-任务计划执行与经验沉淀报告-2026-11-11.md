- **注册表三处同改**（W781 R-1「五处同改」纪律）：门禁元组 / `EXPECTED_SECTION_NAMES` / `_SCOPE_CORE`。
- **槽数声明面五处同改**（69 → 70）：AGENTS.md §4.2 三处 + `docs/agent/gates.md` 标题沿革 / 第 70 条 / 文末详细定义 + HANDOVER.md 一处。

### A. 仓库体积复核（取证结论）

| 取证面 | 读数 |
|:---|:---|
| `.git` 构成 | objects **1198.8 MB**（其余 hooks/logs/index 合计 < 2 MB）⇒ 全部在历史对象 |
| pack 状态 | 单个 pack 1194.5 MB + 104 个 loose；gc 后已归零重复 |
| 全量对象 | blob 58,842 件 / **逻辑 5,499.5 MB** ⇒ pack 物理 1194.5 MB（压缩率 4.6×） |
| 最大单体 | **24 MB**（字体 `NotoSerifSC-var.ttf`）⇒ **无异常巨型文件** |
| 膨胀主因 | `CHANGELOG.md` 927 个历史版本共 **225.8 MB**；`file-index.md` 842 版本 150 MB；台账 940 版本 141.6 MB；reader+data/en 页合计 **2.4 万对象** |
| 难压缩类 | `assets/promo/plate-set/*.png` 13 个历史版本 114 MB（PNG 二进制不可 delta 压缩） |

**结论**：体积膨胀是「**同一路径反复改写**」的累积，不是误提交巨型文件 ⇒ 改写历史要剔的正是治理文档与站点的**历史版本**（可追溯性代价极高）而省下的空间有限（PNG 类最多约 114 MB，逻辑 5.5 GB 的其余部分已靠 delta 压到 1.19 GB）⇒ **改写历史不是把体积降到 1 GB 以下的经济路径**。已改走**不改历史**的深压缩路径。

**不改历史手段已实测到顶**：`git gc --prune=now`（W1207）回收 **643.3 MB**（1844.3 → 1201.0 MB）；本批 `git repack -a -d -f --window=250 --depth=250`（**728 s · rc=0**·重算 delta 链）**再省 30 MB** ⇒ **1.13 GiB，仍越 1 GB 线约 13%** ⇒ 再降只剩改写历史一条路（force-push + 全部 commit hash 失效 + 可追溯性受损）⇒ **本批未擅自执行·待用户单独决策**。

### 7.2 决策记录与理由

| 决策 | 理由 |
|:---|:---|
| 用 `_StrictGate` 而非 `_SimpleGate` 挂槽 | `_StrictGate` 要求汇总行且 crash 即拦 ⇒ 防「脚本没跑却报绿」；第 70 槽是安全面判据，不能只判退出码 |
| 守卫加 `--gate` 而非改动默认输出 | 默认输出形态是既有调用方契约 ⇒ 加开关保持零行为变化 |
| 登记 `_SCOPE_CORE`（恒跑） | 判据与改动范围无关：任何提交都可能夹带产物面回填 ⇒ 必须恒跑 |
| 不新增坑表条目 | 「挂槽五处同改」是 W781 R-1 已在册形态 ⇒ 重复坑不新增条目（E-211 纪律），计数链保持 319 |
| 体积改走不改历史 | 取证显示膨胀源于「同路径反复改写」且无异常巨型文件 ⇒ 改写历史代价高、收益有限；实测 gc + repack 后 1.13 GiB 仍越线 ⇒ 再降须改写历史 ⇒ 待用户单独决策 |
