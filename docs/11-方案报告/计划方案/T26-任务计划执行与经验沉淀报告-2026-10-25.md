## 执行摘要

用户一句「禁止使用 emoji 表情当做图标」被拆成两件可交付的东西：**一次有量的审查** + **一套自绘图标**。

**审查结论**：全仓 emoji 共 **34,530 处 / 2,189 文件**。绝大多数在 Markdown 正文（题材内容，属表达不属图标）。真正承担图标职能的是 **1,910 处 UI 图标位**，分布 **629 个页面**，只用 **21 种字符**——集中在 615 个阅读页（收藏 ★ / 反馈 👍👎）、30 余个可视化页（判定 ✓✗、检索 🔍、年龄段 👶🎒📚🎓、播放暂停 ▶⏸、菜单 ☰、关闭 ✕、卷轴 📜、图钉 📌 等）、以及 3 个共享 JS（`reader-enhance.js` 收藏态切换、`rag-chat.js` 标签前缀、`text-search-app.js` 空态图标）。

**交付物**：**27 枚东方线描 SVG 图标**（24×24 / stroke 1.5 / currentColor，与既有 `.icon-moon`/`.icon-sun` 同参数同族）+ **3 个可复跑脚本**（图标生成器 / 基准扫描器 / 批量替换器）+ **1,957 处替换** + CSS 级联 328 页 + CSP 重算 14 页。

**结果**：UI 图标位 **1,910 → 0**（基准扫描器复扫，AC-01）；正文装饰 emoji **381 处**与箭头符号 **5,000+ 处**按用户裁决**零损伤**（HEAD↔工作树字符净差核验，正文型字符净差 = 0）。

**关键发现（写下来给以后用）**：站点 CSP 是 `img-src 'self'`（**连 data: 都挡**），且 520 个页面走外链 CSS（目录深度不一）⇒ **data-URI 图标方案会被 CSP 拦掉、写在 system.css 的相对路径会在深层目录失效** ⇒ 唯一同时满足 `file://` + CSP + 多层目录的矢量承载方式是**内联 SVG**；唯一例外是 CSS `content` 位（放不了 SVG 元素），该 22 处宿主页全在深度 1，用同源 `mask-image` 成立。

## 6. W946 续作批：补齐三处缺口 + 第 50 门禁

> 用户 2026-10-25 的「禁 emoji 当图标」指令分两批执行：W941（主体 `4e94aa58`）→ **W946（本批·续作 `ed09a65e`）**。
> 本批的起因是**浏览器实开**——W941 的静态判据全绿，实开才发现图标全是黑块。

### 6.1 缺口① 描边参数缺失 ⇒ 1,957 处图标渲染成黑块（严重·视觉）

| 项 | 内容 |
|---|---|
| 现象 | 内联 `<svg>` 只带 class/width/height/viewBox，**漏 `fill="none" stroke="currentColor"`** ⇒ 图形落回 SVG 默认样式（黑填充、无描边） |
| 为何静态判据查不出 | 静态判据能证明「图标位上没有 emoji」，**证明不了「图标画出来是对的」** ⇒ 这是判据的结构性盲区 |
| 修法 | 描边参数写进 `.ico` 基类 CSS（CSS 优先级高于 presentation attribute；`.ico` 类选择器特异性高于站内 `svg` 元素规则）⇒ **零 HTML 改动、全站立即生效**；同时给替换器 `svg_tag()` 模板补 SVG 属性（未来重跑产出更稳的 HTML） |
| 实测复核 | 浅色 stroke=墨色 `rgb(35,32,26)` / fill=none；**暗色 stroke 自动变朱砂 `rgb(224,96,79)`**（主题自适应确认）；尺寸 13–16px 跟随字号（非 300×150 巨图） |

### 6.2 缺口② 时间线 22 条事件换语义专属矢量图标（16 枚）

时间线原用 **15 种 emoji 承载 22 事件**，且「📖」**一符两义**（玄奘西行 vs 连环画普及）⇒ 通用图标集表达不了「成书/游记/评点/戏曲/影剧/数字化」的语义差 ⇒ 另设计 16 枚语义专属图标（`tl-*`）：行脚僧 / 立轴 / 灵光 / 脸谱 / 百回刻本 / 太极 / 整理校注本 / 评点笺注 / 新式标点 / 校注笔 / 数字库 / 连环画格 / 清代年画 / 胶片 / 显像管 / 手柄。数据字段由 emoji 改为图标名，渲染改内联 SVG，映射表内联进页面（保持自包含），**两页 emoji 序列一致性作断言**（22 == 22 且逐位相同）。目视复核重画 2 枚（`tl-pilgrim` 语义太弱 → 加持杖与日轮；`tl-punctuation` 读不出标点 → 改逗号+句号+引号三件套）。

### 6.3 缺口③ 第 50 门禁（`scripts/check_emoji_icons.py`）

| 段 | 判据 |
|---|---|
| A 静态 | 全仓 UI 图标位零 emoji 残留（与基准扫描器同源：控件首位 / 图标槽 class / 标题前缀 / CSS content） |
| B 实测 | 浏览器实开 4 个代表页 × **2 套环境**（`file://` 与 `http://127.0.0.1`）：内联 SVG 的 computed `stroke≠none` 且 `fill=none`、尺寸跟随字号（非巨图）、CSS content 位的同源 mask 已加载、自建图标资产零加载失败 |

**B 段的存在理由**：W941 静态判据全绿却漏掉「黑块」⇒ **必须有浏览器实跑**。本门禁 **PASS**（静态 0 处残留 + 双环境实测 0 判红项）。

### 6.4 双环境判据设计（如实登记）

| 环境 | 判据 | 实测结果 |
|---|---|---|
| `http://`（同源·**线上真实用户环境**） | 全部严格判红 | CSS content 位的同源 mask **全部加载成功（7/7）** ⇒ 线上无问题 |
| `file://`（本地双击） | 图标资产加载失败记 NOTE 不判红 | 同源 mask 被 CORS 拦 ⇒ 该 **22 处图标在本地不显示、线上正常**；与该环境既有的字体子集 CORS、fetch 不支持 file scheme 同级 |

**待修项（已登记）**：把这 22 处改为**真实内联 SVG 元素**（11 个选择器 × 中英两版）可彻底消除该降级 ⇒ 属独立批，不与本批混做（避免本批 diff 从「图标资产 + CSS + 门禁」膨胀到「10 个页面的结构改造」）。
