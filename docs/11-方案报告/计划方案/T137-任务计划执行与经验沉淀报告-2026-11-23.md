## 十、归档腾窗治本（收官链 archive 步死锁根修）

### 10.1 根因（实测取证）

本批收官链首次在 `archive` 步失败，报错原文：

```
AssertionError: 体积迁移后正本仅剩 6 段 < 保留底线 20（AGENTS 铁律 22）——此体量矛盾应压缩段行密度（batch_spec.fi_group_rows 立式）而非归档搬段
```

四组实测数据串起病根：

| 事实 | 实测值 |
|---|---|
| file-index 正本体积 | **262,964 B**（上限 262,144 B ⇒ **仅超窗 820 B**） |
| file-index 正本段数 | 50 段（段窗 110 ⇒ 段数远未超窗） |
| 原 `plan_by_size` 迁出量 | 以 `chunk=50` 为**固定步长** ⇒ 一次迁 44 段 ⇒ 正本仅剩 **6 段** ⇒ 击穿铁律 22 底线（≥ 20 段） |
| 实际所需迁出量 | 最小达标 **2 段**（W1255 / W1253）⇒ 迁出后 260,921 B |

⇒ **病根不是「段数窗与体积窗不可兼得」，而是「迁出量由 `chunk` 决定而非由体积决定」**：为迁 820 B 搬走了 44 段。

### 10.2 三处根修 + 一处新能力（判据只加严不放宽）

### 10.3 为什么必须「两面统一迁出」

`rebuild_section.boundary_check` 是**硬断言**：两面正本的最小 W 号必须一致，否则 `rebuild` 步返红。而本批实况是「只有 file-index 超窗、CHANGELOG 未超窗」⇒ 若只迁 file-index，其下界变 W1256 而 CHANGELOG 仍为 W1253 ⇒ 断言必红 ⇒ 收官链换个地方死。

⇒ 新流程取「各面迁出后下界的**较大者**」为**目标下界**，两面统一迁出「所有 W < 目标下界」的段 ⇒ 迁出后两面同为 W1256。

### 10.6 连带治本：cascade 链首的日期前缀残留

本批 `regsurface` 步首次报红「HANDOVER 无「最后更新」行」——**表面症状是链首缺失，实为链首形态畸形**：

```
最后更新：2026-11-232026-11-23（W1308 …）·2026-11-23（W1307 …）·（W1260 及更早批次详见 CHANGELOG.md）
```

根因：`batch_cascade._upsert_chain_entry` 的「按批号替换」分支（幂等键从「文本」放宽到「批号」的 W1272 改动引入）只替换 `（W#### …）` **括号区间**，而条目左侧还有一段 `YYYY-MM-DD` 日期前缀 ⇒ 同号条目**文本变更**时旧前缀残留 ⇒ 双日期 ⇒ 下游登记面一致性闸的正则 `最后更新：<日期>（W####` 匹配不上 ⇒ 判红。

治本（3 处，判据零放宽）：

| # | 修法 | 说明 |
|---|---|---|
| 1 | 新增 `_entry_start(chain, pos)` | 条目起点自「日期前缀」起算（单一事实源·头链与尾链共用） |
| 2 | `_same` 匹配纳入**可选**日期前缀 | 同号替换时整条替换，不再只换括号段 |
| 3 | 内容一致但存在前缀残留时亦**清理** | 幂等自愈 ⇒ 已落脏盘的形态重跑即自愈 |

判据单测 **3 passed**（首次插入链首 / 同号文本变更替换含前缀 / 双日期残留自愈）。
