## 0. 背景与结论速览

**本批针对**：scripts/agent_start.py 是「开局事实摘要」的唯一入口（AGENTS.md 阅读契约第 0 步），它把 scripts/output/stats.json 当作**事实源**直读。实测发现两处**静默降级**：

- agent_start.py:67-68 读 stats 时用 except (OSError, ValueError): pass ⇒ **文件缺失或 JSON 损坏时 stats 静默变空字典**，摘要照常打印、只是「规模口径」段缺失 ⇒ Agent 察觉不到「事实缺失」，只当「没有规模数据」；
- stats.json **陈旧**时（早于 CHANGELOG.md 的最新改动）**直接输出陈旧值**，无任何提示 ⇒ Agent 拿到过期篇数仍当作当前事实。

**本批判定**：这类降级是铁律 15 的反面形态——「声明≠落地」的同族问题在**事实供给侧**的重演（摘要声称「实读磁盘·勿用记忆值」，但读的是可能缺失或过期的生成件）。**正解不是提示 Agent 小心，而是让降级显形**（告警而非静默）。

**核心产出**：

1. 新增 load_stats_with_warnings(stats_path, changelog_path, stale_tolerance=2.0) ⇒ 返回 (stats, warnings)，覆盖**四类**异常：缺失 / 不可读或损坏 / 空对象或非对象 / 陈旧；
2. gather() 接入该函数，--json 输出新增 stats_warnings 字段；render() 在摘要中输出「⚠ stats 状态告警：…」行；
3. 新增 tests/unit/test_w1104_agent_start_freshness.py：**5 例单测**（缺失 / 损坏 / 空对象 / 陈旧 / 正常不告警）全绿；
4. **附带清障**：修掉 PR #95 的 CI 死锁（详见 §2.2）⇒ W1100 得以合并。

**本批不做**（属 P-3 L2 与另两件，须等并行会话 W1102 合并后）：异源复算对账（复用其 C10）、第 53 槽判据、Playwright skill、PowerShell 权威源文件。

### 3.2 实测读数

- 单测：py -3 -m pytest tests/unit/test_w1104_agent_start_freshness.py -q ⇒ **5 passed in 0.15s**；
- 真实仓内运行 py -3 scripts/agent_start.py ⇒ 摘要含「规模口径：HTML 857（data 88/en 138/根 9/reader 622）·可视化页 87·CSP 856·门禁 52 槽」，**无告警行**（stats.json 当前新鲜且非空）；

- **四类告警正样本自证**（在 worktree 副本上实跑 agent_start.py）：① 正常态 ⇒ **告警行数 0**；② mtime 改旧 1 小时 ⇒ 报「stats.json 陈旧（早于 CHANGELOG.md 的最新改动）」；③ 写入非法 JSON ⇒ 报「不可读或损坏」并附解析错误；④ 写成空对象 ⇒ 报「为空或非对象」；⑤ 删除文件 ⇒ 报「缺失」；⑥ 还原后 ⇒ **告警行数回到 0** ⇒ 四类均真能显形且正常态零误报。

### 3.3 影响判读

- **对 Agent 的行为影响**：开局摘要若缺 stats，Agent 现在会看到显式告警行而非「静默没有数据」⇒ 不会基于过期篇数做决策；
- **对门禁的影响**：本批**未新增门禁槽** ⇒ 不改变 CI 时长与失败面；
- **对并行会话的影响**：零共享面（未碰 verify_delivery.py / gates.md / 台账他方行）⇒ W1102 可照原计划推进；
- **风险残留**：陈旧检测依赖 mtime ⇒ 若有人在同一分钟内改 CHANGELOG 并刷新 stats，理论上不报（2 秒容差内）⇒ 属可接受的漏报窗口（不影响「缺失/损坏」两类硬告警）。

### 3.4 总体自评结论

本批达成 G-01：agent_start.py 的 stats 读取从**静默降级**改为**四类显式告警**（缺失 / 损坏 / 空对象 / 陈旧），5 例单测全绿，正常态零噪声，并顺带清掉 W1100 的 CI 死锁。**未达成 / 顺延**：① 异源复算对账（P-3 L2·须复用并行会话 W1102 的 C10，其实现目前尚未入仓）② 第 53 槽判据接线 ③ PowerShell / Playwright 权威源与 skill（另两件）。

## 4. 复盘

### 4.1 做对了什么

1. **先查 CI 卡点再动手**：本批名义上只改一个工具函数，但实测发现 CI 两红中有一半是**自己上一批留下的**（标题笔误 + 体积窗口）⇒ 若只顾本批，W1100 会永远卡着，后续所有号段都受影响 ⇒ 先清障再施工。
2. **告警而非阻断**：工具层告警与门禁阻断分层，避免「stats 坏了 ⇒ 整仓不可开工」。
3. **隔离 worktree**：主工作树有并行会话在途件，直接施工会把它卷进本批提交。

### 4.2 该改什么

1. **提交标题不得混入他方批次号**（C4 判据会抽标题做版段对账）⇒ 已入 E-91 相邻条目，提交前应自检标题。
2. **陈旧检测只是 mtime 近似**：真正的口径一致性要靠异源复算（L2）⇒ 等 C10 落地后接入。
3. **告警文案可再收敛**：目前把绝对路径写进摘要，跨机器复现时路径噪音大 ⇒ 后续可改为相对路径。

### 4.3 交接口径

- **L2 接线条件**：本批留了 load_stats_with_warnings() 的返回结构（warnings 列表）⇒ 并行会话 W1102 的 C10（stats 异源复算）落地后，只需在同函数内追加一次复算对账并把差异追加进 warnings ⇒ **无需改调用点**。

- **下一批建议**：等 W1102 合并后，开一批把「P-3 L2 复算接线 + 第 53 槽 PowerShell 解析判据 + FAIL 输出分类（新问题 vs 旧豁免）」一并落地（都改同一共享面，宜合批）。

### A.2 判据口径

- **告警四类**：缺失（FileNotFoundError）· 不可读或损坏（OSError/ValueError）· 空或非对象 · 陈旧（mtime(stats) + 2s 小于 mtime(CHANGELOG.md)）。
- **事实源参照**：CHANGELOG.md（现役顶段的唯一权威源）⇒ stats 由 stats.py --w 在链序末端生成，理论上晚于 CHANGELOG。
- **不阻断**：告警只影响摘要可读性，不改退出码（开局摘要不是门禁）。
