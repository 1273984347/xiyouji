## 0. 执行摘要

**一句话核心判定**：Playwright 在本仓的历史问题**不是「工具不稳定」，而是四类可归因的系统性偏差**——① 依赖三态不同步（本地有 / CI 无 / gitignore 排除）；② file:// 与 http 走两条代码路径，只测一条就测的不是用户入口；③ 浏览器是**物理量**不是确定性量（动画中途值 / 真实度量抖动 / 单次采样尖峰）；④ 断言锚**字符串存在性**而非**行为**，故假绿可长期掩盖真缺陷。

**本批产出**：全仓 256 处 Playwright 引用（文档 40+ / 脚本 8 / CI 4 / 历史提交 40+）逐项取证，归并为 **8 族 25 项**，每项带可复验证据锚点（文件:行号 或 W 批次号）；其中 **22 项已修复**、**3 项仍开放**；另收录用户评审提出的 **2 项新增风险**与 **P0–P3 优先级表**。

**本批最重要的实证修正（3 处，与评审初判不一致，以仓内实读为准）**：

| # | 评审初判 | 实测结论 | 依据 |
|:---:|:---|:---|:---|
| 1 | 「`^1.63.0` 按 semver 会解析到 1.64.x，本地与 CI 已差一个 minor」 | **不成立**。`scripts/package-lock.json` **已入库**且把 playwright 钉死为 **1.63.0 精确版**（含 integrity），本机实装亦为 1.63.0；`npm ci --prefix scripts` 路径**不漂移** | `git ls-files scripts/` 实证入库 · `scripts/package-lock.json:873` · `scripts/node_modules/playwright/package.json` 实测 1.63.0 |
| 2 | 「漂移来自 `^1.63.0` 浮版」 | **漂移面另在他处**：`ci.yml:47` 的 `npm install playwright @playwright/test` **无版本约束 → 装 latest tag**，且装在**仓库根**（不是 `scripts/`），**完全绕过 lockfile** | `.github/workflows/ci.yml:47` · 对比 `ci.yml:345 / 389 / 418` 三处均为 `npm ci --prefix scripts` |
| 3 | 「BL-32 截图审查没有影响面概念」 | **部分不成立**。W421 已实现三档 scope（`skip` / `targeted` / `full`）+ `--only-pages`；真实缺口是**映射粒度停在目录级**（`site/*` → 全量，而非映射到该页本身），而非「没有影响面概念」 | `.github/workflows/screenshot-review.yml:86-166` scope 判定块 |

**新增最高价值发现（评审与首轮答复均未点出）**：`pages-smoke` job 安装了 Playwright 与 chromium，**但该 job 从不使用浏览器**——其「Run screenshot baseline」步骤是内联 Node HTTP 存活扫描（仅 `fs` / `path` / `http`）。即：**每个 PR 白付一次浮版 Playwright + chromium 下载，且这是全仓唯一无版本约束的 Playwright 安装点**。详见 §14.1。

**本批最重要的一处实操发现（非 Playwright 域·但属「新增文档连带面」族）**：原计划改 4 个联动面，**实测 8 处**——`report_docs` 统计键有**两处** `<!--stats:...-->` 消费点；且站内搜索索引扫描 `docs/**/*.md`，故新增一篇文档会连带改两个站点页面的内嵌索引，进而改其 CSP 哈希。漏的 2 处均由门禁当场报出（§14.4 + E-09）。

**本章结论**：审计面已闭合（25 项全部有锚点或明确标注为未验证）；三项开放项的收敛路径已由「评审建议」修正为「仓内实证 + 最小改动方案」；修复动作**本批未动工**，待用户裁决排期。交付 11 件，2 提交（`e5b262e7` + `92175003`）。

**待确认事项**：§16 的 P0–P3 是否排入后续 W 批次；§14.1「pages-smoke 删除 Playwright 安装」是否直接执行（该项改动会改变 CI job 依赖面，需用户确认）。

## 14. 三项开放项的收敛建议（含实证修正）

### 14.1 BL-30 依赖浮版 → 真实漂移面是「绕过 lockfile 的那条路径」

**评审初判与实测的差异**：评审认为「`^1.63.0` 按 semver 会解析到 1.64.x，本地与 CI 已差一个 minor，根因是 `package.json` 不是唯一真相源」。

**实测结论**：`scripts/package-lock.json` **已入库**（`git ls-files scripts/` 实证），并把 playwright 钉死为 **1.63.0 精确版**（`scripts/package-lock.json:873` 含 `version` + `resolved` + `integrity`）；本机实装 `scripts/node_modules/playwright/package.json` = **1.63.0**。故 `npm ci --prefix scripts` 路径**不漂移**，「已差一个 minor」不成立。

**真实漂移面**（H-1 + H-2）：`ci.yml:47` 的 `npm install playwright @playwright/test` **无版本约束** → npm 装 `latest` tag，且该命令在**仓库根**执行（不在 `scripts/`），**完全不读 `scripts/package-lock.json`**。它是全仓唯一的浮版安装点，且其所属 job 根本不调用浏览器。

**建议方案（按改动量从小到大）**：

| 方案 | 动作 | 改动量 | 收益 | 验收判据 |
|:---|:---|:---|:---|:---|
| **A（推荐）** | **删除 `pages-smoke` job 的「Install Playwright」步骤** | 删 4 行 YAML | 消除唯一浮版安装点 + 省一次 chromium 下载（约 120MB）+ 消除 H-1 的版本分裂 | `ci.yml` 中 `npm install playwright` 命中数 = **0**；`pages-smoke` job 仍绿（HTTP 存活扫描不依赖浏览器） |
| B | 三 job 统一 `cd scripts && npm ci` | 改 1 处 | 版本一致（仍 1.63.0） | 三处安装块字节级一致 |
| C | 改用官方镜像 `mcr.microsoft.com/playwright:v1.63.0-noble` | 改 job 容器 | 库版本 + 浏览器 revision + 系统依赖三层同时锁死 | 镜像 tag 与 lockfile 版本一致 |

**建议**：**A + B 组合**。A 是零风险净删（该 job 无浏览器调用），B 消除剩余不一致。C 留作依赖治理批的独立决策（镜像引入 ubuntu 基础差异，需另批验证）。

**评审建议的「本地/CI 版本对账」动作保留并前置**：`npm ls playwright` 在本地与 CI 各跑一次写入对账表，作为 V-05 的证据。

### 14.3 BL-32 截图审查粒度 → 缺口是「映射停在目录级」，不是「没有影响面概念」

**真实缺口**（两处）：

1. **映射停在目录级**：`site/*` 一律判 `full`——哪怕只改 `site/reader/xxx.html` 一个页面（622 reader 页中的 1 页）也触发全站审查。**改法**：把 `site/*` 分支细化——`site/reader/*.html` 与 `site/data/*.html` 归 `targeted`（映射到该页自身），保留「全局样式源变更」走 `full`（判据：`site/static/css/*`、`site/static/js/*`、`scripts/inline_css.py`、`scripts/tokens*`、`scripts/system*`、`.github/workflows/screenshot-review.yml` 自身）。

**验收判据**：仅改 1 个 `site/reader/*.html` 时 `scope=targeted` 且 `only_pages` 含该页；改 `site/static/css/*` 时 `scope=full`。
