## 4. 复盘

1. **「多会话共用同一工作树 ⇒ 级联式工具整面重写 ⇒ 互相覆盖 + 代提 + 计数基线漂移」**：本仓的级联/收官链会整面重写 HANDOVER / CHANGELOG / AGENTS / SKILL / 坑表 / 台账 ⇒ 一方跑链即覆盖另两方未提交改动；计数类面按「含他方条目的中间态」算出漂移值；一方整文件 git add 即代提他方改动 ⇒ **工作树隔离是并行协作的默认前提，不是可选项**（独立 worktree 或独立克隆；worktree 共享 .git 故分支名不可重名；迁出后按自己的条目唯一前缀精确回滚，禁整文件覆盖）。
2. **「计数链同步的基线必须是最终合并态」**：按当前 HEAD 算出的合计在其他会话先落地条目后会立刻失真 ⇒ 合并前必须 merge 新 main 并按新基线复核（本次 267 → 268 即为此类）。
3. **「修复步必须排在 fail-closed 预检之前」**（W1117 同族·本批固化为顺序锁）：precheck 一旦中止，排在它后面的修复步在最需要它时不可达 ⇒ 重建步与腾窗步同理前置。
4. **「工具链不支持新协作形态 ⇒ 制度落不了地」**：隔离 worktree 是并行协作的默认前提（AGENTS 铁律 24），而第 52 门禁把 worktree 形态下的根目录 .git 指针文件当「未声明文件」判红 ⇒ **任何 worktree 会话都会被门禁拦下** ⇒ 制度与工具不匹配时，门禁必须同步适配（本次在 scan 层排除 .git，judge 层判据强度不降并补单测）。
5. **「幂等守卫要下沉到被调函数内部，而不是只守调用点」**：守卫放在调用点时，任何其它调用路径都会绕过它 ⇒ 本批把滚动守卫下沉到函数内，并补「守卫不得退化为一律跳过」的对照组用例。
