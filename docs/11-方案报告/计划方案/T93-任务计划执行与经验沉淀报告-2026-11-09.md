## 执行摘要

**一句话结论**：合并后平台重算的 43 条 Dependabot 告警并非同质——**2 条 minimatch 是真告警**（依赖链实查确证），**41 条 Pillow 是未随清单变更重算的陈旧投影**（advisory 的 `first_patched_version` 全为 13.0.0，而清单已钉 13.0.0）；本批对前者做真修（精确版本选择器 override，受影响实例升到 11.0.5、非受影响实例版本不动），对后者改用**能触发重算的实质变更**（依赖名大小写归一，PyPI 名大小写不敏感，安装与导入行为零变化），不刷基线、不降判据、不靠 dismiss 掩盖。

**核心判定（三条）**：

1. **告警必须逐条判定，不能按包名批量处置** —— 43 条里 2 条 npm + 41 条 pip，两条生态的告警性质完全不同：npm 侧的 `minimatch@10.2.6` 确实落在 advisory 的 vulnerable 区间 `>= 7.0.0, < 11.0.1` 内；pip 侧的 41 条 Pillow 全部是「已钉到 `first_patched_version` 但告警未重算」。
2. **stale 告警要用「实质变更」触发重算，纯注释无效** —— W1191 曾以注释方式在 `requirements.txt` 记录复核结论，告警的 `updated_at` 仍停在 2026-10-24 ⇒ 平台未重新解析该清单。本批改为依赖名大小写归一（`Pillow` → `pillow`），使依赖行内容真实变化，钉版与依赖面均不变。
3. **npm 侧只能走 override，升级路径已被证伪** —— `eslint@latest`（10.14.0）仍声明 `minimatch: ^10.2.6`；`electron-builder@26.18.0` 仍带 `@electron/universal@2.x`（该包声明 `minimatch: ^9.0.3`）⇒ 升级两个上游包都不解除告警。精确版本选择器 override `minimatch@>=9.0.0 <11.0.1` 只覆盖落在 vulnerable 区间的实例，`glob@7` 的 `minimatch@3.1.5` 与 `filelist` 的 `5.1.9` 保持原版本，不引入 glob 7 与 minimatch 11 的兼容风险。

**本批产出**：① `scripts/package.json` 与 `xiyouji-desktop/package.json` 各加一条精确版本选择器 override + 两份 lock 同步；② `scripts/requirements.txt` 的 Pillow 依赖名大小写归一以触发重算；③ 面板基线逐条判定留痕（2 条真修 / 41 条 stale 源头处置 / 20 条 Code scanning 逐条定位核对）；④ 文档链：CHANGELOG 段 + 台账认领行 + HANDOVER + file-index + 本报告 + README 登记 107。

**本章结论**：43 条 Dependabot 告警全部有判定依据与处置去向；2 条真告警已真修并由 `npm audit` 双端 0 漏洞佐证；41 条 stale 告警的源头已改为实质变更，重算由平台侧异步完成，合并后复查确认。

**待确认事项**：41 条 Pillow 告警是否随本批清单实质变更被平台重算并关闭，取决于平台的异步重算节奏，合并后二次复查确认；`secret_scanning_validity_checks` 在 public + 个人账户仓由平台判定为不可用（需 GitHub Advanced Security 订阅），沿用 W1191 登记，本批未重复处置。

### 附录 B：Pillow 41 条为何判 stale

Dependabot 的 pip 告警给出两组关键字段：`security_vulnerability.vulnerable_version_range`（受影响区间）与 `first_patched_version`（首个修复版本）。本仓 `scripts/requirements.txt` 钉的是 `pillow==13.0.0`。41 条告警的 `first_patched_version` 集合基数为 1（全部为 `13.0.0`），21 种 `vulnerable_version_range` 的上界全部 ≤ `13.0.0`（形如 `< 13.0.0`、`<= 12.3.0`、`>= 10.0.0, < 13.0.0`）⇒ 13.0.0 落在全部区间之外。若告警为真，仓库应存在低于 13.0.0 的安装实例；清单里没有任何一条低于 13.0.0 的 Pillow 依赖行。

再取 `updated_at`：41 条全部停在 2026-10-22 与 2026-10-24，即最后一次清单解析的时间点，而 W1191 的清单变更（2026-11-09）没有让告警时间前进 ⇒ 平台未重新解析该清单。两组证据一致 ⇒ 判定为 stale 投影。

处置上，本批不选「dismiss 41 条」（掩盖信号、且告警会在下次清单变更时复活），而选「让清单发生实质变更以触发重算」。
