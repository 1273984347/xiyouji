## 执行摘要

**一句话结论**：PR #150 的 5 处红灯不是平台故障，而是**本地 65 个未推送提交的潜伏存量缺陷**在 Actions 上的投影；本批五处根因全修——其中暗色门禁 625 项恒红的真因是「断言域（全部基线行）与采集域（charts 面）错配」，修法是让断言域回到采集面内并把采集面口径收进单一模块，同时补一条「已下线页未登记即 FAIL」的补偿判据，使收窄不等于降判据。

**核心判定（五条）**：

1. **暗色门禁的 625 项恒红是断言域越界，不是缺陷激增** —— 基线文件 `scripts/output/render-state-audit-baseline.jsonl` 784 行混装两个采集面（charts 面 160 行 + reader 面 621 行 + 3 个已下线页），CI 只采 charts 面；W1155 深度审计新增的「基线页缺失 / 采集面萎缩」断言遍历全部基线行 ⇒ reader 面与已下线页被恒判缺失。W662 段原文已定口径「gate compare 只遍历 charts scope 当前输出侧，reader 行不参与比对」，W1155 的新增断言未按该口径限定 ⇒ 属实现偏离设计意图。
2. **CodeQL #120 是真问题，不能按假阳性 dismiss** —— `scripts/stat_event_probe.py:286` 用 `"goatcounter.com" in u` 做 URL 归属判定：既会误判 `https://evil.example/?u=goatcounter.com`，又被 CodeQL 判为不完整 URL 净化（security_severity_level=high）。改用 hostname 标签精确比对后语义更严，CodeQL 规则面同时消除。
3. **4 条断链是「相对路径跨目录复制」** —— W1181 段把正文（位于 `docs/` 下）的相对链接原样抄进仓库根的 CHANGELOG，`../03-主题与情节专题/…` 解析到仓库外；改为根相对即可，链接门禁 29321 条 0 broken。
4. **E2E 与 evals 两处是「上游变更后下游未跟上」** —— 页面自 W1169 起监听 `pointerenter`（测试仍派发 `mouseenter`）；evals dataset-039/041 指向的 `dataset/dashboard.json` 已于 W1157 删除（属孤儿件，不恢复）⇒ 两处都改下游，不改上游、不放宽断言。
5. **本批自身触发了一个存量工具缺陷，且该缺陷此前从未被执行过** —— CHANGELOG 段落盘后体积 264907 B 越过 262144 B 上限（pytest `test_real_tree_within_size_budget` 判红），迁段时 `archive_segments.py` 的 `_a3_ok` 因断言方向与 `split_tail_block` 行为相反而恒假 ⇒ **体积迁移路径自 W1130 起从未被真正跑通过**。根因在工具，不在本批代码；已根修并补 3 条回归锁。

**本批产出**：① 新建 `scripts/_render_scope.js` 作采集面口径单点来源，采集端与比对端共用；② 暗色门禁断言域限定到采集面内 + 已下线页白名单门禁 + 自测由 5 例扩到 9 例；③ CodeQL #120 真修（hostname 标签精确比对 + 7 例自测）；④ CHANGELOG 4 条链接订正；⑤ E2E A1 改派 `PointerEvent`、evals 两条改指现存等价数据集；⑥ 连带清偿：CHANGELOG 与 file-index 双面体积回窗（迁出 W1108-W1109 两段）+ 归档工具 `_a3_ok` 根修 + 3 条回归锁；⑦ 文档链：CHANGELOG 段 + 台账行 + HANDOVER + file-index + 本报告 + README 登记 106。

**本章结论**：五处红灯的根因全部定位到「哪一层错了」，修法均为改根因而非改判据强度；暗色基线未刷新（刷新会把 784 行砍到 168 行并抹掉 reader 面 621 行，属降判据），其余判据强度持平或加严。

**待确认事项**：PR #150 重推后的平台侧重算结果（Dependabot 与 Code scanning 的残余 open 计数）需在 CI 跑完后二次复查，依赖平台异步任务；`secret_scanning_validity_checks` 在 public + 个人账户仓由平台侧判定为不可用，需 GitHub Advanced Security 订阅方可开启（沿用 W1191 登记，本批未重复处置）。

## 0. 任务背景（读者无需回看会话即可理解）

《详解西游记》仓（xiyouji）是一个静态站点 + 多 Agent 协作治理仓。本批的起点是用户诉求「把 GitHub 上面的 Security and quality 里面的所有问题一并解决」的延续处置。

上一批（W1191）把 65 个本地提交推上远端并开出 PR #150（head 分支 `sync/w1191-main`）。PR 的 **required checks 已双绿**：`Delivery Gate (verify_delivery.py)` 与 `Unit Tests (pytest)` 两个 job 均 success。但 PR 的其余 CI job 仍有 5 处红灯：

| 失败 job | 症状 | 根因层 |
|---|---|---|
| `CI-side simulation` | 链接门禁 4 条 broken | 文档面（CHANGELOG 路径基准写错） |
| `Agent Web Build` | step 11 `Golden evals validate`：FAIL 2 项 | 语料面（指向已删数据集） |
| `CodeQL` | 1 new alert including 1 high severity（#120） | 判据代码面（URL 子串匹配） |
| `Dark-state gate (merge shards)` | 625 项 FAIL（基线 784 页 / 当前 168 页） | 门禁判据面（断言域越界） |
| `E2E Interaction` | `FAIL A1 popup 转义拼串` | 测试面（事件族迁移未跟上） |

**共同结构**：五处都不是平台侧故障，而是**本地 65 个未推送提交从未跑过 Actions** 而暴露的潜伏存量缺陷。required checks 之所以双绿，是因为它们只跑单测与交付门禁，不跑上述五条链路。

**本批的处置边界**：修根因，不降判据强度（不改门禁阈值、不改测试断言让它变绿、不刷暗色基线）；证据一律来自实跑命令或 API 响应。
