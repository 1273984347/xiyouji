## 0. 背景与结论速览（执行摘要）

**本批针对**：用户批准三项后续工作（① 暗色补偿失配的 ΔL\* 阈值机器判据 ② 补偿机制改按令牌匹配 ③ 档 3 铺开）。三项工作都缺同一份前提：**档 3 的真实范围与补偿机制的真实规模与来源**。本批为**只读盘点批**（site/ 页面改动 **0** 件·结论可由 git diff 直接核验）。

**核心判定**：

1. **档 3 真实口径 = 1412 处 / 145 页**（互斥归类·层内再分调色板色与自有 hex）：L2 echarts 配置色 **348**（84 页）· L3 Canvas fillStyle/strokeStyle **0**（调色板色）· L4 通用 CSS 属性值 **6**（16 页）· L5 裸 hex 字面量 **1058**（143 页）。
2. **校验项通过**：以「任意 6 位 hex」统计会把档 1/档 2 误算成 994 处 ⇒ 与「已归零」矛盾；分层后实测**档 1/档 2 的调色板色 = 0** ⇒ 证实两档确已归零。
3. **另有 3404 处页面自有 hex**（非 12 色调色板）⇒ 属**设计色板扩充**议题，**不并入档 3**（混在一起会把 1412 处放大成 4816 处）。
4. **补偿机制盘点**：前缀型规则 **990 条** + 字面值型 **20130 条**，覆盖 **330 页**；**规则集合指纹仅 1 种**（每页 112 条一模一样）⇒ 同源模板复制；scripts/ 内**无生成器** ⇒ 属历史一次性粘贴；tokens.css 另存**共享副本 114 处**。
5. **工程次序定案（三项工作的落地序）**：
   - **W1101 = ΔL\* 阈值机器判据**（工具层·独立可做·不依赖页面改动）；
   - **档 3 施工**（1412 处 / 145 页 ⇒ 按 ≤10 页/批切 **15 批**）⇒ 其中 echarts 层（348 处）机制与 SVG 层不同源（库自解析颜色串·不吃 CSS 变量）⇒ **先做 1-2 页机制原型验证批**，再规模化；
   - **补偿机制收口** ⇒ **必须等档 3 令牌化完成后再做**：补偿表含 12 色调色板色条目且当前对仍以字面值存在的调色板色**仍生效** ⇒ 此时删除会让 1412 处暗色失去补偿而变暗 ⇒ 属**真实视觉变化**，不可先做；
   - **补偿按令牌匹配的长期解法**（让补偿对令牌元素也生效）⇒ 需新增语义类机制 + 330 页改造，收益（令牌暗色值已上调）与成本不匹配 ⇒ 建议以「补偿表只服务自有色、令牌色自带暗色值」的口径固化收口。

**本章结论**：三项工作已全部具备开工依据；建议按 W1101（ΔL\* 判据）→ 档 3 原型验证批 → 档 3 规模化 → 补偿收口 的次序推进。

## 4. 复盘

### 4.1 做对了什么

1. **先校验口径再报数**：用任意 hex 口径算出 994 处时，发现它与「档 1/2 已归零」矛盾 ⇒ 立刻定位到口径缺陷并分层修正 ⇒ 避免把 4816 处当档 3 铺开。
2. **用指纹判同源**：330 页 × 112 条规则若逐页看会是 20130 条的巨量工程量；指纹仅 1 种 ⇒ 一眼看出可机械处理 ⇒ 工程量判断从「逐页改写」降为「一段文本替换 + 断言」。
3. **抽验补偿表是否含调色板色**：这一步直接决定了「收口必须排在档 3 之后」⇒ 否则会做出让 1412 处暗色变暗的真实退化。

### 4.2 该改什么

1. **归档盘点脚本的输出文案与实现不一致** ⇒ 建议修文案或补互斥实现，避免下一批沿用错误口径（E-90 已记纪律）。
2. **补偿规则应有一份机器判据化清单**（哪种字面值 ⇒ 哪条补偿 ⇒ 令牌化后是否失配）⇒ 可直接支撑死规则收口的自动判定。
3. **ΔL\* 阈值判据**（W1101）应把「补偿失配的可接受幅度」变成可机读数字，并能用本批的 1412 处调色板色清单做全量体检。
4. **生成链顺序须固化为单一入口**：本批把「add → 目录 refresh → 搜索索引 → CSP → 文档索引 → **再**搜索索引 → **再** CSP → 再 add」固化为 archive/scripts/batches/w1100/_w1100_refresh_chain.py ⇒ 免去每批重新推导顺序（见 §2.2 B-04）。

### 4.3 交接口径（后续三批的次序与切法）

- **次 1（W1101）= ΔL\* 阈值机器判据**：工具层，独立可做，不依赖页面改动。建议做法：J2 探针新增「补偿失配 ΔL\*」读数（暗色下补偿前后色的 ΔL\* 差），阈值取**建议值并可配**（推荐先取 12 作为告警线，实测校准后再收紧），超阈值页自动列出 ⇒ 落 scripts/visual_regression_probe.py + 单测。
- **次 2 = 档 3 原型验证批（1-2 页）**：优先挑 **echarts 层**（L2 348 处 / 84 页）里的 1 页做「读令牌喂图表」原型（echarts 不吃 CSS 变量 ⇒ 须从 getComputedStyle 读令牌值再喂给 echarts）⇒ 实测确认后再规模化；SVG 层的 L5（1058 处 / 143 页）与 L4（6 处）可直接照档 1/2 的路径推进。
- **次 3 = 档 3 规模化**：145 页 ⇒ 按 ≤10 页/批切 **15 批**；建议**中英双胞胎页同批**（内容对应 ⇒ 同批处理省一半工序与取证量）；每批验收沿用「差异清单与预期一致」口径 + 元素数取稳定值（E-89）。
- **次 4 = 补偿机制收口**：档 3 完成后，补偿表中的调色板色条目成为**死规则**（已无字面值可匹配）⇒ 330 页 + tokens.css 的机械删除（断言每页替换数 = 112）⇒ **零视觉变化**（失配规则本就未命中）⇒ 同时把「补偿只服务页面自有色、令牌色自带暗色值」的口径写进 tokens.css 注释与坑表。
- **长期解法（可选·成本高收益低）** = 让补偿对令牌元素生效：需给令牌元素加语义类并改 330 页规则 ⇒ 与「令牌暗色值已上调」的既有裁决部分抵消 ⇒ 建议不做，改以口径固化收口（D-03）。
