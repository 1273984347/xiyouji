## 执行摘要

W1282 起因于用户在浏览器对 `site/data/81-hardships.html` 与 `site/en/81-hardships.html` 的两处图表（treemap 树图 / 桑基图）连续追问「图表内的文字你能看清楚吗？」，并明确指出「中文页、英文页都有问题」。**本批最重要的产出不是修复本身，而是一次对既有结论的自我证伪**：上一批（W1281）把该现象归因为「treemap 标签两行 y 坐标相同 ⇒ 文字重叠成糊」，本批用 Playwright 逐元素取证**推翻了这个机制解释**，坐实真因是**对比度崩塌**（白字压浅赭底 CR=1.80）与**字号被公共层 `!important` 压到 10px**；同时查出第 80 门禁（SVG 文字对比度）存在**判据级盲区**——它的底色口径只找 CSS `backgroundColor`，而 SVG 图形的底色是 `fill` 属性 ⇒「文字压在色块上」的真实对比度**从未被测量过**，这正是该类缺陷能长期存活的门禁层根因。

**本批产出**：① treemap 6 页（ZH/EN × `81-hardships`/`aesthetics`/`global-pattern`）标签可读性修复，最低对比度 **1.80 → 3.99**（明）/ **4.61**（暗），字号 **10px → 12px**；② 第 80 门禁新增 `graphic` 底色口径（几何配对 + CTM 归一化 + 光晕分离度判定），实测使 site/data 存量违例从 **0 条 → 646 条 / 45 页**首次可见；③ 两处既有结论的错误机制描述已订正入仓（CHANGELOG ⑦ 条、T114 §十一 ③、台账 W1281 行）；④ 门禁自测 8→18 项、新增回归锁 13 例、node 探针几何自测 8 例，全绿。

## 一、执行前计划

**目标**：把「图表内文字看不清」从主观观感转成可量测、可拦截的工程判据，并修复已确认的真缺陷面。

**取证优先（承 AGENTS 铁律 7「先取证再假设」）**：用户反馈是「看不清」，可能对应多种机制（重叠 / 低对比 / 字号过小 / 描边冲淡 / 渲染失败），**不得凭视觉印象选一个机制开修**。故本批第一步是建探针实测，不是改代码。

**取证手段**：Playwright + 浏览器 CSSOM 逐元素采集（`getComputedStyle` 的 fill / font-size / stroke / stroke-width / paint-order、`getBBox` 几何、`document.elementFromPoint` 归属），并**亲自看渲染图**（AGENTS 铁律 E-244：视觉问题必须交付者本人看图，不交探针数字）。

## 二、根因取证（本批核心）

### 2.1 自我证伪：上一批的机制解释是错的

W1281 结论写的是「treemap 标签两行（名称 + 百分比）y 坐标相同 ⇒ 文字重叠成糊」，依据是「treemap 文本 bb=[5,4,66,27] 而 font-size 仅 10px ⇒ 单个 text 内两行同位」。

本批逐元素实测（`site/data/81-hardships.html`，`#chart-cause`）：

| 项 | 实测值 | 判定 |
|---|---|---|
| 名称行 bbox | y = 4.3 ~ 16.8 | — |
| 百分比 tspan bbox | y = 16.8 ~ 31.1（`dy=1.25em`） | — |
| 两行是否相交 | **否**（16.8 相接，不重叠） | ❌ 上一批结论不成立 |

**上一批是把「整体 bbox 高度 27px 看起来像两行叠一起」误读成「两行同位重叠」**。这是「用单个聚合指标（bbox 高度）代替分元素逐项取证」造成的误判——数字本身没错，**解读错了**。

### 2.2 真因三条（逐条实测）

**真因一：对比度崩塌（致命）**

treemap 标签用硬编码白字 `.style('fill','#fff')` 压在单元格色块上。实测各色块的前后景对比度（WCAG 标准公式）：

| 单元格底色 | 前景 | 对比度 CR | 判定 |
|---|---|---|---|
| `#e9b885`（浅赭·ENDING 分类） | 白字 | **1.80** | ❌ 远低于 3:1 图形对象线，实不可读 |
| `#8E7D62`（褐·CAUSE 分类） | 白字 | **3.99** | ⚠️ 勉强 |
| `#C0392B`（朱砂） | 白字 | 5.44 | ✅ |
| `#40619E`（靛蓝） | 白字 | 6.14 | ✅ |
| `#3A473A`（苔绿） | 白字 | 9.80 | ✅ |

**只有浅色底必然糊** ⇒ 这是**配色与前景绑死**（白字写死）的结构性缺陷，不是偶发。

**真因二：字号被公共层 `!important` 压到 10px**

页面内 d3 代码写 `.style('font-size','0.74rem')`（html font-size = 16px ⇒ 11.84px），但公共层 `site/system.css` 有：

```css
svg text { font-family: var(--font-data) !important; font-size: max(9px, 0.625rem) !important; }
```

`!important` 覆盖内联 style ⇒ 实测 computed font-size = **10px**。中文在 10px 下辨识度极差，英文亦然。

**真因三：白描边叠加**

`site/data/81-hardships.html:159` 有 `svg text { paint-order: stroke; stroke: rgba(255,255,255,0.88); stroke-width: 3px; }` ⇒ **白字叠白描边**，浅底上轮廓与填充一起糊掉。

### 2.3 范围：不止两页

全站普查（168 个含 `<svg>` 的页，Playwright 逐页实测）：

- 中心点配对口径：命中 **112 页**
- 收紧为「文字 bbox ≥60% 落入图形 bbox」：命中 **107 页 / 1286 处**，最低 CR = **1.00**

按图元类型分层（真缺陷候选）：`node-circle`（网络图节点圆）73 处、`event-node` 62 处、`matrix-cell` 16 处、`radar-poly`（雷达多边形）10 处、`heat-cell` 5 处、`scatter-dot` 6 处等。

**中英文站同款**（`en/` 与 `data/` 命中页一一对应）。

### 2.4 探针自身的误判（取证纪律：不把探针数字直接当结论）

第一版普查探针用「文字中心点是否落在图形 bbox 内」配对前后景 ⇒ **大量假阳性**。亲自看渲染图复核发现三类误判：

1. **条形图**：数值标签（`7`/`6`/`5`）在条形**外**的米底上，却被配到了条形矩形 ⇒ 假阳性
2. **折线/力导向图**：节点标签在曲线旁，**不压任何图元** ⇒ 假阳性
3. **环形图**：`12.6%`/`57.6%` 压在深色扇区上 ⇒ **真缺陷**

**结论**：探针命中数 ≠ 缺陷数。须以「标签位置是否由该图元决定」为判据（treemap 单元格内、雷达顶点上、热力格内 = 真；条形/折线旁的标注 = 假），且**每个结论类别必须抽样目视复核**。

## 三、门禁级根因：第 80 槽的判据盲区

第 80 门禁（`scripts/check_svg_text_contrast.py` + `scripts/svg_text_contrast_probe.js`）声称在管「SVG 文字对比度 ≥ 3:1」，但其底色口径只有两种：

- `body`：页面 body 的 `backgroundColor`
- `backdrop`：自元素向上找第一个非透明 CSS `backgroundColor`

**而 SVG 图形（rect/circle/path）的底色是 `fill` 属性，不是 CSS `backgroundColor`** ⇒ `backdropOf()` 永远找不到它 ⇒「文字压在 SVG 色块上」的真实对比度**从未被测量过**。

实证：`#e9b885` 上的白字真实 CR = 1.80，但探针因找不到图形底色而回退到 body 背景（米色）⇒ **判绿（漏检）**。

现有基线 `scripts/output/svg-text-contrast-baseline.txt` 记录「违例键 0 条」⇒ 该门禁自建立以来，在这块面上**一直是空跑**。这与 W1259 审查报告里「既有门禁没抓住」的自述一致，但至今未被修复。

## 四、施工（两路并行）

### 4.1 线路一：treemap 标签可读性修复（6 页）

**范围判定**：全站 14 页使用 treemap 的页面中，8 页（`cultural-misreading`/`deconstruction`/`jurisprudence`/`game-webnovel` 的 ZH+EN）**已实现**按底色亮度自适应填充；仅 6 页仍是硬编码白字 ⇒ **缺陷面精确为 6 页**，修法**复用既有同款写法**（禁另创阈值）。

**三处改动（每页）**：

1. **前景色自适应**：`.style('fill','#fff')` → 按单元格底色亮度取 `#23201A`（深墨）/ `#fff`（白），阈值 0.62（沿用仓内既有口径）；
2. **字号下限**：页内私有 class `tm-cell-label` 以 `font-size: 12px !important` 压过公共层 `svg text { font-size: max(9px,0.625rem) !important }`（**不动公共层**·全站 875 页不涉）；
3. **描边自适应**：白字配深色描边（`dark-halo`）、深字配浅色描边（`light-halo`），并在所选色 CR < 3 时改用对比更高的一方；百分比 tspan 的 `opacity: .85` 合成后 CR < 3 时按最小幅度提浓。

**暗色态的额外发现（实施者提出·主会话复核采纳）**：公共层在暗色态会把图形填充映射成暗色序列色并加 `brightness()` 提亮（实测 `#8E7D62` → `rgb(193,190,139)` **变浅**），与字面色的亮度方向**相反** ⇒ 只按字面色判断会在暗态选错前景。故按**渲染后实际色**重算，并挂 `MutationObserver` 监听 `data-theme` 变化重算。

**英文长标签裁切（存量缺陷·本批收口）**：EN 站 `Heavenly / Western steeds incarnate` 等标签在 12px 下超出单元格右边界被裁断（修复前 10px 时同样被裁 ⇒ 存量缺陷，但字号放大后更明显 ⇒ 属本批必须收口的视觉退化）。修法：**二分法按可用宽度截断并加省略号**（`getComputedTextLength()` 实测宽度）。

### 4.2 线路二：第 80 门禁新增 graphic 底色口径

**几何配对判据**（本批核心技术点）：

| 图形 | 覆盖规则 | 假阳性排除依据 |
|---|---|---|
| `rect` 等实心盒 | 文字中心点在图形 bbox 内 **且** 交集面积/文字面积 ≥ **0.6** | 「旁边有色块」时交集≈0 ⇒ 必然排除 |
| `circle`/`ellipse` | 文字中心点落在**真实椭圆**内 且 交集比 ≥ 0.6 | bbox 是外接矩形，角落不在椭圆内 ⇒ 避免「环形图中心孔洞」误判 |
| `path`/`polygon` | **仅当 bbox 完全包含文字 bbox** 才算覆盖 | path 的 getBBox 是几何近似 ⇒ 宁可漏检不可误报 |

**坐标系归一化（必须）**：`getBBox()` 取几何、`getCTM()` 把 4 角点变换到同一 `<svg>` 的 viewBox 用户空间再比较；**禁用 `getBoundingClientRect()`**（视口像素在 CSS 缩放 / viewBox 变换 / 滚动后会与图形层错位）。实证：不归一化时 treemap 中分属不同 `<g transform=translate(...)>` 的 rect 会互相错配 ⇒ 真实违例被漏掉。

**光晕处理**：body/backdrop 两口径**一字未改**（有光晕即整条跳过）；graphic 口径按「光晕是否真有分离」判定——光晕色按 alpha 合成到底色后与底色对比度 ≥ 3.0 才豁免 ⇒ **白字+白晕压浅底**时光晕零增益（对比仅 1.68）⇒ 豁免失效 ⇒ 按真实 CR 1.80 判红。

**其余规则**：候选须同 `<svg>`；有效 alpha = fillAlpha×fillOpacity×opacity ≥ 0.3；多层重叠取**面积最小**者；找不到覆盖图形 ⇒ 回退 body 口径。

**门禁侧同步**：基线新增 `# bg_mode:` 声明与**口径隔离**（报告口径 ≠ 基线口径 ⇒ fail-closed 拒绝通过）；`--baseline` 独立基线路径；自测由 8 项扩到 **18 项**；既有语义（基线冻结 / `--strict` / `--report` / `--generate-baseline` / 报告缺失 fail-closed）**全部保持**。

### C. 术语与口径说明

- **CR**：WCAG 相对亮度对比度 `(L1+0.05)/(L2+0.05)`，本批图形内文字阈值取 **3.0**（WCAG 1.4.11 图形对象最低可读线）。
- **graphic 口径**：第 80 门禁新增的第三种底色口径，底色 = 几何上真正覆盖该文字的 SVG 图形的 computed `fill`（与 body/backdrop 两口径并存且行为不变）。
- **光晕分离度**：把光晕色按 alpha 合成到底色后与底色的对比度；≥ 3.0 才视为光晕真的提供了可读性分离。
- **存量基线**：门禁基线内的违例记「存量」不计 FAIL；基线外新增 = FAIL；基线缺失 = fail-closed。
