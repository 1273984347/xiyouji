## 执行摘要

**一句话结论**：这 41 条 Pillow 告警不是 stale 投影，而是**依赖图里残留着一条活条目**——GitHub 依赖图对同一 manifest 路径的依赖条目只增不减，清单内容变更（连同改版本号、改依赖名大小写）只会新增条目、永不删除旧的 `pillow@12.3.0`；而告警引擎按依赖图当前状态评估 ⇒ 告警永远 open。本批用「删除该 manifest 再逐字重建」让路径在 `main` 上消失一次，迫使依赖图移除该路径贡献的全部条目，随后重建写入干净的 `pillow@13.0.0`。

**核心判定（三条，均为实测读数）**：

1. **依赖图当前快照里确有 12.3.0 的活条目** —— SBOM API（`GET /repos/1273984347/xiyouji/dependency-graph/sbom`）返回三个 pillow SPDXID：`13.0.0`（`…-a79831`）、`12.3.0`（`…-aa74cb`）、`13.0.0`（`…-604b40`），其中 `12.3.0` 被 `SPDXRef-github-1273984347-xiyouji-main-93a52b` 以 `DEPENDS_ON` 直接引用；`creationInfo.created = 2026-11-10T08:26:12Z`，`creators` 含 `Tool: dependabot`。
2. **12.3.0 不是任何一次解析的产物** —— 抓 GitHub 自身 Graph Update run 的日志：run `42753213397`（2026-11-10T04:01:57Z）与 `42633604982`（2026-11-09T14:19:50Z）的 `manifests → resolved` 段里，`scripts/requirements.txt` 与 `scripts/requirements-hashed.txt` 解析出的都是 `pkg:pypi/pillow@13.0.0`，**从未出现 12.3.0**；run `39845764755`（2026-10-22T20:05:17Z）的 `blob_oid = 888997d89068c2da07bc10d772b8622acd7bbbb4` 与 `654a289c:scripts/requirements.txt` 逐字相同（该版内容已是 `Pillow==13.0.0`），而 `654a289c^` 的 blob 是 `3a012297fbb3721c84fa6e37d2a3f524f87ed45b`（内容为 `Pillow==12.3.0`）⇒ 12.3.0 只能来自历史 blob 留下的条目。
3. **前两批修法在机制上不可能生效** —— W1191（纯注释变更）与 W1193（依赖名大小写归一）都只是让依赖图**新增**条目，从不触发删除；这解释了「清单早已钉 13.0.0 而告警仍在、`updated_at` 停在 2026-10-22」的现象。

**本批产出**：① 修法落地为两个相邻提交——先删除 `scripts/requirements.txt`（CI 的真实安装源自 W1195 起本就是哈希化清单，删除不改变 CI 行为），再逐字重建（`git diff 0fa83828 -- scripts/requirements.txt` 行数为 0），使 `main` 上依次出现「该路径不存在」与「该路径重建」两个状态；② CI 判据同源修正：4 处 `cache-dependency-path` 与 2 处 pip-audit 扫描源改指 `scripts/requirements-hashed.txt`（审计覆盖面由 9 项直接依赖扩到 51 项闭包，实测 rc 0）；③ J3 判据漂移修正：`test_ci_wiring.py` 的 PyYAML 登记断言自 W1195 起已与 CI 安装源脱节，本批改绑真实安装源并加回第二段断言；④ 坑表 E-219 入表与计数链同步（312 → 313）。

**本章结论**：41 条告警的成因已从「平台未重算」纠正为「依赖图条目累积」，修法已按该成因落地；面板终态读数的核验方法已固化（见 §7 附录 A），终态数值待合并后由下一批回填登记。

《详解西游记》仓（xiyouji）是静态站点 + 多 Agent 协作治理仓。用户诉求：把 GitHub「Security and quality」面板里的问题一并解决。

W1193 据此判定这批告警是「未随清单变更重算的 stale 投影」，并用依赖名大小写归一（`Pillow==13.0.0` → `pillow==13.0.0`）制造依赖行实质变更以触发重算。合并后告警数未变（仍是 41 条），`updated_at` 仍停在 2026-10-22 与 2026-10-24。

本批用户诉求：**触发依赖清单实质重算并核验面板是否归零**。
