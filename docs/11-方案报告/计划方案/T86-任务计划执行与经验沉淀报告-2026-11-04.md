## 0. 背景与结论速览

**触发**：2026-11-04 代第三方会话解 W1125 与 main 的合并冲突时，第 51 槽「提交范围门禁」把归属判成 **W1127（他批）** 而非本批 W1125 ⇒ 提交面被拿他批 spec 判定 ⇒ 报「索引含本批 spec 之外的文件」。

**根因（实读确认，非推断）**：`scripts/check_commit_scope.py` 的 `pick_target_merged()`（W1123 批新增）**主路径已实现 merge 带入面剔除**（`new_segs = idx_segs - segments(head_text) - carried_segs`），但其**兜底调用** `return pick_target_with_coverage(index_text, head_text, staged)` **未透传 `main_text` / `carried`** ⇒ 兜底分支内「恰 1 个新增段且非顶位」判定用的是**含 main 侧带入段**的段集合 ⇒ merge 提交把 main 的更高号批带入、而本提交自己的段在下方时 ⇒ 顶段判据落**带入段（他批）** ⇒ 归属劫持。

**修法（公开 API 零变更，默认路径逐字不变）**：① **不追加公开函数参数**——公开函数 `pick_target_with_coverage()` 签名与行为**逐字恢复 HEAD 原样**，新语义下沉到**私有助手** `_pick_target_with_coverage_merged(..., main_text=None, carried=None)`，`pick_target_merged` 的兜底改指该私有助手（首版「给公开函数追加可选参数」方案被 api_diff 判为破坏性 API 变化 ⇒ 改用仓内 W1117/W1123 既有惯例，见 D-06 / DD-07）；② 「新增段集合」改为「索引段 - HEAD 段 - **main 侧带入段**」；③ 剔除后无新增段 ⇒ 用「**剔除带入文件后**的路径集」做 spec 覆盖性反查；`pick_target_merged()` 兜底调用改为透传 `main_text` / `carried`。

**结论**：**符合**。单测 **5** 例全过 · pytest **1326 passed / 4 skipped** · 全量门禁 **62 段 0 FAIL** · ruff 0 违规 · 坑表计数链 268 不动。

### 1.2 目标与完成标准

#### 1.2.1 任务目标

根修第 51 槽在 **merge 场景**下的归属劫持：使「merge 提交把 main 的更高号批带入、而本提交自己的段在下方」时，归属仍落**本批**而非带入段（他批）。

#### 1.2.2 不完成定义

1. 归属仍落带入段批号；
2. 默认参数（`main_text=None` / `carried=None`）下既有行为发生变化；
3. 真·代提（文件不在本批 spec 内）不再判红；
4. 既有 W1129 多批归属单测回归失败。
