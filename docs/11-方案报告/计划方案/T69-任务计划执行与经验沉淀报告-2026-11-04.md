## 0. 背景与结论速览

**一句话**：把「Actions 消耗 782 分钟是我方连续推 PR 造成的」这句归因从**推测**变成**实测**，并把最大的两个成本单点（暗色态门禁在 PR 事件下无跳过路径、Lighthouse CI 对未变页面重复采集）在 CI 侧根修；同时把只存在 Agent Memory 里的 13 条教训**同步进项目内坑表**（E-141 ~ E-153）。

**为什么做这一批**：用户 2026-11-04 指出「40 个 run / 152 个 job 已耗 782 分钟是你一直在推送开 PR」。实算复核确认归因成立，并定位到**更硬的一层根因** —— 成本不是 push 次数单独造成，而是「收官链版本面推进会改 site/ 页面」×「CI 的 paths 过滤是文件级」×「暗色态门禁的跳过判定只挂 push 事件」三者相乘。

## 2. 执行记录

### 2.1 执行经过

1. **归因实测**：gh api 取最近 60 个 run，按 headSha 聚合 ⇒ 我方 37 run / 330.7 分钟（79.1%），对方 23 run / 87.5 分钟（20.9%）；PR 数 14:6。最刺眼单点：W1116 一批推 4 笔 ⇒ 约 30 个 run ≈ 全部 run 的一半。
2. **根因定位**（比推得多更硬的一层）：PR #122 的文件清单含 site/data/search.html 与 site/en/search.html ⇒ 命中 site/** 的 paths；而 screenshot-review.yml 的暗色态门禁跳过判定写着 if 事件等于 push ⇒ **PR 事件下没有任何跳过路径** ⇒ 每次 push 命中即跑全站约 163 页 × 4 分片。
3. **根修**：暗色态门禁判定扩展到 pull_request 且 schedule 与 workflow_dispatch 恒全量；非渲染面文件（页脚版本号页 / 搜索索引数据页 / 部署数据副本）进免审名单；Lighthouse CI 在 5 个采集页未变时跳过采集；merge 汇总 job 与上游 skipped 联动。
4. **经验同步**：Agent Memory 内 W1114~W1118 的 13 条教训落坑表 E-141 ~ E-153，坑表 242 → 255 条，计数链 11 处同步。
5. **节奏收紧**：本批一次提交一次推送一个 PR。
