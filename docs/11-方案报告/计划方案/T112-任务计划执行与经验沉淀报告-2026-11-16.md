## 八之三、色盲安全色板的搜索与落地（W1261 追加）

**触发**：独立盲审后跑第 29 槽（色盲安全），发现**本批新序列色板自身**在色盲下不可辨——
8 槽里有 **8 对** ΔE < 10（最差 series-3 × series-8 = **0.5**，赭与陶几乎同色）。

**根因**：初版色板是「按审美挑的暖色有序渐变」，**没有把色盲可辨性当约束**。

**修法（约束搜索，不是手工挑色）**：

1. 约束：每槽对画布对比度 ≥ 3.2（亮）/ ≥ 3.0（暗）；**每两两配对**在 Machado 2009 两型矩阵
   （deuter / protan）下最小 CIEDE2000 ΔE ≥ 10（沿用第 29 槽既有阈值）；
2. 色相锚定在宣纸刻本色族内（朱砂 / 靛 / 赭 / 苔 / 淡墨 / 紫檀 / 青灰 / 紫梅），
   避免优化跑偏到亮蓝柠檬黄；
3. 暗色组**独立取值**（不是亮色反色），同色相下用亮度阶梯拉开可辨度。

**结果**：亮色组最小 ΔE = **12.03**、暗色组 = **11.04**；两组的每槽对比度均 ≥ 3.0。

**关键发现（值得复用的经验）**：

- **暖色槽位密度是瓶颈**——朱砂与赭同属暖色族，二者 ΔE 天然偏低；
  第 8 槽最终取**紫梅**而非陶土：陶土与朱砂/赭构成三暖色，ΔE 落到 8.6–8.7（不达标）。
- **--accent-text 必须与 --accent-primary 同值**——两者都是「朱砂」，若各自取值就变成
  第二种难辨的朱砂（ΔE = 3.3）⇒ 改为 `--accent-text: var(--accent-primary)`，
  暗色组无需单独声明（自动跟随）。
- **--accent-muted 也要色盲可辨**——原深朱砂 #9E2E23 与 accent 的 ΔE 仅 5.9 ⇒ 改 #7E2A1F（ΔE 10.46）。

**连带修的判据侧缺陷（3 处，均为「口径把非数据色当数据色」或「把补偿目标当色板成员」）：**

| 判据 | 原行为 | 修后 | 依据 |
| --- | --- | --- | --- |
| 第 29 槽色板提取 | 把**暗色补偿规则**里的 hex 当色板成员 | 剔除 dark 主题的 fill/stroke 属性选择器规则 | 那些 hex 是补偿目标值，不是页面实际绘制的系列色 |
| 第 29 槽色板提取 | 把 **UI chrome 令牌**（轴线 / 网格线 / 卡片边 / 表面层 / 文本层）当数据系列色 | 显式排除这些令牌名 | 色盲安全是数据系列问题，轴线与卡片边不同框出现 |
| 第 43 槽稳定性判据 | 签名含 **KPI 文本内容** | 签名只用元素数 | 本站 KPI 带 count-up 动效（W462·900ms），动画期文本持续变化 ⇒ 签名永不稳定 ⇒ 假红 dom-unstable |

**效果**：第 29 槽基线外违规 **2934 → 0**（同步冻结新基线 149 对存量）；
第 43 槽 **1 FAIL → 0 FAIL**；页面内 347 处旧色板字面量迁移到新序列色。


### 8.3.1 色板迁移的连带处理（实测）

色板换了之后，有三处「跟着旧色板走」的资产必须同步，否则会出现「令牌是新色、页面画的是旧色」
或「暗色补偿指向不存在的 hex」：

| 资产 | 规模 | 处置 | 实测 |
| --- | --- | --- | --- |
| 页面内 colorMap 字面量（`"标签": "#hex"`） | 347 处 / 54 页 | 重写到新序列值 | 抽测 `chapter-stats` 图例已用 #C0392B / #40619E / #3A473A |
| 页面内数组形态与 d3 `.attr('fill','#hex')` | 3,024 行 / 869 页 | 同上（跳过暗色补偿规则） | 抽测 `ecology` / `hardship-heatmap` 渲染填色 = 新序列值 |
| 暗色补偿规则（`html[data-theme=dark] svg [fill="#xxx"]`） | 1,732 处 / 866 页 + 源 111 条 | 选择器与补偿值一起对齐到新色板 | 源 `tokens.css` 已同步（2 条规则改写） |

**为什么补偿规则必须一起改**：补偿规则的**选择器**匹配「页面实际画的那个 hex」，
**值**是针对那个色在暗底上重新提亮的结果。色板换了之后只改选择器不改值 ⇒
暗色下会拿到为旧色调校的提亮值（偏色）。两者必须成对改。

**抽测渲染读数**（浏览器 computed style）：
`rgb(192,57,43)` = 朱砂 `#C0392B` · `rgb(64,97,158)` = 靛 `#40619E` ·
`rgb(58,71,58)` = 苔 `#3A473A` · `rgb(142,125,98)` = 赭 `#8E7D62` —— 全部落在新序列色上。

### 8.3.4 暗色态「形状不可见」的三层根因与逐层处置

暗色态门禁（第 56 槽）报「每页新增 10 处 invisible」⇒ 形状填充亮度 < 0.16 在深墨底上看不出来。
逐层定位后共三个独立根因，**每层都需要不同修法**：

| 层 | 根因 | 修法 | 关键认识 |
| --- | --- | --- | --- |
| ① | 页面 JS 用**亮色序列色的字面值**（fill="#C0392B"，亮度 0.1431） | 加暗色态**属性选择器映射**：`svg [fill="#C0392B"] { fill: var(--series-1) !important }`（大小写两种变体各写一条） | **换令牌不换页面 = 白换** —— 页面画的是字面值，不是令牌引用 |
| ② | 图表层覆写里的 `filter: none` **静默废掉**了 tokens.css 既有的暗色提亮补偿（brightness 1.12） | 移除该 `filter: none`；补 `brightness(1.45) saturate(1.05)` | 覆写层会**级联废掉**既有补偿规则；且 **filter 不改变 computed fill** ⇒ 靠 filter 过不了门禁 |
| ③ | **连续色阶**（热力图 `.range([...])`）插值出的中间值不在任何调色板里（如 rgb(166,50,43)） | 把色阶末端统一改为 `#E0604F`（亮度 0.2478·暗底可辨；亮底对比度 3.42:1 ≥ WCAG 图形门槛 3:1） | 连续色阶必须**两端都在两个画布上可读**，不能只看亮底设计 |

另有一处判据侧缺陷：属性选择器的 `i` 标志（HTML 大小写不敏感**属性匹配**）在 SVG 表现属性上不按预期工作
⇒ `el.matches(...)` 返回 false ⇒ 整条映射零命中而门禁全绿。已改为逐个枚举大小写变体（E-241）。

**暗色色板的第三道约束**：除「对暗底对比度 ≥3」与「两两色盲 ΔE ≥10」外，暗色组每槽**亮度须 ≥ 0.17**
（第 56 槽把 <0.16 判为不可见）。首版暗色板 #7C6175（亮度 0.1412）虽 ΔE 达标仍不可见 ⇒ 重搜后得
暗色组 min ΔE = **11.04**、每槽亮度 0.174–0.500。

## 四、经验沉淀

### 4.1【坑】门禁红不等于本批引入——先归因再动手

**现象**：跑 `check_icon_fields.py` 判红，报「白名单中已消失（需核销）8 条」，全部在
`site/data/narrative-experiment.html`。

**归因实证**（关键做法）：`git stash push` 把该文件回到 HEAD 版本后**重跑门禁**，**仍同样判红**
⇒ 该红**不是本批引入**。再 `git log -S '🪷'` 定位到 **W1231 批**（单侧键 schema 清理·
EMBEDDED 面板重灌）删掉了那 4 个 emoji avatar，白名单未同步核销 ⇒ **既有缺陷**。

**处理**：按门禁自身口径（`file + field + chars` 三元组，不含行号）核销 8 条 → 门禁转绿。

**纪律**：① 门禁红**先归因再动手**——用 `git stash` 回到基线重跑是最低成本的归因手段；
② 归因结论必须留证（本次留了 stash 前后两次门禁输出）；
③ **核销既有白名单 ≠ 掩盖缺陷**：核销前必须查清「为何消失」（本次查到 W1231 的真实动因），
若消失原因不明则不可核销。

### 4.2【坑】令牌追加会击穿「暗色计数」门禁——同主题同名声明产生 `_override_2`

**现象**：把旧令牌映射写成**追加**的第二个 `:root` + 第二个 `html[data-theme="dark"]` 块后，
`check_design_doc_drift.py` 判红：`JSON dark 78 != CSS dark 56`。

**根因**：`export_design_tokens.build_tokens` 对同主题同名声明生成 `_override_2` 键（键数按声明数，
门禁按**名数**计数）⇒ 追加即失衡。

**修法**：**就地改原声明**（把旧 `:root` 与旧 dark 块里的值直接重写为新语义层引用），
不追加第二套 ⇒ 每个主题每个名只有一处声明 ⇒ 门禁 `52 == 52` 通过。

**纪律**：① 「双轨过渡」若用**追加**实现，会与导出器的键生成规则冲突——**过渡映射应改写原声明**；
② 门禁报错时先看**判据的两侧口径**（名数 vs 声明数），别急着改内容。

### 4.3【坑】跨字体去等宽要按选择器分流，不是改令牌值

**问题**：新方向要求「数据用无衬线以利扫读」（禁科技感），但 `--font-mono` 被
`.cite-block code` / `pre.cite-text`（**代码与引文原文**）消费——代码等宽是**语义需要**，不是科技感。

**修法**：不动 `--font-mono` 的值，改为**选择器级**分流——代码块用新增的 `--font-code`（保留等宽），
其余数据位（轴标签 / 表格数字 / 索引编号）走 `--font-data`。

**配套实测**：去等宽前先在浏览器量了字体特性——Noto Sans SC 每个数字等宽（100px 下均 55.5px）
⇒ `tabular-nums` 对齐不破，换字体是安全的。

**纪律**：① 「某个令牌看起来该全局换」时，先查它的**全部消费面**（本次用脚本统计出 8 个系统级选择器 + 39 个页面私有选择器）；
② 换字体前**实测目标字体的数字等宽性**——「支持 tnum」不等于「默认就等宽」。

### 4.4【坑】探针自身的正则会被生成链的转义吃掉

**现象**：对比度探针跑出「SVG 文字总数 = 0」，但单页诊断显示实际有 243 个 `svg text`、
fill 为 `rgb(74,70,63)`（合法）。

**根因**：探针 JS 由 Python 脚本生成，`/rgba?\(([^)]+)\)/` 在写入时被转义破坏 ⇒ 颜色串永远解析失败 ⇒
**全部命中被静默丢弃**，而探针本身**退出码为 0**（不 fail-closed）。

**修法**：改用 **canvas 像素读色**（`fillRect` + `getImageData`）——完全绕开字符串解析，
且 `fill: none` 天然被 alpha=0 过滤。

**纪律**：① **产物类工具在「零命中」时必须 fail-closed**——零命中与「全部失败」不可区分；
② 跨语言生成代码时，**正则/转义是首要怀疑点**；③ 用**无正则的机制**（canvas 读色）比修补正则更稳。

### 4.5【经验】大范围视觉改版的高杠杆点排序

本批 866 页改动，**真正决定成败的不是逐页改，而是三个杠杆点**：

1. **令牌单一事实源**（`site/tokens.css`）——一处改，全站生效（866 页零页面代码改动即吃到新视觉）
2. **公共壳**（`site/system.css`）——组件级覆写，6 条交互原则一次落地
3. **d3 标准轴的 CSS 可治理性**——122 页用 `axisBottom`/`axisLeft` ⇒ 自动生成 `.domain`/`.tick` 类 ⇒
   **CSS 一处覆写即全站生效**，无需逐页改 JS

**纪律**：大批量改版先找「杠杆点」而不是「工作量面」——
把 866 页的视觉一致性压缩成 3 个文件的改动，是本批能在一次会话内完成的原因。

## 9. 增补：视觉落地复核轮的缺陷修复与遗留清单（2026-11-17）

### 9.1 触发与定性

用户实拍首页并追问「你确定现在的页面没有问题了？」⇒ 复核轮启动。定性：**不是"页面没问题"，而是"落地质量不达标"**——本批令牌层重构把「UI 交互强调色」与「数据序列色」绑成同值，导致全站链接/CTA 呈靛蓝，与朱砂单点强调冲突；同时发现本批自身引入的**暗色补偿规则零命中**缺陷。

### 9.2 根因（4 项）

1. **UI 色与数据色绑成同值**：本批把 `--accent-2/3/4` 就地重定向到 `--series-2/3/4`，而这两个令牌的旧语义是「链接 / 提示文字 / 正向数据」等**交互语义**（旧注释原文）。⇒ 全站 **6,834 处** `color: var(--accent-2)`（871 页）变成数据序列色靛蓝 #40619E，「唯一彩色强调=朱砂」失效。
2. **公共层与模板层不同步**：`_template.html` 早已把链接改为 `var(--accent-primary)`，但**公共层 `site/system.css` 仍写 `var(--accent-2)`**（7+2 处）⇒ 两处 CSS 各自演化，公共层成为漏网面（E-202 同族：「同一判据两处实现」）。
3. **暗色补偿规则带 `i` 标志 ⇒ 整层零命中**：`site/tokens.css` 的 111 条 `svg [fill="#xxxxxx" i]` 规则，在 SVG **表现属性**上 `i` 标志不生效（E-241 已实证）⇒ 公共层补偿从未命中；页面私有层虽已去掉 `i`，但**公共层这一层**仍失效，且 `rgb()` 形式的 fill 完全无映射。
4. **accent-soft 浅赭金（对宣纸底 1.58:1）被当作文字色**：2,035 处 `color: var(--accent-soft)`，其中各页 `.kicker` 眉题在浅底上不可读。
