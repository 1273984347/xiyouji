## 摘要

本批对全站界面布局做**复核 + 补审 + 落地方案**三件事，不改一行界面代码。

1. **复核**：用户指令的四维（信息层级 / 区块分布与留白 / 操作动线 / 不同屏幕适配）与 W854《界面布局审计报告》（2026-10-21）的四维几乎逐字相同 ⇒ 按仓内既有规矩（W926 §7.1 E-03「同一条指令重复下达时先查历史再动手」），本批不重做，而是**重跑 W854 的探针做四天后现状对拍**。
2. **补审**：补 W854 与 W926 均未覆盖的四个面 —— 页面级内联断点分布、375px 下装饰图压字、可见工程文本对布局度量的污染、v4 令牌族消费进度差。
3. **落地方案**：出 6 批可施工方案，每批带现状、理由、可机检验收判据与成本，交用户拍板后再动代码。

**为什么先出方案不动代码**：用户问卷明确「先出审查报告与落地方案、用户过一遍再动代码」；且本批复核发现多条问题需与并行批次（W928 D-1 实跑批 / W929 素材图批）协调共享面，先落方案可避免三批同时改 `site/`。

**本章结论**：本批为**只读审查批**，产物是报告与方案，不含任何界面代码改动。

## 0. 任务背景（读者无需回看会话即可理解）

**项目**：《详解西游记》AI 速查层 —— 一个静态站（`site/`，857 页：根 9 / reader 622 / en 138 / data 88）加一套 React 应用（`xiyouji-agent-web/`，对话式 Agent 前端）。

**用户诉求（2026-10-25）**：优化现有界面布局，逐项过四个维度 —— 信息层级梳理、区块分布与留白、操作动线、不同屏幕适配 —— **每处调整讲清理由**。问卷答复：范围**全站都做**；最想先解决**信息层级（重点不突出、一屏信息量过载）**；产出到**审查报告 + 落地方案**，用户过一遍再动代码。

**为什么这不是一份从零开始的审查**：同一工作区已有两份高完成度的同类产出 ——

| 产出 | 日期 | 管什么 |
|:--|:--|:--|
| W854《界面布局审计报告》 | 2026-10-21 | 四维（信息层级 / 区块留白 / 操作动线 / 多屏适配），18 条 |
| W926《站点交互流程审查复核报告》 | 2026-10-25 | 四维交互可用性（跳转 / 按钮 / 表单 / 空状态），12 条 |
| v4《界面视觉重设计方向 + 细化规格》 | 2026-10-20 | 五轴决策 A–E，已裁决落档 |
| T-08 / W865 | 2026-10-22 | 首页三任务区重组 + 目录页检索动线（已施工） |

用户本次指令 ≈ W854 原指令 ⇒ 若直接开审，会产出第四份高度重叠的报告。正确做法是**复核 W854 的 18 条 + 补它没覆盖的面 + 出落地方案**。

**待确认事项**：6 批施工方案需用户拍板排期（见同批报告 §5 的 U1–U4 四项决策）；本计划件不预设施工次序。
