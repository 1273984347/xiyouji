## 六、经验沉淀

- **物理约束类欠账只能自动化，不能靠人记**：提交含自身 hash ⇒ 台账 hash 每批必然欠一笔 ⇒ 纪律（「下批第一动作回填」）写在文档里**不会自动发生** ⇒ 必须**机器化进收官链**（W1298 实测：自动回填一次补齐 5 行）。
- **回填类工具动作要最小副作用**：只用 `--hash` 不传 `--status` ⇒ 状态列的详细终态结论不丢（`--from-git` 会覆盖它·W1289 实证）。
- **「叙事不可考」的条目要写成独立可执行纪律**，而不是留空或硬凑原文 ⇒ 空正文会让该坑**失去可执行性**；写成纪律后即使原文丢失，坑仍可用。
- **双面类结构要先问「各自的受众是什么」**：根壳（索引 + 反查）与 docs 壳（历史链接兼容）受众不同 ⇒ **不该收敛**，而该记录保留理由 ⇒ 避免后人误判为冗余而删掉。

## 十、W1297 CI 失败实证与本批（W1298）根治

### 10.1 失败清单与根因（逐条取证）

### 10.2 根治动作（判据强度未降）

| # | 动作 | 判据强度论证 |
|---|---|---|
| ① | **刷新步在单测中被 mock**（3 个调 main() 的测试加 monkeypatch.setattr(bc, '_run_refresh_artifacts', lambda **k: True)） | 单测验的是**步骤顺序**不验采集 ⇒ mock 掉的是「采集」不是「顺序」；**生产链仍 fail-closed**（真缺 playwright ⇒ 刷新步红 ⇒ 链断）；CI 单测 job 本就不该跑浏览器采集器（快档原则） |
| ② | test_source_has_no_git_add_all 判据口径改**形态锚定** | 改的是**匹配口径**不是放宽强度：git add --all / git add -A 的**命令文本形态**与**参数数组形态**仍一律判红 ⇒ 防代提承诺守住 |

### 10.3 教训

- **「新增一条会真跑外部依赖的步骤」会连带打断既有单测** ⇒ 新步骤引入时必须同步评估「哪些单测会真调它」⇒ 本批把「刷新步在单测中 mock 掉」固化为纪律。
- **代理断言（proxy assertion）过宽会被后续无关改动误伤** ⇒ 「禁 X」类断言应锚定**形态**（命令/参数数组）而非**裸字面量** ⇒ 误伤面收敛到真实语义。
