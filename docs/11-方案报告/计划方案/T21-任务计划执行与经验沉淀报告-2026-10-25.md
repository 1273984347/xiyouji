## 3. 本批新增发现详述

### 3.1 N1 · @1440 首页同标签混两档字号

**取证**（`scripts/output/_w930_layout_metrics.json` → `index.html@1440` 的 `heads` 序列）：

```
H2 40px  查资料
H3 24px  精选必看      ← 分区标题
H3 20px  百回结构图谱
H3 20px  人物动态网络
…（10 张 20px 卡片）
H3 24px  全卷索引      ← 分区标题
H2 40px  看数据与工具
H3 20px  数据看板 …
```

**判定**：@1440 下 h3 出现 **24px（2 处）与 20px（10 处）**两种字号；@375 下 h3 全部为 20px（12 处）。

**为什么 W854 没抓到**：W854 的 S2/S3 判据是「标题序列相邻两级差 ≥4px」，它检查的是**不同标签之间**的层级差；「同一标签内部字号不一致」不在其判据内。

**为什么这是真问题**：读者判断"这是分区还是卡片"的默认线索是字号。当一个区的两个分区标题是 24px、十个卡片是 20px 时，24px 者更像"更重要的卡片"而非"分区"，**分区的存在被视觉抹平了**。修法有两种（升 h2 / 改非标题标签 + 分区样式），取舍见 §4 B5。

### 3.2 N2 · @375 首页装饰图压正文文字

**取证**：`tmpe/_shot/ui-audit-2026-10-25-w930/home-index_html-375.png`。

**判定**：hero 装饰山脉图位于文字层之上或与之重叠 —— 「一百回的山水与人情，一千年的回响与重读。」一行被人物剪影贯穿；副标题「A DIGITAL HUMANITIES READING OF JOURNEY TO THE WEST」第二行被裁切。

**为什么两批都没抓到**：W854 的静态几何审计测的是字号、容器宽、行列数、触达目标尺寸、横向溢出 —— **不测元素间重叠**；W926 的四维是交互可用性 —— 不看视觉。且 `overflowX` 仍为 false（不是溢出，是**层叠**）。

**影响面**：@375 是本站最窄的常用档；该装饰图是 W885 批接入的首页浅色 hero 横幅（`site/static/images/hero-01` 系列），属**素材接线批的遗留问题**。

### 3.3 N3 · 可见工程批次号同时是布局度量污染源

**取证**：① 本批重跑 `scripts/_w926_visible_leak.py --out scripts/output/_w930_visible_leak.json` ⇒ `pages_total=857 / pages_with_leak=796 / visible_batch_terms=6,827 / visible_jargon_terms=807`（与 W926 同数 ⇒ 4 天未修，且本批为独立复算）；② 归因脚本 `_w930_layout_attr.py` 逐区块对比新旧几何，页高增量 **+20 ~ +215px** 集中在尾部区块；③ 可视化页 @375 截图首屏第一屏即见 `run_all_批量生成 JSON 快照 / 限于构建映射表 / 权限 2026-10-04 (由 scripts/run_all.py 批量生成)`。

**W926 与本批的分歧点**：W926 §2.2 把这批问题定性为「访客可见正文裸露工程批次号」= **文本污染**；本批补一条：**它同时是布局审计的基准污染源** —— 任何以"整页高度""首屏元素数"为判据的布局审计，若不先剥离页脚工程行，读数会被批次级联带偏。

## 4. 落地方案（每条：现状 → 理由 → 建议 → 可机检验收判据 → 成本）

### B1（P0）应用侧移动端可用性 —— A6 / A4 / A5

**现状**：`@375` 侧栏恒 260px、主区 115px；`src/index.css` 零 `@media`；开聊前「选 Agent / 工作目录 / 权限模式」三控件同权平铺；权限模式在两处出现。

**理由**：主区 115px = 视口的 **31%**，标题被裁、说明文字压成 3–4 字宽 —— 这是"不可用"而非"体验差"。而应用是本站"从读懂到用活"的产品面；静态站的移动端问题（卡片列数、长行、KPI）都已可修，**应用侧是整条动线上唯一没有断点的环节**。三控件平铺则把"选 Agent"这个唯一必答项与两个可选项混为一谈，用户不知道先做哪个。

**建议**：
1. `≤768px`：侧栏改**抽屉**（overlay，触发按钮常驻），主区 `width: 100%`；根容器用 `100dvh` 替代 `100vh`（解决移动端地址栏高度抖动）。
2. 首个 `<768px` 档建立 `@media (max-width: 768px)` 与 `@media (max-width: 1024px)` 两档（应用当前 0 档）。
3. 新对话页首屏只留「**选 Agent → 开始对话**」两件事；「工作目录（可选）」与权限模式收进「高级设置」折叠区。
4. 权限模式选择器**只在输入框左下保留一处**，新对话页改为文案提示（不再独立控件）。

**可机检验收判据**：
- `@375` 下主区宽 **≥ 320px**（≥ 视口 85%），侧栏不再占常驻宽度（`position: fixed` + `transform: translateX(-100%)`，或 `display:none`）。
- `xiyouji-agent-web/src/index.css` 的 `@media` 计数 **≥ 3**。
- `src/` 全树 `bg-background` / `text-foreground` 使用数 **= 0** 保持；`--color-*` 声明数从 12 **降到 ≤ 4**（A3 残留 8 条死令牌清掉）。
- 渲染实测 @375 截图：标题「西游记·渡口问津」**单行完整显示**，无横向裁切。

**成本**：1 批 · 约 1.5 人日。

### B2（P0）可见文本去工程化 + 页脚收口 —— N3 / R-02

**现状**：796/857 页（92.9%）可见正文含 6,827 处工程批次号 + 807 处内部黑话。

**理由**：两层代价。①**读者层**：92.9% 的页面在正文里出现「W094 / W126 / A4 方向第 11 个新维度」这类只有工程人员看得懂的串，读者无法分辨内容与工程记录的边界，直接损伤"这是一份严肃的学术站点"的可信度。②**工程层**：它正在污染布局审计的度量基准（§3.3），让每一批布局批次的读数都带上批次级联的噪声 —— **先清源，再谈布局度量**。

**建议**（拆两档，先摘低垂果实）：
- **档一（0.5 人日）**：页脚批次行移出可见流 —— 收进"源码溯源"折叠区或 `/about` 页；页脚可见字数压到 ≤ 120。
- **档二（2.5 人日）**：元信息块对外只留「版本 / 日期 / 作者 / 状态」四件套；生成模板里的工单式引用（如「见 W321 line 1393 紧箍咒：正则项在收敛后归零」）改成对读者有意义的形式。

**可机检验收判据**：
- `py -3 scripts/_w926_visible_leak.py` ⇒ `visible_batch_terms = 0`、`visible_jargon_terms = 0`、`pages_with_leak = 0`。
- 首页与可视化页页脚可见文本 **≤ 120 字符**（折叠空白后）。
- 布局度量基线重建：重跑 `_w930_layout_probe.mjs` 后，4 天前后的页高差 **归零**（即排除了批次行噪声）。

**成本**：2 批 · 约 3 人日（档一 0.5 + 档二 2.5）。

### B3（P1）排版与间距刻度消费化 —— S6 余两族 / S5

**现状**：`--type-*`（九个排版角色）与 `--gap-*`（六档语义 gap）**已在 `tokens.css` 定义但 0 页消费**；硬编码 px 仍有 24,127 处，刻度外 22 种取值（10px 独占 3,651 次）。

**理由**：① 令牌定义了却不用，等于**给改版者埋雷** —— 改了 `tokens.css` 里的 `--type-title` 看不到任何变化（T-11 已记过同类"CSS 源不是生效源"的经验）；② 间距无刻度使**节奏不可控**：10px 一种值用了 3,651 次（占硬编码 15.1%），区块间距在 8/10/12/14/16/18px 之间摇摆，读者感到"忽宽忽窄"却说不清哪一处；③ 这两族是 v4 方向 C1（九个排版角色）与 D1（间距刻度）的**落地收尾**，做完即整份 v4 规格闭环。

**建议**：
1. `--type-*` 九档接入 `system.css` 的 `h1–h4` / 正文 / 标签 / 数字类（**改共享层 ⇒ 一次生效 855 页**），并把页面里写死的 `font-size` 逐步换成 `var(--type-*)`。
2. `--gap-*` 六档接入 `.section` / `.card` / `.card-grid` / `.section-head` 的间距。
3. 刻度外取值按「10px→8 或 12、6px→8、14px→12、16px→16、18px→20、3px→4、5px→4、9px→8、22px→24、34px→32」批量归并（**改生成器不手改页**，按 T-08/W865 先例）。

**可机检验收判据**：
- `--type-*` 消费页 **≥ 850**、`--gap-*` 消费页 **≥ 850**。
- 刻度外间距取值种类 **22 → ≤ 8**；硬编码 px 总数下降 **≥ 40%**。
- 阶段 1「视觉零变化」证明法：抽样 ≥20 页 computed style 快照 diff = 0（`_w827_visual_regression_probe.py`）。

**成本**：2 批 · 约 2 人日（须灰度 ≤10 页）。

### B4（P1）可视化页自适应降级 —— S12 / S13

**现状**：@375 KPI 区单列下堆、首屏只见 2 张；@1440 长段 77.9 字/行（阅读页 39.2–42.8 达标）。

**理由**：① KPI 是**摘要**，摘要在首屏的价值是"概览"不是"读完" —— 占满首屏等于逼用户滚屏才能看图；② 77.9 字/行是**同一站点两种正文纪律** —— 阅读页守住了 760px 容器，可视化页的说明段却在 1147px 上排 78 字，长行让眼睛回扫时找不到下一行起点；③ 根因是**可视化页没有文字块容器**（只有图表容器 1320/1147），而 v4 容器三档（760 / 1120 / 1320）本就是为"文字与图表用不同档"设计的。

1. `≤768px`：KPI 区改 **2×2 紧凑网格** + 数字 `--type-number` 32px→24px + 去描述行，高度压到 ≤320px；或改为"首屏留 1 个主 KPI + 查看全部"。
2. 可视化页**文字块**（图表说明、结语、引用块）套 `--container-read`（760px）或 `max-width: 70ch`；**图表本身保持宽版容器不变**。

**可机检验收判据**：
- @375 KPI 区高度 **≤ 320px**，且第一个图表 section 的 `top` **≤ 812px**（首屏内可见至少一张图）。

**成本**：1 批 · 约 1 人日（灰度 10 页）。

### B5（P2）首页宽屏层级 + 断点体系 —— N1 / S1′ / S11

**现状**：① @1440 h3 混 24px/20px 两档；② 「100 回」mega 数字与 H1 同屏等权；③ 公共层断点仅 768/640/480，桌面侧 ≥1024 零分支；④ 全站 3,373 处内联断点散在 760 个文件里。

**理由**：① 同标签两档字号使"查资料"区的分区身份被抹平（§3.1）；② mega 数字与 H1 争夺首屏焦点，而首屏只有一个视觉焦点该给内容入口；③④ 断点散在页面级意味着**改一次要动几百个文件、且无法保证跨页一致** —— 这不是"缺两档断点"的问题，是**响应式规则没有事实源**的问题；v4 规格里断点常量本就该写进 `tokens.css` 供共享层引用。

**建议**：
1. 「精选必看」「全卷索引」**升为 `h2`**（与「查资料」形成 h2 下的 h3 卡片）—— **首选**：语义与视觉同时归位，且不新增样式；备选是保留 h3 但加分区样式（`.sub-head`），改动更小但语义仍错位。
2. @1440 把「100 回」**降为与 tagline 同行的计量标签**（`--type-number` 降档 + 去掉独立大号字形），@375 同样降档。
3. 断点常量写进 `tokens.css`：`--bp-md: 768px` / `--bp-lg: 1024px` / `--bp-xl: 1280px`（+ 375 最小档），`system.css` 统一引用；先在共享层落 1024 与 1280 两个分支，再逐页把内联断点替换为常量引用。

**可机检验收判据**：
- 首页 @1440 **同一标签内字号种类 = 1**（h3 全 20px 或全 24px，不得混）。
- 首页 @1440 首屏 H1 仍是最大字号元素，mega 数字字号 **≤ H1 的 50%**。
- `system.css` 出现 **1024 与 1280** 两个断点分支；`tokens.css` 含 4 个断点常量。
- 页面级内联 `@media` 处数 **3,373 → ≤ 500**（分批收敛，不要求一批到位）。

**成本**：1 批 · 约 1 人日（首页为手工页，非生成产物，可直接改）。

### B6（P2）目录页动线与触达目标 —— S8 余项 / S14 余项

**现状**：目录页 @375 高 30,548px（37.6 屏），检索已上线但**只能"找"不能"跳"**；@375 小目标（<32px）首页 6 个、阅读页 15 个、可视化页 8 个。

**成本**：1 批 · 约 1 人日。

### 9.2 逐条展开

### E-01 · 判据若以「某种语法形态」实现，必假红 —— 令牌化改造会把「改好了」显示成「更差了」

W854 的间距判据是「匹配 `padding|margin|gap: Npx` 字面量」。四天内 5,158 处间距被改写成 `var(--space-*)` 令牌形态，正则不再计数 ⇒ 命中率从 43.3% 掉到 **31.2%**，看起来像布局纪律崩塌，实际是**刻度化改造的成果被自己的判据滤掉了**。修正口径（令牌形态同计入分母）给出 **86.2%**。

**可复用判据**：任何"X 的合规率"类指标，其分母定义必须覆盖**改造前与改造后两种表达形态**；判据升级时**新增口径而非替换口径**，两套同时输出，让旧数字仍可复算。
**与既有教训同源**：W926 §7.1 E-01「以语法形态实现判据 = 必假红」的第二个实例 —— 前者错在"漏认合法写法"，本条错在"漏认改造后的新写法"。

### E-02 · 指标劣化先归因，再下结论 —— 否则会把别人的修复算成你的退化

W854→W930 对拍显示 11 组测点里 6 组页高上升（+20 ~ +215px）、首屏元素普遍 +1 ~ +7，直觉结论是"最近变差了"。归因脚本逐区块对比后发现：增量集中在**尾部区块**，来源是 W926 批次往 4 页页脚注入的工程批次行。⇒ **不是布局劣化，是内容增量。**

**可复用判据**：任何"跨批指标劣化"的判断，先做**归因分离**（把增量落到具体元素），再下"劣化/改善"的结论。判据：若能说清增量出在哪个元素上，就不是劣化。

### E-03 · 并发取号：查表 + 查工作树 + 查会话 三态之外，还要**立即登记**

本批取号时连续撞两次：W928 在我读完台账后被「D-1 实跑批」会话落地认领（工作树 `deploy/pg/` 改动在途），W929 在我登记脚本运行**期间**被「Hero 素材图成套批」会话占位。登记脚本的幂等检查（`if re.search("^| W929 |")`）直接挡住了双占。

**可复用判据**：① 取号后**立刻登记**，把窗口压到最短；② 登记脚本必须**幂等且永不覆盖他人认领的号**（本批脚本遇已存在即退出）；③ 让号依据、共享面、写顺序写进认领行，让后续会话能自行判断是否需要再让。

### E-04 · 同族审计做「复核 + 补审」：复用前批探针并改落点，比重写快且天然可比
