# 双索引可追溯改造

> CHANGELOG W### ID（正向时间线）+ file-index.md（反向文件索引）
> 改造时间：2026-07-22（v0.8 阶段）
> 参考来源：Vannevar 项目方法论
> 严重度：中等（影响跨文件追溯 + 影响面扫描）
> 最新案例：W086 v2.0.59 双索引同步（CHANGELOG W086 段 + file-index.md W086 段，含 4 篇新建随笔 + 1 篇新建专题 + 6 篇文档同步文件）

---

## 一、问题背景

### 单索引的局限

仅 CHANGELOG（正向时间线）的局限：
- 给定文件查改过几次 → 需全文 Grep CHANGELOG，效率低
- 跨文件影响面追溯同一变更 → 无法快速定位所有相关文件

仅 file-index（反向文件索引）的局限：
- 给定时间点查改了什么 → 无法快速定位
- 时间线追溯 → 需要按文件查询，无时间维度

### 复现计数器

- **影响面扫描遗漏**：1/1（2026-07-22 双索引改造：主任务 3 文件完成后未同步 4 文件，user 追问后才补齐）

---

## 二、核心方法论

### 双索引结构

```
CHANGELOG.md（正向时间线）
    ↓ W### ID
file-index.md（反向文件索引）
```

**W### ID 是双向链接的锚点**：
- CHANGELOG 按 W### 顺序记录变更
- file-index 按文件记录被哪些 W### 修改过

### 双向链接字段

CHANGELOG W### 段必含：
```markdown
### v0.5 — 已完成（2026-XX-XX）：[标题]

> **W001 四件套**
> - **来源**：[变更来源]
> - **文件**：[修改文件列表]
> - **验证**：[验证命令 + 输出]
> - **状态**：[已完成/进行中/待开始]
```

file-index 文件段必含：
```markdown
## 文件路径

| W ID | 修改类型 | 修改内容 |
|:---:|:---|:---|
| W001 | 新建 | [简述] |
| W002 | 修改 | [简述] |
```

## 三、使用场景

### 场景 1：时间点 → 变更

**问题**：v0.5 改了什么？

**操作**：
1. 读 CHANGELOG.md
2. 找 v0.5 段
3. 看 W### ID + 文件列表

### 场景 2：文件 → W### 条目

**问题**：README.md 改过几次？

**操作**：
1. 读 file-index.md
2. 找 README.md 段
3. 看 W### ID 列表

### 场景 3：跨文件影响面追溯

**问题**：W020 改了哪些文件？

**操作**：
1. 读 CHANGELOG.md W020 段（看文件列表）
2. 读 file-index.md，按 W020 反向查所有引用 W020 的文件
3. 两个索引配合使用，确认无遗漏

### 场景 4：改动后影响面扫描

**问题**：本次改动完成后，还有哪些文件需要同步更新？

**操作**：
1. Grep 搜索所有可能引用改动内容的文件
2. 同步更新所有交叉引用文件
3. 不等用户提醒"还有其他文件需要更新吗"

**扫描范围（最小集）**：
- docs/00-导读/
- README
- STRUCTURE
- CHANGELOG
- memory 文件（work-log/project_memory/topics）

详见 [user_profile.md 改动后主动影响面扫描](file:///C:/Users/12739/.trae-cn/memory/user_profile.md)（E4 毕业经验，跨文件外部链接）。

## 五、CHANGELOG.md W### 段结构

### 标准 W### 段

```markdown
### v0.5 — 已完成（2026-XX-XX）：[标题] · [简述]

> **W001 四件套**
> - **来源**：[变更来源]
> - **文件**：[修改文件列表]
> - **验证**：[验证命令 + 输出]
> - **状态**：已完成

#### 详细变更

[正文描述]

#### 方法论沉淀

[本次 W### 的方法论沉淀]
```

### 版本号格式

```
v主版本.次版本.修订号 — 已完成（YYYY-MM-DD）
```

示例：`v2.0.42 — 已完成（2026-07-26）`

## 六、维护规则

### 新增 W### 时

1. 在 CHANGELOG.md 顶部添加 W### 段（紧接 v 当前版本）
2. 在 file-index.md 添加 W### 段（紧接 v 当前版本）
3. 更新 file-index.md Top 5 修改次数表
4. 更新 file-index.md footer 的 W### 范围

### 修改现有文件时

1. 在 CHANGELOG.md W### 段添加文件路径
2. 在 file-index.md 对应文件段添加 W### 引用
3. 更新 file-index.md Top 5 修改次数表（如该文件进入 Top 5）

### 版本号 bump 时

1. 更新 CHANGELOG.md 头部版本号
2. 更新 README.md 版本号
3. 更新 STRUCTURE.md 版本号
4. 更新 docs/00-导读/项目说明.md 版本号
5. 更新 交接文档.md 版本号
6. 更新 file-index.md 头部 + footer 版本号
7. 更新 W### ID 范围（如 W001-W069 → W001-W070）
