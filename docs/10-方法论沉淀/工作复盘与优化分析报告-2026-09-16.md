### 2.2 关键待优化技能（3 项）

**S1 暗色态门禁缺口（验收矩阵盲区的常驻化，影响最高）**

- 措施：① `_audit_render_states.js` 已常驻（--states 参数化）；② 下一批将「图表页暗色态抽查」并入 check_screenshot_gates 或 CI 独立 job（审计器 --states S2 单态跑批 8 分钟，成本可控）；③ 门禁阈值：S2 缺陷条目不高于 318 基线（只拦新增）。
- 验收：暗色新增缺陷 0/批。时间表：T0+1 方案入档 → T0+7 挂载评估（用户确认后实施）。

**S2 浏览器自动化操作纪律（效果 3，摩擦显著）**
- 问题量化：screenshot "capture failed for guest" 间歇故障 3 次（重试缓解）；tab 选错 1 次（点击落到错误页面）；fresh-kernel 绑定丢失 5 次（协议性恢复）。
- 措施：① 每次 JS cell 自包含（bootstrap + tab 恢复 + 动作 + emitImage 同 cell）；② tab 绑定前必须 tabs.list() 按验证事实匹配（禁 [0]）；③ screenshot 失败等 2s 重试一次。
- 验收：选错 tab 0 次/会话。时间表：即时生效（本 arc 后半已 0 失误）。

**S3 批量规则前置设计惯例盘点（E28 的操作化）**
- 问题量化：v2 规则返工 1 轮（tokens 精修 + 226 页重内联 + W571 修正批），合计约 1.5 小时。
- 措施：全局规则变更前执行三查——① 页内注入机制盘点（style 块/id 标记：audit-halo 类）；② 页内双轨设计（码/标签、光晕、fill=none）；③ 规则带豁免条件与实拍复验。
- 验收：批量规则返工 0 次/批。时间表：写入 AGENTS §4.3（W571 已含教训条目）→ 下一全局批次实测。

### 5.2 根因 5Why（两项最高影响）

**P01 一刀切反白误伤光晕页**：为什么反白？→ 深色下墨字不可读。为什么不知道部分文字本就可读？→ 168 页有 W553 光晕注入（墨字+白晕任意底可读），审计器不识别光晕。为什么验收没发现？→ CI/审计/复审全部浅色单态。为什么设计惯例未被穷举？→ 全局规则设计前无「页内设计惯例盘点」步骤。根因：**全局批量规则与页内局部设计惯例的冲突缺乏前置排查机制**。→ 措施：三查前置（E28/S3）+ :has 豁免模式；复发监控 = 渲染状态审计新增缺陷 0/批。

**P02 漏跑 --force 分发**：为什么规则没生效？→ 精修只改了 tokens.css 源，226 页内联副本未更新。为什么没意识到要分发？→ 收尾清单①只写了「改内联脚本必跑 generate_csp」，tokens/system 改动的分发步骤不在清单。为什么实测才发现？→ 门禁不校验「内联副本 ≡ 源」。根因：**源-副本一致性无门禁，分发步骤靠记忆**。→ 措施：AGENTS §4.3 W571 条目（教训固化）+ 收尾七步①扩写「改 tokens/system 必跑 inline_css --force」；复发监控 = tick/样式类实测抽查。
