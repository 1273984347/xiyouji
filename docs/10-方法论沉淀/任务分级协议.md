# 任务分级协议（计划-执行-沉淀三级制）

> 用途：任何 Agent/人类在本仓执行任务的统一工作协议——任务先分级，再按级套流程。
> 创建：2026-10-30（W1040）·来源：用户提供的《任务计划、执行与经验沉淀系统提示词》+ Anthropic 锚定项目同日跨项目移植裁决。
> 适用边界：本仓全部任务；跨项目（如 Anthropic 锚定）同源执行，分级口径一致。

## 一、任务分级（先分级再动手）

| 级别 | 判定标准 | 流程要求 |
|---|---|---|
| 战役级 | 多批次/跨渠道/跨项目/新管线 | 完整《执行前计划》（目标/完成标准/范围/假设/步骤/指标/风险/决策记录/自包含检查九要素）+ 执行记录 + 验收表 + 经验沉淀 |
| 任务级 | 单批内容、单个脚本、单个索引更新 | 最小计划 5 行（目标/完成标准/步骤/验证方式/风险与假设）+ 验收表 |
| 微任务 | 改一行、答一问、格式修正 | 一句目标 + 一句验证方式，免表格 |

## 二、流程六阶段（战役级全跑，任务级取 1/3/5/6 骨架）

接收任务 → 信息基础与假设（事实/假设/待补充三分，缺失标【待验证】不编造）→ 执行前计划 → 计划自检门禁 → 执行与追踪（偏差即记录：描述/原因/影响/修正/新时间）→ 验收（对照完成标准逐项给证据）→ 复盘与经验沉淀。

## 三、统一编号

目标 G、验收 AC、假设 ASM、步骤 ST、决策 D、风险 R、验证 V、经验 E、问题 P、行动 A、流程 WF、场景 SC、预防 PRE，一律 `前缀-序号`（如 ST-01），全文档唯一。

## 四、模糊词替换（强制）

| 禁用 | 替换为 |
|---|---|
| 尽快 | 在 X 小时内完成 |
| 尽量 | 至少完成 X 项 |
| 大概 | 区间 X 至 Y |
| 可能 | 假设：…；验证方式：… |
| 较好/差不多 | 指标从 X 到 Y / 差异 ≤ X% |
| 合理/适当 | 满足条件 A、B、C / 按阈值 X |

## 六、责任人/验收人默认口径

单人 + AI 协作项目：责任人 = 执行 Agent；验收人 = 用户（抽查或 7 日无异议视为通过）。用户另有指定时从其指定。

## 七、经验沉淀卡（每次战役/任务级收官输出）

做对了什么 → 为什么有效 → 适用条件 → 不适用条件 → 复用步骤 → 量化效果 → 证据来源；登记入本目录 README 索引（深度篇）或 docs/agent/pitfalls.md（坑位类）。
