# Markdown 写作规范

> 本规范从 product-lifecycle-workbench:product-doc-writing skill §3 Language to Avoid 提炼，作为《详解西游记》项目所有 markdown 文档的写作标准。
> 创建于 2026-07-29（W202 第一波方法论补强），比赛级质量标准适用。

## 1. 段落级反模式

| 规则 | 描述 | 违规示例 |
|:-----|:-----|:---------|
| **禁止 heading-echo** | 段落首句不得复述或解释标题已表达的内容。应以事实、数据或判断开头。 | ❌ "本章介绍用户增长策略。" / "本节将分析孙悟空的成长轨迹。" |
| **禁止 meta-narration** | 不得使用自指式叙述描述文本即将做什么。直接进入实质内容。 | ❌ "下面我们来看…" / "接下来将详细分析…" / "让我们考察…" |
| **禁止"不是…而是…"修辞框架** | 不得使用"不是…而是…" / "真正的问题不是…而是…" / "不仅仅是…更是…" / "本质上不是…而是…"等纯粹为了显得深刻的对比结构。读者通过内容判断文本价值，而非作者的自我定位。直接陈述真实判断，不依赖对比拐杖。 | ❌ "这不是一篇新闻解读，而是一篇从热议反推逻辑的复盘。" → ✅ 直接给出复盘逻辑 |
| **一次性陈述规则** | 一个结论在其规范位置完整出现一次。其他章节引用时必须贡献新证据或新角度，绝不只是换词重述。 | ❌ 引言说"A是核心壁垒"，正文说"A构成关键护城河"，结论说"A最终成为不可替代的优势" |

## 2. 句子级反模式

| 规则 | 描述 | 修复 |
|:-----|:-----|:-----|
| **禁止 dummy-verb 结构** | 消除"进行"/"开展"/"实施" + 名词的模式。直接使用动词。 | "进行分析" → "分析"；"开展调研" → "调研"；"实施优化" → "优化" |
| **禁止不可验证的"确保"** | "确保"后跟不可验证的目标时，替换为可量化标准。 | ❌ "确保用户体验良好" → ✅ "页面加载 ≤ 2s，操作反馈 ≤ 200ms" |
| **禁止空洞强调词** | 删除"非常"/"极其"/"高度"/"显著"等未跟量化证据的强调词。 | ❌ "显著提升了效率" → ✅ "处理时间从 4.2s 降至 1.1s" |

## 3. 格式纪律

| 规则 | 描述 |
|:-----|:-----|
| **加粗范围** | 加粗保留给：专有名词、工具/命令名称、关键警告。不得在行文中用加粗表示修辞强调——靠句法结构传达重要性。限制：每节 ≤ 3 个加粗跨度。 |
| **禁止加粗+斜体堆叠** | `***text***` 禁止使用。 |
| **禁止 emoji（除非要求）** | 文档不得包含 emoji 或装饰性 Unicode 符号（✅❌⚠️ 仅在本文档等清单/诊断场景允许，用户面向的交付物不允许）。 |
| **标题无标点** | Markdown 标题不得以句号、冒号或问号结尾（例外：真正的疑问标题）。 |

## 4. 内容体反模式

| 避免 | 优先 |
|:-----|:-----|
| 伪装成散文的命令式清单 | 描述性、解释性语言 |
| 翻译腔（生硬直译） | 目标语言地道自然的表达 |
| 无上下文的术语堆砌 | 术语首次出现时附简短行内解释 |
| 过度压缩的要点风暴 | 逻辑流重要时用流畅段落 |
| 空洞最高级（"世界级"/"尖端"） | 具体、有证据支撑的声明 |
| 公式化残段（"参考资料"/"致谢"/"附件列表"） | 仅在明确需要时包含 |
| 修辞式或说服性标题 | 描述性、中性标题 |
| 生硬、官僚或过度抽象的措辞（"进行赋能"/"实现闭环"/"显式标注"） | 非专家首读可理解的朴素对话式措辞 |
| 造词过载——堆叠自创抽象名词（"飞轮"/"入口层"/"会话层"） | 每段最多 1 个自创抽象；其余用具体描述替代 |
| 同一结论换词重复 3 次（引言摘要 ≈ 核心判断 ≈ 结论） | 结论在规范位置陈述一次；其他章节引用须加新证据或新角度 |

## 5. 默认不创建的章节

除非用户明确要求，不创建以下章节：
- "图表与附件" / "附件列表"
- "参考资料" / "References" / "Bibliography"
- "致谢" / "Acknowledgments"
- "数据源" / "Data Sources"
- "XX清单" / "XX Checklist"

## 6. 任务描述反模式

委派给 agent 或规划内容时，**禁止**使用清单式、企业行话或工作狂式语言：

❌ **禁止措辞**：
- "可操作"/"可执行"/"检查清单"/"可参考"/"定期复盘"/"x 天行动计划"
- "actionable checklist"/"30-day action plan"/"weekly review cadence"
- 将人类体验框架为可优化工作流

✅ **应自然表述**：直接进入实质思考，不预设框架。
