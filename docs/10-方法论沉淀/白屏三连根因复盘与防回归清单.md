## 一、项目目标与需求理解

**目标理解**：V2 阶段的核心诉求是「可视化深化 + 站点显示质量」，具体拆为：
1. 1 个全新维度（西游地理 3D，W454）+ 3 个既有维度交互深化（W455）。
2. 站点页面在任何访问方式（file:// 双击 / http 本地服务 / GitHub Pages 线上）下均能正常显示。

**完成情况**：

| 维度 | 预期 | 实际 | 差距 |
|---|---|---|---|
| V2 四项可视化 | 全落地 | W454 + W455 全落地，验收门禁全绿 | 无 |
| 站点显示质量 | 稳定显示 | W456（CDN 本地化）+ W457（CSS/脚本修复）后全站 232 页异常 0 | **诊断过程两轮偏航**，见下 |

**核心差距不在最终交付，而在问题定位过程**：白屏问题从 18:34 首次报告到 20:00 锁定真因，经历三轮假设——① 误判为「外域 CDN 阻断」；② 误判为「浏览器缓存旧版」；③ 靠用户截图才锁定「CSS 未生效」。前两轮均在缺乏直接证据的情况下自行假设根因。

## 三、代码质量、架构设计与技术选型的得失

**值得肯定的设计（得到验证）**：
- **EMBEDDED_DATA 回退模式**：数据 fetch 失败时回退内嵌数据，是 file:// 双击可用性的关键兜底，在 JSON 缺失/404 场景下救回了大量页面。
- **CSP 严格化（script-src 哈希 + script-src-attr none）**：错误 4 能在几分钟内被识别并消除，正是 CSP 把「哈希失配」显式暴露出来。
- **单一事实源（tokens.css/system.css）+ inline_css.py**：设计令牌集中管理，避免 85 页手工维护。

**暴露的短板**：
- **批量正则无平衡校验**：改 CSS/JS 后从不验证括号/引号配平，是错误 2、3 的共同温床。
- **内联化放大改动风险**：CSS/script 内联进 233 个 HTML，使「一处源文件笔误」放大为「全站 222 页受影响」，且反向定位难（只能逐页扫）。
- **门禁断言维度单一**：`_smoke_batch.js`/`_p1_viz_audit.js` 只查渲染形状与零尺寸，`validate_en.py` 只查 CJK，均不覆盖「样式生效」与「JS 语法」。
- **技术选型基本合理**：Three r128 固定 + 手动 OrbitControls + 程序化地形，符合 file:// 零依赖约束；D3 v7 本地化后彻底消除外域单点。无选型级失误。

## 四、时间管理与执行效率

| 阶段 | 时间 | 产出 | 效率评价 |
|---|---|---|---|
| W454–W455（规划内） | 早先 | V2 四项全落地 | 高效，3 subagent 并行 |
| 白屏第一轮（W456） | 18:34–19:20 | CDN 本地化 + 陈旧 JSON 对齐 | 方向正确但**非用户当前主诉根因**，属「顺手修了个真问题但没解决眼前问题」 |
| 白屏第二轮 | 19:21–19:30 | 复测 4 点名页 + 全量复扫 | **误判为缓存问题**，未要证据就下结论 |
| 白屏第三轮（W457） | 19:30–20:00 | 锁定 CSS 根因 + EN 腐蚀 + 全量修复 | 高效，靠用户截图一击命中 |

**效率教训**：前两轮共消耗约 50 分钟做「正确但非对症」或「误判」的工作。根因是**先假设、后取证**——在用户已经给了图片证据、且问题可快速复现的情况下，仍先跑大范围环境扫描而非直接询问症状细节。改进方向：**遇到显示类问题，第一步向用户索取截图 + DevTools Console 输出，而非自行假设**。

## 五、可沉淀的经验教训与工具

### 5.1 一次性工具的去留

| 工具 | 定性 | 建议 |
|---|---|---|
| `_diag_style_assert.js` | 样式生效断言全量扫描器 | **转正为常驻门禁**（并入 verify_delivery 或 CI） |
| `_find_css_breaks.py` | CSS 断点定位（括号/引号平衡） | **转正**，作为批量改 CSS 后的必跑校验 |
| `_fix_css_paren.py`、`_fix_en_quote_corrosion.js` | 一次性修复器 | 保留于仓库留痕，不常驻 |
| `_diag_white_pages.js`、`_diag_http_mode.js` | 双环境白屏诊断 | 保留，补「样式生效」断言后合并为一个诊断器 |

### 5.2 需优化的现有工具

1. **`validate_en.py`**：补「内联脚本编译通过」断言（vm.Script 编译），杜绝 EN 引号腐蚀漏网。
2. **`_smoke_batch.js` / `_p1_viz_audit.js`**：断言中补「getComputedStyle(body).backgroundColor 非透明 + 主 style 块 cssRules>1」。
3. **`verify_delivery.py`**：新增「CSS 括号平衡 + 内联 script 语法」门禁（等价于 `_find_css_breaks.py` 的全量版）。
4. **`inline_css.py`**：补「路径改写」逻辑（`url('static/` → `url('../static/`），并输出后校验括号平衡，避免未来 `--force` 回归 W408 问题。

### 6.1 流程规范

| 错误类别 | 预防措施 | 落地方式 | 优先级 |
|---|---|---|---|
| 批量自动化改动隐性破坏（错误 1/2/3） | 任何批量正则/脚本改代码后，**强制运行「结构平衡 + 语法」校验**（括号/引号配平、vm.Script 编译、CSS 解析） | 沉淀 `_find_css_breaks.py` 为通用校验器，纳入 W 批次流程 | P0 |
| 内联脚本/CSS 改动 | 改内联脚本后**立即重跑 generate_csp.py**（已入 MEMORY 铁律） | pre-commit 钩子强制 | P0 |
