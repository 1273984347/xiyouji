# 多 Agent 干扰治理与 touches 纪律

## 一、问题背景：三类暴露面（N × p × T）

多个会话在同一仓库并行时，干扰可拆成三个量：

- **T（时间窗重叠）**：两个批次的施工时间是否交叠——这是**主要暴露面**；
- **p（同文件概率）**：两批是否改同一文件；
- **N（并发方数）**：同时写的会话/子代理数量。

实测结论：**p 已被级联单写路径显著压低**（级联面由 `batch_cascade` 统一写、不参与并行声明），**T 无法消除**（会话长度不可控）——所以治理重心必须放在"T 重叠时如何仍不互相覆盖"。

典型实证（W738/W739）：A 会话读到 W738 未提交 → 开始施工 → 写完发现 W738 已收官。**读→写窗口漂移**，双方都没错，但文件级覆盖随时可能发生。

## 二、机制三件套（缺一不可）

| 机制 | 位置 | 作用 |
|:---|:---|:---|
| **touches 声明** | `docs/00-导读/W批次编号对账表.md` 的 touches 列 | 认领批次时，登记本批**计划手工修改的共享文件**（级联面不列） |
| **交集拒绝** | `python scripts/preflight_check.py --touches "<清单>" --self W###` | 与在途批次（状态非已收官且 touches 非空）取交集，**非空即 FAIL 拒绝并行** |
| **pathspec 互斥提交** | `python scripts/safe_commit.py -F <msg> -- <pathspec...>` | 提交只动自己的路径；ref-lock 竞争自动重试一次，并核对并行增量与自己无交集 |

**语义**：touches 是"同文件 Edit 串行"铁律的**跨 Agent 版**——串行保证"我一人不并发"，touches 保证"跨人无覆盖"。两者是叠加关系，不是替代关系（[并行Edit竞态问题.md](并行Edit竞态问题.md) 仍然现役）。

## 三、登记口径（哪些列、哪些不列）

**必须列**：
- 本批**手工**修改的共享文件（AGENTS 正文、gates.md、pitfalls.md、根 README/STRUCTURE、HANDOVER、文档规范等）；
- 对账表本身的**结构性**修改（改表头/规则/历史行）——纯追加认领行属 append 安全操作，可不列。

**不必列**：
- 级联自动写的 10 面（由 `batch_cascade` 单写路径 + `_cascade_files_<批号>.txt` 清单保护）；
- 只读审计、报告归档、单目录新文件（未被他人引用的路径）等冲突概率为零的面。

判据一句话：**"另一个批次可能同时改它吗？"** 会 → 列；不会 → 不列，避免误报把并行度压死。

## 四、拦不住的两件事（如实记账）

1. **T 可见性**：对方未声明 touches，或声明滞后于实际动手 → 交集检查看不到它。兜底纪律：动工前 `git log --oneline -5` + `git status` 识别并行增量；提交前再确认一次。
2. **解析鲁棒性**：touches 清单靠人写字符串比对，路径写法不一致（相对/绝对/带引号/中文路径转义）会漏配。兜底：清单用 repo 相对路径、逐条列名，不用通配（`docs/*` 这类宽模式无法参与交集判定）。

这两项属于"机制边界"，不是缺陷——**边界要写进文档，否则下一个人会以为有了门禁就绝对安全**。

## 五、复现案例

| 案例 | 事实 | 结论 |
|:---|:---|:---|
| **W738/W739 交错** | 两个并行会话间交错完成，读时 W738 未提交、写完已收官，幸未损坏 | 催生 touches 机制（把冲突检出从写回阶段前移到计划阶段） |
| **W741 评估实施** | 干扰治理长文逐类实证：16 类干扰 → 5 已覆盖 / 4 值得做 / 7 登记；N×p×T 实测 | touches 落地 + 两处边界登记 |
| **W751-W753 三批并行** | 三批同会话并行收官，门禁面统一由 W751 单写（同面串行纪律） | 证明"共享面单写"可行：并行的前提是**指定唯一写方** |
| **W754 本批** | 3 个写方（Lead + 2 组执行子代理）分 18 个文件，文件集两两不交；preflight 交集检查 `PASS`；全程零冲突 | 并行度来自"文件集不相交"，不来自"小心一点" |

## 六、与其他纪律的关系

- **与级联**：级联面不列 touches，但级联**落盘后必须按清单逐面 add**（漏 add 是另一类错误，见 [批次交付流水线.md](批次交付流水线.md) §五）；
- **与提交**：并行期用 `safe_commit.py`；跨批共享文件（AGENTS/CHANGELOG 等）让行给已暂存方；
- **与子代理**：派发子代理时按其文件集切分（disjoint write scopes），子代理之间同样适用"不重叠即安全"；
- **与编号**：批次号认领本身也是并发资源——取号权威源是对账表表格 max+1，禁止"凭记忆 Grep CHANGELOG"。
