## 一、问题背景

单批交付有 7 个必经环节，每一环都有一个**静默失败面**——本地看到"全绿"，仓库状态却已错位：

| 环节 | 静默失败面 | 首次实证 |
|:---|:---|:---|
| 取号 | 凭记忆写批次号 → 撞号；预留 bullet ≠ 认领 | W463 撞 v2.3.77 |
| 前置核验 | 不知有并行批次在写同一文件 → 写回阶段才发现 | W738/W739 交错（读时未提交·写完已收官） |
| 施工 | 改完不 spot-check → 声明≠落地（假收敛） | E1 铁律（本目录 [E1铁律.md](E1铁律.md)） |
| spec 组装 | desc 内嵌分隔符 → 下一批级联锚点正则失配 | W664（desc 含「·」） |
| 级联落盘 | 级联面漏 add → 检出树 ≠ 工作树 | W649（同族三犯：sitemap/CITATION/版本行） |
| 分级门禁 | 本地 scope 档绿而 CI 全量红（本地跑的是工作树新版，CI 拉提交树） | W700 教训 |
| 提交与收官 | 对账表行不翻状态 → 下一批 preflight 取号漂移 | W720 强制 |

结论：**流水线不是"若干工具"，而是一条有断言、可回放的链**——每一步的判据都必须由机器给出，人只负责解读红灯。

## 二、七步流水线（命令 + 判据 + 常见失败）

### 第 1 步 取号 + 认领
```bash
python scripts/reserve_w.py                                                  # 开批占号（铁律 17）
python scripts/preflight_check.py --touches "<本批手工共享面>" --self W###   # 开工核验 + 交集检查
```
- **判据**：输出 `PREFLIGHT PASS`；取号权威源 = `docs/00-导读/W批次编号对账表.md` 表格 **max + 1**（不是 Grep CHANGELOG，版段递延时后者会滞后）。
- **认领动作**：对账表**加表格行**（状态「进行中」）——认领行须由 `ledger_backfill.py --append-claim` 产出；W737 起不再维护「下一自由号豁免 bullet」（该块已碑化，取号唯一依据＝对账表 max+1）。
- **常见失败**：先施工后认领 / 认领行含裸竖线致列错位（E-253 同族）。

### 第 2 步 施工
- **纪律**：改内联脚本必跑 `generate_csp.py`；批量改 CSS/JS 验括号平衡；同文件 Edit 串行；多行文本一律落 `.py` 文件再调用（禁 shell heredoc）。
- **判据**：每个文件改完即 Grep spot-check（E1 铁律）；批量脚本改完 `git diff --name-only` 与预期范围对账。

### 第 3 步 组装 spec
```bash
python scripts/release_prep.py --init W### --title "<批次标题>" --out scripts/output/_w###_spec.json   # 生成模板
python scripts/release_prep.py --check-spec scripts/output/_w###_spec.json --pytest-count <N>            # spec 全量四检
```
- **判据**：spec 三检——字段必填 / 分隔符黑名单（desc 禁 `·`、`；`、`—`；head_sentence 禁 `；`、`—` 与全角括号）/ title 以批次号领衔。
- **必填**：`changelog_body` 必须含 `**文件**：` 行（第 31 门禁 C4-f 据其对账手工件入库）。

### 第 4 步 级联落盘
```bash
python scripts/batch_cascade.py --spec scripts/output/_w###_spec.json          # dry-run（零落盘）
python scripts/batch_cascade.py --spec scripts/output/_w###_spec.json --apply  # 断言全过后统一写
```
- **10 面**：CHANGELOG / README / STRUCTURE / 项目说明 / HANDOVER / workflows README / site 页脚 4 页 / AGENTS 脚注 / CITATION / file-index。
- **判据**：dry-run 全过才 `--apply`；落盘后产出 `scripts/output/_cascade_files_<批号>.txt` 清单，**提交时按清单逐面 add**。
- **写后自检**：CR 串收敛 / 交接文档段序 / 头尾链首条 == 当批。

### 第 5 步 分级门禁
```bash
python scripts/verify_delivery.py            # 批收尾与 CI 恒全量
python scripts/verify_delivery.py --scope auto   # 本地 pre-commit 轻量档（11 段恒跑 + 其余短路）
```
- 段数/槽数以 `scripts/verify_delivery.py` 实跑输出为准（现役 83 槽）；`docs` 档约 2.3s vs 全量约 62s（W698 实测·时点值）。
- **不可缩水点**：批收尾与 CI 必须全量；本地绿 ≠ CI 绿——目标侧不入仓件先 worktree 预演。

### 第 6 步 提交
```bash
git -c core.autocrlf=false add CHANGELOG.md <CRLF-blob 文件>   # 行尾保真（见 §四）
git add -- <清单逐面>
git commit -F scripts/output/_w###_commit.txt                  # 多行信息走临时文件
```
- 并行会话用 `python scripts/safe_commit.py -F <msg> -- <pathspec...>`（ref-lock 竞争自动重试）。
- **巨批分笔（容量 #7 <500 文件·W1321 固化）**：单批文件数越线时按目录分组拆 2 笔（实证形态：`site/reader/people` + `themes` 一笔、余下 reader 子目录 + 章节一笔），每笔 ≤500；**每笔必须自洽**——该笔检出的页面须与其同笔入库的探针/渲染档案同源（第 80/82 槽按页 sha fail-closed）⇒ 页面与探针产物不得跨笔拆开。
- **逐笔推送 + 临时 worktree**：推前闸门要求「一次推送只带 1 笔」且工作树干净 ⇒ 多笔批次逐笔推；首笔在主线不干净时用 `git worktree add <tmp> <sha>` 后在临时树 `git push origin HEAD:main`，其余笔待主线干净后逐笔推。禁止把多笔合成一次 push（闸门物理拦截）。
  - **W1363 放宽（积压模式）**：该条的**原意**是「同一批的修复笔不得拆成多轮 CI」，不是「历史积压也要逐笔」。故闸门改为：单笔直接通过；多笔时须同时满足 ① 每笔可解析 W 号 ② W 号时间序单调不减（禁回插旧批）③ 每批在 CHANGELOG 有独立段 ⇒ 判为「连续批次积压」放行。实证：origin/main 停在 W1340 时本地积压 45 笔 / 22 批，逐笔推需 45 轮 CI ≈ 60 分钟，而积压推送 1 轮即可且批次可追溯。
- **两轮推送的 CI 等待纪律（W1326·E-321）**：内容笔 push 后须等其 CI（含 Security）全绿再推回填笔；否则第二轮 push 会触发 GitHub 并发组取消第一轮。回填笔早于修复时其 CI 红无法通过 rerun 转绿（它 checkout 的是旧树），只能新增 forward-fix 提交；禁 force-push 改写已推历史。
- **索引态提交前须无「暂存后改写」分歧（W1321 机器化）**：`--expect-spec` 无 pathspec = 索引态提交；若级联在 `git add` 之后又改写了页面（versions/csp 步实测），提交会捕获旧版本 ⇒ `safe_commit` 现直接拒绝并列出分歧件（`git status` X∈MARC 且 Y∈MD·W1320 dukou 页脚实证）；改法 = 重新 `git add` 后再提交。
- **克隆后一次性启用仓内 pre-push 闸门**：`git config core.hooksPath .githooks`——仓内版本化的 `.githooks/pre-push`让「一批 = 一轮 CI」成为**物理约束**（闸门红 ⇒ push 被拒）；但 `core.hooksPath` 是**仓库本地配置·不随 clone 走** ⇒ 新克隆的工作副本默认**不加载**该 hook ⇒ 闸门**静默失效**（push 照样成功，只是没人拦）⇒ 判「是否真生效」看 `git config --get core.hooksPath` 的**实际取值**，不看「文件在仓内」（E-312）。

### 第 7 步 收官登记
- 对账表行：状态翻「已收官（hash）」+ 提交列回填 hash（hash 一律 `git log --oneline` 实证后转录）。
- **台账回填的物理边界**（E-311）：「回填类永不单独开 PR」= 不单独开 PR，**不是「不回填」**——回填缺席会累积成「登记滞后」（实测 4 批同时滞后 ⇒ 开工告警成噪音 ⇒ 真滞后也看不见）。**状态在收官当批翻「已收官」**；**hash 列**：提交内容含自身 hash ⇒ 自指不可知，故以**第二笔「回填」提交**补齐——首笔推送后 `origin/main` 前进 1 笔，回填笔即 1 笔领先 ⇒ 闸门放行（W1318/W1319/W1320 连续实证）；「同批回填物理不可行」仅指**同一次 push 带两笔**，不是禁止同批第二笔；关键是**不得跨批累积**。回填用 `python scripts/ledger_backfill.py --w <W号> --from-git` 实证反填，hash 列口径＝**最早一笔（首笔）**。
- 预约释放：收官后跑 `python scripts/reserve_w.py release W###`（TTL 24h 也会自动过期）；W737 起不再轮换豁免 bullet。
- 推送后 `gh run list` 盯 CI；本地不推时如实标注「未推送」。

## 三、编号锚点的三种形态

| 形态 | 触发条件 | 处置 |
|:---|:---|:---|
| **正常** | 认领号 == CHANGELOG 现役段 max + 1 | 直接 `batch_cascade` |
| **跳号 / 合并段** | 认领号 ≠ max + 1（预留号占用、作废号跳号） | 手工级联：复刻锚点断言写一次性脚本（W663/W666/W679/W751 四先例），自建 `_cascade_files_<批号>.txt` 清单 |
| **递延补登记** | 前批已收官但版段/索引段缺失 | 先补前批段（来源标「递延补登记」），使 max+1 == 当批号后再级联；对账表「递延批豁免登记」区留存说明 |

**W754 实证**：认领 W754 时 CHANGELOG 现役段停在 W751（W752/W753 已收官但段未插），`batch_cascade` 直接断言 `批次号应为 W752` 拒跑；补登记两段并去重 W751 重复段头后，dry-run 10 面一次通过。→ **级联拒跑不是工具故障，是仓库编号不变量被破坏的信号**。

## 四、行尾与编码纪律（最容易被忽略的三条）

1. **先探行尾再动手**：`batch_cascade` 的 `load()` 对**混行尾文件 fail-closed**（CRLF/裸 LF 并存 → 断言中止）。修前先按主导行尾归一并复验。
2. **CRLF blob 文件禁用默认暂存**：`core.autocrlf=true` 会把工作树的 CRLF 归一为 LF 写进 blob——对**HEAD blob 本身是 CRLF** 的文件（本仓实测：CHANGELOG.md、scripts/output/file-index.md）会造成整文件行尾翻动。暂存用 `git -c core.autocrlf=false add <file>`；判据 = `git diff --cached --numstat` 行数应与内容改动量同阶（整文件级数字 = 翻动信号）。
3. **BOM / NUL / 控制字符**：批量改 md 一律 Python `open(encoding='utf-8')`（禁 PowerShell `Set-Content`，默认写 BOM）；文本文件出现真 NUL 会被编辑器判为二进制并使部分工具拒写（W754 实证：`\u0000` JSON 转义落盘成真字节 2 处）。

## 五、失败模式速查

| 症状 | 根因 | 处置 |
|:---|:---|:---|
| `批次号应为 WNNN` 断言 FAIL | CHANGELOG 现役段 max+1 ≠ 认领号 | 补前批段或走手工级联（§三） |
| `混合行尾文件` 断言 FAIL | 目标文件 CRLF/裸 LF 并存 | 按主导行尾归一后重跑 |
| `现役段标题行首命中 2` | 同一段头重复（手工插入遗留） | 去重后重跑 |
| `编号规则段锚点异常` | 编号规则行上限 ≠ 现役段 max | 先把上限推进到当前 max |
| 第 31 门禁 C4-f 红「漏 add」 | 提交树 ⊉ 文件行清单 | 按清单 + 手工件逐面 add |
| 第 17 门禁「段倒序」红 | file-index 新段插错位置 | 按数值序插到较小号段之上 |
| 第 38 门禁命中残留标记 | 级联文本里写了旧页面/旧实体名 | 现役文本改中性表述，旧名只留在历史记录 |
| CI 红而本地绿 | 本地跑工作树、CI 跑提交树 | 用 `git stash`/worktree 复现提交树再验 |
| 容量 #7 报「单批提交文件数 > 500」 | 巨批未拆笔 | 按目录分组拆 2 笔（每笔 ≤500·逐笔推·见 §二 第 6 步） |
| 推送闸门第 80/82 槽报「探针报告陈旧」而主线绿 | 被推的那一笔捕获了 `add` 之后的旧页面（索引态分歧·W1320） | 重新 `git add` 并把该笔重建为自洽提交；禁 `--no-verify` 绕过 |
| 首轮 CI 被 cancelled 且回填笔 CI 红 | 第二轮 push 在第一轮 CI 未跑完时触发 ⇒ GitHub 并发取消首轮；回填笔 CI 跑旧树 ⇒ rerun 仍红 | 内容笔 push 后等 CI 全绿再推回填笔；已红只能 forward-fix，禁 force-push（E-321） |

## 六、复现案例（W754 全链实测）

## 七、外部产出落地七步（W775 实证）

> 场景：外部会话/外部工具产出整包代码或文档（如 0.9MB 重构产出汇编）。**红线：禁止直接 cp 覆盖仓库文件**——外部产出可能基于旧版仓态，整包覆盖会静默回滚期间修复。

1. **提取**：按锚点从产出包提取目标文件到 `tmpe/_inbox/`，做 round-trip 逐字节自检（写回后 read-back 与源段全等）。
2. **静态契约核验**：对照仓库现版逐项核（exports/CLI 参数/退出码/消息文本 sorted diff/基线格式）；不跑不知道，先看清单。
3. **旧版行为快照**：对「会被真实执行」的工具先采快照（self-test / 子集运行 / 输出文件），计时类字段留待归一。
4. **落地**：字节级写入（CRLF 文件走 Python 脚本，禁 Edit 大块替换）；异体系溯源标识（外来 W 号/版本号）就地修正为本仓编号。
5. **对拍**：新版重跑同套快照，diff 前归一计时/像素/并发序等固有抖动；差异逐条定性（可解释 or 缺陷），不可解释即回滚。
6. **全量验证**：pytest + verify_delivery 全量（局部绿不算数——W775 的 `.gitignore lib/` 误伤即此步前险漏）。
7. **差异定性表归档**：每条差异记「现象/根因/判定/处置」——意外收获（如潜伏 bug）同样入账（W775 引号腐蚀即对拍副产品）。

**判据**：外部契约零漂移（消息逐字节/退出码/导出面）+ 差异表零未定性项。**常见失败**：跳过第 2 步直接落地（回滚风险）；diff 不归一计时（满屏假差异）。

## 八、重构/替换的对拍 SOP（W775 实证·E-09）

> 场景：任何「被真实执行」的门禁/检查器脚本的重构、拆分、替换。**前提**：先有旧版快照，再落新版；跳过快照直接覆盖 = 失去唯一对照物。

**五维对拍矩阵**（按可用性降级，至少三维）：

| 维度 | 内容 | 归一化 | 不可用时的降级 |
|---|---|---|---|
| ① self-test | 注入式负样本逐行 PASS/FAIL + N/M 通过 | 无（顺序变化需说明） | 必须有（无 self-test 先补） |
| ② 纯函数面 | `--judge` 类注入载荷的 JSON 输出 | 无（应逐字节一致） | 静态契约 diff |
| ③ 单页/小样执行 | `--pages`/`--only` 子集实跑（含浏览器） | 计时、像素计数 | 结构对比 |
| ④ 全站/全量执行 | 全量跑（可与验证步合并） | 同上 | 抽样 |
| ⑤ 产物格式 | 基线文件/报告 JSON/汇总末行 | 日期、计时 | 字段名清单 diff |

**差异判定规则**：① 计时/像素/并发序 = 固有抖动，归一后放行；② 文案/字段/退出码 = 契约，零容忍；③ 覆盖集合变化（如可比页数）必须追到根因——若是修复（更多页被纳入），显式记录并保留，不得为了「逐字节一致」而回滚修复本身。

**模板**：`docs/_templates/duipai/duipai.py`（W798 转正入库·快照采集 + 归一化 diff 两命令）。

## 九、收官链时间纪律（W1266 实测）

> 来源：W1266 收官逐项计时复盘（tmpe/w1266/time_opt.md·实测单轮浪费 ≈25–30 分钟）。坑位全量见 [pitfalls.md](../../pitfalls.md) E-265~E-270；本节是收官编排视角的时间视角汇总。

| # | 浪费形态（实测损失） | 修法 | 判据锚 |
|---|---|---|---|
| 1 | 提交前手工全量 verify 与 pre-commit 钩子重复（≈4 分钟） | 提交期门禁分层：提交只靠钩子 `--scope auto` 子集；全量恒属 pre_push_gate，跑过不重复 | E-265 |
| 2 | 长任务前台跑撞 120 秒交互墙被中止 ⇒ 整任务重跑（≈15 分钟） | >2 分钟的探针/全量门禁/收官链一律后台＋输出落文件；前台只做秒级判据 | E-266 |
