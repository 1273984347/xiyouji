## 一、问题背景

单批交付有 7 个必经环节，每一环都有一个**静默失败面**——本地看到"全绿"，仓库状态却已错位：

| 环节 | 静默失败面 | 首次实证 |
|:---|:---|:---|
| 取号 | 凭记忆写批次号 → 撞号；预留 bullet ≠ 认领 | W463 撞 v2.3.77 |
| 前置核验 | 不知有并行批次在写同一文件 → 写回阶段才发现 | W738/W739 交错（读时未提交·写完已收官） |
| 施工 | 改完不 spot-check → 声明≠落地（假收敛） | E1 铁律（本目录 [E1铁律.md](E1铁律.md)） |
| spec 组装 | desc 内嵌分隔符 → 下一批级联锚点正则失配 | W664（desc 含「·」） |
| 级联落盘 | 级联面漏 add → 检出树 ≠ 工作树 | W649（同族三犯：sitemap/CITATION/版本行） |
| 分级门禁 | 本地 scope 档绿而 CI 全量红（本地跑的是工作树新版，CI 拉提交树） | W700 教训 |
| 提交与收官 | 对账表行不翻状态 → 下一批 preflight 取号漂移 | W720 强制 |

结论：**流水线不是"若干工具"，而是一条有断言、可回放的链**——每一步的判据都必须由机器给出，人只负责解读红灯。

## 二、七步流水线（命令 + 判据 + 常见失败）

### 第 1 步 取号 + 认领
```bash
python scripts/preflight_check.py --touches "<本批手工共享面>" --self W###   # 五检 + 取号 + 交集检查
```
- **判据**：输出 `PREFLIGHT PASS`；取号权威源 = `docs/00-导读/W批次编号对账表.md` 表格 **max + 1**（不是 Grep CHANGELOG，版段递延时后者会滞后）。
- **认领动作**：对账表**加表格行**（状态「进行中」）——预留豁免 bullet 只是防 C4 误拦的登记，**不算认领**（W720）。
- **常见失败**：忘了给"下一自由号"加豁免 bullet（W710/W713 同族两犯）。

### 第 2 步 施工
- **纪律**：改内联脚本必跑 `generate_csp.py`；批量改 CSS/JS 验括号平衡；同文件 Edit 串行；多行文本一律落 `.py` 文件再调用（禁 shell heredoc）。
- **判据**：每个文件改完即 Grep spot-check（E1 铁律）；批量脚本改完 `git diff --name-only` 与预期范围对账。

### 第 3 步 组装 spec
```bash
python scripts/release_prep.py --init        # 生成模板（首次）
python scripts/release_prep.py --spec scripts/output/_w###_spec.json
```
- **判据**：spec 三检——字段必填 / 分隔符黑名单（desc 禁 `·`、`；`、`—`；head_sentence 禁 `；`、`—` 与全角括号）/ title 以批次号领衔。
- **必填**：`changelog_body` 必须含 `**文件**：` 行（第 31 门禁 C4-f 据其对账手工件入库）。

### 第 4 步 级联落盘
```bash
python scripts/batch_cascade.py --spec scripts/output/_w###_spec.json          # dry-run（零落盘）
python scripts/batch_cascade.py --spec scripts/output/_w###_spec.json --apply  # 断言全过后统一写
```
- **10 面**：CHANGELOG / README / STRUCTURE / 项目说明 / HANDOVER / workflows README / site 页脚 4 页 / AGENTS 脚注 / CITATION / file-index。
- **判据**：dry-run 全过才 `--apply`；落盘后产出 `scripts/output/_cascade_files_<批号>.txt` 清单，**提交时按清单逐面 add**。
- **写后自检**：CR 串收敛 / 交接文档段序 / 头尾链首条 == 当批。

### 第 5 步 分级门禁
```bash
python scripts/verify_delivery.py            # 批收尾与 CI 恒全量
python scripts/verify_delivery.py --scope auto   # 本地 pre-commit 轻量档（11 段恒跑 + 其余短路）
```
- 全量实测 48 段（43 槽 + 汇总）；`docs` 档约 2.3s vs 全量约 62s（热缓存·W698 实测）。
- **不可缩水点**：批收尾与 CI 必须全量；本地绿 ≠ CI 绿——目标侧不入仓件先 worktree 预演。

### 第 6 步 提交
```bash
git -c core.autocrlf=false add CHANGELOG.md <CRLF-blob 文件>   # 行尾保真（见 §四）
git add -- <清单逐面>
git commit -F scripts/output/_w###_commit.txt                  # 多行信息走临时文件
```
- 并行会话用 `python scripts/safe_commit.py -F <msg> -- <pathspec...>`（ref-lock 竞争自动重试）。

### 第 7 步 收官登记
- 对账表行：状态翻「已收官（hash）」+ 提交列回填 hash（hash 一律 `git log --oneline` 实证后转录）。
- 现势 bullet 轮换：为下一自由号加豁免 bullet，并在尾部记本次遗留。
- 推送后 `gh run list` 盯 CI；本地不推时如实标注「未推送」。

## 三、编号锚点的三种形态

| 形态 | 触发条件 | 处置 |
|:---|:---|:---|
| **正常** | 认领号 == CHANGELOG 现役段 max + 1 | 直接 `batch_cascade` |
| **跳号 / 合并段** | 认领号 ≠ max + 1（预留号占用、作废号跳号） | 手工级联：复刻锚点断言写一次性脚本（W663/W666/W679/W751 四先例），自建 `_cascade_files_<批号>.txt` 清单 |
| **递延补登记** | 前批已收官但版段/索引段缺失 | 先补前批段（来源标「递延补登记」），使 max+1 == 当批号后再级联；对账表「递延批豁免登记」区留存说明 |

**W754 实证**：认领 W754 时 CHANGELOG 现役段停在 W751（W752/W753 已收官但段未插），`batch_cascade` 直接断言 `批次号应为 W752` 拒跑；补登记两段并去重 W751 重复段头后，dry-run 10 面一次通过。→ **级联拒跑不是工具故障，是仓库编号不变量被破坏的信号**。

## 四、行尾与编码纪律（最容易被忽略的三条）

1. **先探行尾再动手**：`batch_cascade` 的 `load()` 对**混行尾文件 fail-closed**（CRLF/裸 LF 并存 → 断言中止）。修前先按主导行尾归一并复验。
2. **CRLF blob 文件禁用默认暂存**：`core.autocrlf=true` 会把工作树的 CRLF 归一为 LF 写进 blob——对**HEAD blob 本身是 CRLF** 的文件（本仓实测：CHANGELOG.md、scripts/output/file-index.md）会造成整文件行尾翻动。暂存用 `git -c core.autocrlf=false add <file>`；判据 = `git diff --cached --numstat` 行数应与内容改动量同阶（整文件级数字 = 翻动信号）。
3. **BOM / NUL / 控制字符**：批量改 md 一律 Python `open(encoding='utf-8')`（禁 PowerShell `Set-Content`，默认写 BOM）；文本文件出现真 NUL 会被编辑器判为二进制并使部分工具拒写（W754 实证：`\u0000` JSON 转义落盘成真字节 2 处）。

## 五、失败模式速查

| 症状 | 根因 | 处置 |
|:---|:---|:---|
| `批次号应为 WNNN` 断言 FAIL | CHANGELOG 现役段 max+1 ≠ 认领号 | 补前批段或走手工级联（§三） |
| `混合行尾文件` 断言 FAIL | 目标文件 CRLF/裸 LF 并存 | 按主导行尾归一后重跑 |
| `现役段标题行首命中 2` | 同一段头重复（手工插入遗留） | 去重后重跑 |
| `编号规则段锚点异常` | 编号规则行上限 ≠ 现役段 max | 先把上限推进到当前 max |
| 第 31 门禁 C4-f 红「漏 add」 | 提交树 ⊉ 文件行清单 | 按清单 + 手工件逐面 add |
| 第 17 门禁「段倒序」红 | file-index 新段插错位置 | 按数值序插到较小号段之上 |
| 第 38 门禁命中残留标记 | 级联文本里写了旧页面/旧实体名 | 现役文本改中性表述，旧名只留在历史记录 |
| CI 红而本地绿 | 本地跑工作树、CI 跑提交树 | 用 `git stash`/worktree 复现提交树再验 |

## 六、复现案例（W754 全链实测）

- **工具链建立**：`preflight_check.py`（W736 建·五检 + 取号 + W739 起 `--touches`）、`release_prep.py`（W736·spec 三检）、`batch_cascade.py` 两阶段与行尾护栏（W706/W553 教训固化）。
- **本批数据**：dry-run 10 面一次通过 → apply 落盘 14 文件 → 全量门禁 48 段自洽锁 OK → 提交 36 文件 +415/−196 → 收官 chore 1 文件。
- **本批暴露**：三处编号/编码不变量破坏（段头重复、前批段缺失、NUL 污染），均在**级联前置**被工具拦下——证明"断言前置"比"事后审计"便宜一个数量级。
