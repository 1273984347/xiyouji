# dispatching-parallel-agents 四 subagent 并行模式

> W257·v2.2.46·S1 方法论沉淀第 10 篇·与 W253-W256 记忆研究四篇并行形成"经验-方法论"双轨

## 一、模式定义

四 subagent 并行模式指主代理同时分发 4 个独立 subagent 执行无共享状态任务的高效协作模式。边界条件：4 个任务必须相互独立、无状态依赖、无文件冲突，主代理通过统一 spot-check 机制验证交付质量。该模式区别于串行单 subagent 模式与三 subagent 并行模式，通过四路并行实现吞吐量最大化，同时以主代理 spot-check 与三 skill 闭环兜底保证交付质量，避免并行带来的质量塌陷风险。

## 二、适用场景

适用于 4 个独立任务无共享状态的场景，典型如 4 篇独立文档创建（W253-W256 记忆研究四篇）、4 个独立页面开发、4 个独立模块重构。不适用于存在数据依赖、文件冲突或需要顺序执行的任务。判断标准：4 个任务可在任意顺序下独立完成，且最终交付物可独立验证。若任务间存在共享状态或顺序依赖，应降级为串行或三 subagent 并行模式，避免并行冲突导致交付失败。

## 三、设计原则

三大设计原则：(1) 独立无共享——4 个 subagent 任务边界清晰，无文件读写冲突、无状态依赖、无共享变量；(2) 主代理统一 spot-check——主代理对 4 个交付物执行统一五维度抽查（文件存在性、结构完整性、核心内容、footer 双索引、无 placeholder），避免 subagent 自报虚高；(3) 三 skill 闭环兜底——DRL 审查、mem-wrap-up 收尾、self-evolution 沉淀形成质量闭环，确保并行模式下质量不打折。

## 四、执行流程

五步执行流程：(1) 主代理分发任务——明确 4 个 subagent 的任务边界、交付物路径、质量要求；(2) 四 subagent 并行执行——4 个 subagent 独立完成各自任务，互不干扰；(3) 主代理 spot-check——对 4 个交付物执行五维度抽查；(4) DRL R1b 验证——深度复检循环确保无假收敛；(5) mem-wrap-up 收尾——更新记忆系统、写入 user_profile.md 计数器，self-evolution 沉淀方法论。

## 五、主代理 spot-check 策略

五维度抽查策略：(1) 文件存在性——验证 4 个交付文件均实际创建于指定路径；(2) 结构完整性——核对段落数、标题层级、footer 格式符合规范；(3) 核心内容——抽查每段 100-200 字、无 TBD/TODO 等占位符；(4) footer 双索引——验证 W 编号、版本号、专题序号、关联文档齐全；(5) 无 placeholder——全文扫描确认无待补充标记。五维度缺一不可，任一不达标即触发补齐流程。

## 六、E1 memory 层假收敛应对

E1 memory 层假收敛指 subagent 自报完成但实际交付缺失的虚高状态。应对策略：(1) Step 7a spot-check——主代理在 subagent 报告完成后立即执行五维度抽查，不信任 subagent 自报；(2) 三件套补齐——发现缺失时强制补齐文件、结构、内容三件套，确保交付完整；(3) user_profile.md 计数器更新——核实计数器与实际交付一致，防止计数器虚高导致方法论失真。

## 七、与三 skill 闭环关系

三 skill 闭环构成质量保障三层防线：DRL（deep-review-loop）负责 R1b 深度复检，识别假收敛与过度拟合；mem-wrap-up 负责收尾归档，更新记忆系统与计数器；self-evolution 负责方法论沉淀，将经验提炼为可复用模式。四 subagent 并行模式通过三 skill 闭环实现"执行-验证-收尾-沉淀"全链路质量保障，避免并行模式下的质量塌陷，确保方法论可追溯、可复用。

## 八、案例：W253-W256 记忆研究四篇并行

W253-W256 记忆研究四篇并行执行案例：W253 文化记忆（阿斯曼）+ W254 集体记忆（哈布瓦赫）+ W255 记忆之场（诺拉）+ W256 记忆伦理（利科）四 subagent 并行。四篇文档相互独立、无共享状态，主代理分发后四 subagent 同时执行，主代理 spot-check 验证五维度，DRL R1b 复检确认无假收敛，mem-wrap-up 收尾更新计数器至 W256，self-evolution 沉淀为 W257 方法论。
