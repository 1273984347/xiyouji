# 幂等守卫与判定口径：级联面三类自相矛盾根修

> **定位（W1147 建）**：把 W1144 批连撞三类「机制自己跟自己打架」缺陷的根修模式固化——它们共同的症状是**门禁/守卫单独看都正确、组合起来互相抵消**。
> **谁该读**：要改级联/收官链任何带幂等守卫或反查判据的函数的人。
> **一句话**：**幂等守卫的判定条件必须覆盖「它被调用的所有路径」；反查命中后的判定必须用与反查同源的口径——任何一处「退回旧口径」都会让机制自己打自己。**

---

## 一、rotate 幂等守卫 × 插入路径的自相矛盾（概要块只增不减）

### 症状

HANDOVER 里程碑概要块每批 +1、从不减少——体积门禁 C7「概要块 7 > 6」在 W1142、W1144 两批连续复发，手工滚动后下一批又积回来。

### 根因链（两行代码的合谋）

```python
# 调用点（插入路径）：
s, _mst = _upsert_handover_milestone(...)   # 本批块刚被插入
if _mst == "inserted":
    s = _handover_rotate_oldest(s, ...)     # 首次插入 → 执行滚动

# 滚动函数（W1124 加的幂等守卫）：
def _handover_rotate_oldest(s, ctx, ...):
    if _locate_handover_milestone(s, ctx.batch) is not None:
        return s                            # 本批块在链上 ⇒ 视为已滚动 ⇒ 零变化
```

**本批块刚被 upsert 进链 → locate 恒命中 → rotate 恒零变化**。W1124 守卫的本意是防「单独重跑滚动再淘汰一块」（信息丢失），但它无法区分「重跑场景」与「插入后正常滚动场景」——**守卫把两条路径一刀切了**。

### 根修

守卫条件改为「本批在链上 **且** 窗口未超限（≤6）」：超限 = 本批插入后未滚（补救路径·继续滚）；未超限的重跑维持零变化。**教训泛化：幂等守卫若拦截了「本应发生的第一次」，它就不是幂等守卫而是死开关——守卫条件必须逐一覆盖调用路径。**

## 二、宽松定位器 × 严格口径的 min 漂移

根修滚动后第二个炸点：淘汰目标改用 `_handover_milestone_blocks()`（进度段有界）取 min 批号——但该函数是**宽松定位器**（`^- \*\*W\d+\b` 匹配一切行首 bullet），实测进度段内 19 个命中 vs 真正的概要块 7 个——min 漂到 1096（旧待办区 bullet）→ 指针自愈断言 fail-closed 拦下（正确的失败）。

**根修**：旋转窗口的块清单改用与体积门禁 C7 **同口径**的严格正则（`**：` 尾约束）。**教训泛化：同一份文档的「块」在不同判据里必须有同一个定义——定位器（宽）与计数器（严）混用是隐形分叉。**

## 三、双 W f-string：恒早退路径里的潜伏炸点

rotate 修复后首次真正跑到滚动深处，连续炸出三个**从未被触达过的潜伏 bug**（rotate 恒早退 = 这些行是死代码）：
`_remain` 的 findall 捕获组含 W 前缀（`int('W1144')` 炸）、W534 断言拼出「WW1127」、指针 replace 的 f 串双 W（replace 恒不命中 → 指针不随淘汰同步）。

**教训泛化：恒早退的守卫会让守卫之后的所有代码变成「从未运行过的代码」——它们的 bug 不暴露、测试不覆盖、直到守卫被修的那天集中爆发。修守卫时必须把守卫后面的路径当新代码审。**

## 四、第 51 槽：反查与判定的口径断裂

group-aware 反查（batch_spec.covers·分组行子树展开）命中归属 W1144 后，随后的 plan 判定**退回精确集**（spec_paths_for）——332 件合法同步面被全列表误报「多出」。且 gate 与 report 两个入口只有一处同步（修一处漏一处·W1076 教训复刻）。

**根修**：反查与判定的口径统一——归属判定（无论反查还是直查）命中后，**plan 一律走同源 rows**（`_spec_rows_for(target)`）。

**教训泛化：一个归属决策只能有一个口径；反查用什么判据命中，判定就必须用什么判据验收。双入口（gate/report）的工具，修任何口径必须两侧同改并互相对拍。**
