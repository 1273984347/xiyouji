# E2 文档同步区分历史 vs 现役

> 文档同步时区分历史变更日志条目（保留旧值）与现役描述（必须更新为新值），Grep 搜索旧值会同时命中两类条目
> 首次复现：2026-07-22 xiyouji B7
> 当前复现计数器：2/2 证据毕业
> 严重度：严重（影响文档一致性 + 历史事实完整性）
> 最新案例：W086 v2.0.59 文档同步阶段主代理 Grep 搜索 v2.0.58 旧值时同时命中 CHANGELOG 历史段与 README 头部

---

## 一、问题背景

### 触发场景

版本 bump 后做文档同步（README 头部 / STRUCTURE 表格 / CHANGELOG 当前段 / file-index 反向索引）时，主代理用 Grep 搜索旧版本号或旧值以确认"哪些位置需要更新"。Grep 返回结果中既包含**当前版本段（现役描述）**也包含**历史变更日志段（历史事实）**。

若主代理不区分两类条目，把历史变更日志中的旧版本号也"修复"为新版本号，会破坏历史事实的完整性——CHANGELOG 中"W085 v2.0.58"的历史记录不应被改成"W085 v2.0.59"。

### 两类条目的本质区别

| 类别 | 典型位置 | 描述内容 | 处置 |
|:---|:---|:---|:---|
| 历史条目 | CHANGELOG v0.5 段 / STRUCTURE 版本史 v0.5 行 | 描述"某历史版本当时的状态" | 保留旧值（历史事实不可改） |
| 现役描述 | README 头部 / STRUCTURE 表格 / CHANGELOG 当前版本段 | 描述"当前状态" | 必须更新为新值 |

### 共同根因

Grep 是无状态文本匹配，无法区分"该条目描述当前状态还是历史状态"。主代理必须基于条目所在**语义位置**做判据，不可基于"是否命中旧值"做判据。

---

## 二、核心铁律

### 判据

> 该条目是否描述"当前状态"？
> - 是 → 更新为新值
> - 否（描述历史某版本状态）→ 保留旧值

### 操作步骤

1. **Grep 搜索旧值**：列出所有命中位置
2. **逐条分类**：基于命中行所在的语义段落（README 头部 / STRUCTURE 表格 / CHANGELOG 当前段 = 现役；CHANGELOG 历史段 / STRUCTURE 版本史历史行 = 历史）
3. **更新现役条目**：Edit 现役描述为新值
4. **保留历史条目**：不动历史变更日志中的旧值
5. **Grep spot-check 验证**：搜索新值确认现役条目已更新 + 搜索旧值确认仅剩历史条目命中

### 5Why 根因分析

```
Why 1: 主代理用 Grep 搜索旧值准备更新 →
Why 2: Grep 返回结果同时命中历史段和现役段 →
Why 3: 主代理基于"是否命中旧值"判据决定是否更新 →
Why 4: 该判据无法区分历史事实与现役描述 →
Why 5: 主代理把历史变更日志中的旧版本号一并改成新版本号

  根本原因：Grep 无状态文本匹配，不可基于"命中旧值"做更新判据
  预防措施：必须基于条目所在语义位置（历史段 vs 现役段）做判据
```

## 四、修复策略

### 三步分类法

| 步骤 | 动作 | 工具 |
|:---:|:---|:---|
| 1 | Grep 搜索旧值，列出所有命中位置 | `Grep "v2.0.58"` |
| 2 | 逐条分类：现役描述 vs 历史条目 | 人工判断（基于语义位置） |
| 3 | 仅更新现役描述，保留历史条目 | Edit + Grep spot-check |

### 典型文件分类

| 文件 | 现役部分 | 历史部分 |
|:---|:---|:---|
| README.md | 头部"当前版本 v2.0.59" | 无（README 不保留历史版本号） |
| STRUCTURE.md | 表格当前结构 | 版本史段（v0.1/v0.5/...保留原值） |
| CHANGELOG.md | 当前版本段（W086 v2.0.59） | 历史版本段（W085 v2.0.58 保留） |
| file-index.md | 当前反向索引 | 历史变更记录（保留） |
| 项目说明.md | 当前项目说明 | 无 |

### 错误示例与正确示例

| 错误处置 | 正确处置 |
|:---|:---|
| Grep "v2.0.58" 命中 30 处，全部 Edit 改为 v2.0.59 | 逐条分类：现役 6 处更新为 v2.0.59，历史 24 处保留 v2.0.58 |
| 把 CHANGELOG W085 段的 "v2.0.58" 改为 "v2.0.59" | CHANGELOG W085 段保留 "v2.0.58"（历史事实） |
| 把 STRUCTURE 版本史 v0.5 行的版本号改成当前版本 | STRUCTURE 版本史 v0.5 行保留 v0.5（历史事实） |

## 五、预防措施

### 文档同步前必读

1. **Grep 搜索旧值只是发现候选位置**，不可作为"必须更新"的判据
2. **逐条分类**是必须步骤，不可省略
3. **历史变更日志条目永远保留旧值**，这是历史事实完整性要求

### 与 E1 升级版铁律互补

| 铁律 | 验证对象 | 验证方法 |
|:---|:---|:---|
| E1 升级版 | prior session 报告"已落地"是否真实 | Grep 搜索新值 spot-check |
| E2 本铁律 | Grep 搜索旧值的命中结果如何处置 | 逐条分类（历史 vs 现役） |

E1 升级版验证"是否落地"，E2 验证"如何处置命中结果"，两者互补。

### 与 mem-wrap-up Step 4a 协议升级协同

mem-wrap-up Step 4a 协议升级要求文档同步后 Grep spot-check 验证新值落地。本铁律补充：Grep spot-check 时也要验证**旧值仅剩历史段命中**（确认历史段未被误改）。
