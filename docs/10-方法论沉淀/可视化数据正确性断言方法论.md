## 一、问题背景：三层既有防线为何全都漏

站点的数据装载故障（数据没装上、装错、KPI 与数据不符）长期只能靠人工发现，因为当时三条防线各有盲区：

| 既有防线 | 实际覆盖面 | 盲区 |
|:---|:---|:---|
| 第 24 槽 图表静态自洽 | 页面内嵌数据与页面文本的自洽 | 不执行 JS——**"数据没装上但不报错"完全不覆盖** |
| `tests/unit/test_d3_data_processors.py` | 用 Python 重写 D3 逻辑做模拟测试 | 模拟 ≠ 真实渲染；D3 侧改动不与断言联动 |
| Playwright 截图审查 | 布局/溢出/视觉回归 | 空图与有图在缩略图上难以区分，且只看"有没有画出来" |
| 第 28 槽 可视化可引用性 | 数据源四要素（C1-C4）声明面 | 只查数据源"是否存在/是否声明"，不查渲染值 |

结论（W753 取证原话）：**W676 批次的数据装载族缺陷只能靠人工发现**。缺口是"真实渲染 × 取值一致性"，必须专门建一层。

## 二、方法论四件套

### 2.1 真实渲染优先，禁"起服务再测"
- 站点是 `file://` 双击可开的纯静态页 → 断言器用 Playwright **`file://` 直开**，不开本地服务器；
- 理由：起服务会改变 fetch 路径与 EMBEDDED 回退分支，测的不是用户真实入口（也就不再是同一份代码路径）。

### 2.2 双签名稳定等待（本方法论最关键的一条）
- **单一信号必踩坑**：只数元素会把 count-up 动画的中途值采成终值——实测 chapter-stats 采到 `96/100`；
- **双签名**：`图元数` + `KPI 文本`两个信号同时稳定才取样；
- 通用形态：`await 稳定(选择器签名A) && await 稳定(文本签名B)`，任一抖动即重试，超时按 fail-closed 处理。

### 2.3 先普查后定阈（禁拍脑袋阈值）
- 判据类门禁的阈值必须来自**全站普查分布**，不来自直觉；
- 本门禁实证：`S/L`（图元数 ÷ best-fit 数组长度）全站普查 `p00 = 0.82`、`p05 = 2.8` → 取远端下限 **`S/L ≥ 0.5`** 为 FAIL 线；
- 好处：阈值可解释、可复算、可随普查更新；坏处：首轮普查成本高——一次投入换长期稳定。

### 2.4 基线冻结 + fail-closed + 缺口报告
- **基线冻结**：`scripts/output/chart-values-baseline.txt`（87 页 × 6 项 = 522 行）。基线外新增、回归、图元数跌破基线 50% 恶化 = FAIL；**基线缺失拒绝通过**（不允许"没基线所以跳过"）；
- **fail-closed**：探针异常/超时/未产出结果 → `PROBE` 与 `V1-V5` 全 FAIL（宁可红，不可静默放过）；
- **缺口报告**：判不了的项记 `na` 并逐页逐条进 `chart-values-report.json`——**禁静默跳过**，缺口清单本身是可收敛的工作面。

## 三、五判据（V1-V5）与实际取值

| 判据 | 内容 | 判定 |
|:---|:---|:---|
| **V1 无 pageerror** | 页面级错误是数据装载失败的第一信号 | 任一 pageerror = FAIL |
| **V2 视图非空** | SVG 图元数 / 2D 画布像素 / Three 场景子对象 / 表格行 / DOM 数据项**任一 > 0** | 全为 0 = FAIL（防"数据没装上但不报错"） |
| **V3 数据量级自洽** | `S/L ≥ 0.5`（S=图元数，L=best-fit 数组长度） | 低于阈值 = FAIL；算不出 = na |
| **V4 KPI 可复算** | `[data-value]` / `.kpi-value` / `.kpi-card .num` 类数字须能由数据源复算（长度 / sum / max / mean / uniq） | 完全对不上 = na 缺口；**差 <2% 而不等 = 近失配 FAIL**（最危险的一类：看起来对，其实错） |
| **V5 数据源四要素** | 复用第 28 槽 C1-C4 口径 | 缺失只计缺口，不 FAIL |

## 四、实施步骤（建同类门禁的通用流程）

1. **划覆盖面**：确定"哪些页 × 哪些取值"算作正确性面（本门禁 = site/data 全部可视化页的图元与 KPI）；
2. **写探针**：真实入口（`file://`）+ 双签名等待 + 逐页采样；
3. **全站普查**：先只采集不判定，拿到分布（p00/p05 等）；
4. **定阈 + 冻结基线**：阈值取普查远端下限；基线文件入库（只增不改）；
5. **挂门禁槽位**：接入 `verify_delivery` 与 CI，声明 fail-closed 与缺口报告路径；
6. **写缺口台账**：首轮 na 逐页逐条落 JSON，作为后续收敛清单（而不是"沉默通过"）。

## 五、实测数据（W753 建线基线）

- **规模**：87 页 · 20 秒（5 workers）；
- **结果**：`0 FAIL` · `0 probe_error`；V1 ok=87、V2 ok=86/na=1、V3 ok=78/na=9、V4 ok=70/na=17、V5 ok=87；
- **解读**：17 页 KPI 不可复算不是"页面错了"，而是**口径不可机器推导**（历史累计去重、含未展开关联学者等）——这类差异的正确处置是记 na + 报告，而不是放宽阈值或改数据迎合门禁。

## 六、适用边界

- ✅ 覆盖：数据装载失败、空图、量级明显不足、KPI 与数据源不一致（含"近失配"）；
- ❌ 不覆盖：**语义正确性**（"数据值 == 原著"）——那属于内容可信度轨（第 20 门禁引文硬验证 + 抽检），成本高、暂作抽检候选；
- ⚠️ 维护成本：页面改版会使图元签名漂移 → 基线更新必须走门禁重跑 + 人工确认，禁手工改基线数字。
