# 菩提授业 · 避坑判据速查

> **编制位出处**：《取经编制表》§2 丙组 · **菩提祖师 · 授业官**（回目锚点 1）。
> 「那洞中有一个神仙，称名须菩提祖师。」（第 1 回）——**教完本事，不留姓名，不受香火**；
> 留下的是本事，不是人设。
> 编制表对本位的约束：**「技能内容仍以仓内 `pitfalls.md` 为唯一权威源，避免双源漂移」**——
> 所以本 skill 只放速查子集，完整条目永远在坑表里。

## 这个名字的意思

`puti-shouye` = 菩提授业。不叫 `guard` 是因为：守卫是挡在门外，授业是把本事交到你手上。
本 skill 不拦人，它只在你动手前提醒一遍——**该记得的都在这儿，要细节去查坑表**。

## 一、批次收官（最容易白跑门禁的地方）

1. **先 `git add` 再 `gen_folder_docs.py --refresh`**——生成器按 Git 索引收集，顺序反了必漏新件（第 45 槽报「索引有清单无」）。
2. **refresh 之后要再同步一次 spec 的 `file_index_rows`**——refresh 会新增/改动目录文档；不同步则第 51 槽必判「含本批 spec 之外的文件」。此坑在 W1019–W1028 连踩 6 次，每次白跑一轮门禁。
3. **`git mv` 的删除侧旧路径也要进 spec**——索引里同时记录新增与删除，只写新路径就过不了第 51 槽。
4. **`changelog_body` 必须以 `\n\n` 开场**——否则级联把段标题与正文粘成同一行，只能手工定向订正（级联不可重跑）。

## 二、判据与门禁（别把真缺陷修成假绿）

5. **判据禁止依赖脆弱特征**——块内注释文本、固定下标 `cells[4]`、纯子串匹配，都会在"内容格式一变"时静默失效。要改就改成**稳定契约**（标记配对 / 内容定位 / 词边界），并补回归锁。
6. **门禁红了先读 FAIL 原文 + 读判据源码**，不要只看汇总数字（汇总说"1 项 FAIL"，原文才有脚本名与明细）。分类只有四种：数据错 / 判据错 / 期望值过期 / 未落盘。
7. **禁止用豁免、白名单、补产物把红灯压绿**——那是补丁加补丁。判据错了就改判据，数据错了就改数据，二者必居其一。
8. **token 类触发器只认「状态列」，且「在途」不算事件**——否则写一行在途登记就能永久压制告警（fail-open）。建器还要与「给历史事件补 token」同批做，否则首跑必报「从未做过」。

## 三、历史与时效（改错了历史就变假）

9. **历史段不改写；可以改的是「状态」与「时效标注」**——判据：这一行描述的是「过去做了什么」（不改）还是「现在是什么状态」（必须改准）。
10. **删归档之前，先辨认「策略决定」与「已完成叙述」**——把仍在生效的策略约束（如"停止模板化扩容"）一起埋进归档，就是越界。
11. **文档里的操作步骤绑定当时的工具环境，环境一换即失效，而文档不会自己告诉你**——引用旧步骤前先确认它依赖的工具是否存在；写「待某工具重核」之前，先搜一遍当前可用的等效接口。
12. **归档只解「纵向增长」，不解「横向堆积」**——单文件无限追加才需要归档器；独立文件堆积该配「生命周期状态」。给 docs 正文配归档器＝用错工具。

## 四、给出与人协作

13. **给用户复制粘贴的命令/路径必须完整，禁用 `...` 省略号**——用户会原样照抄。要标明「整行替换」还是「插入到第 N 行之后」。
14. **「零引用」判定不能按 `.class` 搜**——HTML 写的是 `class="x"`（不带点）。要解析 class 属性分词，并并上 JS 的 `querySelector('.x')` 字面量；删零引用前两种写法各搜一次取并集。
15. **改/加 `docs/**.md` 会连锁触发搜索索引与 CSP**——顺序固定：改 md → `_gen_search_index.py` → `generate_csp.py` → 跑门禁。跳过前者第 46 槽红，跳过后者第 20 槽红。

## 怎么查完整条目

```bash
grep -n "关键词" docs/agent/pitfalls.md     # 六主题：CSS / JS·CSP / git·提交 / 级联·CHANGELOG / 数据可信度 / 流程协作
```

**六主题分项计数由第 31 槽 C5e 五处交叉对账**（坑表声明 / 实测 / AGENTS 总数 / AGENTS 分项 / HANDOVER 总数），改坑表必须实算分项，别手算。
