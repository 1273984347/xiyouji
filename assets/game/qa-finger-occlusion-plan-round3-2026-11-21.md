# 手指遮挡专项处理方案（第三轮）

> 2026-11-21 ｜ 范围：15 款单文件游戏（重点：7 款棋盘解谜 + 6 款动作/潜行 + 蟠桃园/取经牌途）
>
> **状态：已实施并复验（2026-11-21）**。实施结果见第九节；实测数据见 `qa-report-2026-11-21.md` 第七节。
>
> **定位**：第二轮已解决动作类“手指追角色、控制甲板、张力条、左右手”问题。第三轮处理**真机安全区、放大入口、剩余小目标、多指与起始点**，并把“竖屏 9:16”作为评估项而非默认改造。

## 一、第二轮后的剩余风险（实测）

测试口径：430×844、DPR 2、`pointer: coarse`、`file://` 直开；逐款开始后采集可见控件矩形。

| 风险 | 实测证据 | 影响 |
|---|---|---|
| 安全区完全缺失 | 15/15 无 `env(safe-area-inset-*)`；所有页面 `viewport-fit=cover` | 刘海、圆角、Home 指示条会压住控件 |
| 放大入口在拇指区 | 7 款棋盘页的“放大棋盘”固定 `right:10px; bottom:10px`，实测 86×41，y=793/844 | 想放大棋盘时，入口正好被持机手/Home 条盖住 |
| 放大工具条贴底 | `#qaZoombar` `bottom:12px`，在 Home 指示条热区 | 退出/撤回/重来可能被系统手势截获 |
| 顶部小按钮 | 15/15 的“音效/重来/全屏”高 33px | 低于 40–44px，误触率高 |
| 解谜 HUD 小按钮 | 五行阵/平顶山“?”25×28、镇火石“? 规则”46×25、蟠桃园暂停 31×28 | 关键帮助/暂停键偏小 |
| 棋盘外的小格 | 五行阵 17px、镇火石/平顶山 19px、法宝连消 20px、甘露引 27px、千灯阵 30px、经卷归位 32px | 未放大时仍难精准点选 |

| 多指未仲裁 | 火焰山/夜探瑶池使用单一 `drag`/`dragTarget` 状态，未记录 `pointerId` | 第二根手指落在画布会重置锚点/目标，拖拽跳变 |
| 起始点遮挡 | 若第一触点落在角色身上，相对拖拽仍会让角色停在手指下，直到移动 | “第一下”仍可能看不见角色 |

| 真机未验证 | 目前仅 Chrome Headless 触摸模拟 | iOS Safari 的 `100dvh`、安全区、音频解锁未知 |

## 二、目标与优先级

| 级别 | 目标 |
|---|---|
| P0 | 任何关键控件不落入安全区/Home 热区；放大入口可见可点；多指不重置拖拽；高频操作 ≥44px |
| P1 | 次级 HUD ≥40px；起始点脱困；真机回归；横屏全屏/方向锁定 |
| P2 | 按钮大小/透明度预设；竖屏 9:16 单款评估 |

**验收硬指标**

- 关键控件与 `safe-area-inset` 区域零相交。
- 放大入口 ≥48×48px，且不落在屏幕底部 96px 内。
- 高频按钮 ≥44×44px；次级按钮 ≥40×40px。
- 双指“移动 + 炸弹/定身”同时操作 3 秒，拖拽不重置、角色不跳变。
- 第一触点落在角色身上时，手指下移 28px 后角色仍完整可见。
- 15/15 smoke 0 error、0 横向溢出；桌面布局零变化。

## 三、方案

### 3.1 安全区基线（15 款统一）

在每款游戏注入同一段安全区变量与规则：

```css
:root{
  --safe-top: env(safe-area-inset-top, 0px);
  --safe-right: env(safe-area-inset-right, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left: env(safe-area-inset-left, 0px);
}
```

应用点：

- 顶栏：`padding-top: calc(10px + var(--safe-top))`。
- 竖屏触控条/控制甲板：`padding-bottom: calc(6px + var(--safe-bottom))`。
- 横屏左右栏：`right: calc(8px + var(--safe-right))` / `left: calc(8px + var(--safe-left))`。
- 放大工具条：`bottom: calc(12px + var(--safe-bottom))`，左右留 `--safe-left/right`。
- 首启“建议横屏”提示：`top: calc(6px + var(--safe-top))`。
- 全屏/刘海机型下，舞台保持居中，不贴安全区。

### 3.2 放大入口前移（7 款棋盘）

**问题**：放大按钮在右下 10px，是拇指和 Home 条的位置。

**方案（实施时调整为右侧中部入口）**：

1. 把“放大棋盘”从固定右下改为**右侧中部浮动入口**，48×48，距右 `calc(8px + var(--safe-right))`，垂直居中；静默 55% 透明度，按下恢复 100%。
   - 未采用顶部工具栏：430px 下顶栏已有“横屏/音效/重来”三键，再加“放大”会换行，压缩舞台高度。
   - 右侧中部入口不改变页面布局，单手右手拇指可直接触达，且远离底部 96px 热区。
2. 放大后的工具条改为 `bottom: calc(12px + var(--safe-bottom))`，按钮高度 ≥44px；工具条紧凑为 193×58，避免压住放大后的棋盘。
3. 进入棋盘页时，开始页/暂停菜单保留“放大棋盘”说明；入口本身常驻右侧。
4. 只保留一个放大入口，避免双入口增加遮挡面。
5. 375px 宽度下入口仍为 48×48，不压底部 Home 区。

**验收**：430×844 与 375×667 下，放大入口 48×48、不落入底部 96px；点击后棋盘内格 ≥42px；工具条按钮 ≥44px。

### 3.3 剩余触控目标清偿

| 对象 | 现状 | 目标 |
|---|---|---|
| 顶栏“音效/重来/全屏” | 33px 高 | coarse 指针下 `min-height:40px`，必要时收起重来 |
| 解谜 HUD “?”/“规则”/暂停 | 25–31px | 40×40，图标化并加 `aria-label` |
| 蟠桃园“卖出全部”/地块操作 | 30px 高 | `min-height:40px`；地块按钮 ≥44px |
| 黄风岭“开战” | 34px 高 | `min-height:44px` |
| 取经牌途“结束回合” | 34px 高 | `min-height:44px` |
| 棋盘格（未放大） | 17–32px | 不强行放大布局；以顶部放大入口 + 首启提示解决；放大后 ≥42px |

同时给所有按钮加 `touch-action: manipulation`，避免 iOS 双击缩放与 300ms 延迟；`-webkit-tap-highlight-color: transparent` 减少误触高亮。

### 3.4 多指与 pointerId 仲裁（火焰山/夜探瑶池/通天河）

现状：单一 `player.drag` / `dragActive`，第二根手指落到画布会覆盖 `touchAnchor` 与目标。

方案：

- 记录 `activePointerId`；`pointerdown` 时若已有活动指针则忽略。
- `pointermove` / `pointerup` / `pointercancel` 只处理 `e.pointerId === activePointerId`。
- 按钮（炸弹/定身/变身/收线）继续使用独立 DOM 事件，不受画布指针影响。
- 双指测试：一指拖动，另一指按炸弹/定身；拖拽连续、角色不跳、按钮正常触发。
- 通天河：按住收线时第二指点击画布不重置 `holding`；收线键与画布共享同一 `activePointerId`。

### 3.5 起始点脱困（火焰山/夜探瑶池）

问题：第一触点落在角色身上时，角色仍会被手指盖住。

方案：

- `pointerdown` 时计算触点到角色的屏幕距离；若 <28px，进入“脱困模式”。
- 脱困模式下，先忽略移动，直到指针相对起点向下移动 ≥28px（或任意方向移动 ≥28px），再开始相对拖拽；期间显示向下箭头与锚点。
- 脱困阈值 28px 可配置为“小/中/大”（0/28/44），默认中；关闭时等同当前行为。
- 这样第一下即使点在角色上，手指也会先离开角色再开始拖动。

**验收**：在角色中心按下→下移 30px→左右拖动；截图角色始终在触点上方 ≥20px。

### 3.6 横屏全屏与方向锁定（P1）

竖屏 410×231 的根因是 16:9 横向玩法。第三轮先提供低成本出口：

- 顶栏增加“横屏”按钮：`requestFullscreen()` + `screen.orientation.lock('landscape')`（支持的浏览器）。
- iOS Safari 不支持方向锁定：只进入全屏并提示“请旋转设备”，不报错。
- 记录 `localStorage` 偏好；下次进入可提示“上次横屏”。
- 该功能不改画布尺寸，不引入 9:16 布局风险。

### 3.7 按钮大小/透明度预设（P2）

- 动作类 6 款的触控按钮提供 S/M/L（48/56/64px）与 70%/85%/100% 透明度。
- 入口在暂停菜单，存 `localStorage`；默认 M/85%。
- 解决不同手型、拇指遮挡与误触差异；不改键位逻辑。

### 3.8 竖屏 9:16 评估（P2，先做一款）

- 只对火焰山做实验分支：竖屏舞台按 9:16 填充高度，HUD 顶部，炸弹键底部甲板。
- 评估指标：可见弹幕面积、角色可见率、单局误触次数、与 16:9 横屏的体验差。
- Go/No-Go：若可见面积提升 <20% 或弹幕判读变差，则不做全量 9:16，保留 16:9 + 横屏全屏。
- 不在本轮直接改 15 款布局。

### 3.9 真机回归矩阵（P1）

## 五、验证方法

- **安全区**：CDP `Emulation.setSafeAreaInsets`（支持时）或临时 CSS 变量注入，检查控件矩形与安全区零相交。
- **放大入口**：430×844 / 375×667 下读取 `#qaZoomBtn` 矩形，要求 ≥44×44 且 `bottom < innerHeight - 96`。
- **触控目标审计**：复用第二轮审计脚本，要求高频控件 `smallCount=0`（棋盘格除外）。
- **双指**：CDP `Input.dispatchTouchEvent` 两个 touchPoint，一指移动、一指按按钮，记录拖拽是否连续。
- **起始点脱困**：触点落在角色中心，下移 30px 后拖动，截图检查角色与触点圆不相交。
- **回归**：15/15 桌面/竖屏/横屏 smoke；0 error、0 横向溢出；桌面 1120×630 不变。

## 六、风险与回退

| 风险 | 处置 |
|---|---|
| 放大入口移到顶部后单手难触达 | 顶栏按钮 44px；真机回归验证；必要时增加右侧中部半透明副入口（可关闭） |
| 安全区变量在旧浏览器为空 | `env(..., 0px)` 回退；不影响桌面 |
| pointerId 仲裁破坏鼠标 | 仅对 `pointerType==='touch'` 启用仲裁；鼠标保持原逻辑 |
| 脱困模式产生“死区” | 阈值 28px + 向下箭头反馈；设置可关闭 |
| 横屏方向锁定 iOS 不支持 | 仅全屏并提示旋转；不报错 |
| 9:16 实验破坏弹幕判读 | 单款实验 + Go/No-Go；不默认全量 |
