# 残余问题修复方案：9:16 渲染管线与按钮尺寸溢出

> 2026-11-22 ｜ 状态：**批次 A、B、C、D 已全部实施（C 结论 Go）** ｜ 范围：15 款单文件游戏
>
> 上游依据：`qa-report-2026-11-21.md` 第七节、`qa-finger-occlusion-plan-round3-2026-11-21.md` 第八节。
> 本文只定方案与验收口径，不含代码改动。

**一句话结论**：9:16 缺的不是一条 `aspect-ratio`，而是「动态逻辑视口 + 等比映射 + 输入逆映射 + 布局重排」四件事；按钮溢出也不是「L 太大」，而是甲板单行定宽、无换行、甲板高度未参与舞台计算。建议**按钮先治（低风险、可独立交付）**，9:16 先做火焰山试点，过 Go/No-Go 再谈扩展。

## 一、取证

### 1.1 9:16 管线缺失（15/15 同构）

| 层 | 现状 | 证据 | 后果 |
|---|---|---|---|
| 逻辑视口 | 写死 `960×540` | `xiyou-huoyanshan.html` 第 295 行 `VIEW = { w: 960, h: 540 }`；15 款 `<canvas width="960" height="540">` | 竖屏没有第二套世界尺寸 |
| 绘制映射 | 横纵独立缩放 | 同文件 `render()` 第 1609–1612 行 `sx = canvas.width / VIEW.w`、`sy = canvas.height / VIEW.h`，`setTransform(sx,0,0,sy,0,0)`；15/15 同写法 | 竖屏容器直接拉伸，圆变椭圆、角色变形 |
| 输入映射 | 画布矩形直接映射到 `VIEW` | 第 1694–1726 行，无留白偏移 | 一旦引入等比留白（letterbox），触点会整体偏移 |
| 舞台尺寸 | 固定 16:9 | 第 54–62 行 `aspect-ratio:16/9`，`max-width` 按 `(100dvh - 196px) * 16 / 9` | 高度受限时宽度被公式锁死，竖屏无出口 |

结论：第三轮「CSS-only No-Go」成立——只改 CSS 必然拉伸；真正 9:16 必须新增一条渲染管线。

### 1.2 按钮尺寸溢出（实测 + 计算）

当前 5 款有触控甲板，尺寸各不相同：

| 游戏 | 键数 | 当前单键 | 单行内容宽（含 5×8px gap 与 16px 内边距） |
|---|---|---:|---|
| 白虎岭 | 6（5 圆 + 1 宽） | 56 / 64 | **400px** |
| 筋斗云 | 3（2 圆 + 1 宽） | 58 / 70 | 218px |
| 夜探瑶池 | 2 | 58 | 132px |
| 通天河 | 1 宽键 | 132 | 148px |
| 火焰山 | 1 | 58 | 74px |

- **375px 宽**：body 左右各 `clamp(10px, 2.2vw, 26px)` → 内容宽 355px；白虎岭当前 M 档需 400px，**已经溢出 45px**，不是只有 L 档的问题。
- **410px 内容宽**（430px 机型）：M 档 400px 仅余 10px；L 档 `64×5 + 72 + 40 + 16 = 448px`，溢出 38px。这与第三轮「6 键甲板 410px 下 L 号溢出」一致。
- `.touch-group` 无 `flex-wrap`（白虎岭第 412 行），甲板不会换行。
- 甲板高度未进入舞台公式：白虎岭 `max-width: min(1120px, (100dvh - 168px) * 16 / 9)`（第 399 行）、火焰山 `(100dvh - 196px)`（第 137 行）均为固定值；甲板换行后舞台不会让位，会顶出首屏。

结论：溢出的根因是「单行定宽 + 无换行 + 高度不联动 + 无尺寸档位」，修尺寸档位必须同时修前三项。

## 三、按钮尺寸方案（批次 A，已实施）

### 3.1 尺寸档位：按各游戏基准 ±8px

不强行统一到 48/56/64，保留各游戏现有手感，只做相对档位：

| 游戏 | S | M（默认，即现状） | L | 宽键规则 |
|---|---|---|---|---|
| 白虎岭 | 48 | 56 | 64 | 宽键 +8（56 / 64 / 72） |
| 筋斗云 | 50 | 58 | 66 | 宽键 +12（58 / 70 / 82） |
| 夜探瑶池 | 50 | 58 | 66 | — |
| 通天河 | 56 | 64 | 72 | 宽键 −16（116 / 132 / 148） |
| 火焰山 | 50 | 58 | 66 | — |

S 档下限 48px，仍高于 44px 高频门槛；L 档只影响触控甲板，不影响顶栏/HUD。

### 3.2 CSS 变量 + 允许换行

```css
body{
  --qa-tbtn:56px; --qa-tbtn-wide:64px;
  --qa-deck-gap:8px; --qa-deck-pad:6px 8px;
}
body[data-qa-btn-size="s"]{--qa-tbtn:48px;--qa-tbtn-wide:56px}
body[data-qa-btn-size="m"]{--qa-tbtn:56px;--qa-tbtn-wide:64px}
body[data-qa-btn-size="l"]{--qa-tbtn:64px;--qa-tbtn-wide:72px}
.tbtn{width:var(--qa-tbtn);height:var(--qa-tbtn)}
.tbtn.wide{width:var(--qa-tbtn-wide)}
.touch-group{flex-wrap:wrap;gap:var(--qa-deck-gap);justify-content:flex-end}
```

- 每款把自身基准写进 `:root` 覆盖（如筋斗云 M=58/70），共享层只负责档位切换。
- 换行策略：≥520px 单行；390–519px 允许两行；<390px 强制两行（6 键 3+3，3 键 2+1），提示文字隐藏。
- 换行后行高一致，圆键不缩放，只重排。

### 3.3 甲板高度与舞台联动

```js
// 共享脚本：只在实际换行时写入额外高度
var deck = document.querySelector('.touch');
function syncDeck(){
  var wrapped = deck && deck.scrollWidth > deck.clientWidth + 1;
  document.body.dataset.qaDeckWrap = wrapped ? '1' : '0';
  document.body.style.setProperty('--qa-deck-extra',
    wrapped ? Math.max(0, deck.offsetHeight - 70) + 'px' : '0px');
}
```

```css
@media (pointer: coarse){
  .stage{
    max-width:min(1120px,
      calc((100dvh - 196px - var(--qa-deck-extra,0px)) * 16 / 9))!important;
  }
}
```

`196px` 用各游戏现有常量替换（白虎岭 168、筋斗云 196），避免统一值造成回归；只在 `data-qa-deck-wrap="1"` 时生效。

### 3.4 防溢出兜底（机器判据，不靠肉眼）

档位应用后测量一次，仍溢出则临时降级并提示，**降级结果不写回 localStorage**：

```js
function fitSize(){
  var deck = document.querySelector('.touch');
  if (!deck) return;
  if (deck.scrollWidth <= deck.clientWidth + 1) return;
  if (current === 'l') applySize('m', {transient:true});
  else if (current === 'm') applySize('s', {transient:true});
  toast('屏幕较窄，已临时使用小号按钮');
}
```

LS 只保存用户选择（`xyj_touch_size_v1` = `s|m|l`，默认 `m`）；实际档位允许随屏宽临时下调。

### 3.5 入口与持久化

- 暂停菜单 `.actions` 追加「按钮：中/小/大」，位置紧随第三轮透明度按钮 `#qaOpacityBtn`（实施时因竖屏暂停面板会被裁切，调整为一体式底部固定设置条，见第九节）。
- `aria-label="切换触控按钮大小"`；点击循环 S→M→L→S，立即重排并 `fitSize()`。
- `localStorage` 键 `xyj_touch_size_v1`；读写全程 `try/catch`（`file://` 下部分浏览器禁存储）。
- 桌面（`#qaOpacityBtn` 不注入的场景）不显示尺寸按钮。

### 3.6 逐款适配

| 游戏 | 改动 |
|---|---|
| 白虎岭 | 6 键甲板变量化；<520px 两行；甲板高度联动 |
| 筋斗云 | 3 键甲板变量化；两行阈值 360px |
| 夜探瑶池 | 2 键变量化，溢出不明显，仅接入档位 |
| 通天河 | 单宽键变量化，宽键 116/132/148 |
| 火焰山 | 单键变量化，仅接入档位 |
| 其余 10 款 | 无 `.tbtn` 甲板，不接档位；不动 |

## 四、9:16 方案（批次 B–D）

### 4.1 三条路线对比

| 路线 | 做法 | 收益 | 结论 |
|---|---|---|---|
| A. 只改 CSS | `aspect-ratio:9/16` | 0 | 拉伸变形，已知 No-Go，不再考虑 |
| B. 等比留白（letterbox） | 保持 960×540 世界，竖屏画布上下留黑 | 无变形、改动小 | 可见战场仅 364×205，比现在更小，只作技术兜底 |
| C. 真竖屏世界 | 新增 540×960 逻辑视口，布局按竖屏重排 | 可见面积约 2.5 倍 | **推荐，仅对竖屏友好玩法** |

推荐组合：**C 用于试点与竖屏友好款；B 作为未适配游戏的兜底（其实维持 16:9 + 横屏提示即可，不必启用 B）**。

### 4.2 渲染管线改造（四件事）

1. **动态逻辑视口**：`VIEW` 从常量改为按方向取值，例如 `portrait ? {w:540,h:960} : {w:960,h:540}`；所有 `VIEW.w/h` 引用不改名。
2. **等比映射 + 留白**：

```js
const s = Math.min(canvas.width / VIEW.w, canvas.height / VIEW.h);
const ox = (canvas.width - VIEW.w * s) / 2;
const oy = (canvas.height - VIEW.h * s) / 2;
ctx.setTransform(s, 0, 0, s, ox, oy);
ctx.fillStyle = '#17120E';
ctx.fillRect(-ox / s, -oy / s, canvas.width / s, canvas.height / s);
```

3. **输入逆映射**（CSS 像素直接算，避开 DPR 换算）：

```js
const rect = canvas.getBoundingClientRect();
const k = Math.min(rect.width / VIEW.w, rect.height / VIEW.h);
const x = (e.clientX - rect.left - (rect.width - VIEW.w * k) / 2) / k;
const y = (e.clientY - rect.top - (rect.height - VIEW.h * k) / 2) / k;
```

4. **舞台与 HUD**：竖屏下 `.stage{aspect-ratio:9/16; max-width:min(100%, calc((100dvh - var(--qa-chrome-h)) * 9 / 16))}`；HUD 用百分比/安全区定位，不写死横向像素；触控甲板仍在舞台下方。

> 管线必须同时覆盖 `pointerdown/move/up`、`resetDrag()`、起始点脱困的触点坐标，否则会出现「画面对了、拖拽偏了」。

### 4.3 玩法适配（火焰山试点）

竖屏不是把 960×540 塞进 540×960，而是 540 宽世界重排。初值如下，试点标定：

| 量 | 横屏 960×540 | 竖屏 540×960 | 规则 |
|---|---:|---:|---|
| 世界宽 / 高 | 960 / 540 | 540 / 960 | 宽度 ×0.5625，高度 ×1.778 |
| 玩家初始 y | 438 | 780 | 底部约 81% |
| 玩家 clamp | x 22–938，y 70–510 | x 22–518，y 70–930 | 边距沿用 22/70/30 |
| 玩家速度 | 290（慢速 140） | 180（慢速 90） | 目标屏幕速度与横屏接近（≈120px/s） |
| Boss 初始 y | 196 | 330 | 上 1/3 |
| 敌弹纵向速度 | 240 | 380–430 | 保持「从刷出到玩家」时间不变 |
| 刷怪 x 范围 | 0–960 | 40–500 | 两侧留 40 |
| 屏幕内弹幕目标 | 当前基准 | 当前基准 ±15% | 以密度而非数量为准 |

同时检查：Boss 血条宽度（`min(520px,72%)` 在 540 世界下会偏宽，改 `min(300px,86%)`）、三阶段火环半径按 540 宽重算、擦弹判定 `hitR` 不随宽度缩小。

### 4.4 方向策略

- **自动识别**：`orientation: portrait` 且该游戏 `data-qa-portrait="1"` 时启用竖屏世界；否则维持 16:9。
- 不新增用户开关；第三轮顶栏「横屏/全屏」按钮保留，横屏仍可强制。
- 监听 `orientationchange` 与 `resize` 重建 `VIEW`、重算画布与输入映射；切换时暂停一帧并清空拖拽状态，避免跨方向残留坐标。

### 4.5 试点与 Go/No-Go

只改火焰山，连续 3 局（390×844、430×932、360×800）采集：

| 指标 | Go 条件 |
|---|---|
| 可见战场面积 | ≥ 现 16:9 的 2 倍（预期 410×231 → 375×666，约 2.6 倍） |
| 画面变形 | 截图圆形成像宽高比误差 ≤2% |
| 帧率 | 中端模拟 60fps，`requestAnimationFrame` 平均 ≤17ms |
| 可玩性 | 3 局试玩：玩家可见率 100%，不出现「弹幕从身后出现」；误触次数 ≤ 横屏 |
| 桌面/横屏 | 1440×980 与 844×390 截图与当前逐像素级布局一致（文案/HUD 位置不变） |

任一硬指标不过 → 火焰山回退 16:9，9:16 结论改为「仅技术储备」，不进入扩展。

### 4.6 扩展清单（Go 之后）

| 游戏 | 是否扩展 | 理由 |
|---|---|---|
| 火焰山 | 试点 | 纵向弹幕天然适配 |
| 通天河 | 第二批 | 静态河景，只需重排岸线/浮标，风险低 |
| 取经牌途 | 第三批 | 卡牌竖排天然，但手牌区需重排，改动中等 |
| 白虎岭、筋斗云、黄风岭 | 不扩展 | 横版卷轴，竖屏会压缩预判距离 |
| 夜探瑶池 | 不扩展 | 960×540 地图已定，竖屏只能裁切或留白 |
| 7 款棋盘/经营 | 不扩展 | 已有放大棋盘；竖屏只增加空白，无收益 |

### 4.7 回退

- `data-qa-portrait="0"` 一键关闭竖屏世界，回到 16:9（默认值）。
- 保留等比映射：即使误开竖屏，也只是留白，不再拉伸。
- 不改 `localStorage` 玩法数据；方向切换不触发重开。
